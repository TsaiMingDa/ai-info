**繁中改寫：**
加入 Anthropic 之前，我曾經花了大概兩週，用 Opus 4 把這個東西當 side project 在做。那時候用的是 Agent SDK，所以需要一個一直跑著的 process，效果也不太好。

結果現在只丟一個 prompt 給 Opus 5.5，它就把整個專案移植到 Claude Managed Agents 上，穩定度大幅提升。

**核心概念（簡單說）：**
這則在講兩種「跑 agent」的架構差異。Agent SDK 是一個函式庫：agent loop 跑在你自己的機器或伺服器上，所以你得自己維持一個常駐 process、自己處理當機重啟、排程、環境與沙箱——就像自己架一台 Node server 跑 cron job。Claude Managed Agents 則是「agent in the cloud」的託管 API：沙箱、執行環境、長時間任務的生命週期都由平台負責，你只要定義 agent 要做什麼、什麼時候跑。差別有點像「自己在 VPS 上跑 PM2」對比「丟到 serverless / managed job 平台」。

另一個重點是「模型能力讓遷移成本歸零」。以前把專案從一套 runtime 搬到另一套，要讀文件、改架構、debug 好幾天；Thariq 說 Opus 5.5 一個 prompt 就搬完。這代表當你在選技術架構時，「之後換掉很麻煩」這個顧慮的權重正在下降，可以更大膽地先選最快能動的方案，之後再讓 agent 幫你遷移。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端工程師常做的「個人小工具」（每日摘要頁、自動截圖比對、依賴更新報告）最卡的往往不是寫程式，而是「要放在哪裡持續跑」。託管式 agent 讓你不必再顧一台常駐機器。
- **具體場景：** 你有一個用 Agent SDK 寫的 Node script，每天抓公司 Storybook 與 Figma 的變更做差異報告，但它只能在你筆電開著時跑。把專案丟給 Claude Code，請它「把這個 Agent SDK 專案改成用 Claude Managed Agents 執行，排程每天早上 8 點」，產出的報告再寫成靜態 HTML 推到 GitHub Pages。
- **這週可以嘗試：** 挑一個你目前靠本機 cron／工作排程器在跑的小 script，請 Claude Code 評估移植到 Managed Agents 需要改哪些地方（環境、權限、輸出位置），先讀它的分析，再決定要不要真的搬。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.296 / October 9, 2026

**變更項目：**
- Added `autoCompactWindow` to subagent frontmatter and `--agents` definitions, so a subagent can auto-compact earlier than the main conversation's window — subagent 可以設定自己的 auto-compact 門檻，比主對話更早壓縮 context。
- Added `CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL` to run every workflow agent on one model while other subagents keep theirs — 新環境變數，讓所有 workflow agent 統一使用指定模型，其他 subagent 不受影響。
- Added `CLAUDE_CODE_OVERLOADED_RETRY_MAX_DELAY_MS` to set a longer maximum delay for the backoff when retrying an overloaded (529) request — 新環境變數，可拉長遇到 529（過載）時重試退避的最長等待時間。
- Added an `allow_large` option to the Read tool so Claude can read a text file past the usual size limits in one call — Read 工具新增 `allow_large`，context 有空間時可一次讀完超過一般大小上限的檔案。
- Added a `code` key to the Claude apps gateway's `managed.policies[]`, also applied in Claude Desktop's Code tab — Claude apps gateway 的管理政策新增 `code` 設定，同時套用到 Claude Desktop 的 Code 分頁。
- Added a note in `/plugin` on a plugin whose hooks are left out because another enabled plugin has the same name — `/plugin` 會提示因同名 plugin 而被略過 hooks 的情況。
- Changed the default limit on MCP tool descriptions sent up front and on MCP server instructions from 2,048 to 4,096 characters — 預先送出的 MCP 工具描述與 server instructions 上限從 2,048 放寬到 4,096 字元。
- Updated `/cost`, the status line, `--max-budget-usd` and the SDK's cost figures to price Sonnet 5.5 cache reads at $0.10 per million tokens (was $0.20) — 成本計算改用 Sonnet 5.5 cache read 新價格：每百萬 token $0.10（原為 $0.20）。
- Changed ←: a turn or `!` command started while the session moves to the background is now stopped instead of finishing out of sight — session 移到背景時，正在啟動的 turn 或 `!` 指令會被停止，不再在看不到的地方偷偷跑完。
- [VSCode] Changed Claude in Chrome to ask before browser actions in every session — VS Code 中 Claude in Chrome 每個 session 都會在瀏覽器操作前先詢問。
- Improved `--debug` output for hooks: command hooks now log their command, plugin, outcome and duration, so a slow hook is identifiable — `--debug` 會記錄每個 hook 的指令、所屬 plugin、結果與耗時，方便找出拖慢的 hook。
- Improved `--debug` output to name unrecognized frontmatter fields in custom agent files, with a hint for likely typos — 自訂 agent 檔的 frontmatter 有未知欄位時會指出，並提示可能的拼字錯誤。
- Improved transcript toggle (ctrl+o) responsiveness in code-heavy conversations by caching syntax-highlighted code blocks — 快取語法高亮後的程式碼區塊，程式碼多的對話切換 transcript 更順。
- Fixed Edit and NotebookEdit replacing every non-ASCII character in files that are not valid UTF-8 (Windows-1252, Shift-JIS, GBK); such edits are now refused — 修正編輯非 UTF-8 檔案（Windows-1252、Shift-JIS、GBK 等）時把所有非 ASCII 字元弄壞的問題，現在改為拒絕編輯。
- Fixed Bash permission checks auto-approving some commands that assign the `BASH_ARGV0` shell variable and then use it — 修正部分設定 `BASH_ARGV0` 的 Bash 指令被自動核准的權限漏洞。
- Windows: Fixed PowerShell commands longer than about 1 KB always asking for permission; allow rules and read-only detection now apply up to 32 KB — Windows 上超過約 1 KB 的 PowerShell 指令不再一律詢問權限，allow 規則可套用到 32 KB。
- Windows: Fixed the Workflow tool refusing script files with CRLF line endings — Workflow 工具可接受 CRLF 換行的 script 檔。
- [VSCode] Fixed chat links written as a full Windows path, such as `C:\repo\file.ts`, not opening the file on Windows — VS Code 中完整 Windows 路徑的連結現在能正確開啟檔案。
- 另含 Claude Tag、Cloud sessions、Code Review、mods／plugins 等多項變更，以及 9 項改善、56 項 bug 修正（詳見原始 changelog）。

**核心概念（簡單說）：**
這版的主軸是「讓多 agent 工作流更可控」。`autoCompactWindow` 讓 subagent 在 context 用到一定程度時就先壓縮，而不是等到跟主對話一樣大才處理——適合那些會讀大量檔案、log 的 subagent，避免它們塞爆 context 後品質下降。`CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL` 則讓你把整批 workflow agent 統一換成較便宜的模型（例如 Haiku 5.5）來省成本。搭配 Read 的 `allow_large`，Claude 遇到大型檔案（例如一個肥大的 bundle 報告或 lockfile）時可以一次讀完，不用分段讀到一半就斷。

另一條線是除錯與安全：hook 的 `--debug` 紀錄終於會列出耗時，能找出「每次跑工具都卡兩秒」的元兇；而非 UTF-8 檔案的編輯從「默默弄壞」改成「直接拒絕」，Bash 權限也補了一個 `BASH_ARGV0` 繞過的漏洞。Windows 使用者則受惠於 PowerShell 長指令權限判斷與 CRLF 修正。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端專案常有大型產物（`package-lock.json`、`stats.json`、Lighthouse 報告）和大量 hook（lint、format、type-check），這版正好同時改善「讀大檔」與「找出慢 hook」兩個痛點；在 Windows 上開發的人也少了很多莫名的權限詢問。
- **具體場景：** 你有一個專門分析 webpack／Vite bundle 的 subagent，每次都要讀幾 MB 的 `stats.json`；在它的 frontmatter 加上 `autoCompactWindow`，讓它讀完報告整理出結論後就先壓縮，再把精簡結果交回主對話。同時用 `claude --debug` 跑一次，看看 PostToolUse 的 `prettier --write` 或 `eslint --fix` hook 各花了多少時間。
- **這週可以嘗試：** 執行 `claude --version` 確認已更新到 2.1.296，接著用 `claude --debug` 開一個 session 做幾次檔案編輯，檢查 debug log 裡每個 hook 的耗時，把超過 1 秒的 hook 改成只針對變更檔案執行（例如 `eslint --fix <file>` 而非整個專案）。
