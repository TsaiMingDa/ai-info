- Added sign-in to organizations managed in Anthropic’s Enterprise Admin Console: after `claude auth login`, Claude Code applies the organization’s settings and uses its cloud provider or gateway — 支援登入由 Enterprise Admin Console 管理的組織，登入後自動套用組織設定與指定的雲端供應商／gateway。
- Added easel, a built-in mod that draws charts when asked and under MCP metrics results, on Pro, Max and, where available, Team and Enterprise on macOS and Linux; turn automatic charts off in `/config` — 新增內建 mod「easel」，會依要求或在 MCP 指標結果下方畫圖表（macOS／Linux），可在 `/config` 關閉自動圖表。
- Added `CLAUDE_CODE_FULL_SIGN_IN_LINK=1` to print the full sign-in link — 可印出完整登入連結，短連結出錯時使用。
- Self-hosted runner: Added `--start-dir` / `SELF_HOSTED_RUNNER_START_DIR` to have Claude start its work in a folder of a repository — self-hosted runner 可指定從 repo 內某個子資料夾開始工作（適合 monorepo）。
- [VSCode] Added `/fork` to fork a conversation after its last reply — VS Code 可用 `/fork` 從最後一則回覆分岔對話。
- [VSCode] Added `/workflows`, which opens the agent map with running workflows — 開啟顯示執行中 workflow 的 agent map。
- [VSCode] Added the `claudeCode.escapeStopsClaude`, `claudeCode.pinPrompt` and `claudeCode.contextUsageThreshold` settings — 可設定 Esc 是否中止 Claude、訊息是否固定在頂部、context 用量指示何時顯示。
- Changed recurring scheduled tasks and `/loop` to run up to 30 days instead of 7 while their session keeps running, and say when they end — 週期排程任務與 `/loop` 的最長執行期間從 7 天延長為 30 天（舊任務仍為 7 天）。
- Changed more `rm` commands aimed at the root, home, a top-level folder or the working folder to ask for approval; where nobody can answer, they’re refused — 更多針對根目錄、家目錄、頂層資料夾或工作目錄的 `rm` 指令改為需要確認；無人可回應時直接拒絕。
- Reverted 2.1.329’s removal of the automatic retry when `max_tokens` exceeds a model’s or gateway’s limit — 撤回 2.1.329 移除 `max_tokens` 超限自動重試的變更。
- Changed `claude --teleport` in some setups to print the git commands for switching branch instead of running them — 部分情境下 `--teleport` 改為印出切換分支的 git 指令，而非直接執行。
- Changed prompt hooks to accept model aliases such as `haiku` or `sonnet` in their model field — prompt hook 的 model 欄位可用 `haiku`、`sonnet` 等別名。
- Changed subagent progress summaries in sessions signed in to a Claude apps gateway to be written from short notes, using far fewer tokens — gateway 環境下 subagent 進度摘要改用精簡筆記產生，大幅省 token。

**核心概念（簡單說）：**
2.1.330 有三條主線。一是企業管理：組織可以透過 Enterprise Admin Console 統一下發設定，工程師 `claude auth login` 後就自動套用公司規定的 provider、gateway 與權限，不必每人手動配置。二是安全再收緊：危險範圍的 `rm` 一律要確認，延續最近幾版「預設嚴格」的路線。三是體驗面：內建 easel mod 會把數據自動畫成圖表，VS Code 擴充功能補上 `/fork`、`/workflows` 與多個可調設定，排程任務與 `/loop` 也能一路跑到 30 天。

可以把企業登入想成前端專案的共用 ESLint／Prettier 設定包：與其每個人各自設定，不如由組織統一發布，個人只要「登入」就自動同步。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你用 `/loop` 或排程任務做每日檢查（例如每天跑 Lighthouse、檢查依賴更新），現在可以連續跑一個月不用重設；在 VS Code 裡用 `/fork` 也能在不破壞原對話的情況下嘗試另一種實作方向。
- **具體場景：** 你在 VS Code 裡和 Claude 討論一個表單狀態管理的重構，已經走到「用 `useReducer`」的方向，但想試試 React Hook Form 會不會更好。用 `/fork` 從目前對話分岔出去試，兩條路線各自保留脈絡，比較完再決定，不用重新解釋需求。
- **這週可以嘗試：** 升級後在 VS Code 設定裡調整 `claudeCode.contextUsageThreshold`（例如設成 60%），讓 context 快滿時提早看到提示，搭配 `/fork` 或開新對話，避免長對話後期品質下降。

**版本號 / 日期：** 2.1.329 / November 19, 2026

**變更項目：**（以下節錄與日常開發最相關的部分）
- Added a trust dialog warning that says where a folder’s hooks are declared — 信任資料夾的對話框會標出 hooks 宣告在哪個檔案。
- Added this session’s scheduled tasks, `/loop` wakeups, the goal and this conversation’s forks to `/tasks`; `x` stops one after asking — `/tasks` 現在列出排程任務、`/loop` 喚醒、goal 與對話分岔，按 `x` 確認後可停止。
- Added a “Server message” row to a server’s page in `/mcp` that shows the JSON-RPC error message of a remote HTTP MCP server that refuses the connection — `/mcp` 會顯示遠端 HTTP MCP server 拒絕連線時的 JSON-RPC 錯誤訊息。
- Added support for turning on Code Mode while OpenTelemetry events and metrics are enabled — 開啟 OpenTelemetry 事件與指標時也能使用 Code Mode。
- [VSCode] Added a line above the message box after you decline the trust prompt, with Review trust to bring the prompt back without reloading the window — 拒絕信任後可直接重新叫出信任提示，不必重新載入視窗。
- Changed `/code-review` with no target on most models to review the whole branch against the default branch, and fixed it losing the diff on multi-commit branches — `/code-review` 不帶參數時改為審查整個分支相對預設分支的變更，並修正多 commit 分支遺失 diff 的問題。
- Changed `/code-review <pr number> --fix`, and `/code-review` given a pull request URL, to stop without reviewing when `gh pr diff` is refused or fails — 取不到 PR diff 時直接停止，不做無效審查。
- Changed auto mode to run `git status` less often so most requests wait less in large repositories — auto mode 減少執行 `git status`，大型 repo 等待時間變短。
- Changed saved scheduled tasks: in new signed-in sessions, most saved by earlier versions need scheduling again — 舊版存下的排程任務，在新登入的 session 中多數需要重新排程。
- Changed Code Mode so a PreToolUse hook that errors no longer refuses a script’s tool call; set `"onFailure": "block"` on a hook that must refuse — Code Mode 中 PreToolUse hook 出錯不再自動擋下呼叫，必須擋的要明確設 `"onFailure": "block"`。
- Updated computer use on macOS to newer safety rules, so some actions are refused and some apps have less access — macOS computer use 套用新的安全規則，部分動作與 App 存取受限。
- Removed 2.1.326’s automatic retry at the limit named in a `max_tokens` error（已於 2.1.330 撤回）— 移除 `max_tokens` 超限自動重試（2.1.330 又恢復）。

**核心概念（簡單說）：**
2.1.329 聚焦在「看得見」與「控得住」。`/tasks` 變成背景工作的總控台，排程、`/loop`、分岔對話都集中在同一處管理；`/mcp` 直接顯示遠端 server 的錯誤訊息，除錯 MCP 連線不用再盲猜；信任對話框會告訴你 hooks 寫在哪個檔案，避免不知情地執行陌生 repo 裡的 hook。

`/code-review` 的預設行為也變了：不帶參數時審查「整個分支 vs. 預設分支」，而不只是未提交的變更，更接近 PR review 的實際範圍。另外要注意，舊版存下的排程任務可能需要重新排程，有用排程跑例行工作的人升級後要檢查一下。

**前端工程師實際應用：**
- **跟你工作的關聯：** 開 PR 前跑 `/code-review` 現在預設就會看整個 feature branch，跟 reviewer 看到的 diff 範圍一致；串接 Figma、Linear 等遠端 MCP 失敗時，`/mcp` 頁面能直接看到錯誤原因。
- **具體場景：** 你在 `feature/checkout-redesign` 分支上累積了 8 個 commit，改了結帳流程的多個元件。以前 `/code-review` 可能只看到最後的變更或漏掉 diff，現在直接跑就會審查整個分支相對 `main` 的差異，抓到早期 commit 留下的問題（例如某個 `useMemo` 依賴陣列寫錯）。
- **這週可以嘗試：** 升級後執行 `/tasks`，確認你之前設定的排程任務是否還在；如果消失了就重新排程，並順手把不再需要的任務按 `x` 停掉。
