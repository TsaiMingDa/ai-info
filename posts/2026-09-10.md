**原文：**
> New on Claude Marketplace: @CrowdStrike, @cursor_ai, @FactoryAI, @GammaApp, and @vercel.
>
> Enterprises can now use their Anthropic spend commitment to buy more Claude-powered products and agents.
>
> Get started: claude.com/platform/marketplace

**繁中改寫：**
Claude Marketplace 新上架：CrowdStrike、Cursor、Factory AI、Gamma、Vercel。企業客戶現在可以直接用手上既有的 Anthropic 消費承諾（spend commitment）購買更多 Claude 驅動的產品與 agent，不需要另外走一輪採購流程。

**核心概念（簡單說）：**
這是 Anthropic 持續擴張的「Claude Marketplace」生態系公告：企業跟 Anthropic 簽的年度消費承諾（類似雲端服務常見的 committed spend），現在可以拿去買第三方廠商（像資安公司 CrowdStrike、IDE 廠商 Cursor、簡報工具 Gamma、部署平台 Vercel）推出的 Claude 整合產品。對企業採購來說，這等於把「買 Claude API 額度」跟「買生態系夥伴的產品」合併成同一筆預算，降低採購摩擦，也讓這些第三方廠商更有動機把 Claude 整合進自家產品。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果公司是用 Anthropic 企業合約，之後採購 Vercel、Cursor 這類你日常會用到的開發工具時，可能可以直接動用既有的 Claude 預算，值得跟內部採購或平台團隊確認一下。
- **具體場景：** 例如團隊想導入 Vercel 的進階功能或 Cursor 的企業版授權，過去要走獨立的採購申請，現在若公司有 Anthropic spend commitment，理論上可以直接折抵，加快內部流程。
- **這週可以嘗試：** 到 claude.com/platform/marketplace 瀏覽一下目前上架的夥伴清單，看看有沒有你團隊正在用、或想導入的工具已經在裡面，回報給負責採購/平台的同事參考。

**核心概念（簡單說）：**
這個版本是一次以「穩定性收斂」為主軸的大更新，重點集中在兩塊：第一是大量修復 prompt-cache 在各種恢復（resume）情境下失效的問題——包括 subagent、多模型切換、MCP connector 重連、`-p` 模式恢復等十幾個相關 bug，這些過去都會導致 Claude Code 在長任務中反覆重算整個 context，既慢又燒 token；第二是新增 `maxEffortLevel` 這類企業級的用量控管設定，以及一系列安全邊界檢查修復（backslash 路徑繞過、managed 設定讀取失敗時預設拒絕）。此外 VS Code 與 Claude Tag 分別也修了多個各自平台特有的顯示與連線問題。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你日常會用 subagent、`/model` 切換模型、或透過 `-p --resume` 跑自動化流程，這版修的一大串 prompt-cache bug 會直接反映在回應速度和 token 花費上；VS Code 使用者也會感受到 diff 主題跟隨、CRLF 檔案編輯等實際體驗改善。
- **具體場景：** 例如你在 VS Code 裡用淺色主題開發，但過去 diff 區塊永遠是深色、看起來很突兀，這版修完後 diff 會正確跟隨你的編輯器主題；如果你的專案用 Windows CRLF 換行，之前在 diff 畫面接受修改常會噴「String not found in file」，這版也一併修掉了。
- **這週可以嘗試：** 升級到 2.1.267 後，若你有用 `--resume` 恢復大型 session（尤其是含大量 Bash 呼叫的），實測一下首次渲染速度是否變快；VS Code 使用者可以切換一下編輯器主題，確認 diff 區塊是否正確跟隨。
