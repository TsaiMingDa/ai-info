**繁中改寫：**
Claude 推出 Claude Duet 研究預覽版：一個讓 Claude 以「主動型 agent」身分工作的新 app。它會主動告訴你哪些事需要你處理、幫你完成交辦的任務、在你離開時繼續做事，並在代表你採取行動前先跟你確認。

Duet 以 Claude Opus 5.5 為核心，由模型判斷哪些事需要你、哪些可以等、什麼時候該先問你。它會沿用你 Claude 帳號裡的 memory、skills 與已連接的 app，幾乎不用另外設定。安全方面，Duet 從不直接看到你的密碼，還有新的 classifier 防止敏感資訊外流，重要決定仍由你拍板。目前是早期研究預覽，只開放美國 Pro / Max 方案用戶透過 waitlist 申請，官方也坦言它有時還會誤判急迫程度。

**核心概念（簡單說）：**
過去的 AI 助理是「被動型」：你問它才答，你關掉視窗它就停。Duet 換成「主動型」模式：它常駐背景、持續觀察你連接的服務（信箱、行事曆、各種 app），自己判斷什麼值得打擾你，並在動手前請你核准。關鍵難題不是「會不會做事」，而是「判斷力」：什麼該自己處理、什麼該問人，這就是官方強調用 Opus 5.5 的原因。

用前端的話說，舊模式像是 request/response 的 REST API，Duet 則像一個帶有權限確認（confirm dialog）的 background service worker：持續跑、主動推播，但碰到有副作用的操作一定要使用者點「確定」。

**前端工程師實際應用：**
- **跟你工作的關聯：** 主動型 agent 會成為新的 UI 典範：「agent 什麼時候該打斷使用者」「確認對話框怎麼設計才不會被無腦按同意」「背景任務的進度怎麼呈現」，都是前端與 UX 接下來要面對的設計問題。
- **具體場景：** 如果你在做內部工具或 SaaS 後台，未來很可能要做一個「AI 幫你處理了 5 件事、2 件等你核准」的收件匣介面，這需要 optimistic UI、可撤銷操作（undo）、以及清楚的 diff 預覽，讓使用者在核准前看得懂 agent 要做什麼。
- **這週可以嘗試：** 讀一下官方的 Claude Duet 介紹文章，觀察它的「確認前行動」流程；然後檢查你自己產品裡有破壞性操作的按鈕（刪除、送出、付款），看看確認對話框是否清楚說明「會發生什麼事」，而不是只有「確定 / 取消」。

**繁中改寫：**
Claude Security 現在會跟著你的程式碼一起更新。repo 只要連一次，Claude 會先做一次深度掃描，之後每當有變更進來就重新掃描，讓資安發現（findings）始終貼近程式碼的最新狀態。目前在 Claude Enterprise 以 public beta 提供。

修正上線後，Claude 會檢查變更過的程式碼並把該問題標成已修復，就算你們是在 Claude Security 之外修的也算；如果問題又出現，finding 會自動重新開啟。每個專案還會有一份由 Claude 根據程式碼撰寫的 threat model，團隊可以自行編輯。專案可以橫跨 GitHub、GitLab 等不同 Git 平台的 repo，findings 也能透過新的 API 與 MCP connector 送進你們既有的工具。符合資格的組織在 2026 年 12 月 31 日前，可連續兩個月每月獲得 2.5 萬美元的使用額度。

**核心概念（簡單說）：**
傳統的資安掃描多半是「某個時間點的快照」：跑一次、產一份報告，過兩週程式碼改了，報告就過期了。這次更新把 Claude Security 變成「持續掃描」：像 CI 一樣跟著每次變更重跑，並自動追蹤每個 finding 的生命週期（開啟 → 修復 → 若回歸則重開），就像 issue tracker 會在 PR merge 後自動關 issue，regression 時再打開。

另一個重點是 threat model：Claude 會讀你的程式碼，推論出系統的攻擊面（哪些地方接受使用者輸入、哪些 API 有權限邊界），寫成一份可編輯文件。後續掃描就能以這份模型為基準判斷什麼才是真正的風險，而不是一堆誤報。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端是 XSS、敏感資料外洩（token 寫進 localStorage、API key 打包進 bundle）、不安全的第三方 script 等問題的第一線。持續掃描能在你 push 後就抓到，而不是等到季度資安稽核。
- **具體場景：** 你在 Next.js 專案裡為了渲染 CMS 內容用了 `dangerouslySetInnerHTML`，或把 `NEXT_PUBLIC_` 開頭的環境變數誤放了私密 key；Claude Security 會在變更進來後標出 finding，你修正（例如改用 DOMPurify 消毒 HTML）並 merge 後，它會自動把該 finding 標成已修復。
- **這週可以嘗試：** 就算公司沒有 Enterprise 方案，也可以先在 Claude Code 裡請它「根據這個 repo 寫一份前端 threat model，列出所有使用者輸入點與 `dangerouslySetInnerHTML` / `eval` / `innerHTML` 用法」，看看你的專案有哪些攻擊面。

**變更項目：**
- Added `/claude-api api-version` to move Claude API code to API version 2026-10-21 — 新增指令，協助把專案裡的 Claude API 程式碼遷移到 2026-10-21 版 API
- Added the `claude_code.safety_event` OpenTelemetry event for each tool call a permission rule, auto mode, a safety check, a hook or the sandbox stopped, prompted or sent back — 每當 tool call 被權限規則、auto mode、安全檢查、hook 或 sandbox 擋下、詢問或退回時，都會送出一個 OpenTelemetry 事件
- [VSCode] Added a notice on the microphone button when voice dictation stops by itself — VS Code 語音輸入自動停止（15 秒沒辨識到語音或達 2 分鐘上限）時，會說明原因並保留已輸入文字
- [Code Review] Added `@claude review stop` (also `off` and `pause`) — 可在 PR 上用這個指令結束 `@claude review always` 的自動審查訂閱，且不會觸發新審查
- Changed the notice Claude gets when the WebSearch budget is used up to also tell it not to query search engines in a browser or through computer use — WebSearch 額度用完時，也會告訴 Claude 不要改用瀏覽器或 computer use 去查搜尋引擎
- Changed the `axScreenReader` setting and `CLAUDE_AX_SCREEN_READER` in a settings env block to apply only from user, managed or `--settings` settings — 螢幕閱讀器設定只接受 user、managed 或 `--settings` 來源，專案層級設定不再生效
- Self-hosted runner: Changed checkout hooks to be stopped after 30 minutes by default — 自架 runner 的 checkout hook 預設 30 分鐘逾時，需要更久可調 `--checkout-hook-timeout-min` 或設為 0
- [VSCode] Changed the extension's own requests to filter their trusted certificates as the CLI does, and to trust the `NODE_EXTRA_CA_CERTS` file — VS Code 擴充套件的憑證處理與 CLI 一致，並會信任 `NODE_EXTRA_CA_CERTS` 指定的憑證
- Improved recovery from unparseable tool calls: Claude Code now retries the call up to twice before ending the turn with an error — 無法解析的 tool call 會先重試最多兩次，不會馬上中斷
- Improved fork subagents launched together: each is now told which launch is its own — 同時啟動的 fork subagent 會知道哪個任務是自己的，減少互搶工作
- Improved browser sign-in: the success page now appears as soon as sign-in completes — 瀏覽器登入完成後立即顯示成功頁面
- Fixed HTTP MCP tool calls being sent twice when the connection closed mid-call; only read-only or idempotent tools are now retried — 修正連線中斷時 HTTP MCP tool 被重送兩次，現在只重試唯讀或冪等的工具
- Fixed MCP servers being reported as timed out when a macOS or Linux computer went to sleep while they were connecting — 修正電腦在 MCP 連線途中進入睡眠，醒來後 server 一直顯示逾時
- Fixed some "Autocompact is thrashing" errors in turns that read many PDF pages, images or other large tool results — 修正讀取大量 PDF、圖片時出現的「Autocompact is thrashing」錯誤
- Fixed a conversation cleared with `/clear` sometimes coming back when a cloud or self-hosted runner session restarted — 修正 cloud / 自架 runner session 重啟後，已 `/clear` 的對話又跑回來

**核心概念（簡單說）：**
2.1.307 有三條主線。第一是「可觀測性」：新的 `claude_code.safety_event` OpenTelemetry 事件，讓團隊能在 Grafana、Datadog 等監控平台上看到 Claude 有哪些操作被權限規則、hook 或 sandbox 擋下，等於替 agent 加上 audit log。第二是「MCP 穩定性」：HTTP MCP 斷線時不再盲目重送（避免非冪等操作執行兩次，例如重複建立 issue）、電腦睡眠後不再卡在逾時。第三是 API 遷移工具 `/claude-api api-version`，協助把既有 Claude API 程式碼升到 2026-10-21 版。

「只重試冪等操作」這個原則前端應該很熟：就像 `fetch` 重試策略只該套在 GET，不該對 POST 建立訂單自動重送，否則使用者會被扣款兩次。Claude Code 現在把同樣的原則套到 MCP tool call 上。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端常透過 MCP 串 GitHub、Figma、Linear、chrome-devtools 等工具；筆電闔上再打開、或網路不穩時，以前可能遇到 MCP 一直顯示逾時，或同一個操作被執行兩次。另外有在專案裡直接呼叫 Claude API（例如做 AI 功能的前端團隊），可以用新指令協助遷移。
- **具體場景：** 你的 Next.js 專案在 API route 裡用 `@anthropic-ai/sdk` 做 AI 摘要功能，執行 `/claude-api api-version` 後，Claude Code 會掃描相關程式碼並提出遷移到新 API 版本所需的修改；同時，若團隊導入 OpenTelemetry，可以設 dashboard 統計哪些 Bash 指令最常被 sandbox 擋下，回頭調整 `.claude/settings.json` 的 allow 清單。
- **這週可以嘗試：** 升級到 2.1.307 以上後，在使用 `@anthropic-ai/sdk` 的專案裡跑一次 `/claude-api api-version` 看看它建議哪些改動（先在新 branch 上試）；如果有在 PR 開 `@claude review always`，也試試 `@claude review stop` 關掉不需要的自動審查。
