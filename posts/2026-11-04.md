## boris_cherny · X

**原文網址：** https://x.com/bcherny/status/2117693181651542387

**原文：**
> Signing in to your company's plugins one by one is annoying, so we let Claude auto-connect to them now.
>
> Team and Enterprise admins can set them up, and teammates are connected automatically the first time they use the plugins.

**繁中改寫：**
公司內部的 plugin 要一個一個登入真的很煩，所以我們現在讓 Claude 自動幫你連上它們。

Team 和 Enterprise 的管理員可以先把 plugin 設定好，團隊成員第一次使用這些 plugin 時，就會自動完成連線。

**核心概念（簡單說）：**
Claude 的 plugin 常常會帶著需要授權的 connector（例如 Jira、Notion、內部 API 的 MCP server）。以前每個人要自己逐一跑一次 OAuth 登入流程，plugin 一多就變成「裝了十個 plugin、要點十次授權」。這次的改動是把連線設定集中到管理員那一層：管理員在組織層級設定好 plugin 與其連線，成員第一次觸發時就自動接上，不必自己處理授權。

可以把它想成公司的 SSO：以前像是每個 SaaS 都要各自註冊帳號，現在變成「用公司帳號一鍵登入」。對團隊來說，最大的價值是 onboarding 成本降低，而且大家連的是同一組、經過管理員審核的設定，比較不會出現「我的環境可以、你的不行」的狀況。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的團隊有把設計系統文件、Figma、issue tracker 或內部 API 包成 plugin / connector，新人或新專案不再需要一一手動授權，就能直接讓 Claude 查元件規範、讀 ticket。
- **具體場景：** 團隊有一個「前端規範」plugin，裡面包含連到 Storybook 文件與 Linear 的 connector。新同事加入後打開 Claude Code，第一次問「這個 `Button` 元件的 variant 規範是什麼？」就會自動連上，不用先去找誰要 token、跑 OAuth。
- **這週可以嘗試：** 列出你每天在 Claude 裡手動連線的 2～3 個工具，跟團隊管理員討論能否改成組織層級設定的 plugin；如果你就是管理員，先挑一個最常用的 connector 試著設定自動連線。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.318 / November 4, 2026

**變更項目：**
- Added the date a stored claude.ai sign-in ends to `claude auth status` (`loginExpiresAt`) and to `claude -p` JSON results (`credential_expires_at`) — `claude auth status` 與 `claude -p` 的 JSON 結果會顯示 claude.ai 登入憑證的到期時間。
- Added a one-line stderr warning to `claude -p` text output, starting 10 days before a stored claude.ai sign-in ends — 登入到期前 10 天起，`claude -p` 會在 stderr 印一行警告。
- Added an effort option to a mod's `$.model.fork`, so a quick side job can run at low whatever effort the session uses — mod 的 `$.model.fork` 可以指定 effort，讓小型支線任務用 low effort 跑，不受 session 設定影響。
- Added a record of your answer when Claude Code asks to turn on the mods it writes in a session — Claude Code 詢問是否啟用它寫的 mod 時，會記錄你的回答。
- Added `assume_role` on mantle upstreams of the Claude apps gateway — Claude apps gateway 支援跨 AWS 帳號的 `assume_role`，可按開發者拆分 AWS 成本。
- [Cloud sessions] Added a No repository option — 雲端 session 可以不選 repository 直接開始。
- [Cloud sessions] Added the usual Chrome names to cloud sessions, so tools other than Playwright can find the built-in Chromium through `google-chrome` and `CHROME_PATH` — 雲端 session 內建的 Chromium 可透過 `google-chrome` 與 `CHROME_PATH` 找到，Playwright 以外的工具也能用。
- Changed Claude Code to no longer install or update the IDE extension when started in an IDE terminal — 在 IDE 內建 terminal 啟動時不再自動安裝 / 更新 IDE extension，改用外部 terminal 跑 `/ide` 或從編輯器的 extensions 面板處理。
- Changed background subagents to move a shell command to the background after 3 minutes on all providers, so the prompt cache doesn't expire while it runs — 背景 subagent 的 shell 指令跑超過 3 分鐘會自動轉到背景，避免 prompt cache 過期。
- Changed subagents to stop instead of switching models when "Switch models when a message is flagged" is set to "Ask each time" — 設定為「每次詢問」時，subagent 會停下來而不是自動切換模型。
- Changed `deniedMcpServers` URL entries to also block Anthropic-provided servers whose upstream URL matches — `deniedMcpServers` 的 URL 規則也會擋掉 upstream URL 相符的 Anthropic 提供的 server。
- Changed the `/permissions` rule details, built-in rules and delete confirmation views to use the standard dialog; pressing Ctrl+C twice there now goes back or cancels instead of quitting — `/permissions` 相關畫面改用標準 dialog，連按兩次 Ctrl+C 改為返回 / 取消，不會直接退出。
- Removed the 2.1.288 fix that kept the model's earlier thinking when resuming a conversation started on 2.1.286 or earlier — 移除 2.1.288 的相容修正，恢復 2.1.286 以前的舊對話時，先前的 thinking 可能被丟棄。
- （另有 15 項 improvements 與 47 項 bug fixes，頁面預設收合，未逐條列出）

**核心概念（簡單說）：**
這版的主軸是「讓自動化流程更可靠」。最實用的是登入到期提醒：在 CI 或 cron 裡用 `claude -p` 跑任務時，最怕某天憑證默默過期導致整條 pipeline 失敗；現在可以從 JSON 的 `credential_expires_at` 主動監控，或在 stderr 提前 10 天看到警告。另外，背景 subagent 的長指令 3 分鐘後自動轉背景，是為了讓 prompt cache 不會在等待中失效——cache 一過期，下次請求就要重新付完整 context 的成本，速度也會變慢。

其他改動偏向行為收斂：IDE terminal 不再偷偷裝 extension（避免版本互相打架）、`/permissions` 的 Ctrl+C 不再誤退出、雲端 session 可以不綁 repo 直接開，以及內建 Chromium 對非 Playwright 工具更友善。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你用 `claude -p` 在 GitHub Actions 或本機排程跑 lint 修正、測試補寫、每日報告之類的任務，現在能提早知道憑證何時到期，不會某天早上才發現 job 全掛。
- **具體場景：** 在每日排程腳本裡把 `claude -p --output-format json` 的結果用 `jq '.credential_expires_at'` 取出，若距今少於 7 天就發 Slack 通知；或在雲端 session 裡用 Puppeteer / Lighthouse CLI 透過 `CHROME_PATH` 直接跑前端效能檢測，不必另外裝瀏覽器。
- **這週可以嘗試：** 升級到 2.1.318 後跑一次 `claude auth status`，確認 `loginExpiresAt` 的日期，並在你自己的自動化腳本加一行檢查到期日的邏輯。
