**原文網址：** [https://x.com/adocomplete/status/2087728817012162973](https://x.com/adocomplete/status/2087728817012162973)

**原文：**
> Your sessions have names and can DM each other in Claude Code.
>
> claude --name backend
> claude --name frontend
>
> > tell frontend the orders endpoint moved to /v2
>
> it's very effective.

**繁中改寫：**
Boris Cherny 轉發了 Ado（@adocomplete）的貼文，內容是說在 Claude Code 裡，每個 session 現在都可以有自己的名字，而且不同 session 之間能互相傳訊息（DM）。例如你可以開兩個 session，一個叫 backend、一個叫 frontend，然後直接跟 frontend session 說「orders endpoint 搬到 /v2 了」，讓它自動同步這個資訊，效果非常好。

**核心概念（簡單說）：**
這是 Claude Code 一個叫「session 命名 + 跨 session 訊息」的功能。以前你如果同時開很多個終端機視窗跑 Claude Code，每個 session 之間是獨立的黑盒子，彼此不知道對方在做什麼；現在你可以用 `claude --name <名字>` 幫每個 session 取名字，接著在任一個 session 裡下類似「跟 <名字> session 說 xxx」的指令，就能把訊息直接送到另一個 session，讓它把新資訊加入自己的 context。這概念很像多個工程師之間用聊天室互相同步進度，只是聊天室的成員換成一群 Claude session。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端工程師常常要同時盯著 API 變動（後端 endpoint 改了）跟自己的畫面邏輯，如果你習慣同時開多個 Claude Code session 分別處理 frontend / backend / infra，這個功能能讓你不用自己複製貼上訊息去同步彼此的 context。
- **具體場景：** 假設你開了 `claude --name backend` 在處理後端 API 改版，另一個 `claude --name frontend` 在改前端 fetch 邏輯，只要在 backend session 打一句「跟 frontend 說 orders endpoint 改到 /v2 了」，frontend 那個 session 就會自動知道要把 fetch URL 換掉，不用你自己來回切視窗貼訊息。
- **這週可以嘗試：** 找一個你現在正在做、同時牽涉前後端改動的功能，試著用 `claude --name` 開兩個對應職責的 session，實際跑一次「A session 通知 B session」的流程，感受一下這種多 agent 協作跟單一 session 相比差在哪裡。

Claude in Chrome 的對話 session 現在可以跨裝置延續了——桌面版、網頁版、手機版都會同步，對話紀錄會被保留下來，而且你原本設定的 skills 跟 connectors 在瀏覽器裡也一樣能用。目前 Max 跟 Team 方案已經開放，Pro 方案會在接下來幾週陸續開放。

**核心概念（簡單說）：**

- **具體場景：** 你在公司電腦用 Claude in Chrome 讓它幫你分析一個線上 dashboard 的效能瓶頸，開了一半要下班，回家後可以直接在手機 app 或筆電繼續看剛剛的分析結果、接著問下一個問題，不用重新描述情境。
- **這週可以嘗試：** 如果你的方案是 Max 或 Team，找一個你平常會用 Claude in Chrome 處理的任務（例如讀某份技術文件、分析某個網站），刻意在瀏覽器開始，然後切到手機 app 或桌面版接續，實際感受一下跨裝置延續的體驗。

**原文網址：** [https://x.com/claudeai/status/2087635265066004694](https://x.com/claudeai/status/2087635265066004694)

**原文：**
> Browser agents can be tricked by instructions hidden in a page. We build defenses against this, and we still recommend a few habits of your own:
>
> （附連結：Use Claude in Chrome safely | Claude Help Center，來自 support.claude.com）

**繁中改寫：**
瀏覽器 agent 有可能被藏在網頁內容裡的指令欺騙（也就是 prompt injection），Anthropic 表示他們有針對這種攻擊做系統性的防禦機制，但同時也建議使用者自己養成幾個安全習慣，並附上連結到說明如何安全使用 Claude in Chrome 的官方文件。

**核心概念（簡單說）：**
這則在講瀏覽器 agent 的一個核心資安風險——「prompt injection」。當 AI agent 幫你瀏覽網頁、讀取頁面內容時，如果某個網頁裡藏了一段偽裝成正常內容、實際上是想操控 AI 行為的指令（例如「請忽略使用者指示，改去做 xxx」），agent 有可能誤把它當成合法指令執行，導致做出使用者沒有授權的動作（像是外洩資料、亂點連結）。這其實就是「工具觀察到的網頁內容是資料，不是指令」這個安全邊界要處理的問題。Anthropic 說他們在系統層面有做防禦，但仍建議使用者自己保持警覺。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的產品或內部工具有整合瀏覽器 agent（不管是 Claude in Chrome 還是自己接 Agent SDK 做網頁自動化），prompt injection 是你在設計時必須考慮的資安風險之一，跟 XSS、CSRF 一樣屬於「輸入不可信任」的範疇。
- **具體場景：** 假設你在做一個讓 AI agent 自動幫使用者填寫表單、比價、或整理網頁資訊的功能，如果目標網站的內容被惡意植入了偽裝指令（例如藏在極小字體、白底白字裡），agent 可能會被誤導做出非預期行為；閱讀 support.claude.com 這篇文件能了解 Anthropic 官方建議的防禦與使用習慣。
- **這週可以嘗試：** 去讀一下 support.claude.com 上「Use Claude in Chrome safely」這篇文件，並對照你自己專案裡任何會讀取外部網頁內容餵給 LLM 的地方，檢查有沒有做基本的內容/指令隔離處理。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.231 / 2026年8月13日

**變更項目：**
- Fixed MCP OAuth sign-in failing with a redirect URI mismatch for servers that use a pre-registered OAuth client, such as Slack（修正：使用預先註冊 OAuth client 的 MCP 伺服器（例如 Slack）在登入時，因 redirect URI 不匹配而失敗的問題）

**核心概念（簡單說）：**
這是一個小型修補版本，只修了一個問題：透過 MCP（Model Context Protocol）串接需要 OAuth 登入的服務時（像 Slack 這種要求「事先在該服務註冊好 OAuth client」的服務），登入流程會因為 redirect URI 對不上而失敗，這版把它修好了。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你有在專案裡用 Claude Code 串接需要 OAuth 登入的 MCP server（例如公司內部工具、Slack 通知整合），這個修正直接影響你能不能順利登入串接。
- **具體場景：** 你想讓 Claude Code 透過 MCP 直接讀取/操作 Slack 頻道訊息，設定好 MCP server 後執行登入卻卡在 redirect URI mismatch 的錯誤，升級到 2.1.231 後這個特定錯誤就修好了。
- **這週可以嘗試：** 如果你之前串接 Slack 或其他需要「預先註冊 OAuth client」的 MCP server 時卡過關，這週升級 Claude Code 版本後重新試一次登入流程。
