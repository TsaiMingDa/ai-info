## claudeai · Anthropic Blog

**原文網址：** [https://www.anthropic.com/news/model-hardware-standard-research-preview](https://www.anthropic.com/news/model-hardware-standard-research-preview)

**原文：**
> We're opening a research preview of the Model Hardware Standard (MHS), a shared specification for AI agents to safely operate physical devices, to a first group of scientific research labs and advanced manufacturers. MHS enables AI agents to operate multiple lab and manufacturing instruments, such as microscopes, liquid handlers, and robotic arms, in parallel, and perform intricate tasks ranging from routine drug discovery experiments to laser calibration on a quantum computer.
>
> It typically takes a lab or manufacturing facility weeks, if not months, to set up and integrate their hardware. Most devices don't communicate with each other, instead requiring specialists to build bespoke integrations. MHS reduces this integration work to hours or minutes.
>
> MHS addresses these challenges by introducing a standardized driver: software that translates between a computer's operating system and a hardware device. The MHS driver uses a simple set of primitives — commands like "read" (for example, "get temperature") or "write" (for example, "set temperature") — that any hardware device can understand and act on. It works with any device that has a programmable interface, is model-agnostic, and any agent harness can access it using standard protocols, such as the Model Context Protocol.
>
> For MHS, there are three control mechanisms: MCP, the command line interface, and code files (APIs). As we've tested MHS, we've found that Claude interacts with experiments and hardware in an exploratory manner, much as a scientist would — making an adjustment, observing the result, and repeating the process, then packaging what it learned into a deterministic script so the whole process could run as a single command.

**繁中改寫：**
Anthropic 開放了「Model Hardware Standard（MHS）」的研究預覽版，這是一套讓 AI agent 能安全操作實體裝置（例如顯微鏡、液體處理機、機械手臂）的共用規格，優先開放給第一批科學研究實驗室與先進製造廠商使用。過去要讓實驗室或工廠裡不同廠牌的裝置互相溝通，往往得花上數週甚至數個月客製整合，因為每台裝置都有自己的介面、彼此不相容。MHS 透過一套標準化的「driver」解決這個問題：用簡單的 read / write 指令（例如「讀取溫度」「設定溫度」）讓任何有可程式化介面的硬體都能被理解與操作，且不綁定特定模型，任何 agent 都能透過標準協定（例如 MCP）存取。控制方式有三種：MCP、CLI、以及程式碼檔案（API）。實測下來，Claude 操作實驗裝置的方式很像真正的科學家：先做一個調整、觀察結果、重複這個過程，最後把學到的經驗打包成一支確定性的腳本，讓整個流程能一鍵重現。

**核心概念（簡單說）：**
可以把 MHS 想像成「硬體世界的統一 API 規格」。過去每一台實驗儀器都像是用不同語言在講話，AI 想要控制它們就得幫每一台寫專屬的轉接程式；MHS 定義了一套所有裝置都能懂的共同語言（read/write 指令 + 用自然語言描述的裝置能力說明檔），讓 AI agent 可以像操作一組標準化 API 一樣，同時協調多台裝置完成複雜的實驗流程，而不用為每個裝置各自客製整合邏輯。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端工程師平常不太會直接碰觸實體硬體，但 MHS 的設計思路其實很眼熟——用一份「能力描述檔」讓消費端（agent）知道怎麼操作未知裝置，這跟前端常見的 OpenAPI/GraphQL schema、或是 MCP server 讓 LLM 知道有哪些工具可用的做法是同一種「自我描述介面」的思維。
- **具體場景：** 如果你在做內部工具串接多個第三方 API，與其為每個 API 各寫一支 adapter，可以參考 MHS 的做法：定義一份共同的介面規格（如統一的 request/response 格式），再讓每個服務各自實作對應的 driver，新增服務時只要補一份規格檔，不用改動呼叫端邏輯。
- **這週可以嘗試：** 去讀一下這篇文章裡提到 MHS 使用 MCP 作為其中一種控制通道的段落，順便重新複習一次 Model Context Protocol 的基本概念（tool discovery + 標準化呼叫），這對之後要串接任何 AI agent 工具都會用到。

- Changed agent view 派送輸入框中 shift+enter 改為插入換行（與一般 prompt 輸入一致）；ctrl+enter 才會派送並附加。
- Changed `/loop`：自我步調的 dynamic 模式、以及無 prompt 的自主模式預設現在在 Bedrock/Vertex/Foundry 上也一律可用。
- Changed Anthropic telemetry 匯出失敗的訊息改為以 `[Anthropic telemetry]` 標籤在 debug 層級記錄，而非 `[3P telemetry] OTEL diag error`，避免被誤認成是使用者自己的 OTel collector 出錯。
- Changed Linux user namespace 下的跨 session 訊息機制：未對映擁有者的 root 等級信任範圍現在限制在標準系統目錄內。
- Changed 從 subagent 透過 `SendMessage` 傳訊到另一個 session 時，結果會註明任何回覆都會送到「父」session 的對話中，而不是送回該 subagent。

**核心概念（簡單說）：**
這是一個內容量非常大的版本更新，涵蓋新增功能（`--restricted` 受限模式、跨 session 傳訊擴大支援、`/usage-credits` 等）、大量錯誤修正（涵蓋 agent 管理、MCP、登入、安全性等面向）、以及多項體驗優化（prompt 效能、UI 對齊、設定審核流程）。整體方向可以看出兩個重點：一是持續強化「多 session 協作」（跨 session 傳訊、agent view 穩定性）的基礎設施；二是補強安全與權限管控（`--restricted` 模式、避免憑證檔被誤上傳到雲端 session）。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你日常用 Claude Code 開多個背景 session 協作開發，這次修的一大票 `claude agents` 相關 bug（重複行程、session 復活邏輯、鍵盤無反應等）會直接影響你的使用體驗；另外新增的 `--restricted` 模式對於在較不受信任的環境（如公用機器、CI）跑 Claude Code 很有幫助。
- **具體場景：** 假設你需要在一台不完全信任、或只想讓 Claude 讀取程式碼但不執行任何指令的機器上跑審查任務，可以直接用 `claude --restricted` 啟動，這樣就不會誤執行到會跑指令或呼叫 WebFetch 的工具。
- **這週可以嘗試：** 更新到 2.1.248 以上版本後，實際跑一次 `claude --restricted` 體驗受限模式的行為差異；如果你有用到跨 session 訊息功能（`SendMessage`/`ListAgents`），也可以留意這次修正的「父 session 收到回覆」邏輯是否符合你原本的預期。
