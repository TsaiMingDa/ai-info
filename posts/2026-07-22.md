**原文：**
> New in Claude Cowork: teach Claude a skill.
>
> Record your screen while you do a task, talk through it as you go, and Claude turns it into a skill it can run again. Find it under Record a skill in the + menu of the Claude desktop app.
>
> Available on Pro, Max, and Team plans.

**繁中改寫：**
Claude Cowork 推出新功能：教 Claude 一項技能（skill）。做法是一邊錄下你的螢幕操作，一邊口頭講解你在做什麼，Claude 就會把這整段錄製內容轉換成一個「skill」，之後可以重複執行。這個功能在 Claude 桌面版 App 的「+」選單裡，找「Record a skill」就能用，目前開放給 Pro、Max、Team 方案的使用者。

**核心概念（簡單說）：**
過去要讓 Claude 學會一個重複性任務（skill），通常得手動寫 SKILL.md 或用文字描述步驟，對不熟悉寫技術文件的人來說門檻不低。這次的新功能反過來，讓你「示範」給 Claude 看：錄螢幕操作 + 口頭講解，Claude 自己去理解你做了什麼、為什麼這樣做，然後把這個流程萃取成一個可重複執行的 skill。這其實是把「skill 建立」從「寫文件」變成「錄影片教學」，降低了一般使用者建立自動化流程的門檻，也讓 Claude 能從實際操作中學習隱含的步驟細節（例如你點了哪個選單、輸入了什麼），而不只是靠使用者事後憑記憶寫下來的文字說明。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端工程師常常要重複執行一些固定但繁瑣的操作（例如：每次發版前檢查特定頁面的 UI、跑一遍固定的測試流程、在某個後台系統填固定格式的資料），這種「操作型」的重複工作正好適合轉成 skill 讓 Claude 代勞。
- **具體場景：** 假設你每次要在公司內部的 CMS 後台建立一篇新文章，都要重複同樣的十幾個步驟（切換分類、填 SEO 欄位、設定發布時間、上傳圖片並裁切）。你可以錄一次自己操作的螢幕，邊做邊說明每一步在做什麼，讓 Claude 把它變成一個 skill，之後只要說「幫我建一篇新文章，標題是 XXX」，Claude 就能照著你錄的流程執行。
- **這週可以嘗試：** 找一個你每週至少要手動重複 2-3 次、步驟固定的畫面操作（不限於寫程式，後台操作、報表填寫都算），用 Claude Cowork 的 Record a skill 錄一次示範，看看 Claude 轉換出來的 skill 執行結果跟你預期的是否一致。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.217 / July 21, 2026

**變更項目：**
- Added emoji shortcode autocomplete in the prompt input: type `:heart:` to insert ❤️, or `:hea` for suggestions — disable with the `emojiCompletionEnabled` setting（在提示輸入框新增 emoji 短代碼自動完成功能，輸入 `:heart:` 可插入 ❤️，或輸入 `:hea` 顯示建議清單，可用 `emojiCompletionEnabled` 設定關閉）
- Added warnings when transcript writes are failing (e.g. disk full) or when session saving is off due to an inherited environment variable, instead of losing transcripts silently（新增警告：當對話紀錄寫入失敗（例如硬碟空間不足），或因繼承的環境變數導致 session 儲存被關閉時，不再默默遺失紀錄而是跳出提示）
- Fixed a memory leak where truncated MCP tool outputs kept the full untruncated result in memory for the rest of the session（修正 MCP 工具輸出被截斷顯示時，完整未截斷結果仍留在記憶體中整個 session 期間的記憶體洩漏問題）
- Fixed Windows auto-update failures that could leave `claude.exe` missing; failed updates now restore the preserved executable automatically（修正 Windows 自動更新失敗可能導致 `claude.exe` 遺失的問題，更新失敗時現在會自動還原保留的執行檔）
- Fixed background session isolation not canonicalizing symlinked working directories, which could let sessions escape their workspace folder（修正背景 session 隔離機制未正規化符號連結工作目錄的問題，避免 session 逃出原本的工作區資料夾）
- Fixed auto-compact never triggering for Claude Opus 4.8 on Bedrock and `/compact` failing once over the limit（修正 Bedrock 上的 Claude Opus 4.8 永遠不觸發自動壓縮，以及超過限制後 `/compact` 執行失敗的問題）
- Fixed corporate mTLS, TLS-verify, OAuth scope, and proxy settings being ignored in Claude Desktop sessions（修正企業版 mTLS、TLS 驗證、OAuth scope 與 proxy 設定在 Claude Desktop session 中被忽略的問題）
- Fixed screen reader mode's startup announcement being cut off, and the thinking status row re-rendering every few seconds unnecessarily（修正螢幕報讀模式的啟動提示被截斷，以及思考狀態列每隔幾秒不必要地重新渲染的問題）
- Fixed managed `OTEL_EXPORTER_OTLP_ENDPOINT` settings being overridden by lower-scope signal-specific settings（修正受管理的 `OTEL_EXPORTER_OTLP_ENDPOINT` 設定被較低層級的訊號專屬設定覆蓋、導致遙測資料被導離受管端點的問題）
- Fixed `--resume`/`--continue` and `/resume` failing with a TypeError when a transcript has a malformed attachment entry（修正對話紀錄含有格式錯誤的附件項目時，`--resume`/`--continue` 與 `/resume` 會拋出 TypeError 失敗的問題）
- Fixed background shells sometimes becoming impossible to stop after a session is backgrounded or exits on a heavily loaded machine（修正 session 被丟到背景執行、或在高負載機器上退出後，背景 shell 有時無法被停止的問題，Windows 上最明顯）
- Fixed a CLAUDE.md/SKILL.md `paths` frontmatter value with many brace groups OOM-killing or stalling the CLI at startup — brace expansion is now budget-bounded（修正 CLAUDE.md／SKILL.md frontmatter 的 `paths` 欄位含有大量大括號群組時，會導致 CLI 啟動時記憶體爆掉或卡住的問題，現在大括號展開有預算上限）
- Added a cap on concurrently-running subagents (default 20, override with `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`) so one message can't fan out unbounded background agents（新增同時執行 subagent 數量上限，預設 20 個，可用 `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` 覆寫，避免單一訊息無限制地展開背景 agent）
- Changed subagents to no longer spawn nested subagents by default; set `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` to allow deeper nesting（變更為 subagent 預設不再產生巢狀 subagent，可用 `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` 允許更深層的巢狀）
- Fixed `--max-budget-usd` not stopping background subagents: once the cap is reached, new spawns are denied and running background agents are halted（修正 `--max-budget-usd` 無法停止背景 subagent 的問題，達到上限後會拒絕新增派生並停止正在執行的背景 agent）

**核心概念（簡單說）：**
這次更新的重點分兩塊。第一塊是「穩定性與安全修復」：修了一個 MCP 工具輸出造成的記憶體洩漏、Windows 自動更新可能弄丟執行檔、背景 session 可能透過符號連結逃出工作區資料夾、以及 CLAUDE.md 設定檔可能因為大括號展開被濫用而讓 CLI 卡死或爆記憶體等問題，這些都是關於「讓 Claude Code 長時間、大量使用時更穩定安全」的修復。第二塊是「subagent 資源治理」：新增了同時執行 subagent 的數量上限、預設不再讓 subagent 巢狀產生 subagent、並修正了 `--max-budget-usd` 預算上限無法真正擋住背景 subagent 繼續花錢執行的漏洞。這代表官方注意到，隨著多 agent 協作越來越普遍，如果沒有這些防線，一個訊息可能不小心觸發大量背景 agent 失控地跑下去、燒掉大量 token 預算。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你已經在用 Claude Code 的 subagent（Task 工具）做並行任務分派，這次新增的並行數量上限與巢狀限制會直接影響你能同時開多少背景 agent，需要留意預設值是否符合你的工作流。
- **具體場景：** 假設你寫了一個腳本或流程，讓 Claude Code 針對專案裡幾十個檔案各自派一個 subagent 去做重構或掃描，過去可能因為沒有上限而一次炸出過多背景 agent 拖垮效能或超支預算；現在預設最多同時 20 個 subagent，且 `--max-budget-usd` 真的能擋住背景 agent 繼續執行，你可以更放心設定預算上限來控管成本。
- **這週可以嘗試：** 如果你的專案有用到 `--max-budget-usd` 或大量 subagent 並行的工作流程，更新到 2.1.217 後實際測試一次預算上限是否確實生效、以及確認 `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` 的預設值 20 是否符合你的並行需求，需要更高並行度就手動調整這個環境變數。
