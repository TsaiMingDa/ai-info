## Claude Code · Changelog

**版本號 / 日期：** 2.1.160 / 2026-06-02

**變更項目：**

*安全性與權限控制*
- `Added a prompt before writing to shell startup files (.zshenv, .zlogin, .bash_login) and ~/.config/git/` — 寫入 shell 啟動檔案和 git 全域設定前，現在會先詢問確認，防止 Claude 意外修改影響所有 terminal session 的設定
- `acceptEdits mode now prompts before writing build-tool config files that grant code execution (.npmrc, .yarnrc*, bunfig.toml, .bazelrc, .pre-commit-config.yaml, .devcontainer/, etc.)` — acceptEdits 模式現在在寫入可觸發程式碼執行的 build 設定檔前，也會要求手動確認

*開發流程改善*
- `Edit no longer requires a separate Read after viewing a file with grep: single-file grep/egrep/fgrep commands now satisfy the read-before-edit check` — 用 grep 查看過單一檔案後，Edit 工具不再需要額外再 Read 一次，減少冗餘步驟
- `Fixed copy-on-select not writing to the Windows clipboard on WSL — now uses PowerShell interop instead of OSC 52, which terminals like MobaXterm don't support` — 修復 WSL 環境下框選文字沒有寫入 Windows clipboard 的問題，改用 PowerShell interop

*Background Agent 穩定性修復*
- `Fixed restoring a completed session from claude agents dropping chat history and re-running the original prompt` — 修復從 agents 清單恢復已完成 session 時，對話歷史消失並重新執行原始 prompt 的問題
- `Fixed background sessions re-attached after overnight retire losing their conversation and re-running the original prompt` — 修復隔夜休眠的 background session 重新連線後遺失對話的問題
- `Fixed claude --bg occasionally failing with "socket missing" when the background daemon was cold-starting on a loaded machine` — 修復 background daemon 冷啟動時偶發 socket missing 錯誤
- `Fixed an issue on Windows where the directory a background session was started in could not be deleted after claude rm until the background daemon exited` — 修復 Windows 上 background session 的工作目錄無法刪除的問題
- `Fixed background agents that resumed work being shown under Completed in the agents list` — 修復繼續工作的 background agent 被錯誤標示為已完成
- `Fixed claude agents freezing for several seconds when returning to the session list due to the auto-updater re-checking on every exit` — 修復回到 session 清單時因自動更新重複檢查造成的數秒凍結
- `Fixed Esc, arrow keys, and typing becoming unresponsive on Windows when attached to a background session` — 修復 Windows 上連線 background session 時鍵盤輸入無回應的問題
- `Fixed background agents emitting terminal sync-output markers to terminals that don't support them (Apple Terminal, tmux), causing render artifacts` — 修復在 Apple Terminal 和 tmux 下出現的渲染雜訊
- `Fixed mouse wheel scrolling prompt history instead of the transcript right after opening a session from the agents list` — 修復從 agents 清單開啟 session 後滾輪翻的是 prompt 歷史而非對話記錄
- `Fixed CJK IME composition appearing at the bottom-left of the screen instead of at the input caret in the claude agents view` — 修復中日韓輸入法候選字框位置跑到左下角的問題
- `Fixed valid file:///C:/... links being rewritten to a broken path on Windows terminals with hyperlink support` — 修復 Windows 上 file:/// 連結被改寫成錯誤路徑的問題
- `Fixed voice mode failing to connect when the project directory or branch name contains non-ASCII or special characters` — 修復專案路徑或分支名含非 ASCII 字元時 voice mode 連線失敗的問題
- `Fixed /effort ultracode incorrectly blaming the dynamic workflows setting when the model cannot run xhigh; ultracode is no longer offered on models that do not support it` — 修復不支援 xhigh 的模型上 ultracode 錯誤歸咎於設定的問題

*功能調整與效能*
- `Removed CLAUDE_CODE_OPUS_4_6_FAST_MODE_OVERRIDE; the environment variable is now a no-op` — 移除 `CLAUDE_CODE_OPUS_4_6_FAST_MODE_OVERRIDE` 環境變數，設定後已無效果
- `Removed the JetBrains plugin install suggestion from startup` — 移除啟動時的 JetBrains plugin 安裝提示
- `Renamed the dynamic-workflow trigger keyword from "workflow" to "ultracode". The trigger keyword is highlighted in violet in the prompt input` — 動態工作流程觸發關鍵字從 `workflow` 改為 `ultracode`，在 prompt 輸入框中以紫色高亮顯示
- `Improved performance of opening recently-inactive background agent sessions in claude agents` — 提升開啟非活躍 background agent session 的速度
- `Improved auto mode classifier latency by reducing reasoning on routine actions` — 降低 auto mode 分類器延遲，減少「could not evaluate this action」類型的阻斷
- `Improved background-session teardown (claude rm/stop, idle reap) to send SIGTERM to running shell subprocesses before SIGKILL, so cleanup handlers run` — 改善 session 關閉流程，先發 SIGTERM 讓清理腳本有機會執行再強制終止

**核心概念（簡單說）：**
這次更新有兩個重心：**安全性** 和 **background agent 穩定性**。安全性方面，Claude Code 在「有副作用的寫入操作」上更謹慎了——寫入 shell 啟動檔案（影響所有 terminal session）或 `.npmrc`、`.yarnrc` 等 build 設定（影響 dependency resolution）前，都要先確認。這遵循最小權限原則，避免 Claude 在 agentic 模式下無聲無息改到你不知道的設定。Background agent 方面，修了一大批邊緣情況，特別是 CJK 輸入法位置和 WSL clipboard 等非英語、非 macOS 環境的體驗問題。動態工作流程的關鍵字改成 `ultracode`，是為了防止使用者在自然語言中無意間用到 "workflow" 這個詞就觸發特殊模式。

**前端工程師實際應用：**
- **跟你工作的關聯：** `.npmrc` 被納入「寫入前需確認」的清單對前端開發者影響很直接——`.npmrc` 掌控 npm registry、auth token 和 private package 設定，意外被 Claude 改寫可能讓整個 CI 環境的 `npm install` 壞掉。現在這層防護讓 acceptEdits 模式在 monorepo 環境下更安全。
- **具體場景：** 如果你在用 pnpm workspace 或 Yarn Berry 的 monorepo 中開啟 acceptEdits 讓 Claude 自動套用修改，更新到 2.1.160 後當 Claude 要動 `.yarnrc.yml` 或 `.npmrc` 時，你會收到確認提示。這是確認 Claude 修改範圍是否符合預期的好時機，特別是在涉及 registry 設定或 private scope 的情境下。
- **這週可以嘗試：** 如果你在 WSL 環境開發，更新到 2.1.160 後測試框選終端機文字是否能正確寫入 Windows clipboard。另外，試試在 prompt 輸入 `ultracode` 觸發動態工作流程（之前是 `workflow`），觀察輸入時出現的紫色高亮效果——這個 UI 提示是為了讓你知道自己正在進入不同的執行模式。
