## Claude Code · Changelog

**版本號 / 日期：** 2.1.294 / October 8, 2026

**變更項目：**
- Fixed prompt and agent hooks written as instructions (such as "Block commands that…") allowing what they should block
  - 修正以「指令句」撰寫的 prompt hook 與 agent hook（例如「Block commands that…」）反而放行了本該阻擋的操作。
- Improved how prompt hooks on Stop and SubagentStop written as instructions (such as "Carry on if the build is broken") are judged, so Claude is less likely to stop early
  - 改善 Stop 與 SubagentStop 上以指令句撰寫的 prompt hook（例如「build 壞掉就繼續做」）的判斷方式，讓 Claude 比較不會提早停下來。

**核心概念（簡單說）：**
Prompt hook 是用自然語言（而非 shell script）寫的 hook，由模型判斷是否放行或要求繼續。過去如果你用「命令句」寫（「阻擋所有 rm -rf」），模型有時會誤判成要放行；這版修正了判斷邏輯，讓指令型寫法的行為符合直覺。對 Stop hook 來說，這代表「build 沒過就不准收工」這類規則會更可靠地讓 Claude 繼續工作。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你用 prompt hook 當 Claude Code 的「護欄」（禁止動 `package-lock.json`、build 失敗不准結束），這版修正直接影響這些護欄是否真的有效。
- **具體場景：** 在 `.claude/settings.json` 設一個 Stop prompt hook：「如果 `pnpm build` 或 `pnpm tsc --noEmit` 還有錯誤就繼續修」，升級後 Claude 會更穩定地修到型別檢查全過才結束。
- **這週可以嘗試：** 執行 `claude update` 升到 2.1.294，檢查你現有的 prompt hook 是否用指令句撰寫，並故意觸發一次被阻擋的情境，確認行為符合預期。
