## Claude Code · Changelog

**版本號 / 日期：** 2.1.158 / 2026-05-30

**變更項目：**
- `CLAUDE_CODE_ENABLE_AUTO_MODE=1` opt-in after setting env var / Auto mode is now available on Bedrock, Vertex, and Foundry for Opus 4.7 and Opus 4.8 — 雲端平台（AWS Bedrock、GCP Vertex、Azure Foundry）的使用者現在可以透過設定環境變數 `CLAUDE_CODE_ENABLE_AUTO_MODE=1` 啟用 auto mode，讓 Claude 在這些平台上自動執行而不需要手動批准每個操作

**核心概念（簡單說）：**
Auto mode 就是讓 Claude 不需要一步一步等你確認，可以直接自動執行任務的模式。之前這個模式只在部分環境下支援，現在延伸到了三個主要雲端平台：AWS Bedrock、GCP Vertex 和 Azure Foundry。簡單說，你的 CI/CD pipeline 或者雲端 AI 工作流程可以讓 Claude 全自動跑，不再卡在「需要批准」的提示上。這對在雲端跑自動化任務的團隊影響很大。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的團隊有在 AWS 或 GCP 上跑 AI 輔助的自動化流程（例如自動化的程式碼審查、PR 摘要生成、測試生成），現在可以讓 Claude 在這些雲端環境中以 auto mode 執行，省去手動確認的麻煩
- **具體場景：** 假設你在 GitHub Actions 裡用 Bedrock 跑 Claude Code 來自動生成 unit test，以前可能需要 interactive 確認，現在只需在 workflow YAML 的 env 裡加上 `CLAUDE_CODE_ENABLE_AUTO_MODE=1`，就能讓 Claude 全程自動完成而不卡住
- **這週可以嘗試：** 如果你有 Claude Code 的雲端使用場景，在 `.env` 或 CI 環境變數設定 `CLAUDE_CODE_ENABLE_AUTO_MODE=1` 試試看，觀察 Claude 的行為是否如預期地完全自動化

**變更項目：**

- Added autocomplete for `/plugin` arguments: subcommands, installed plugin names, and plugins from known marketplaces / `/plugin` 指令現在支援 tab autocomplete
- `claude agents`: the `agent` field in `settings.json` is now honored for dispatched sessions, with `--agent <name>` to override / `settings.json` 的 `agent` 欄位現在對分派的 session 生效
- `EnterWorktree` can now switch between Claude-managed worktrees mid-session / `EnterWorktree` 現在可以在 session 中途切換 worktree
- `tool_decision` telemetry events now include `tool_parameters` when `OTEL_LOG_TOOL_DETAILS=1` / telemetry 新增 tool 參數記錄
- Worktrees managed by Claude are now left unlocked when the agent finishes / Claude 管理的 worktree 在 agent 完成後不再鎖定，可正常用 `git worktree remove`/`prune` 清理
- Fixed unprocessable images (zero-byte, corrupt) crashing the request instead of becoming a text placeholder / 修正損壞或空白圖片導致 request 崩潰的問題
- Fixed sandbox network permission prompts appearing in auto and bypass-permissions mode / 修正在 auto 模式下出現不必要的沙箱網路權限提示
- Fixed `claude agents` completed sessions not retiring / 修正 `claude agents` 已完成的 session 沒有正確退場的問題
- Fixed `claude agents` pressing Esc not cancelling a slow "opening…" / 修正按 Esc 無法取消 agents 開啟動作的問題
- Fixed background agent worktrees being orphaned after 30-day retention sweep / 修正背景 agent worktree 在 30 天保留清除後變成孤兒的問題
- Fixed background sessions re-attached after sleep/wake not telling the model the correct date / 修正電腦睡眠後重連的背景 session 給模型錯誤日期的問題
- Fixed copy-on-select in `claude agents` not reaching clipboard inside tmux / 修正在 tmux 內選取複製無法到達系統剪貼簿的問題（regression in 2.1.153）

- Fixed terminal freezing after approving managed-settings security dialog at startup / 修正啟動時批准安全對話框後 terminal 凍結的問題
- Fixed rare duplicate line in scrollback after terminal UI redraws / 修正 terminal UI 重繪後偶發的重複行問題
- Fixed right-click paste duplicating clipboard in VS Code, Cursor, and Windsurf integrated terminals / 修正在 VS Code、Cursor、Windsurf 的整合 terminal 右鍵貼上導致剪貼簿內容重複的問題

- `/terminal-setup` now disables GPU acceleration in VS Code/Cursor/Windsurf to prevent garbled-text rendering / `/terminal-setup` 現在會停用整合 terminal 的 GPU 加速，避免文字亂碼
- Feature of the Week credit-claim status now appears as a notification in status area / 每週功能的獎勵領取狀態現在改為 status area 的通知顯示
- `claude agents`: slash-command autocomplete now matches substrings / `claude agents` 的指令自動補全現在支援子字串匹配

- Added "Workflow keyword trigger" setting in `/config` / 在 `/config` 新增「Workflow keyword trigger」設定，可停用 workflow 觸發字功能

**核心概念（簡單說）：**
這次更新最重要的兩件事：第一是 **plugin 系統大幅簡化**——以前要讓團隊成員使用自定義 plugin 需要走 marketplace 流程，現在只要把 plugin 放在 `.claude/skills/` 目錄下就會自動載入，可以直接 commit 進 repo 讓整個團隊共享。`claude plugin init <name>` 讓你一行指令就能建立新 plugin 骨架，大幅降低客製化門檻。

第二是大量的 **穩定性修復**，特別是 VS Code/Cursor/Windsurf 整合 terminal 的問題（右鍵貼上、GPU 加速文字亂碼）、WSL 環境的圖片處理、以及 `--resume` 和背景 agent 的各種邊緣情況。如果你之前在 IDE 整合 terminal 裡用 Claude Code 遇過奇怪的行為，很可能被這次修掉了。

**前端工程師實際應用：**
- **跟你工作的關聯：** Plugin 自動載入代表你可以把團隊共用的 Claude Code 自定義設定（例如特定 lint 規則的處理方式、公司內部 design system 的使用指引）寫成 plugin 放進 repo，新人 clone 後就自動生效，不需要額外設定步驟。VS Code 整合 terminal 的 bug 修復對每天在 VS Code 裡用 Claude Code 的前端工程師也直接有感
- **具體場景：** 你在做一個用 Tailwind + shadcn/ui 的專案，想讓 Claude 永遠知道你們的 design token 規範。用 `claude plugin init design-system` 在 `.claude/skills/` 建立一個 skill，把 design system 文件和規則寫進去，commit 到 repo。之後整個團隊的 Claude Code 都會自動載入這個 skill，不需要每個人手動設定
- **這週可以嘗試：** 執行 `claude plugin init my-project-conventions`，在生成的 skill 檔案裡寫上你們專案的 3-5 個最常違反的 coding convention，然後試試看 Claude 在下次寫程式時是否更遵循這些規範
