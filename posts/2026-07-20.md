**原文：**

> working more on a post about what we learned doing this and how you can apply this to your skills and system prompts
>
> Quote — Peter Yang @petergyang:
> Anthropic recently cut Claude Code's system prompt by 80%.
> @trq212 explains why:
> "As the models have gotten smarter, they need less direction, fewer constraints, and fewer examples. The examples are constraining it because now it's like, 'Oh, you want things like this...'"

**繁中改寫：**
Thariq 表示他正在寫一篇文章，說明 Anthropic 這次大幅精簡 Claude Code system prompt（砍掉 80%）背後學到的經驗，以及這些心得要怎麼套用到你自己寫的 skills 和 system prompt 上。他引用 Peter Yang 的貼文補充：隨著模型越來越聰明，需要的指示、限制條件跟範例都變少了——因為範例反而會限制模型的發揮，讓它誤以為「你只想要長得像範例的答案」。

**核心概念（簡單說）：**
這則貼文談的是一個反直覺的 prompt engineering 洞見：早期的模型比較笨，工程師會在 system prompt 裡塞很多詳細指示、規則跟範例（few-shot examples），試圖把模型的行為釘死。但模型能力提升後，這些範例反而變成「枷鎖」——模型會過度模仿範例的表面形式，而不是理解背後真正的意圖，等於用範例把模型的表現上限給框住了。所以 Anthropic 選擇把 Claude Code 的 system prompt 砍掉 80%，讓模型有更多空間依靠自身判斷力解決問題，而不是死板地照著範例的框架走。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你有在寫 Cursor rules、自訂 system prompt，或幫團隊寫 CLAUDE.md / AGENTS.md，這個洞見直接影響你怎麼下指示。
- **具體場景：** 假設你的 CLAUDE.md 裡塞了五個「範例 commit message」，模型很可能會學到範例的字面格式（甚至無關的用詞），而不是「言簡意賅說明 why」這個真正的目的，導致生成的內容機械化、缺乏彈性。
- **這週可以嘗試：** 檢查一下自己專案的 CLAUDE.md 或 custom instructions，把「填鴨式的範例」精簡成「一句話講清楚的原則」，觀察 Claude 的輸出是否反而更靈活、更貼近你要的結果。

**前端工程師實際應用：**
- **跟你工作的關聯：** 這提醒我們：即使是 Anthropic 官方產品，計費／用量顯示這種依賴後端狀態同步的 UI，也會有短暫的資料不一致視窗期，這跟你自己維護的訂閱制或用量制產品是同一類問題。
- **具體場景：** 想像你的 SaaS 產品也有「方案內建額度 vs. 超額按次計費」兩種模式，如果後端計費狀態快取沒有即時失效（cache invalidation），前端就可能顯示錯誤的計費模式，造成使用者恐慌。
- **這週可以嘗試：** 檢查自己專案中「用量／計費狀態」相關的資料，是否有明確的快取失效或輪詢機制，確保後端狀態變更後，前端能在合理時間內反映正確資訊，而不需要使用者手動重新整理或重啟才能看到正確結果。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.215 / July 19, 2026

**變更項目：**
- Claude no longer runs the /verify and /code-review skills on its own; invoke them with /verify or /code-review when you want them（Claude 不再自動執行 /verify 與 /code-review 這兩個 skills，改成需要你自己明確下 /verify 或 /code-review 指令才會觸發）

**核心概念（簡單說）：**
在先前版本中，Claude Code 完成程式碼變更後，有時候會「自作主張」自動跑一次 /verify（驗證變更是否真的有效）或 /code-review（自動審查程式碼品質），即使你沒有要求。這個版本把這個自動行為拿掉了，把主導權交還給使用者：你想要驗證或審查，就得自己明確下指令觸發，Claude 不會再擅自幫你多做這兩件事。這是「降低代理行為預設侵入性」的一個具體調整，讓 Claude Code 的行為更可預期，也更省 token／時間，特別是在你只是想做小改動、還不想跑完整驗證流程的情境下。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你習慣讓 Claude Code 幫你改 code，這個改動直接影響你的工作流程——以前可能會「順便」幫你做 code review，現在不會了，你得自己記得呼叫。
- **具體場景：** 假設你只是要 Claude 幫你改一個小 typo 或調整樣式，以前它可能會自動多跑一次 code review 拖慢流程；現在改完就直接結束，如果你想要品質把關，要自己輸入 /code-review。
- **這週可以嘗試：** 把 /verify 和 /code-review 加進你自己常用的工作流程 checklist（甚至可以寫成一個簡單的自訂 slash command 或 hook），在完成較大改動後手動觸發，確保沒有因為這次行為改變而漏掉品質把關的步驟。
