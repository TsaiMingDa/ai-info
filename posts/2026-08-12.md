## boris_cherny · X

**原文網址：** [https://x.com/bcherny/status/2087284684103537011](https://x.com/bcherny/status/2087284684103537011)

**原文：**
> LLMs still produce bugs, but those bugs are different than what they used to be. It's less off-by-ones and more about system design, ui usability, missing broader context. Some kinds of coding has been solved, but not all.
>
> While models continue to improve, adversarial code review has been an incredibly powerful tool to catch many of these kinds of bugs.
>
> It can be as simple as a one line prompt - "use a dynamic workflow to adversarial test every edge case in an iOS simulator", or use Claude's built in /code-review (or /code-review low, /code-review medium, etc.)

**繁中改寫：**
LLM 還是會產生 bug，但這些 bug 的型態已經跟以前不一樣了。現在比較少是 off-by-one 這種低階錯誤，更多是系統設計、UI 易用性、缺少更廣泛 context 導致的問題。有些類型的 coding 問題已經算被解決了，但不是全部。

隨著模型持續進步，「adversarial code review」（用對抗式的角度去審查程式碼）已經變成抓出這類 bug 非常有效的工具。做法可以很簡單，一行 prompt 就搞定，例如「用動態流程在 iOS 模擬器裡對抗式測試每一個 edge case」，或是直接用 Claude 內建的 /code-review 指令（也可以指定強度，像是 /code-review low、/code-review medium 等等）。

**核心概念（簡單說）：**
這則貼文點出一個現象：LLM 寫程式的錯誤類型正在往「上層」移動。以前常見的是語法錯誤、邏輯低級錯誤（像迴圈邊界算錯），現在這類問題已經大幅減少，取而代之的是更抽象的問題，例如架構設計不合理、UI 操作起來卡卡的、或是 AI 沒有掌握到完整的專案脈絡才做出不合適的決策。作者提出的解法是「adversarial code review」，也就是刻意用挑毛病、找漏洞的心態去 review AI 寫出來的程式碼，而不是照單全收。Claude Code 內建的 /code-review 指令就是把這個流程工具化，讓你能一鍵觸發不同強度的審查。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你已經在用 Claude Code 生成前端元件或邏輯，這則貼文提醒你不能只看「能不能跑」，還要主動用對抗式思維去挑戰邊界情況、UI 互動細節，這正是前端最容易出包的地方。
- **具體場景：** 假設你請 Claude Code 幫你刻一個表單元件，功能面測試都過了，但你可以再下一個 prompt：「用對抗式的角度測試這個表單在極端輸入（超長字串、特殊字元、快速連續提交）下的行為」，逼它自己找出遺漏的 edge case。
- **這週可以嘗試：** 針對你最近一個由 Claude Code 完成的 PR，實際跑一次 /code-review medium，看看它抓出哪些你自己沒注意到的 UI 或邊界問題，並記錄下來養成習慣。

這是配合歐盟 AI Act 的一部分，其他實驗室也在加入類似的浮水印機制。要辨識文字是不是 AI 生成的一直很困難，這個機制能讓大家有更好的工具去判斷。我們也會推出一個文字偵測 API，讓你自己也能拿來用。

**核心概念（簡單說）：**
這則是對 Anthropic 宣布「新版 Claude 模型會在所有生成文字中嵌入不可見浮水印」這件事的補充說明。背景是歐盟 AI Act 對 AI 生成內容有揭露義務的要求，業界（不只 Anthropic）都在往這個方向補齊合規機制。重點是這個浮水印是「嵌在文字本身」而非附加的 metadata，所以複製貼上到別的地方依然存在，甚至部分編輯後也可能保留。Anthropic 之後還會開放一支文字偵測 API，讓開發者可以自行檢查一段文字是不是 Claude 生成的。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的產品有處理使用者輸入內容（例如社群平台、內容審核系統、CMS），未來可能會需要串接這類「AI 生成內容偵測 API」來標示或過濾內容。
- **具體場景：** 想像你在做一個部落格平台，PM 要求加上「AI 生成內容」標籤功能，未來就可以呼叫 Anthropic 開放的文字偵測 API，把偵測結果顯示在文章旁邊的 badge。
- **這週可以嘗試：** 追蹤 Anthropic 這支文字偵測 API 何時開放文件與存取方式，先在自己的專案中規劃好一個「內容來源標示」的 UI 元件位置，之後串接會更順。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.228 / August 11, 2026

**變更項目：**
- Fixed interactive sessions that could stop redrawing entirely, while the process kept running, after a rare internal layout error（修正互動式 session 在極少數內部版面錯誤後完全停止重繪的問題，即使程序其實還在跑）
- Fixed git / Git Bash not being found on Windows when Claude Code is launched from a parent folder of the git installation（修正 Windows 上從 git 安裝目錄的上層資料夾啟動 Claude Code 時，找不到 git / Git Bash 的問題）
- Fixed /tui reverting the session to an earlier model when /model had been changed since the last response（修正 /tui 會把 session 還原成較舊模型，即使前一次回應後已經用 /model 換過模型）
- Fixed cross-session messaging sometimes starting without an inbox in the first session after install or upgrade（修正安裝或升級後第一個 session 的跨 session 訊息功能有時沒有收件匣的問題）
- Fixed Remote Control /resume while connected leaking the resumed conversation's title or history into the connected session（修正連線狀態下用 Remote Control /resume 時，被 resume 的對話標題或歷史紀錄會外洩到目前連線 session 的問題）
- Fixed claude self-hosted-runner sessions failing on every fresh runner when the checkout hook fails for a repository the session doesn't push to; that repository is now skipped with a warning（修正 self-hosted runner 在每個全新 runner 上，因某個 session 不會 push 的 repo checkout hook 失敗而導致整體失敗的問題；現在會跳過該 repo 並顯示警告）
- Fixed self-hosted runners ending sessions in the gap between a background task finishing and the follow-up turn starting（修正 self-hosted runner 在背景任務結束、後續回合開始之間的空窗期會誤把 session 結束的問題）
- Fixed session cleanup deleting contents inside a project's memory folder（修正 session 清理程序會誤刪專案 memory 資料夾內容的問題）
- Fixed background plugin-cache cleanup deleting a plugin's cache when its only version is a symlinked development checkout（修正背景 plugin cache 清理程序，在 plugin 唯一版本是 symlink 開發用 checkout 時會誤刪該 cache 的問題）
- Fixed a settings-merge issue where a marketplace entry redefined in a higher-precedence settings tier could inherit another tier's custom headers; marketplace entries now merge as whole entries（修正設定合併問題：較高優先層級重新定義的 marketplace 項目，會繼承另一層的自訂 headers；現在 marketplace 項目改成整筆合併）
- Fixed the deferred-tools reminder occasionally being sent to the model twice after a skill invocation（修正呼叫 skill 後，deferred-tools 提醒偶爾會被重複傳給模型兩次的問題）
- Hardened skills synced from claude.ai: they no longer shadow local commands or MCP prompts, their descriptions are sanitized and labeled, and on your machine their bodies don't run ! commands or expand @ files（強化從 claude.ai 同步下來的 skills 安全性：不再遮蔽本機指令或 MCP prompts，描述文字會被清理並標示來源，且在本機執行時內文不會執行 ! 指令或展開 @ 檔案）
- Improved cross-session messages: the sender and body now display inline instead of a collapsed line, and messages to Remote Control sessions on other machines show your Remote Control session name as the sender（改善跨 session 訊息顯示：寄件者與內文改成直接展開顯示，不再是折疊成一行；傳給其他機器上 Remote Control session 的訊息，寄件者會顯示你的 Remote Control session 名稱）
- Improved Vertex AI credential handling: expired or missing Google Cloud credentials now fail within seconds instead of retrying for minutes（改善 Vertex AI 憑證處理：Google Cloud 憑證過期或缺失時，幾秒內就會回報失敗，不會再重試好幾分鐘）
- Improved compaction progress: the retry countdown and stall hint now appear during compaction instead of only a progress bar（改善 compaction 進度顯示：重試倒數與停滯提示現在會在 compaction 過程中顯示，而不是只有一條進度條）
- Updated terminal title busy-spinner glyphs to reduce tab-bar jitter on some terminals（更新終端機標題忙碌 spinner 圖示，減少部分終端機分頁列的抖動）
- Changed the Write tool so newer models can overwrite an existing file they haven't read this session, matching the Edit tool's rules; older models still require the read first（調整 Write 工具規則：較新模型現在可以覆寫本次 session 尚未讀過的既有檔案，與 Edit 工具規則一致；較舊模型仍須先讀取檔案）
- Removed the outdated note about auto mode sessions costing slightly more from the first-use notice for Pro, Max, and Team plans（移除 Pro、Max、Team 方案首次使用提示中，關於 auto mode session 費用略高的過時說明）

**核心概念（簡單說）：**
2.1.228 這個版本主要是一輪修 bug + 體驗優化，沒有重大新功能。比較值得注意的幾個重點：一是強化了從 claude.ai 同步下來的 skills 安全性（避免惡意 skill 遮蔽本機指令、偷偷執行指令或讀檔），二是修正了好幾個跟 session/Remote Control 狀態管理有關的 bug（例如訊息外洩、model 被還原），三是放寬了 Write 工具對新模型的檔案覆寫限制，讓工作流程更順暢。整體是一次穩定性與安全性導向的維護更新。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你有使用 Remote Control 跨機器操作 Claude Code，或是有裝從 claude.ai 同步下來的 skills，這次更新直接修掉了幾個資安與資料外洩相關的 bug，建議盡快升級。
- **具體場景：** 假設你用 Remote Control 在辦公室電腦跟筆電之間切換 Claude Code session，之前可能遇過切換後看到不該看到的對話標題或歷史，這個版本已經修掉這個外洩問題。
- **這週可以嘗試：** 執行 claude --version 確認自己是不是已經在 2.1.228（或更新版本），如果不是就手動升級，並留意 Write 工具覆寫規則變寬鬆後，是否需要調整你既有的檔案保護習慣。
