### Version 2.1.166 / 2026-06-06

**變更項目：**
- Added `fallbackModel` setting — 可設定最多三個備用 model，當主要 model 過載或不可用時依序嘗試；`--fallback-model` 現在也適用於互動式 session
- Added glob pattern support in deny rule tool-name position — `"*"` 可以拒絕所有工具；allow rules 拒絕非 MCP glob；未知工具名稱在 deny rules 中會在啟動時警告
- Hardened cross-session messaging — 透過 `SendMessage` 從其他 Claude session 傳來的訊息不再帶有 user authority；receivers 拒絕被轉發的 permission requests；auto mode 會封鎖它們
- `MAX_THINKING_TOKENS=0`、`--thinking disabled`、以及個別 model 的 thinking toggle 現在可以在預設開啟 thinking 的 model 上停用 thinking（第三方 provider 不受影響）
- Claude Code 在 API 回傳非預期的 non-retryable error 時，現在會自動用備用 model 重試一次；auth、rate-limit、request-size、transport 錯誤仍會立即顯示
- `claude update` 現在在下載前會先顯示目標版本號，不再靜默下載
- `claude agents`：在列表中輸入 URL 現在可以過濾出第一個 prompt 包含該 URL 的 session
- Fixed：session 中發送無法處理的圖片時，持續出現的 "image could not be processed" 錯誤和額外 token 消耗
- Fixed：worker 註冊啟動期間後端短暫中斷時，remote session 永久卡住的問題
- Fixed：JetBrains IDE terminal（IntelliJ、PyCharm、WebStorm 等）在 2026.1+ 上的閃爍問題，啟用 synchronized output 解決
- Fixed：使用 Kitty keyboard protocol 的 terminal（WezTerm、Ghostty、kitty）中 Shift+非 ASCII 字元（例如 Shift+ä → Ä）被丟棄的問題
- Fixed：Windows 上 PowerShell 命令驗證偶爾遠超時間預算掛住的問題
- Fixed：macOS 上 daemon 死掉但連線中時，孤立的 `claude --bg-pty-host` 進程 CPU 100% 的問題
- Fixed：切換 `/voice` 後 voice mode 需要 `/login` 才能清除過期 auth 檢查
- Fixed：managed settings 中有無效條目時，靜默停用其餘有效 policy 的問題
- Fixed：managed-settings 的 `allowedMcpServers`/`deniedMcpServers` predicate 在使用 `${VAR}` 參考時不匹配
- Fixed：進入 git worktree 的 background agent session 從 `claude agents` 重開時 crash loop 並顯示 "No conversation found"
- Fixed：串流時 Ctrl+O transcript view 出現重複的 thinking 文字
- Fixed：`/doctor` 在 remote session 內執行時顯示矛盾的 "Not inside a remote session" 失敗檢查
- Fixed：在 `claude agents` dispatch 和 reply 輸入框輸入多行 prompt 時，cursor 卡在第一行末尾
- Fixed：無 Unicode 支援的 terminal 上，任務列表中 background agent 列之間出現空行

**核心概念（簡單說）：**
這次 2.1.166 是一個內容非常豐富的版本，有兩個主要方向：

第一是**可靠性與容錯**。新的 `fallbackModel` 設定讓你可以指定備援 model，當主 model 過載時自動切換，有點像資料庫的 read replica — 主機掛了，自動切備機，使用者感知不到中斷。這對跑長時間 agentic task 的場景很重要。

第二是**安全性強化**。`SendMessage` 跨 session 訊息不再能帶著 user authority，避免一個被惡意操控的 Claude session 透過訊息傳遞取得你的 permission。這是多 agent 架構下的重要安全邊界。

其餘大量的 bug fix 涵蓋 JetBrains 閃爍、Kitty terminal 鍵盤問題、macOS CPU 100%、Windows 掛住等各平台細節，說明 Claude Code 正在積極打磨跨平台體驗。

**前端工程師實際應用：**
- **跟你工作的關聯：** `fallbackModel` 直接解決了「Opus 過載、整個 agentic task 卡住」的痛點；如果你在 CI 裡跑 Claude Code，可以設定備援 model 確保不因 API 過載而失敗；glob deny rule 讓你在 `.claude/settings.json` 裡用 `"*"` 一口氣封鎖所有工具，適合在只需要讀取分析的情境下限制 Claude 的行為範圍
- **具體場景：** 在 `.claude/settings.json` 加入 `"fallbackModel": ["claude-sonnet-4-6", "claude-haiku-4-5-20251001"]`，這樣當 claude-opus-4-8 過載時，Claude Code 會自動嘗試 Sonnet 4.6，不會讓你的 PR review agent 因為 API 限流而整批失敗
- **這週可以嘗試：** 執行 `claude update` 升到 2.1.166+，然後在你的 `.claude/settings.json` 試著加上 `"fallbackModel"` 設定，跑一個長一點的 agentic task 觀察備援 model 是否有機會觸發
