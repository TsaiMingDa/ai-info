## Claude Code · Changelog

**版本號 / 日期：** 2.1.195 / June 26, 2026

**變更項目：**
- Added `CLAUDE_CODE_DISABLE_MOUSE_CLICKS` — 全螢幕模式下可停用滑鼠點擊／拖曳／hover，但保留滾輪捲動功能
- Fixed hook matchers with hyphenated identifiers (e.g. `code-reviewer`, `mcp__brave-search`) accidentally substring-matching — they now exact-match. Use `mcp__brave-search__.*` to match all tools from a hyphenated MCP server.（含連字號的 hook identifier 之前會誤用子字串比對，現在改為完整比對）
- Fixed voice dictation on macOS capturing silence in long-running sessions after the default input device changes（修正 macOS 語音輸入在長時間執行後切換預設輸入裝置時收到靜音的問題）
- Fixed voice dictation auto-submit never firing for languages written without spaces (Japanese, Chinese, Thai)（修正日文、中文、泰文等無空格語言的語音自動送出失效問題）
- Fixed external plugins enabled only by project `.claude/settings.json` not requiring explicit install consent on every loader path（修正僅透過專案設定啟用的外部 plugin 未要求安裝同意的問題）
- Fixed `/plugin Enable/Disable` not working when a plugin's `plugin.json` name differs from its marketplace entry name（修正 plugin 內部名稱與 marketplace 名稱不同時 Enable/Disable 失效問題）
- Fixed background jobs disappearing from `claude agents` or losing data when written by a newer Claude Code version（修正新版本寫入的背景 job 在舊 UI 中消失或資料遺失）
- Fixed reopening a crashed background task showing a blank screen for up to 5 seconds instead of its restart（修正重開當機的背景任務時最多顯示 5 秒空白畫面的問題）
- Fixed background agent daemons running unreachable when the control socket fails to start, blocking restarts（修正 control socket 啟動失敗導致背景 agent daemon 無法重啟的問題）
- Improved voice mode on Linux: now distinguishes "no microphone" from "SoX not installed" when SoX is present but no audio capture device exists（Linux 語音模式現在會區分「無麥克風」vs「SoX 未安裝」）
- Improved `claude agents` completed list to fill available vertical space; on short terminals the header compacts so live sessions stay visible（`claude agents` 完成列表現在充分利用垂直空間，終端機較矮時標題列自動收合）
- Improved Remote session startup with a provisioning checklist while the container starts（Remote session 啟動時顯示 provisioning 進度清單）

**核心概念（簡單說）：**
這次更新主要圍繞三個方向：一是修復語音輸入的多個邊緣案例（macOS 切換裝置、無空格語言自動送出）；二是修正 hook 機制的 substring 比對 bug，這個 bug 會讓含連字號的 hook identifier 意外觸發到不相關的工具；三是大幅穩定背景 agent 的生命週期管理，包含 crash 後重啟、daemon 啟動失敗、job 資料遺失等問題。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你在 CLAUDE.md 或 settings.json 裡設有使用連字號命名的 hook（例如 `code-reviewer`），這次的修正確保它不會誤觸發其他 hook；MCP 工具也一樣，`mcp__brave-search` 以前可能誤匹配 `mcp__brave-search-extra` 之類的工具
- **具體場景：** 假設你用 `code-reviewer` 這個 hook 在每次 Claude 停下來前做 code review，以前若系統中還有 `code-reviewer-strict` 這個 hook，兩個都可能被觸發。現在是精確比對，`code-reviewer` 只會匹配自己；若要批次匹配某個 MCP server 所有工具，改用 `mcp__brave-search__.*` 這樣的 glob pattern
- **這週可以嘗試：** 打開你的 `.claude/settings.json` 或 `CLAUDE.md`，檢視所有 hook identifier 是否有含連字號的命名，確認升級到 2.1.195 後行為是否如預期（可用 `/hooks` 查看目前已載入的 hooks）
