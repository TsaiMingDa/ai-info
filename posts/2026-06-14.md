## Claude Code · Changelog

**版本號 / 日期：** 2.1.163 / June 4, 2026

**變更項目：**
- Added `requiredMinimumVersion` and `requiredMaximumVersion` managed settings — 若版本不在允許範圍，Claude Code 拒絕啟動並引導至核可版本（組織管理版本鎖定）
- Added `/plugin list` command — 列出已安裝的 plugin，支援 `--enabled`/`--disabled` 篩選
- Added `c to copy` shortcut to `/btw` — 可複製 raw markdown 格式的回答到剪貼簿
- Hooks: Stop and SubagentStop hooks 現在可以透過 `hookSpecificOutput.additionalContext` 給 Claude 回饋，讓 turn 繼續而不被標記為 hook error
- Skills: 新增 `\$` escape 語法，可在 command body 裡 literal `$` 前面加數字

**核心概念（簡單說）：**
這個版本的重點是企業版本管控與 hook 彈性。`requiredMinimumVersion` 讓企業 IT 可以強制所有工程師使用在允許版本範圍的 Claude Code，避免過舊版本帶來的安全或相容性問題。Hook 的改善讓 `SubagentStop` 不再只能「中止」，而是可以帶著 context 繼續執行，這對需要多輪驗證的 CI 流程很有用。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的公司有管理 Claude Code 配置，現在可以在 managed settings 裡設定 `requiredMinimumVersion`，統一整個團隊的版本；對個人開發者來說，`/plugin list` 讓你可以快速確認當前 session 裡有哪些 plugin 啟用。
- **具體場景：** 你的 CI 流程裡有個 SubagentStop hook 用來在 agent 完成後做程式碼驗證，現在可以在 hook 回傳 `additionalContext` 說明驗證失敗的細節，讓 Claude 自動修復再繼續，而不是直接中止整個任務。
- **這週可以嘗試：** 在 Claude Code 裡輸入 `/plugin list` 看看你目前有哪些 plugin 啟用，確認你的 Cowork skill 和其他 MCP 都正確載入。

**版本號 / 日期：** 2.1.166 / June 6, 2026

**變更項目：**
- Added `fallbackModel` setting — 可設定最多 3 個備用模型，在主要模型過載或無法使用時依序嘗試（`--fallback-model` 也適用於互動 session）
- Added glob pattern support in deny rule tool-name position — `"*"` 可以 deny 所有 tool
- Hardened cross-session messaging: `SendMessage` 來自其他 Claude session 的訊息不再帶有 user authority，receiver 會拒絕代理的 permission request
- `MAX_THINKING_TOKENS=0` 和 `--thinking disabled` 現在可以停用預設有 thinking 的模型（透過 Claude API）

**核心概念（簡單說）：**
`fallbackModel` 是這個版本最實用的新功能。概念類似 load balancer 的 fallback 機制：你的 primary 模型可以是 Fable 5，但當它過載時自動切到 Opus 4.8，再到 Sonnet，確保 agent 任務不會因模型不可用而中斷。

安全性強化部分：跨 session 的 `SendMessage` 現在有嚴格的 authority 隔離，防止惡意的 prompt injection 攻擊透過 agent 間通訊取得更高權限。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的 CI pipeline 或 background agent 在尖峰時間常常遇到模型過載（429 錯誤），`fallbackModel` 可以讓任務自動降級到較便宜的模型繼續執行，而不是直接失敗。
- **具體場景：** 在 `.claude/settings.json` 裡設定 `"fallbackModel": ["claude-opus-4-8", "claude-sonnet-4-6"]`，這樣你的 background code review agent 在 Fable 5 不可用時，會自動用 Opus 4.8 繼續跑，不需要手動 retry。
- **這週可以嘗試：** 打開 `.claude/settings.json`，加入 `"fallbackModel"` 設定，為你最常用的 agentic 任務加上自動降級備案。

**版本號 / 日期：** 2.1.169 / June 8, 2026

**變更項目：**
- Self-hosted runner: 新增 `post-session` lifecycle hook — session 結束、workspace 刪除前執行，可 snapshot 未 commit 的工作或 export logs
- Added `--safe-mode` flag (and `CLAUDE_CODE_SAFE_MODE`) — 啟動時停用所有自訂設定（CLAUDE.md、plugins、skills、hooks、MCP servers），適用於除錯
- Added `/cd` command — 在不中斷 prompt cache 的情況下切換工作目錄
- Added `disableBundledSkills` setting — 可隱藏 bundled skills、workflows 和內建 slash commands

**核心概念（簡單說）：**
`--safe-mode` 就像瀏覽器的「無痕模式」版的 Claude Code：所有 plugin、hook、skill 都停用，讓你可以快速定位問題是出在 Claude Code 本身還是你的自訂配置。這對調試複雜的 MCP 設定或 skill 衝突問題特別有用。

`/cd` 解決了一個之前的痛點：切換工作目錄會重設 prompt cache，導致後續呼叫的 token 成本升高。現在 `/cd` 會保留 cache，節省費用。

**前端工程師實際應用：**
- **跟你工作的關聯：** `--safe-mode` 讓你在遇到奇怪的行為時，可以快速確認問題來源。如果你的 MCP server 或 skill 有 bug，`safe-mode` 下的 Claude Code 就像「乾淨的基礎版本」，可以做對照組測試。
- **具體場景：** 你的 Claude Code 啟動後一直出現奇怪的錯誤，但不確定是 MCP plugin 還是 CLAUDE.md 造成的。執行 `claude --safe-mode` 開一個乾淨的 session，確認問題是否消失，快速縮小 debug 範圍。
- **這週可以嘗試：** 下次遇到 Claude Code 行為異常時，先試試 `claude --safe-mode`，如果問題消失，再逐一開啟 plugin 和 hook 來找出問題根源。

**版本號 / 日期：** 2.1.172 / June 10, 2026

**變更項目：**
- Sub-agents can now spawn their own sub-agents (up to 5 levels deep) — 子 agent 現在可以再生成子 agent，最多 5 層巢狀
- Amazon Bedrock: 現在從 `~/.aws` config 讀取 AWS region，`/status` 顯示 region 來源
- Added a search bar when browsing a marketplace's plugins in `/plugin` — plugin 瀏覽新增搜尋列
- Fixed sessions using 1M context without usage credits getting permanently stuck

**核心概念（簡單說）：**
「Sub-agent 可以再產生 sub-agent（最多 5 層）」是這個版本最大的架構改變。以前 agent 的架構是 1 層：主 agent → 多個子 agent。現在變成 5 層樹狀結構：主 agent → 子 agent → 孫 agent → ... 這讓更複雜的 agentic workflow 變成可能，例如「一個負責架構的 agent，生出幾個負責不同模組的 agent，每個模組 agent 再生出負責個別檔案的 agent」。

**前端工程師實際應用：**
- **跟你工作的關聯：** 這個改變讓 Claude Code 可以更自然地處理大型 monorepo 專案：主 agent 負責整體策略，子 agent 負責各個 package，孫 agent 負責個別 component 的修改，互相不干擾。
- **具體場景：** 你有一個 Turborepo monorepo，包含 `apps/web`, `apps/mobile`, `packages/ui`, `packages/api`。用 Workflow 讓主 agent 分析整體架構後，派發 sub-agent 分別處理各個 package 的 TypeScript migration，每個 sub-agent 再根據需要派發更細的 sub-agent 處理個別檔案。
- **這週可以嘗試：** 在 Claude Code 裡試試看 Workflow 功能（`/workflows`），設計一個分層的 agent 任務，觀察它如何自動把大任務分解成巢狀的子 agent 並行處理。
