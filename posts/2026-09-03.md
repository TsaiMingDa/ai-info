**繁中改寫：**
背景執行的電腦操作能力被低估了。（引用 Claude 官方貼文）現在 Claude 可以在背景中操作你的電腦，用在 Claude Cowork 和 Claude Code 裡。交代它一件桌面上要做的事，Claude 就會像你一樣點擊、打字、開啟應用程式，同時你可以去忙別的事。

**核心概念（簡單說）：**
這則貼文宣布 Claude 新增「背景電腦操作」（background computer use）功能——過去的 computer use 通常需要你盯著畫面看模型操作（甚至會搶走你的滑鼠鍵盤焦點），現在則可以讓 Claude 在背景默默完成桌面上的操作型任務（點擊、打字、開啟應用程式），不會打斷你手上正在做的其他工作。這代表 Claude 從「你看著它做」進化到「它自己默默做，你事後看結果」的非同步工作模式，跟 Claude Code 裡的背景 agent 是同一種思路，只是套用到整個桌面 GUI 而非終端機。

**前端工程師實際應用：**
- **跟你工作的關聯：** 有些前端工作需要操作沒有 API/CLI 介面的 GUI 工具（例如 Figma 手動調整、內部後台系統的手動測試流程），這類任務以前得自己盯著做，現在可以丟給 Claude 背景執行。
- **具體場景：** 例如要在多個瀏覽器分頁裡手動測試不同裝置解析度下的 RWD 表現、或是要在設計工具裡搬移大量圖層對齊網格，可以請 Claude Cowork 在背景把這些重複性 GUI 操作跑完，你同時繼續寫程式。
- **這週可以嘗試：** 到 Settings → General → Computer use 打開這個功能（目前僅 macOS 桌面版 Pro/Max beta），找一個你手邊重複性高的桌面操作任務試著丟給它做。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.259 / September 2, 2026

**變更項目：**
- Added `managedMcpServers` managed setting: organizations can provide HTTP/SSE MCP servers to every user（新增組織層級 `managedMcpServers` 設定，可統一為所有使用者提供 HTTP/SSE MCP 伺服器）
- Added `--permission-prompts none` for unattended headless hosts（新增 `--permission-prompts none`，讓無人值守的 headless 環境自動拒絕所有原本會跳出的權限提示，而非卡住等待）
- Added recognition of `glab mr create/merge/close/reopen/note/update` so GitLab merge requests show as `MR !N`（新增對 GitLab `glab` CLI merge request 指令的識別，讓 GitLab MR 也能像 GitHub PR 一樣顯示徽章）
- Added `--json` to `claude plugin validate`（新增機器可讀的外掛驗證報告格式）
- Fixed concurrent sessions silently reverting each other's `~/.claude.json` changes（修正多個 session 同時執行時互相覆蓋設定檔的問題，避免 workspace trust 或 MCP 設定無故遺失）
- Fixed Bash `Read()` deny rules not covering files given as option values (`--ignore-revs-file=.env`, `-f.env`, `@file`)（修正 Bash 拒絕規則對「透過參數值指定的檔案」防護不足的資安漏洞）
- Fixed the prompt cache being invalidated when the OAuth token refreshed in sessions with telemetry disabled（修正關閉遙測時，OAuth token 刷新會意外打斷 prompt cache 的問題）
- Fixed auto mode running a turn on a model it doesn't support when a command or skill's frontmatter `model:` named one（修正 auto 模式誤用不支援的模型執行指令/skill 的問題）
- Fixed MCP servers that disconnect while their tools are being listed at startup showing as connected with no tools（修正啟動時斷線的 MCP 伺服器誤顯示為「已連線但無工具」）
- Fixed managed settings silently going unenforced when the config file cannot be parsed: Claude Code now refuses to start and names the source（修正管理員設定檔解析失敗時「靜默失效」的資安風險，改為直接拒絕啟動並指出問題來源）
- Fixed Stop not actually stopping background agents and workflows in remote-control sessions（修正 Remote Control 中 Stop 指令無法真正停止背景 agent 與 workflow 的問題）

**核心概念（簡單說）：**
這個版本延續 Fable 5.1 發布後的收尾性修補，重點集中在三塊：(1) 企業管理功能（`managedMcpServers`、headless 環境的自動拒絕權限提示）讓 IT 團隊更容易大規模部署與治理 Claude Code；(2) 多項資安性質的修正，包含 Bash 拒絕規則的漏洞、管理設定解析失敗時「靜默失效」的風險改為直接拒絕啟動；(3) 多 session 併發使用時的穩定性修正（設定檔互相覆蓋、prompt cache 意外失效）。整體看得出這版是在為企業級大規模部署鋪路。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你常同時開多個 Claude Code session 平行處理不同任務，這版修正了 session 間互相覆蓋設定、cache 被意外清空這類會拖慢你日常工作的邊界情況 bug。
- **具體場景：** 例如你同時在三個終端機視窗跑三個不同專案的 Claude Code session，過去可能遇過某個 session 悄悄把另一個 session 的 workspace trust 設定改掉，這版已修正；另外若你有用 GitLab（而非 GitHub），`glab mr` 指令現在也能正確顯示 MR 徽章了。
- **這週可以嘗試：** 執行 `claude --version` 確認是否已更新到 2.1.259，若你的團隊有用 Bash 拒絕規則保護 `.env` 等敏感檔案，可以重新測試一次 `--ignore-revs-file=.env` 這類參數形式是否確實被擋下。
