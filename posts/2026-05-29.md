**繁中改寫：**
Anthropic 發布 Claude Opus 4.8，在 Opus 4.7 的基礎上帶來更精準的判斷力、更高的誠實度，以及更長時間獨立運作的能力。定價維持不變。

這次最值得關注的有兩個新功能：

**Dynamic Workflows（研究預覽版）**：讓 Claude 在 Claude Code 中自己寫 orchestration script，可以協調數十到數百個 subagent 平行運行。Bun 的作者 Jarred Sumner 用這個功能把 Bun 從 Zig 移植到 Rust——750,000 行 Rust、99.8% 測試通過，從第一個 commit 到 merge 只花了 11 天。

**Effort 控制**：可以設定模型要花多少「力氣」回答。預設是 HIGH effort；`/effort xhigh` 留給最難的任務；fast mode 現在速度快 2.5 倍、只需 2 倍標準費率（比之前便宜許多）。

**核心概念（簡單說）：**
Dynamic Workflows 是這次最重磅的功能。以前你在 Claude Code 跑一個複雜任務，就算開多個 worktree 也是手動管理。Dynamic Workflows 讓 Claude 自己寫一個「調度腳本」，然後在背景自動 spawn 幾十甚至幾百個 subagent，每個 agent 從不同角度攻同一個問題，最後再整合結果。

這就像從「一個工程師做所有事」變成「一個 tech lead 帶一整個團隊，他自己決定怎麼分工」。Claude 從執行者進化成了調度者，而且整個過程你只需要給一個目標。

**前端工程師實際應用：**
- **跟你工作的關聯：** Dynamic Workflows 讓大規模的任務（整個 codebase 的 accessibility audit、全站 TypeScript strict mode migration、跨 component 的 design token 替換）變得可以一鍵委派，不需要手動拆分工作。
- **具體場景：** 你有 200 個 React component 需要從 class component 改成 functional component——可以對 Claude Code 說「用 Dynamic Workflow 把所有 class component 改成 functional component，每個 component 在不同 agent 上平行處理」，然後它會自動規劃並執行。
- **這週可以嘗試：** 在 Claude Code 中輸入 `/workflows` 查看 Dynamic Workflows 的介面，試試跑一個簡單的平行任務（例如對整個 repo 所有 `.tsx` 檔案加上 display name），感受一下 multi-agent 調度的體驗。

## Claude Code · Changelog

### 版本號 / 日期：v2.1.156 / 2026-05-29

**變更項目：**
- **Bug fix:** Fixed an issue when using Opus 4.8 where thinking blocks were modified, leading to API errors.（修正使用 Opus 4.8 時 thinking blocks 被修改導致 API 報錯的問題）

**核心概念（簡單說）：**
這是針對 Opus 4.8 上線（May 28 發布）後立即出現的 bug 所做的緊急修補。Opus 4.8 支援 extended thinking（模型在回答前先「思考」的機制），而 thinking blocks 是這個機制的核心資料結構——API 要求這些 blocks 維持不可修改（immutable）。當 Claude Code 不小心修改了這些 thinking blocks，就會觸發 API 的驗證錯誤，導致整個請求失敗。這是新模型上線後常見的「day one patch」，而且修復速度也很快（隔天就出了）。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你昨天（May 28）更新 Claude Code 到 v2.1.154 後在 Opus 4.8 上遇到神秘的 API 錯誤，更新到 v2.1.156 就會解決。
- **具體場景：** 在 Claude Code 中對需要深度推理的任務（例如 debug 複雜的 race condition 或分析複雜的型別推導問題）使用 Opus 4.8 時，thinking 機制讓模型「先想清楚再說」，v2.1.156 確保這個機制能正常運作。
- **這週可以嘗試：** 確認 `claude --version` 顯示 2.1.156 或以上，然後在 Opus 4.8 上跑一個需要多步推理的任務，確認沒有 API 錯誤。

### 版本號 / 日期：v2.1.154 / 2026-05-28

**變更項目：**
- **Opus 4.8 Released:** Now defaults to high effort; `/effort xhigh` for hardest tasks（Opus 4.8 上線，預設 high effort；最難任務可用 /effort xhigh）
- **Dynamic Workflows:** Ask Claude to create a workflow orchestrating tens to hundreds of agents in background; `/workflows` to view runs（Dynamic Workflows 讓 Claude 自動協調數十至數百個 agent 在背景執行；/workflows 查看執行紀錄）
- **Fast Mode Cost Reduction:** Opus 4.8 fast mode now 2x standard rate for 2.5x speed（Fast mode 降至 2 倍標準費率，速度 2.5x）
- **Lean System Prompt** is now default for all models except Haiku, Sonnet, and Opus 4.7 and earlier（精簡 system prompt 成為大多數模型的預設值，釋放更多 context window）
- **UX:** Claude reserves multiple-choice questions only for decisions it genuinely cannot make（Claude 只在真正無法自決時才問多選題，減少打擾）
- **`/simplify`** now runs cleanup-only review with auto-apply（/simplify 改為自動套用，專注 reuse/simplification/efficiency，不抓 bug）
- **`/effort` labels** renamed from "Speed"/"Intelligence" to "Faster"/"Smarter"
- **`←←` agent view** now works on Bedrock, Vertex, Foundry, and with telemetry disabled
- **Background sessions:** `! <command>` in `claude agents` runs shell commands as background sessions
- **`/logout`** now signs you out instead of sending to background session
- **Plugins:** `defaultEnabled: false` in `plugin.json` supported; Discover tab pins directory-suggested plugins
- **Streaming tool execution** always enabled on all platforms including Bedrock/Vertex/Foundry
- **MCP:** Stdio servers now receive `CLAUDE_CODE_SESSION_ID` and `CLAUDECODE=1` env vars
- **MCP:** `claude mcp list/get` shows unapproved servers as `⏸ Pending approval`
- **Bug fixes:** rm -rf $HOME trailing slash path blocking, $TMPDIR sandbox issue, background session orphan/completion issues

**核心概念（簡單說）：**
這是近期最大的一次 Claude Code 更新，核心是 Opus 4.8 上線和 Dynamic Workflows 的推出。Dynamic Workflows 讓 Claude Code 真正進入「multi-agent orchestration」的時代——你下一個目標，Claude 自己寫調度腳本，管理幾百個 subagent 平行作業，完成後彙整結果。

另一個重要改變是 lean system prompt 成為預設，讓更多 context window 留給你的實際任務，對長任務特別有幫助。`/simplify` 改為自動套用也很值得注意：以前要手動確認每一條重構建議，現在直接幫你改好。

**前端工程師實際應用：**
- **跟你工作的關聯：** `/simplify` 自動套用 + Dynamic Workflows 組合，可以大幅自動化 codebase 的重構：用 Dynamic Workflows 分析所有 component，再用 /simplify 逐一優化，整個流程只需設定一次。
- **具體場景：** 有個積累了很多技術債的 React 專案——可以跑 Dynamic Workflows 讓多個 agent 平行分析不同模組（各自評估型別安全性、accessibility、效能），再讓 `/simplify` 把可自動修的問題直接 apply，最後你只需要 review diff。
- **這週可以嘗試：** 執行 `claude update` 確認版本，然後在 Claude Code 中試試 `/workflows` 探索 Dynamic Workflows 介面，或對你目前最亂的一個 component 執行 `/simplify`，看看自動 apply 的效果。

### 版本號 / 日期：v2.1.153 / 2026-05-28

**變更項目：**
- **Git plugin:** Added `skipLfs` option to `github`/`git` plugin sources to skip Git LFS downloads（git plugin 新增 skipLfs 選項，可跳過 Git LFS 下載）
- **MCP notifications:** Combined auth notifications for MCP servers and connectors into single message（MCP 認證通知合併為單一訊息，減少通知噪音）
- **macOS:** Background agents now appear as "Claude Code" in Privacy & Security with persistent permissions across upgrades（背景 agent 在隱私設定中顯示為 "Claude Code"，升級後不需重新授權）
- Multiple regression fixes and MCP/plugin improvements

**核心概念（簡單說）：**
這是 v2.1.154 同天發布的小版本更新，主要是修回歸問題。macOS 的背景 agent 權限現在「記得住」——以前每次升級 Claude Code 都要重新去系統偏好設定裡授權背景 agent，這次之後就只需要授權一次，之後升級會自動保留。對常用 background agents 跑長任務的使用者很有感。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的 repo 有用 Git LFS 存放大型 asset（設計稿、影片、大型 JSON fixture），`skipLfs` 讓 Claude Code 可以在不下載 LFS 檔案的情況下分析程式碼，速度更快、費用更低。
- **具體場景：** 在一個 monorepo 中，LFS 存放了幾 GB 的設計 assets，但你只需要 Claude Code 幫你改 TypeScript 邏輯——在 `.claude/settings.json` 的 git plugin 設定中加上 `"skipLfs": true` 後，Claude Code 不會花時間下載這些不相關的檔案。
- **這週可以嘗試：** macOS 用戶更新後確認 System Settings → Privacy & Security 裡背景 agent 的授權是否保留，不需要再手動重設。
