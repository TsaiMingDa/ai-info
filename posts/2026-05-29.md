**原文：**
> New in Claude Code (research preview): dynamic workflows.
>
> Claude writes an orchestration script on the fly, then spins up a large fleet of coordinated subagents in parallel to take on your most complex tasks.
>
> Use the word "workflow" in a prompt to get started.

**繁中改寫：**
Claude Code 推出新功能（research preview）：dynamic workflows。Claude 會即時撰寫一個 orchestration 腳本，然後並行啟動大量協調的 subagents 來處理你最複雜的任務。在 prompt 中加入「workflow」這個關鍵字就能啟動。

**核心概念（簡單說）：**
Dynamic workflows 是一種「自動化調度引擎」——你給 Claude 一個大任務，它不是自己一步一步做，而是先寫好一份執行計畫（orchestration script），然後同時派出幾十甚至幾百個 subagent 並行處理各個子任務，最後彙整結果。就像你雇了一個工頭，工頭不是自己蓋房子，而是先畫藍圖、再排班一群工人同時進場施工。

**前端工程師實際應用：**
- **跟你工作的關聯：** 過去 Claude Code 每次只能處理單一 thread 的任務，大型 codebase 遷移或跨多個元件的重構很吃力；有了 dynamic workflows，可以把大型任務拆開並行執行，大幅縮短時間。
- **具體場景：** 對一個有幾百個 React 元件的專案說「workflow: 把所有 class component 重構成 functional component with hooks」，Claude 會自動規劃並派多個 subagent 同時處理不同元件。
- **這週可以嘗試：** 在 Claude Code 中輸入包含「workflow」的 prompt（例如「workflow: 幫我把這個專案裡所有的 var 改成 const 或 let」），觀察它如何生成 orchestration 流程。

2.1.154 是這次發布週期最大的版本，幾乎是 Opus 4.8 整個功能組合的 CLI 實作。最值得關注的三點：一是 dynamic workflows 讓 Claude Code 能處理真正大規模的任務；二是 lean system prompt 成為預設，token 效率提升；三是多個背景 agent 的穩定性修復，讓長時間執行的非同步任務更可靠。

**前端工程師實際應用：**
- **跟你工作的關聯：** Streaming tool execution 全平台開啟代表在 AWS Bedrock 上跑 Claude 的工程師也能享受工具呼叫的即時回饋；lean system prompt 預設也意味著一般任務的 token 消耗會降低。
- **具體場景：** 在 Claude Code 輸入 `/workflows` 查看 dynamic workflow 執行記錄，或試用 `! npm run build` 把 build 指令丟到背景 session 執行，讓主 Claude 視窗繼續可以互動。
- **這週可以嘗試：** 更新到 2.1.154+，然後跑一次你平常做的 codebase 搜尋或重構任務，在 prompt 中加上「workflow」關鍵字，看看 Claude 如何自動規劃執行步驟。

**版本號 / 日期：** 2.1.153 / May 28, 2026

**變更項目：**
- Added `skipLfs` option to `github`/`git` plugin marketplace sources（Git plugin 新增跳過 LFS 下載的選項）
- Claude Code now shows a one-time notice when your npm global install can't auto-update（無法自動更新時顯示一次性提示）
- `claude agents` PR column now shows `PR #N` for single PR or `N PRs` for multiple（agent 列表 PR 欄位顯示優化）
- Fixed stateful MCP servers without the optional GET SSE stream reconnect-looping on tools/list（修復 MCP server 在 tools/list 時的重連迴圈問題）
- Fixed subagent MCP servers ignoring `--strict-mcp-config` and enterprise managed MCP config（修復 subagent 的 MCP 安全設定未正確繼承的問題）
- `/model` now saves your selection as the default for new sessions（`/model` 選擇現在自動儲存為新 session 的預設值）
- Fixed Windows update rollback: Claude Code now restores the original executable if an update fails（Windows 更新失敗時現在會自動還原舊版本）

**核心概念（簡單說）：**
2.1.153 以穩定性和安全性修復為主。最重要的是 subagent MCP servers 忽略 `--strict-mcp-config` 的修復——這是安全性問題，之前在 agent 模式下 MCP 的 allow/deny 政策可能未被正確執行。另外 `/model` 儲存邏輯的改變很實用：選了 Opus 4.8 就會記住，不用每次新開 session 再選一次。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的團隊有設定 Claude Code 的 MCP server allow/deny 政策（企業或 Team plan），這個修復確保 subagent 也會遵守這些設定，不會繞過安全限制。
- **具體場景：** 更新後，用 `/model` 選好 Opus 4.8，它會自動成為後續新 session 的預設，省去每次切換的麻煩。
- **這週可以嘗試：** 如果你有設定 `.mcp.json` 和相關限制，更新到 2.1.153 後用 `claude mcp list` 確認 MCP server 的狀態是否正確顯示。
