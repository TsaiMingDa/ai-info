## Claude Code · Changelog

**版本號 / 日期：** v2.1.166 / 2026-06-06

**變更項目：**
- Added `fallbackModel` setting to configure up to three fallback models tried in order when the primary model is overloaded or unavailable; `--fallback-model` now also applies to interactive sessions（新增 `fallbackModel` 設定，可設定最多三個備援模型，當主模型過載或不可用時依序切換；`--fallback-model` 現在也適用於互動式 session）
- Added glob pattern support in deny rule tool-name position (`"*"` denies all tools); allow rules reject non-MCP globs, and unknown tool names in deny rules warn at startup（deny rule 的 tool-name 欄位現在支援 glob pattern，`"*"` 可拒絕所有工具；allow rule 不接受非 MCP 的 glob，啟動時會對未知 tool name 發出警告）
- Hardened cross-session messaging: messages relayed via `SendMessage` from other Claude sessions no longer carry user authority — receivers refuse relayed permission requests, and auto mode blocks them（強化跨 session 訊息安全：透過 `SendMessage` 中繼的訊息不再帶有 user authority，接收方拒絕中繼的權限請求，auto mode 也會封鎖它們）
- `MAX_THINKING_TOKENS=0`, `--thinking disabled`, and the per-model thinking toggle now disable thinking on models that think by default via the Claude API（`MAX_THINKING_TOKENS=0`、`--thinking disabled` 及 per-model thinking 開關，現在可在預設會啟動 thinking 的模型上停用該功能）
- Claude Code now retries a turn once on the fallback model when the API rejects an unexpected non-retryable error; auth, rate-limit, request-size, and transport errors still surface immediately（API 回傳非預期的不可重試錯誤時，Claude Code 會自動切換到備援模型重試一次；但 auth、rate-limit、request-size、transport 等錯誤仍會立即浮現）
- `claude update` now announces the target version before downloading instead of going silent（`claude update` 現在會在下載前顯示目標版本號，不再靜默執行）
- `claude agents`: typing a URL into the list now filters to the session whose first prompt contained it（`claude agents` 清單中輸入 URL 現在可過濾出第一個 prompt 包含該 URL 的 session）
- Fixed a recurring "image could not be processed" error and extra token usage when an unprocessable image was sent in a session（修復 session 中傳送無法處理的圖片時，反覆出現「image could not be processed」錯誤並消耗多餘 token 的問題）
- Fixed remote sessions becoming permanently stuck when a brief backend disruption occurred during worker registration at startup（修復 remote session 在啟動的 worker 註冊階段遭遇短暫 backend 中斷，導致 session 永久卡住的問題）
- Fixed flickering in JetBrains IDE terminals (IntelliJ, PyCharm, WebStorm, etc.) on 2026.1+ by enabling synchronized output（修復 JetBrains IDE（IntelliJ、PyCharm、WebStorm 等）2026.1+ 版本終端機畫面閃爍問題，透過啟用 synchronized output 解決）
- Fixed Shift+non-ASCII characters (e.g. Shift+ä → Ä) being dropped in terminals using the Kitty keyboard protocol (WezTerm, Ghostty, kitty)（修復在使用 Kitty keyboard protocol 的終端機（WezTerm、Ghostty、kitty）中，Shift+非 ASCII 字元（如 Shift+ä → Ä）被丟棄的問題）
- Fixed PowerShell command validation occasionally hanging far past its time budget on Windows（修復 Windows 上 PowerShell 指令驗證偶爾嚴重超時的問題）
- Fixed orphaned `claude --bg-pty-host` processes spinning at 100% CPU after the daemon dies while connected on macOS（修復 macOS 上 daemon 結束後，孤立的 `claude --bg-pty-host` 程序佔用 100% CPU 的問題）
- Fixed voice mode requiring `/login` to clear a stale auth check after toggling `/voice`（修復切換 `/voice` 後 voice mode 需要執行 `/login` 才能清除過期 auth check 的問題）
- Fixed managed settings with an invalid entry silently disabling enforcement of their remaining valid policies（修復 managed settings 含有無效項目時，靜默停用其餘有效 policy 執行的問題）
- Fixed managed-settings `allowedMcpServers`/`deniedMcpServers` predicates not matching when using `${VAR}` references（修復 managed-settings 中 `allowedMcpServers`/`deniedMcpServers` 使用 `${VAR}` 變數參照時無法正確匹配的問題）
- Fixed background agent sessions that entered a git worktree crash-looping with "No conversation found" when reopened from `claude agents`（修復進入 git worktree 的 background agent session 在從 `claude agents` 重新開啟時，反覆崩潰並顯示「No conversation found」的問題）
- Fixed duplicated thinking text in the Ctrl+O transcript view while streaming（修復串流時 Ctrl+O transcript 顯示重複 thinking 文字的問題）
- Fixed `/doctor` showing a contradictory failed "Not inside a remote session" check when run inside a remote session（修復在 remote session 中執行 `/doctor` 時，顯示矛盾的「Not inside a remote session」失敗訊息的問題）
- Fixed the cursor sticking at the end of the first line when typing a multiline prompt in the `claude agents` dispatch and reply inputs（修復在 `claude agents` 的 dispatch 及 reply 輸入框中輸入多行 prompt 時，游標卡在第一行末尾的問題）
- Fixed blank lines appearing between background agent rows in the task list on terminals without Unicode support（修復不支援 Unicode 的終端機中，task list 背景 agent 列之間出現空白行的問題）

**核心概念（簡單說）：**
v2.1.166 這次更新的核心是兩件事：**容錯機制**和**安全強化**。

容錯方面，新增的 `fallbackModel` 就像高速公路的備用車道——主模型（比如 claude-opus-4-8）被塞爆時，Claude Code 會自動切換到你指定的備援模型繼續工作，不會讓整個任務卡死在那裡。在高峰時段跑長時間任務的人，這個功能能省去很多手動重試的痛苦。

安全方面，跨 session 訊息隔離解決了一個微妙的風險：想像你有多個 Claude agent 透過 `SendMessage` 互相傳話，舊版本的問題是這個「轉發的訊息」還帶著原始 sender 的授權光環，理論上可以讓一個 agent 偷偷要求另一個 agent 做它沒有權限做的事。現在這個漏洞被堵住了。

另外還修了一大批終端機相容性問題，JetBrains 閃爍、WezTerm 按鍵丟失等 issue 全部清掉。

**前端工程師實際應用：**
- **跟你工作的關聯：** fallback model 設定讓你在忙碌時段跑大型 Claude Code 任務（例如整個 repo 的 TypeScript 型別重構）時不再擔心主模型暫時不可用；managed settings 的 bug fix 也讓有團隊管理 Claude Code 配置的環境更穩定
- **具體場景：** 你在 CI 流程裡用 Claude Code 做自動化 code review，設定好 `"fallbackModel": ["claude-sonnet-4-6", "claude-haiku-4-5-20251001"]`，即使 API 在部署高峰期壅塞，review 任務也會自動切到 Sonnet 繼續跑，不影響你的 PR merge 速度
- **這週可以嘗試：** 在 `.claude/settings.json` 加入 `"fallbackModel": ["claude-sonnet-4-6"]`，然後故意在 API 忙碌時段（台灣時間上午 9–11 點）跑一個中等大小的任務，觀察 Claude Code 是否有自動切換的日誌輸出
