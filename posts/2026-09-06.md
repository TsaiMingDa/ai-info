## Claude Code · Changelog

**版本號 / 日期：** 2.1.263 / September 6, 2026

**變更項目：**
- Bug fixes and reliability improvements — 這個版本沒有列出個別條目，官方只註明是一次「錯誤修正與穩定性改善」的版本。

**核心概念（簡單說）：**
2.1.263 是一次沒有公開細節的小維護版本，通常代表官方在背景修了一些不影響使用方式、但會提升穩定度的問題（例如效能調校或邊角案例修正），不需要特別調整使用習慣，升級即可。

**前端工程師實際應用：**

- **具體場景：** 如果你最近在用 Claude Code 跑長時間的重構或多輪 agent 任務時偶爾卡頓，升級到這個版本有機會順帶解掉。
- **這週可以嘗試：** 執行 `claude --version` 確認自己是否已在 2.1.263 以上，若還沒就先升級，日常操作不用改變任何習慣。

**版本號 / 日期：** 2.1.261 / September 4, 2026

**變更項目：**
- Added `bashOutputMaxChars` and `taskOutputMaxChars` settings to raise how much command and background-task output Claude receives inline before it is saved to a file, up to 128K characters — 新增 `bashOutputMaxChars`／`taskOutputMaxChars` 設定，可以把 Claude 直接讀取指令與背景任務輸出的上限調高到 128K 字元，超過才會存成檔案。
- Added `/skill-doctor` to show which loaded skills go unused and what they cost in context, so you can prune them — 新增 `/skill-doctor` 指令，列出目前載入但沒被用到的 skill，以及它們各自佔用多少 context，方便你清理。
- Added `--append-subagent-system-prompt-file` to read the subagent system prompt from a file, for prompts too large to pass on the command line — 新增 `--append-subagent-system-prompt-file` 參數，讓 subagent 的 system prompt 可以從檔案讀取，解決 prompt 太長塞不進指令列的問題。
- Fixed typed or pasted characters occasionally landing out of order or being dropped during fast input or key repeat — 修正快速輸入或按鍵重複時，打字或貼上內容偶爾會亂序或漏字的問題。
- Fixed resuming a session losing hook output and other context around parallel tool calls, which changed the resumed request — 修正 resume session 時，平行工具呼叫周邊的 hook 輸出與其他 context 會遺失，導致 resume 後的請求內容跟原本不一樣。
- Fixed Remote Control showing a stale permission mode when a phone, browser, or claude.ai app attaches to a terminal session, and sessions appearing stuck (spinner/Stop button) after stopping a turn remotely — 修正 Remote Control（手機／瀏覽器／claude.ai 遠端操作終端機 session）顯示過期的權限模式，以及遠端停止一輪對話後畫面卡在「執行中」的問題。
- Fixed SDK and cloud sessions ignoring a Stop or interrupt sent just after the first prompt, before the turn had started — 修正 SDK 與雲端 session 在第一個 prompt 剛送出、對話輪次還沒真正開始時發出的中斷指令會被忽略的問題，現在會確實停止而不是跑到完。
- Improved streaming performance: already-rendered blocks are no longer re-checked by layout on each update — 改善串流輸出效能，已經渲染好的區塊不會在每次更新時被重新排版檢查。
- Improved the dangerous-rm safety prompt to also catch `rm -rf` on positional parameters and inside double-quoted `sh -c` scripts — 加強危險 `rm -rf` 的安全警示，現在也能抓到用位置參數或包在雙引號 `sh -c` 腳本裡的危險刪除指令。
- Changed auto mode to treat a link that packs content into a public diagram renderer's URL as an upload to that site: no longer auto-approved unless you asked for it — 調整 auto 模式的安全判斷：把內容打包進公開圖表產生器網址的連結，視同「上傳到該網站」，除非你本來就要求這麼做，否則不再自動核准。
- Changed the prompt's word-editing keys to match Bash: `Ctrl+W` 刪到空白處、`Alt+F`／`Alt+D` 停在單字結尾、標點符號視為單字分隔 — 讓輸入框的單字編輯快捷鍵行為對齊 Bash 慣例。
- [VSCode] Added an "Add server" form and a "Remove" action to the MCP servers dialog, so MCP servers can be added and removed without leaving the IDE — VS Code 擴充功能新增 MCP server 管理表單，不用離開 IDE 就能新增／移除 MCP server。
- [VSCode] Added a fold button to permission and question prompts so the conversation behind them can be read without dismissing them — VS Code 的權限／提問彈窗新增摺疊按鈕，可以先看清楚背後對話內容，不用直接關掉提示。

**核心概念（簡單說）：**
2.1.261 是一次內容非常豐富的版本，重點分三塊：一是輸入與 session 可靠度的修正（打字亂序、resume 遺失 hook context、Remote Control 卡住）；二是新增了幾個提升可觀察性與客製化彈性的功能（`/skill-doctor` 讓你看清 skill 的 context 成本、可調高的輸出字元上限、subagent prompt 改用檔案讀取）；三是安全性收緊（更嚴格抓 `rm -rf`、把「把內容塞進圖表產生器網址」視為上傳行為來把關）。VS Code 擴充功能這邊則是持續補齊 MCP server 管理與互動細節。整體方向是讓 Claude Code 在長時間、多工具、多 session 的使用情境下更穩、更可控。

**前端工程師實際應用：**
- **跟你工作的關聯：** `/skill-doctor` 跟輸出字元上限的調整，直接影響你每天用 Claude Code 跑大型前端專案（例如 monorepo）時的 context 使用效率；VS Code 的 MCP server 管理表單則簡化了接第三方工具（例如設計稿轉程式碼、API 文件查詢）的流程。
- **具體場景：** 如果你的專案裝了一堆 plugin／skill，`/skill-doctor` 可以幫你抓出哪些 skill 根本沒用到卻一直佔 context，導致 Claude 「記憶力」變差；而 `bashOutputMaxChars` 調高後，跑 `npm run build` 或測試輸出很長的指令時，Claude 能直接看到完整結果而不用你手動存檔案再貼。
- **這週可以嘗試：** 升級後先跑一次 `/skill-doctor`，清掉沒在用的 skill；接著到 VS Code 擴充功能的 MCP servers 對話框試著加一個你常用的 MCP server（例如 context7 查文件），感受一下不用改設定檔的體驗差異。
