這次 IPO 的指標意義在於：Anthropic 將成為 AI 浪潮中第一批大型上市公司之一。市場如何定價一家高燒錢、高成長的 AI 基礎模型公司，將直接影響整個 AI 產業的估值邏輯和後續融資環境。

**版本號 / 日期：** v2.1.158 / 2026-05-30

**變更項目：**
- Auto mode is now available on Bedrock, Vertex, and Foundry for Opus 4.7 and Opus 4.8 — Auto mode 擴展至企業雲端平台（AWS Bedrock、Google Vertex、Azure Foundry）的 Opus 4.7 / 4.8
- Opt in by setting `CLAUDE_CODE_ENABLE_AUTO_MODE=1` — 透過環境變數 `CLAUDE_CODE_ENABLE_AUTO_MODE=1` 啟用

**核心概念（簡單說）：**
Auto mode 讓 Claude Code 根據任務複雜度自動在不同模型間切換，不是每個 token 都用最貴的模型，像自排車在平路自動降回低扭矩模式省油。之前這功能只在直連 Anthropic API 時可用，現在支援企業常見的雲端部署——代表用 Bedrock 或 Vertex 的大公司也能享用更智慧的成本控制。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的公司透過企業雲端方案部署 Claude Code（AWS Bedrock 是常見選擇），這個設定可以直接降低 API 成本
- **具體場景：** 在 CI 設定（如 GitHub Actions 的環境變數）或公司共用的 `.env.production` 中加入 `CLAUDE_CODE_ENABLE_AUTO_MODE=1`，讓自動化任務（code review、test generation）根據複雜度自動選模型，免去手動挑選的麻煩
- **這週可以嘗試：** 如果你的 Claude Code 是透過 Bedrock/Vertex 部署，在本機 `export CLAUDE_CODE_ENABLE_AUTO_MODE=1` 後測試一個標準任務，對比開啟前後的 token 用量差異

**版本號 / 日期：** v2.1.157 / 2026-05-29

**變更項目：**
- Plugins in `.claude/skills` directories are now automatically loaded without marketplace — `.claude/skills` 目錄中的 plugin 現在不需要 marketplace，放進去就自動載入
- Added `claude plugin init <name>` command to scaffold plugins — 新增 `claude plugin init <name>` 指令，快速建立 plugin 骨架
- Added autocomplete for `/plugin` arguments — `/plugin` 指令新增 autocomplete 支援（子指令、已安裝 plugin 名稱、marketplace plugin）
- `agent` field in `settings.json` honored for dispatched sessions — `settings.json` 的 `agent` 欄位現在在 dispatch session 中也會生效
- `EnterWorktree` can now switch between Claude-managed worktrees mid-session — `EnterWorktree` 支援在 session 進行中切換 Claude 管理的 worktree
- Background sessions now retire properly when idle subagents are parked — 背景 session 在閒置 subagent 停放時能正確結束，不再殘留
- `tool_decision` telemetry events now include `tool_parameters` when `OTEL_LOG_TOOL_DETAILS=1` — 啟用 `OTEL_LOG_TOOL_DETAILS=1` 時，telemetry 事件會包含工具參數（bash 指令、MCP/skill 名稱）
- Worktrees managed by Claude are left unlocked after agent completion — Claude 管理的 worktree 在 agent 完成後解鎖，可直接 `git worktree remove` 清理
- Fixed: unprocessable images (zero-byte, corrupt) crashing requests instead of becoming text placeholders — 修正損壞或空白圖片造成請求 crash 的問題
- Fixed: sandbox network permission prompts in auto and bypass-permissions modes — 修正 auto 和 bypass-permissions 模式下的 sandbox 網路權限提示問題
- Fixed: background session worktree isolation issues and orphaned worktrees after cleanup sweeps — 修正背景 session 的 worktree 隔離問題與孤兒 worktree
- Fixed: background sessions re-attached after sleep/wake not showing correct dates — 修正睡眠/喚醒後重連的背景 session 顯示錯誤日期的問題
- Fixed: various terminal rendering and UI issues in fullscreen mode — 修正全螢幕模式及各種終端機環境的渲染和 UI 問題

**核心概念（簡單說）：**
這版最重要的改動是 **Plugin/Skills 系統全面鬆綁**：以前在 `.claude/skills` 放 plugin 還需要 marketplace 設定，現在只要把 skill 資料夾放進去就能自動被 Claude Code 發現。搭配新的 `claude plugin init` 指令，從零建立客製化指令流程變得像 `create-react-app` 一樣快。

另外 worktree 管理更成熟——agent 任務跑完後 worktree 自動解鎖，不再產生讓你苦惱的孤兒 worktree。背景 session 的多個穩定性問題也一併修掉，長時間跑 agent 任務（如大型 codebase 遷移）的體驗會明顯改善。

**前端工程師實際應用：**
- **跟你工作的關聯：** `.claude/skills` plugin 系統讓你可以把重複性的前端工作流（跑 Lighthouse audit、生成 Storybook story、格式化整個 component 資料夾）封裝成一行指令，整個團隊共用
- **具體場景：** 在你的 Next.js 專案中建 `.claude/skills/a11y-audit/` 資料夾，寫一個 CLAUDE.md 告訴 Claude「掃描指定 component 的 accessibility 問題，輸出修改建議和 diff」；之後只要下 `/a11y-audit components/Button` 就能跑完整的無障礙檢查，不用每次重新描述需求
- **這週可以嘗試：** 執行 `claude plugin init my-skill` 建立你的第一個 skill，把你最常反覆告訴 Claude 的工作指示（例如「幫我寫這個 component 的 unit test，包含 edge case」）固化成一個可複用的 skill
