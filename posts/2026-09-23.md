**原文：**
> I used Opus 5.5 to formally verify the Claude Agent SDK using Lean. A couple short prompts = 16 PRs fixing various bugs and race conditions. Video attached.
>
> TLA+ also works well. I sometimes combine Lean and TLA+ to look for issues around data flow, concurrency, and state mgmt.

**繁中改寫：**
我用 Opus 5.5 搭配 Lean 對 Claude Agent SDK 做形式驗證（formal verification）。只下了幾個簡短的 prompt，就產出 16 個 PR，修掉了各種 bug 跟 race condition，影片附上。TLA+ 同樣好用，我有時候會把 Lean 跟 TLA+ 搭配使用，專門用來抓 data flow、並行（concurrency）和狀態管理（state management）方面的問題。

**核心概念（簡單說）：**
Formal verification（形式驗證）是用數學方法證明程式邏輯正確，而不是靠測試「碰運氣」抓 bug；Lean 跟 TLA+ 是這類驗證常用的工具，特別擅長抓傳統單元測試很難覆蓋到的並行（concurrency）與 race condition 問題。Boris Cherny 這則貼文的重點在於：現在讓 Opus 5.5 直接讀懂並操作這些形式驗證工具，把原本需要專家才能做的高門檻驗證工作，壓縮成「打幾句話」就能自動跑完整個驗證流程，並直接產出可合併的修復 PR。這代表 AI coding agent 的能力已經不只是「生成程式碼」，還能深入嚴謹的邏輯驗證領域，幫忙抓出人眼很難發現的並行陷阱。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端雖然較少直接寫 TLA+ 或 Lean，但 race condition、狀態管理錯誤（例如 React state 更新順序錯亂、非同步請求互相競爭）在前端一樣常見，這篇展示了用 AI 加形式化方法抓這類 bug 的可能性。
- **具體場景：** 假設你的 SDK 或狀態管理層（像自製的 store、WebSocket 同步邏輯）出現難以重現的競態問題，可以請 Claude 針對關鍵邏輯寫一個簡化的模型，模擬多個非同步事件交錯發生的情境，幫你在真的動手改程式碼之前，先系統性地抓出邏輯漏洞。
- **這週可以嘗試：** 挑一段你專案裡「感覺很危險」的並行邏輯（例如 debounce、fetch 跟 unmount 之間的競爭），請 Claude 用自然語言窮舉所有可能的執行順序與交錯情境，先不用真的學 TLA+，光是這個系統性列舉的動作就很有幫助。

成本與速度方面，預設設定下 Opus 5.5 的典型工作流成本比 Opus 5 便宜 40%：輸入/輸出 token 價格分別是每百萬 token 4 美元／20 美元（比 Opus 5 便宜 20%），而佔 agentic 與 coding 工作大宗成本的 cache read，價格更是每百萬 token 只要 0.2 美元（比 Opus 5 便宜 60%）。輸出速度也比 Opus 5 快超過 30%。此外，Pro、Max、Team 與座位制 Enterprise 方案的五小時用量上限也同步提高。

**變更項目：**
- Added Claude Opus 5.5 (claude-opus-5-5), now the default Opus model — 1M context, $4/$20 per Mtok with $0.20/Mtok cache reads（新增 Claude Opus 5.5，現在是預設的 Opus 模型，支援 1M context，輸入/輸出價格 $4/$20 每百萬 token，cache read 只要 $0.2 每百萬 token）
- Changed the default model on Pro and Team Standard plans from Sonnet to Opus, matching Max, Team Premium, and Enterprise（Pro 與 Team Standard 方案的預設模型從 Sonnet 改為 Opus，跟 Max、Team Premium、Enterprise 方案一致）
- Fixed writes through a symlinked path being judged by their in-tree spelling: the prompt names where the write lands, and acceptEdits, allow rules and auto mode no longer approve one landing outside（修正透過 symlink 路徑寫入檔案時，權限判斷會誤判寫入位置的問題；現在 prompt 會明確標示實際寫入的位置，acceptEdits、allow 規則跟 auto mode 也不會再誤放行寫到符號連結外部的操作）
- Fixed auto mode retrying an action over and over when a safety check declined to review it; the action is now denied once, noting that retrying won't help（修正 auto mode 在安全檢查拒絕審核某個動作時，會一直重試同一個動作的問題；現在會直接拒絕一次，並提示重試沒有用）
- Fixed a click that only brought the terminal window to the front also triggering the item under the pointer — in search pickers, tab bars, agent/workflow rows, slash-command links and suggestion dropdowns（修正只是把終端機視窗切到前景的點擊，卻誤觸發游標下方項目的問題，影響搜尋選單、分頁列、agent/workflow 列表、斜線指令連結與建議下拉選單）
- Fixed the Artifact tool silently disappearing when your organization's policy can't be loaded (for example behind a web proxy); Claude now says what's blocking it（修正組織政策載入失敗時 Artifact 工具會靜默消失的問題，例如在 web proxy 後方；現在 Claude 會明確說明是什麼原因擋住了）
- Improved artifact pages: no Print buttons, confirm dialogs or device features the viewer blocks, email and phone details shown as text, and dark mode that reaches form controls and scrollbars（改善 artifact 頁面：移除觀看者被封鎖的列印按鈕、確認對話框與裝置功能，email、電話資訊改用純文字顯示，深色模式也涵蓋表單控制項與捲軸）
- [VSCode] Added a Status dialog, Sandbox dialog, Claude in Chrome dialog, and Export conversation feature, each with a typed slash command（VSCode 擴充功能新增 Status、Sandbox、Claude in Chrome 對話框，以及匯出對話功能，都可以用對應的斜線指令開啟）
- [Claude Code on the web] Fixed gh and GitHub API calls inside a cloud session on a GitHub Enterprise Server repository failing after about eight hours; the token now renews automatically（修正雲端 session 在 GitHub Enterprise Server repo 上執行 gh 與 GitHub API 呼叫，約八小時後就會失敗的問題；token 現在會自動更新）

**核心概念（簡單說）：**
這個版本最重要的變更是把新發布的 Claude Opus 5.5 正式加入 Claude Code，並直接設為預設的 Opus 模型，同時 Pro／Team Standard 方案的預設模型也從 Sonnet 升級為 Opus，代表更多使用者會直接用上更強的模型。其他變更則集中在兩塊：一是修掉大量跟「權限判斷、auto mode 重試邏輯、symlink 路徑」相關的安全性與正確性問題，避免自動化操作在邊界情境下做出不該做的事；二是大量 UI／互動體驗的細節修正（鍵盤操作、對話框焦點、捲軸、深色模式），讓 fullscreen 模式跟 VSCode 擴充功能用起來更順手。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你日常用 Claude Code 開發，這次預設模型升級到 Opus（尤其是 Pro/Team Standard 方案）會直接影響你平常對話的模型品質與成本，值得留意 `/model` 目前顯示的實際模型。
- **具體場景：** 如果你的專案有用到 symlink（例如 monorepo 常見的 packages 軟連結結構），這次修正的 symlink 寫入權限判斷問題，直接關係到 Claude Code 的 acceptEdits／auto mode 會不會誤判寫入位置，值得更新後重新測試一次相關工作流程。
- **這週可以嘗試：** 更新到 2.1.280 後，跑一次 `/status` 確認目前使用的模型版本，並在 VSCode 擴充功能裡試試新加的 Sandbox 對話框與 Export conversation 功能，看看能不能簡化你現有的除錯與對話備份流程。
