**繁中改寫：**
Effort 到底是什麼？什麼時候該調整？為什麼不乾脆全部開 max？我深入研究了這個問題，翻了 eval 數據也自己做了實驗，結果蠻出乎意料的。

文章重點：effort 主要改變的是 Claude 做多少「驗證與邊界情況測試」，以及它自己下多少判斷。高 effort 在驗證很重要的領域（硬體、code review、資安）效果明顯；低 / 中 effort 則適合快速完成事情、讓你保持在迴圈裡。

他現在的日常流程是：先讓模型訪談他補齊需求 → 用 low/medium 實作 → 自己 review → 再用 high 做驗證。

經驗法則：
- **Low**：想要快速回應、自己全程參與，例如腦力激盪、畫草圖、簡單修改
- **Medium**：大多數日常軟體開發，例如實作新功能
- **High**：驗證很重要或邊界情況多的工作，例如在老舊 codebase 修 bug
- **Max**：想讓 Claude 完全自主解決難題，例如端對端建置並驗證整個 app、找關鍵軟體的資安漏洞

補充：想要保持參與時我更常用 low；max 基本上只在我完全不想介入、或要找資安漏洞時才用。

**核心概念（簡單說）：**
Effort 可以想成「你給 Claude 的時間預算暗示」。就像同事被告知「這給你 12 小時」和「這給你 1 小時」，交出來的東西會不同——前者會自己多做驗證、補邊界情況、替你做更多決定；後者會先給一個能迭代的版本。Thariq 用 Terminal-Bench 3.0 的資料證明：高 effort 主要減少的是「漏掉邊界情況」這類失敗（例如 HTML sanitizer 從 low 的 1/5 成功到 xhigh 的 5/5，因為高 effort 會自己跑 XSS 測試集、寫 fuzzer），但**無法修正「方法一開始就錯」的失敗**。

關鍵洞察是 effort 與「你想多參與」成反比：低 effort 回得快、假設少，適合你在旁邊邊看邊改；高 effort 做得多，但也代你做了更多假設。所以不是越高越好，而是依任務的「驗證需求」與「你想不想介入」來選。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端工作大量是 UI 迭代（適合 low，快速看效果再調）與少量高風險邏輯（表單驗證、權限、sanitize 使用者輸入，適合 high）；分開使用能同時省時間與 token。
- **具體場景：** 做一個新的 Dashboard 頁面：先 `/effort low` 請 Claude 訪談你並快速搭出版面與假資料，你在瀏覽器看了再迭代；確認方向後切 `/effort high` 請它「補齊 loading / empty / error 狀態、鍵盤操作與 a11y、跑 Vitest 與 Playwright 驗證」。
- **這週可以嘗試：** 挑一個本週要做的小功能，照 Thariq 的四步迴圈跑一次（訪談 → low 實作 → 自己 review → high 驗證），並記錄 high 驗證階段抓到了哪些 low 沒處理的邊界情況。

**核心概念（簡單說）：**
2.1.283 的亮點是 `/doctor prompt-audit`：隨著模型升級（Opus 5.5、Fable 5.1），很多為舊模型寫的 prompt 技巧——全大寫的「MUST」、重複強調、過度細碎的步驟指示——反而會讓新模型表現變差或過度拘謹。這個指令會掃描你的 CLAUDE.md、skills、agents、commands，指出過時寫法、失效路徑與互相矛盾的指示，等於幫你的「AI 設定檔」做 lint。

其他主軸是 MCP 可靠度（背景進度、404 復原、stdio 殘留程序、圖片輸出存檔）、企業管控（精確模型版本白名單、黑名單、gateway prompt id）、以及全面的清單 UI 可用滑鼠操作。Windows 使用者特別注意：修掉了 PowerShell 工具可以繞過保護刪除根目錄的安全問題。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端專案的 CLAUDE.md 往往累積了很多「給舊模型的叮嚀」（例如「絕對不要用 any！！」「一定要先跑 lint」重複好幾次），`prompt-audit` 能幫你清理，讓 Claude 讀到更精簡、一致的專案規範。
- **具體場景：** 你們的 Next.js monorepo 有根目錄與 `apps/web`、`packages/ui` 各自的 CLAUDE.md，內容互相矛盾（一個說用 CSS Modules、一個說用 Tailwind）；跑 prompt-audit 會把矛盾與失效的檔案路徑排在報告最前面。另外 MCP 回傳的截圖（例如 Playwright / chrome-devtools MCP）現在會存成檔案，Claude 能用 Read 再次檢視或比對。
- **這週可以嘗試：** 更新到 2.1.283 後在專案根目錄執行 `/doctor prompt-audit`，依報告刪掉過時的強調語與矛盾規則；再用 `/context` 看看 MCP server instructions 佔了多少 context，考慮停用不常用的 MCP server。
