## Claude Code · Changelog

> 📝 以下為前日精選未收錄、補入的版本（2.1.173–2.1.175，發布於 June 11–12, 2026）。目前最新版本仍為 2.1.176，今日尚無新版釋出。

---

**版本號 / 日期：** 2.1.173 / June 11, 2026

**變更項目：**
- Fixed Fable 5 model names with a `[1m]` suffix not being normalized — Fable 5 includes 1M context by default, so the suffix is now stripped automatically（Fable 5 模型名稱附帶 `[1m]` 後綴的問題已修復，系統會自動移除此後綴）
- Fixed a spurious "sandbox dependencies missing" startup warning on Windows when sandbox was enabled in settings（修復 Windows 上沙盒啟用時誤報 "sandbox dependencies missing" 警告的問題）

**核心概念（簡單說）：**
這是一個小型 hotfix 版本，主要修正 Fable 5 模型 ID 的正規化問題。當你在設定或 `ANTHROPIC_DEFAULT_OPUS_MODEL` 環境變數裡指定帶有 `[1m]` 後綴的 Fable 5 model ID 時（例如 `claude-fable-5[1m]`），Claude Code 現在會自動去掉多餘的後綴，避免 API 呼叫出現 model ID 不符的錯誤。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的 `.claude/settings.json` 或 CI 環境變數裡有手動指定 Fable 5 的 model ID，可能需要確認 ID 格式是否正確，更新後這個格式問題會自動處理掉。
- **具體場景：** 你的 CI 流程設定了 `ANTHROPIC_DEFAULT_OPUS_MODEL=claude-fable-5[1m]`，之前這個值可能導致 API 回傳 400 錯誤。升級到 2.1.173+ 後，系統會自動把 `[1m]` 去掉，用正確的 ID 呼叫 API。
- **這週可以嘗試：** 執行 `claude update` 更新到最新版，然後在 `/status` 確認 model 設定顯示是否正確（不再出現雙重後綴）。

**版本號 / 日期：** 2.1.174 / June 12, 2026

**變更項目：**
- Added `wheelScrollAccelerationEnabled` setting to disable mouse-wheel scroll acceleration in fullscreen mode（新增設定可停用全螢幕模式的滾輪加速）
- Fixed the `/model` picker hiding the model family that Default resolves to（修復 `/model` 選擇器未正確顯示 Default 所對應的模型系列）
- Fixed `/model` picker showing a hardcoded Sonnet version label when `ANTHROPIC_DEFAULT_SONNET_MODEL` pins a different Sonnet（修復 Sonnet 版本標籤顯示錯誤的問題）
- Fixed the "Fable 5 is now consuming usage credits" banner incorrectly showing for enterprise accounts with usage-based billing（修復企業帳戶誤顯示 Fable 5 用量提示橫幅的問題）
- Fixed Bedrock GovCloud regions (`us-gov-*`) deriving the wrong inference profile prefix（修復 Bedrock GovCloud 區域使用錯誤 inference profile 前綴的問題）
- Fixed background sessions inheriting another session's `ANTHROPIC_*` provider env（修復 background session 繼承錯誤 session 的環境變數設定）
- Fixed a 1-2 second pause when exiting Claude Code shortly after a shell command was interrupted on macOS and Linux（修復 macOS/Linux 上指令中斷後退出 Claude Code 的延遲問題）
- Fixed git commit co-author attribution showing an incorrect model name for some models（修復 git commit 共同作者標記顯示錯誤 model 名稱的問題）
- Fixed skill hot-reload re-sending the entire skill listing when a single skill changed（修復 skill 熱重載時重送完整清單的效能問題，現在只重送變動的 skill）
- [VSCode] Added usage attribution to the Account & usage dialog (`/usage`) — cache misses、long context、subagents、per-skill/agent/plugin/MCP breakdowns over last 24h or 7d（VSCode：`/usage` 對話框新增詳細的用量分類統計）

**核心概念（簡單說）：**
這是一個大範圍的修復版本，主要在解決 Fable 5 推出後帶來的後續問題。最值得關注的是兩個改進：

1. **`/model` 選擇器更透明**：以前 Default 模式會隱藏它實際上跑的是哪個模型，現在清楚顯示——Pro 用戶的 Default 等於 Sonnet，Max/Enterprise 等於 Opus。
2. **VSCode `/usage` 用量細分**：現在可以看到每個 skill、agent、plugin、MCP server 分別消耗了多少 token，幫助你找出最「燒錢」的環節。

**前端工程師實際應用：**
- **跟你工作的關聯：** VSCode 的 `/usage` 現在可以看到 MCP server、skill 各自的用量細分，讓你知道哪些工具實際上在 token 開銷上最重，方便做優化決策。
- **具體場景：** 你懷疑某個 MCP plugin 或 skill 呼叫很頻繁、導致 token 費用異常高。打開 VSCode 的 `/usage` 對話框，切換到 7 天視圖，就能看到哪個 plugin 的 cache miss 最高，找出優化方向。
- **這週可以嘗試：** 在 VSCode 裡執行 `/usage`，查看過去 7 天各個工具的用量分類，找出消耗 token 最多的 skill 或 MCP，看看是否有可以減少呼叫頻率的機會。

**版本號 / 日期：** 2.1.175 / June 12, 2026

**變更項目：**
- Added `enforceAvailableModels` managed setting — when enabled, the `availableModels` allowlist also constrains the Default model (a Default that would resolve to a disallowed model now falls back to the first allowed model), and user or project settings can no longer widen a managed `availableModels` list（新增 `enforceAvailableModels` 管理設定——啟用後，`availableModels` 白名單同時約束 Default 模型的解析，且使用者或專案設定無法擴展已管理的 `availableModels` 清單）

**核心概念（簡單說）：**
這是企業 IT 管理員的重要更新。`availableModels` 原本可以限制哪些模型可被選用，但 Default 模型（系統自動選的）不受此約束，而且使用者可以在自己的 settings 裡加入更多模型。

`enforceAvailableModels: true` 修補了這兩個漏洞：Default 現在只能解析成白名單內的第一個模型，使用者的 settings.json 也無法繞過管理員的限制。這對需要嚴格控制模型用量或成本的企業環境非常重要——例如禁止工程師使用 Fable 5（高成本）而只允許 Sonnet（低成本）。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你在企業環境工作，這個設定可能已經由 IT 部門啟用。若你發現 `/model` 無法切換到某些模型，或 Default 顯示的模型跟你預期的不同，可能就是 `enforceAvailableModels` 在作用。
- **具體場景：** 你的公司 IT 設定了 `"availableModels": ["claude-sonnet-4-6"]` 加上 `"enforceAvailableModels": true`。這樣一來，即使你在個人 `~/.claude/settings.json` 加入 `claude-fable-5`，Claude Code 還是只會使用 Sonnet 4.6，防止意外產生高額帳單。
- **這週可以嘗試：** 如果你管理公司的 Claude Code 配置，考慮在 managed settings 加入 `"enforceAvailableModels": true`，確保所有工程師都在你指定的模型範圍內使用，避免因個別設定造成的模型或費用不一致。
