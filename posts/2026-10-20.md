## trq212 · X

**原文網址：** https://x.com/trq212/status/2112219173288120531

**原文：**
> I think most people multi-tasking with agents could benefit from slowing down
>
> most of the stuff you're doing wont really matter- what's your P0? what would it look like if you gave it your full attention?

**繁中改寫：**
我覺得大多數同時開好幾個 agent 在多工的人，其實都可以試著放慢一點。

你手上在做的事情，大部分其實沒那麼重要——你的 P0 是什麼？如果把全部注意力都放在它身上，會長什麼樣子？

**核心概念（簡單說）：**
有了 coding agent 之後，「開五個 session 同時跑五件事」變得很容易，看起來產出暴增，但瓶頸其實從「打字寫 code」轉移到了「人的判斷與審查」。每多開一條平行任務，你就得多切換一次 context、多審一份 diff、多做一次決策；注意力被切碎之後，每個任務都只得到淺層的關注，最後最重要的那件事反而做得不夠好。

Thariq 的意思是：agent 讓「做很多事」的成本變低，但「做對最重要的事」仍然需要人全神貫注。與其追求平行度，不如先找出 P0，把 agent 當成放大你專注力的工具，而不是分散它的工具。這跟他前幾天提到的「coding agent 的技能在於深入細節（being in the details）」是同一條思路。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端任務很容易被切成一堆零碎小工作（調樣式、修 lint、補型別、改文案），很適合丟給多個 agent 平行處理，但真正影響產品品質的往往是一兩個核心互動或架構決策，需要你親自盯細節。
- **具體場景：** 你同時用 `claude --worktree` 開了三個 session：一個重構表單驗證、一個升級 React Router、一個修 Storybook 樣式。與其三個都只看一眼就 merge，不如先判斷「表單驗證重構」才是這週的 P0，把它留在前景、逐步審查每個 diff 並手動測試邊界情況，其他兩個等它完成再處理。
- **這週可以嘗試：** 每天開工前在紙上寫下一件 P0，當天只為它開一個前景 Claude Code session；其他雜事集中到下午用背景 subagent 批次處理，週末回顧一下 P0 的完成品質有沒有比以往好。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.304 / October 19, 2026

**變更項目：**
- Added `/auto-mode-setup`: a guided setup that reads your project and recent sessions to teach auto mode about your environment — 新增 `/auto-mode-setup` 引導式設定，會讀取專案與最近的 session，讓 auto mode 更了解你的環境；現在也支援 Bedrock、Vertex、Foundry、Claude apps gateway 與關閉遙測的 session
- Added `/claude-api managed-agents-secure` — 新增指令，對照 Anthropic 公開的安全指南檢查 Managed Agents agent 的設定（只檢查、不修改）
- Added the names of the tools called earlier to the compaction summary in the transcript view (Ctrl+O) — compaction 摘要現在會列出先前呼叫過的工具名稱
- Added a warning on Pro and Max plans when resuming an inactive conversation would use a noticeable share of your 5-hour usage limit — Pro / Max 方案恢復閒置對話時，若會吃掉明顯比例的 5 小時用量，會先跳出警告，可選擇照常恢復或開新對話
- Added `decider: "person"` and `e.isReadOnly` to a mod's `tool.check` — mod 的 `tool.check` 可指定只能由人（權限對話框）核准，並可得知該工具呼叫是否為唯讀
- [Code Review] Added review levels (Quick / Standard / Deep) and an option to review every repository in a GitHub organization — Code Review 新增審查等級，可整個組織或個別 repo 設定；也能一鍵涵蓋組織內所有 repo（含之後新增的）
- [VSCode] Changed background sub-agents to show as one status line under their Agent card — VS Code 背景 subagent 改成在 Agent 卡片下只顯示一行狀態，完整紀錄放在 `/tasks`
- Changed tool search to be on by default behind a custom `ANTHROPIC_BASE_URL` — 使用自訂 `ANTHROPIC_BASE_URL` 時預設啟用 tool search，gateway 回 400/422 時會自動不帶它重試
- Changed compaction to send Claude the skill list again afterwards; `/reload-skills` now sends only new or changed skills — compaction 後會重新送出 skill 清單；`/reload-skills` 只送新增或變更的 skill
- Changed skill hooks: one source can register at most 1,024 hooks and 16,384 matcher characters per session — 同一來源的 skill hook 數量與 matcher 字元數設上限
- Removed the "(research preview)" label from the `/fast` dialog title on Opus 5.5 — Opus 5.5 的 fast mode 拿掉「research preview」標籤
- Improved responsiveness and throughput when many subagents are running at the same time — 大量 subagent 同時執行時的回應速度與吞吐量提升
- Improved memory use when sending requests in long or resumed conversations — 長對話或恢復的對話記憶體用量改善
- Windows: Improved git command start-up by running git.exe directly instead of through its cmd launcher — Windows 上直接執行 `git.exe`，git 指令啟動更快
- Fixed `claude --worktree` removing the worktree and its branch without asking at exit when HEAD was detached or on another branch — 修正 `--worktree` 在 detached HEAD 或切到其他分支時，離開會不經詢問刪除 worktree 與分支（可能遺失 commit）
- Fixed sandboxed commands failing on Linux when a `denyRead` glob contains brackets like a `[user-id]` route folder — 修正 Linux sandbox 遇到含中括號的路徑（例如 Next.js 的 `[user-id]` 動態路由資料夾）時指令無法啟動
- Fixed `rm -r` of a mounted drive or top-level folder not getting the safety prompt — 修正刪除掛載磁碟或頂層資料夾時沒有安全確認
- Fixed subagents sometimes forgetting their most recent work when messaged or resumed right after finishing — 修正 subagent 剛完成就被傳訊或恢復時，偶爾會忘記最近的工作
- （另有其他 improvements 與共 43 項 bug fixes，詳見原始 changelog）

**核心概念（簡單說）：**
2.1.304 是一個以「agent 治理與規模化」為主軸的版本。一方面讓 auto mode 更聰明：`/auto-mode-setup` 會分析你的專案與歷史 session，告訴 auto mode 的安全分類器「在這個環境裡什麼是正常操作」，減少誤擋或誤放。另一方面針對多 agent 場景做了大量優化——subagent 並行時的吞吐量、記憶體用量、VS Code 裡背景 subagent 的呈現方式，都朝「同時跑很多 agent 也不卡、不吵」的方向調整。

團隊層面則強化了 Code Review（可分 Quick/Standard/Deep 等級、一次涵蓋整個 GitHub org），以及 mod 權限檢查（`decider: "person"` 強制人工核准）。另外有幾個值得注意的安全性修正：`--worktree` 可能誤刪分支、刪除掛載磁碟沒有確認，這些都是會實際造成資料遺失的問題。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你用 Next.js 的動態路由（`app/[slug]/page.tsx`）又開了 sandbox，或常用 `claude --worktree` 平行開發，這版直接修掉了會讓你卡住甚至遺失 commit 的 bug；Windows 使用者的 git 操作也會變快。
- **具體場景：** 團隊在 GitHub org 下有前端 monorepo 與多個元件庫 repo，管理者可以在 Code Review 後台把核心的 `web-app` 設成 Deep、文件站設成 Quick，並勾選「review 所有 repo」，之後新開的 repo 也自動納入審查，不用一個個手動加。
- **這週可以嘗試：** 執行 `claude update` 升到 2.1.304，然後在你的前端專案裡跑一次 `/auto-mode-setup`，看看它從專案結構（`package.json` scripts、測試指令等）歸納出哪些環境描述，再觀察之後 auto mode 被擋的次數有沒有減少。
