**核心概念（簡單說）：**
這是 Thariq 離開 Anthropic 後，持續更新他用 AI 輔助開發的遊戲原型進度：這次加了新的對戰場地（arena）和兩個新角色。重點不在遊戲本身，而在他一路強調的工作方式——「創意決策由人主導，AI 是協作者而不是代工」。角色設計、關卡手感、遊戲平衡這些需要品味的東西他自己決定，AI 負責把想法快速變成可以玩的東西（產生程式碼、搭場景、跑迭代）。

這種「小步迭代、每次只加一個 arena 或幾個角色」的節奏，本質上跟 agentic coding 的最佳實務一樣：把大目標拆成可驗證的小增量，每輪都有一個能跑、能試玩的版本，人負責看結果並調整方向。遊戲是一個很好的試煉場，因為「好不好玩」無法靠自動測試判斷，必須人親自感受。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端的互動設計、動畫手感、視覺層次跟遊戲設計一樣，屬於「需要人用眼睛和手判斷」的領域。用 AI 加速實作，但保留設計決策權，是前端工程師跟 agent 協作時最值得建立的習慣。
- **具體場景：** 用 Claude Code 搭一個 Canvas 或 PixiJS 的小互動頁（例如可拖曳的卡片、帶物理效果的按鈕），先自己寫下「要有什麼手感」的規格（彈性係數、延遲、easing），讓 agent 產生第一版，再自己在瀏覽器裡反覆試玩、只把具體的調整指令丟回給 agent。
- **這週可以嘗試：** 開一個週末 side project（小遊戲或互動 demo），規定自己每次 session 只加一個功能（像 Thariq 的「一個新 arena」），結束時一定要有能跑的版本並記錄哪些決策是你做、哪些是 AI 做的。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.325 / November 13, 2026

**變更項目：**
- Added a spinner tip in VS Code and similar integrated terminals about re-running a notebook cell, shown once Claude has read or edited a Jupyter notebook — 在 VS Code 等整合終端機中，Claude 讀取或編輯過 Jupyter notebook 後，spinner 會提示你重新執行 cell。
- Added a line under the error shown when your organization's policy blocks a request, saying how to continue: run /rewind and change the message, or run /clear — 被組織政策擋下的錯誤訊息下方，會告訴你怎麼繼續：用 `/rewind` 改訊息或用 `/clear`。
- [VSCode] Added prompt suggestions wherever the terminal shows them: Tab accepts the suggested next prompt; promptSuggestionEnabled: false turns them off — VS Code 擴充也有「下一個 prompt 建議」了，按 Tab 採用；`promptSuggestionEnabled: false` 可關閉。
- [VSCode] Added a Console sign-in that creates no API key; added a field to paste the redirect URL when signing in to an MCP server in SSH, WSL and container windows — VS Code 新增不產生 API key 的 Console 登入，以及在 SSH / WSL / 容器視窗登入 MCP server 時可貼上 redirect URL 的欄位。
- Changed sandboxed Bash commands to follow the normal permission flow by default; set sandbox.autoAllowBashIfSandboxed: true to keep running them without prompts — **重要行為變更**：sandbox 內的 Bash 指令預設改走一般權限詢問流程，想維持免詢問要設 `sandbox.autoAllowBashIfSandboxed: true`。
- Changed read-only git commands to ask first in a repository that isn't the project's or one you trusted; use --add-dir to run them without prompts — 在非專案、未信任的 repo 裡，連唯讀 git 指令也會先詢問；用 `--add-dir` 指定即可免詢問。
- Changed scheduled tasks and /loop to ask before running a skill that declares allowed-tools or hooks; add Skill(name) to permissions.allow to run it unattended — 排程任務與 `/loop` 執行宣告了 allowed-tools 或 hooks 的 skill 前會先詢問；要無人值守執行需在 `permissions.allow` 加 `Skill(name)`。
- Changed "Always allow" in Desktop, IDE and SDK hosts: a rule alone is offered only when saving it would allow that command again — 「Always allow」只在存下規則真的能再次放行該指令時才提供，依賴舊行為的排程任務可能會停下來等你。
- Changed the sandbox to refuse sandboxed writes to .claude settings, skills, agents, commands and hooks in added directories — sandbox 拒絕寫入額外目錄中的 `.claude` 設定、skills、agents、commands、hooks。
- Changed worktree isolation to refuse git bisect run, git maintenance register|start and scalar's set-up commands — 隔離的 worktree session 不能執行 `git bisect run`、`git maintenance` 等指令。
- Changed plugin MCP bundles (.mcpb, .dxt) to unpack under the plugins directory; plugin loading skips and `claude plugin validate` reports unsafe paths and links — `.mcpb` / `.dxt` 改解壓到 plugins 目錄；載入時會略過不安全路徑與連結，`claude plugin validate` 會回報。
- Changed nested skill loading: .claude/skills folders in --plugin-dir plugins no longer load from a session started above them — 從上層目錄啟動的 session 不再載入 `--plugin-dir` plugin 內的 `.claude/skills`。
- Changed prompt suggestions in the terminal to refresh less often after 8 turns in a row started by background or scheduled tasks — 連續 8 輪由背景／排程任務觸發後，prompt 建議更新頻率降低以節省用量。
- Changed Esc on a background MCP task's question to "answer later" — 對背景 MCP 任務的提問按 Esc 改為「稍後回答」，問題保留在 `/tasks`。
- Changed CLAUDE_CODE_MAX_CONTEXT_TOKENS to also set the context window of unrecognized model IDs that start with claude- — `CLAUDE_CODE_MAX_CONTEXT_TOKENS` 也套用到未知的 `claude-` 開頭 model ID（例如 gateway 的 `claude-sonnet-latest`）。
- Changed /cost, --max-budget-usd and cost/token metrics to count a mod's $.model.complete and $.model.classify calls — 成本統計會納入 mod 呼叫模型的用量。
- Changed sandbox helper programs, ripgrep and local git to run without Claude Code's sign-in tokens, API keys or the mTLS key passphrase in their environment — sandbox 的輔助程式、ripgrep、本機 git 執行時不再帶有登入 token、API key 或 mTLS 金鑰密碼。
- Changed claude -p with no cached account data to wait for that data before its first request — 乾淨環境第一次跑 `claude -p` 會先等帳號資料，啟動可能慢幾秒。
- Changed marketplace ref to accept the full ID of any commit on a branch or tag — marketplace 的 ref 可指定任一 commit 完整 ID（舊版 client 無法 clone 這種 pin）。
- 另有 14 項 improvements 與 88 項 bug fixes（頁面上預設收合）。

**核心概念（簡單說）：**
2.1.325 是一次以「安全收緊」為主軸的版本。最大的改變是 sandbox 不再等於「自動放行」：以前只要 Bash 指令在 sandbox 裡跑就不會詢問，現在預設回到一般權限流程，要明確設定 `sandbox.autoAllowBashIfSandboxed: true` 才會恢復。同樣的思路延伸到很多地方：非信任 repo 的唯讀 git 指令要先問、排程任務跑帶 hooks 的 skill 要先問、sandbox 輔助程式拿不到你的 token、plugin 載入會擋掉可疑的路徑與 symlink。可以把它想成瀏覽器的 CSP 從寬鬆預設改成嚴格預設——功能都還在，但「信任」必須是你明確宣告的，而不是隱含的。

另一條主線是 VS Code 體驗補齊：prompt 建議（Tab 接受）、不產生 API key 的 Console 登入、遠端環境下的 MCP OAuth 登入補強，讓在 VS Code 內用 Claude Code 跟在終端機裡的體驗更一致。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你有用排程任務或 `/loop` 自動跑 lint、測試、內容整理之類的 routine，升級後可能會突然停下來等你按允許——這不是 bug，是新的預設。
- **具體場景：** 你的專案 `.claude/settings.json` 開了 sandbox，排程任務每天跑 `npm run build && npx vitest run`。升級到 2.1.325 後這些 Bash 指令會開始詢問權限；你可以在設定裡加上 `"sandbox": { "autoAllowBashIfSandboxed": true }`，或更精準地在 `permissions.allow` 加 `Bash(npm run build)`、`Bash(npx vitest run:*)`，若任務會呼叫帶 hooks 的 skill 也要加 `Skill(名稱)`。
- **這週可以嘗試：** 執行 `claude --version` 確認版本後，檢查自己的排程任務與 `/loop` 設定，把需要無人值守的指令與 skill 明確寫進 `permissions.allow`；用 VS Code 的話順便試試按 Tab 採用 prompt 建議。
