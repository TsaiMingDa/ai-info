## Claude Code · Changelog

**版本號 / 日期：** v2.1.145 / 2026-05-19

**變更項目：**
- `claude agents --json`：以 JSON 格式列出所有進行中的 Claude sessions，適合用於 tmux-resurrect、status bar、session picker 等腳本整合
- OTEL span 新增 `agent_id` 與 `parent_agent_id` 欄位，方便追蹤 agent 呼叫鏈
- Status line JSON 現在包含 GitHub repo 與 PR 資訊（自動偵測）
- `/plugin` 的 Discover 與 Browse 畫面在安裝前就顯示 plugin 的 commands、agents、skills、hooks、MCP/LSP servers
- Slash command 與 @-mention 建議清單在全螢幕模式下支援滑鼠 hover 與點擊
- Stop / SubagentStop hook 的 input 新增 `background_tasks` 與 `session_crons` 欄位
- 修正：bare variable assignment 到未允許的環境變數被自動核准的權限繞過漏洞
- 修正：MCP prompt slash commands 顯示 raw server validation error
- 修正：terminal resize / refocus 後 spinner 和計時器凍結
- 修正：Windows PowerShell 5.1 跨專案 resume hint 失效
- 修正：agent view 的 reply pane 中 voice push-to-talk 無法使用
- 修正：task list 以隨機順序渲染
- 修正：`gh pr create` 後 PR badge 沒有立即更新
- 修正：Agent Teams 中 non-ASCII 名稱的 teammate 造成 API 呼叫失敗
- 修正：`/review` 使用了 deprecated GraphQL query（對有 Classic Projects 的 repo）
- 改進：Read tool 在檔案過大時改為回傳截斷的第一頁，而非直接報錯

**核心概念（簡單說）：**
這次更新的重點有兩個方向。第一是 **可觀察性**：`claude agents --json` 讓你可以用程式碼查詢目前所有 Claude session 的狀態，配合 `agent_id`/`parent_agent_id` 的 OTEL span，整個 multi-agent 執行鏈變得更可追蹤。第二是 **plugin 生態體驗**：安裝前就能預覽 plugin 的完整組成，讓你在決定是否安裝前可以更有把握地評估。另外也修了一個安全性問題：未允許的環境變數指定本來會被自動核准（繞過權限提示），現在已修正。

**前端工程師實際應用：**
- **跟你工作的關聯：** `claude agents --json` 讓你可以在自己的腳本中查詢 Claude session 狀態，例如製作一個 tmux status bar 顯示目前有幾個 Claude 在跑、哪個在等你回應
- **具體場景：** 在 iTerm2 或 tmux 中建立一個簡單的 shell 腳本，定期執行 `claude agents --json | jq '.[] | select(.status == "waiting_for_input") | .session_id'` 來找出需要你回覆的 session
- **這週可以嘗試：** 更新 Claude Code 到最新版（`npm update -g @anthropic-ai/claude-code`），然後執行 `claude agents --json` 看看輸出格式，試著用 `jq` 過濾出你感興趣的欄位

**版本號 / 日期：** v2.1.144 / 2026-05-19

**變更項目：**
- `/resume` 現在支援 background sessions（`claude --bg` 啟動的 session），在列表中以 `bg` 標示
- Background subagent 完成通知新增 elapsed duration 顯示
- `/plugin` browse 和 discover pane 顯示 plugin 的最後更新時間
- `/model` 現在預設只改變當前 session 的 model；按 `d` 才會設定為新 session 的預設 model
- 將「extra usage」重新命名為「usage credits」
- 修正：`api.anthropic.com` 無法連線時 startup 最多卡住 75 秒（改為 15 秒 timeout）
- 修正：漏掉 window-resize 事件後 terminal 輸出亂碼
- 修正：超長 session 中漸進式 terminal 顯示損壞
- 修正：macOS background session 崩潰（Full Disk Access 問題）
- 修正：進入 worktree 後 `/branch` 失敗（"No conversation to branch"）
- 修正：Bedrock/Vertex 用戶無法選擇 "Opus (1M context)"
- 修正：remote session 登入失敗（"Can't access this organization"）
- 修正：MCP servers 分頁回傳 `tools/list` 只讀第一頁
- 修正：在 skill 目錄內跑 build 時 file descriptor 耗盡
- 修正：自訂 `ANTHROPIC_BASE_URL` 的 background side-queries 沒有使用 Haiku fallback

**核心概念（簡單說）：**
這個版本的核心是讓 background session 的使用體驗更完整。原本 `claude --bg` 啟動的 session 在 `/resume` 清單裡看不到，現在補上了，而且有完成通知和耗時顯示。另一個值得注意的是 `/model` 行為的調整——以前改 model 可能會影響到你其他開著的 session，現在是 session 隔離的，要改全域預設要明確按 `d`。startup 卡 75 秒的 bug 也修了，這個在網路不穩的環境下特別惱人。

**前端工程師實際應用：**
- **跟你工作的關聯：** `/model` 的 session-only 行為改變意味著你可以在不同 session 用不同 model 跑不同任務（例如一個用 Opus 跑複雜分析、一個用 Sonnet 跑快速修 bug），不會互相影響
- **具體場景：** 在一個 session 裡輸入 `/model`，選 Opus，然後開一個新的 session 確認它還是用 Sonnet（預設），驗證隔離行為是否如預期
- **這週可以嘗試：** 如果你有需要長時間跑的任務（例如讓 Claude 分析整個 codebase 或跑一批測試），試試 `claude --bg "你的任務描述"` 讓它在背景執行，然後用 `/resume` 查看結果
