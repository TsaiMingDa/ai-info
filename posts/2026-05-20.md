## Claude Code · Changelog

**版本號 / 日期：** 2.1.145 / 2026-05-19

**變更項目：**
- `claude agents --json` — 以 JSON 格式列出活躍的 Claude 會話，可供 tmux-resurrect、狀態欄、會話選擇器等工具使用
- OTEL 追蹤增強 — 新增 `agent_id` 與 `parent_agent_id` 屬性到 `claude_code.tool` spans，修正後台子代理 spans 的層級結構
- 狀態行 JSON 增強 — 現在包含偵測到的 GitHub repo 與 PR 資訊
- 插件發現改進 — `/plugin` 畫面在安裝前顯示插件的 commands、agents、skills、hooks 和 MCP/LSP 伺服器清單
- 代理會話改進 — `claude agents` 終端分頁標題現在顯示等待輸入的數量
- 斜線命令增強 — 建議列表在全屏模式支援滑鼠懸停與點擊
- 修復：Bash 命令中的裸變數賦值權限提示繞過問題
- 修復：MCP prompt 斜線命令顯示原始伺服器驗證錯誤
- 修復：終端調整大小後微調與經過時間顯示凍結
- 修復：非 ASCII 名稱的 Agent Teams 隊友導致 API 呼叫失敗

**核心概念（簡單說）：**
這次 2.1.145 的更新主要圍繞「多 agent 可觀察性」和「工具生態整合」。`claude agents --json` 讓外部工具（像 tmux 腳本或狀態欄）可以程式化地讀取當前有哪些 Claude session 在跑，等於把 agent 狀態暴露成機器可讀的介面。OTEL 追蹤的強化則讓你在有分散式 tracing 系統的情境下，能看清楚哪個 agent 呼叫了哪個工具、parent/child 關係是什麼，對除錯複雜的多 agent 流程很有幫助。

**前端工程師實際應用：**
- **跟你工作的關聯：** `claude agents --json` 讓你可以寫腳本來監控背景跑的 Claude Code session，例如在終端狀態欄即時顯示「目前有幾個 agent 在等輸入」，不用手動切換視窗確認
- **具體場景：** 你同時開了三個 Claude Code 背景 agent 各自處理不同 feature，用 `claude agents --json | jq '.[] | select(.waiting_for_input)'` 可以快速知道哪個 agent 在等你回應，搭配 tmux 自動跳到該 pane
- **這週可以嘗試：** 在終端跑 `claude agents --json` 看輸出結構，再嘗試搭配 `jq` 過濾出「目前活躍的 session」，熟悉格式後可以整進你的 statusline 或 shell prompt

**版本號 / 日期：** 2.1.144 / 2026-05-19

**變更項目：**
- 後台會話恢復 — 透過 `claude --bg` 或代理視圖啟動的會話現在在 `/resume` 中可見，標記為 `bg`
- 模型選擇改進 — `/model` 現在僅改變目前會話的模型；按 `d` 在模型選擇器中為新會話設置預設值
- 啟動時間改進 — 修復當 `api.anthropic.com` 無法存取時最多掛起 75 秒的問題（現在側通道 API 呼叫在 15 秒後逾時）

**核心概念（簡單說）：**
2.1.144 的重點是讓背景 agent 的生命週期更好管理。過去用 `claude --bg` 跑起來的 session 很難在 `/resume` 裡找到，這次修好了。`/model` 的調整也解決了一個常見的混淆：改了 model 不知道是改了整個帳號預設還是只改這個 session，現在行為明確了。

**前端工程師實際應用：**
- **跟你工作的關聯：** `/resume` 現在能看到背景 session，讓你可以把 Claude Code 當成「在背景跑的長時間任務」來管理，不怕 session 跑起來就找不回來
- **具體場景：** 下班前用 `claude --bg` 跑一個 refactor 任務，隔天早上開 Claude Code 直接 `/resume` 看到標記 `bg` 的 session，接續昨晚的進度
- **這週可以嘗試：** 用 `/model` 切換一次 model，確認只影響目前 session，再用 `d` 鍵設定你偏好的預設 model，熟悉新的兩層設定邏輯
