## Claude Code · Changelog

**版本號 / 日期：** v2.1.175 / 2026-06-12

**變更項目：**
- Added `enforceAvailableModels` managed setting — when enabled, the `availableModels` allowlist also constrains the Default model（啟用後，Default 模型選擇也受 allowlist 限制，設為不允許的模型時會自動 fallback 到第一個允許的模型），且 user 或 project 層級的設定無法再擴大 managed `availableModels` 名單

**核心概念（簡單說）：**
這個更新是針對企業/管理者的控管功能。`enforceAvailableModels` 就像給 AI 模型存取加了一道「強制門鎖」——以前管理員可以設定 `availableModels` allowlist，但 "Default" 模型選項可以繞過這個限制；現在啟用此設定後，連 Default 的解析路徑也受到管制，並且下游的 user/project 設定無法再偷偷把限制放寬。

**前端工程師實際應用：**
- **跟你工作的關聯：** 若你在企業環境中使用 Claude Code，IT 或平台管理員可能會啟用這個設定來限制可使用的 AI 模型；這直接影響你在 IDE 中可以呼叫的模型範圍。
- **具體場景：** 公司合規政策要求只允許使用特定版本的 Claude Sonnet，但以前選「Default」可能悄悄解析到 Fable 5；現在管理員啟用 `enforceAvailableModels: true` 後，Default 若解析到不在清單內的模型，會自動 fallback 到清單第一項，使用者也無法透過 project settings 繞過。
- **這週可以嘗試：** 若你有 Claude Code 的管理員權限，確認 `.claude/settings.json`（或 managed settings）中的 `availableModels` 清單是否符合團隊 AI 使用政策；若有需要強制執行，可試著加入 `enforceAvailableModels: true`。

**版本號 / 日期：** v2.1.174 / 2026-06-12

**變更項目：**
- Added `wheelScrollAccelerationEnabled` setting（可關閉 fullscreen 模式中的滑鼠滾輪加速）
- Fixed the `/model` picker hiding the model family that Default resolves to（修正 `/model` 選擇器隱藏 Default 實際對應模型系列的問題）— Opus 現在在 Max/Team Premium/Enterprise 方案中會顯示為獨立列，Sonnet 在 Pro/Team 方案，Opus 在 pay-as-you-go API 帳戶
- Fixed `/model` picker showing a hardcoded Sonnet version label when `ANTHROPIC_DEFAULT_SONNET_MODEL` pins a different Sonnet（修正 `ANTHROPIC_DEFAULT_SONNET_MODEL` 指定不同 Sonnet 版本時，選擇器仍顯示寫死版本標籤的問題）
- Fixed the "Fable 5 is now consuming usage credits" banner incorrectly showing for enterprise accounts with usage-based billing（修正企業按用量計費帳戶誤顯示 Fable 5 用量提醒 banner）
- Fixed Bedrock GovCloud regions (`us-gov-*`) deriving the wrong inference profile prefix（修正 Bedrock GovCloud 區域推導出錯誤 inference profile 前綴 `global` 而非 `us-gov`，導致 400 錯誤）
- Fixed background sessions inheriting another session's `ANTHROPIC_*` provider env（修正 background session 繼承其他 session 的 gateway URL、custom headers、`/model` 別名等設定）
- Fixed a 1-2 second pause when exiting Claude Code shortly after a shell command was interrupted or killed on macOS and Linux（修正 shell 指令被中斷後退出 Claude Code 時出現 1-2 秒卡頓）
- Fixed git commit co-author attribution showing an incorrect model name for some models（修正 git commit 共同作者標記顯示錯誤模型名稱）
- Fixed the `/advisor` dialog pre-selecting a saved advisor model that is blocked by the `availableModels` allowlist（修正 `/advisor` 預選被 allowlist 封鎖的模型）
- Fixed skill hot-reload re-sending the entire skill listing when a single skill changed; only changed skills are now re-announced（修正 skill 熱更新時重送整份清單，現在只重送有變動的 skill）
- Fixed Workflow tool `agent()` subagents missing per-agent attribution headers（修正 Workflow tool 的 subagent 缺少 attribution headers）
- \[VSCode\] Added usage attribution to the Account & usage dialog (`/usage`) showing cache misses, long context, subagents, and per-skill/agent/plugin/MCP breakdowns over the last 24h or 7d（VSCode 新增 `/usage` 用量歸因細項，含 cache miss、長上下文、subagent、各 skill/agent/plugin/MCP 的用量，可查 24h 或 7d）
- Fixed pre-warmed background workers failing with "Could not resolve authentication method" when claimed after sitting idle（修正 pre-warmed background worker 閒置後被使用時出現認證失敗）

**核心概念（簡單說）：**
這次是一個大型修補 + 小功能釋出。最實用的新增是 VSCode 的 `/usage` 用量歸因：你終於可以看到「我的 token 到底花在哪裡」——cache miss、subagent、還是哪個 skill 吃掉的，時間範圍還能切 24 小時或 7 天。另外 `/model` 選擇器的透明度大幅提升，Default 實際對應哪個模型現在一目了然，不再是黑盒子。Background session 的隔離性問題也一併修好，避免不同 session 的設定互相汙染。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你在 VSCode 用 Claude Code 開發，現在可以透過 `/usage` 精確追蹤每個元件（skill、MCP、subagent）的用量消耗，幫助你優化 workflow 設計或找出「耗用大戶」。
- **具體場景：** 你設計了一個 CI/CD 整合 skill，發現每月用量比預期高出很多；打開 `/usage` 查看 7 天的 per-skill breakdown，發現那個 skill 每次執行都有大量 cache miss（因為 prompt 沒設計好 cache 結構），針對性改寫後成本下降。
- **這週可以嘗試：** 在 VSCode 的 Claude Code 中輸入 `/usage`，查看新的用量歸因面板，記錄目前 24h 內各來源的 token 消耗比例，作為後續優化 Claude Code workflow 的基準線。
