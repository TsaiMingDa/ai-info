## claudeai · Anthropic Blog

**原文網址：** [https://www.anthropic.com/news/rare-disease-research-grants](https://www.anthropic.com/news/rare-disease-research-grants)

**原文：**
> Apply for Anthropic's AI for Science rare disease research grants
> Announcements · Jul 20, 2026
>
> Last spring, we announced Anthropic's AI for Science program, an initiative designed to accelerate scientific research and discovery through access to our API. Since launching, we have supported researchers working on a variety of high-impact projects, ranging from drug repurposing to quantum simulation. Throughout this initiative, we have found that projects are more generative when multiple AI for Science grantees are working on related questions and exchanging tips. So we now plan to launch thematic calls for projects within the broader AI for Science program.
>
> Today, we are sharing a focused call for applications centered specifically on rare genetic diseases. Accepted applicants will receive up to $50,000 in Claude credits over six months, with the goal of building a community of researchers looking into how AI can reshape our understanding of rare disease. This program has two tracks: one for scientists doing basic research, and another for early-stage biotechs working on speeding up clinical development for rare diseases.
>
> Track one (Scaling our basic science partnerships): partners with the Monarch Initiative, an international consortium building resources like the Mondo Disease Ontology and the Monarch Knowledge Graph, plus a new agent-friendly mechanistic disease classification library called DisMech, where Claude can read case reports, variant databases, registry schemas, and raw public data to point out mechanistic similarities between diseases.
>
> Track two (Scaling our biotech partnerships): supports biotechnologists and early-stage biotechs accelerating drug development for rare diseases, by using Claude to speed up documentation (regulatory dossiers), therapeutic strategy selection, and finding shared mechanisms across genetic therapies that could allow approval under a single "basket trial."
>
> Applications are open through August 2, 2026 at 11:59 PM PST via a linked application form. Accepted applicants can use credits on Claude Opus or other generally available models approved for biology use.

**繁中改寫：**
去年春天 Anthropic 推出了「AI for Science」計畫，透過提供 API 額度來加速科學研究。這次他們宣布針對「罕見遺傳疾病」開放專項申請：獲選者可在六個月內拿到最多 5 萬美元的 Claude 額度，目標是集結一群研究者一起探索 AI 如何改變我們對罕見疾病的理解。這個計畫分兩個方向：一是給做基礎研究的科學家，二是給正在加速臨床開發的早期生技新創。

基礎研究方向會跟 Monarch Initiative（一個國際聯盟）合作，運用他們建立的 Mondo 疾病本體論、Monarch 知識圖譜，以及一套全新、對 AI agent 友善的疾病機制分類庫「DisMech」——讓 Claude 可以讀病例報告、變異資料庫、登錄表格式跟公開原始資料，找出不同疾病之間潛在的共同機制。

生技方向則是協助早期生技公司加速藥物開發：用 Claude 加快撰寫法規文件（regulatory dossier）、篩選治療策略，以及找出多個基因療法之間的共通機制，讓它們有機會透過同一個「basket trial（籃式試驗）」一起申請核准，而不用每個病人都各自跑一次獨立的 IND 申請流程。申請將收到 2026 年 8 月 2 日晚上 11:59（美西時間）截止。

**核心概念（簡單說）：**
這篇文章的核心是「AI 如何幫上罕見疾病研究的忙」。罕見疾病雖然單一病種患者很少，但全球加總起來影響數億人，而且種類多達 7000 種以上，每種疾病的資料量都很稀疏、分散在不同的資料庫跟命名系統裡，研究者很難靠人工整合出共同的致病機制，藥物開發流程也因為法規文件繁瑣、試驗設計困難而拖得很長（常常要一到兩年才能從基因診斷走到可用的治療）。Anthropic 的做法是用 Claude 當作「大規模文獻整合與模式辨識引擎」：一方面幫研究機構把散落各處的病例、變異資料、術語系統串起來找出共同機制（基礎研究方向），另一方面幫生技公司加速寫法規文件、評估藥物標的可行性（臨床開發方向）。簡單說，就是把 Claude 當成一個能同時讀懂海量分散資料、又能協助生產專業文件的研究助理，用在資料稀少但影響人數眾多的醫療領域。

**前端工程師實際應用：**
- **跟你工作的關聯：** 這則新聞本身偏向科學研究資助計畫，前端工程師的日常工作不會直接用到，但它示範了一個很值得參考的模式——用 Claude 處理「大量分散、格式不一致的資料整合」這類任務，這個模式其實可以套用到很多前端／後端交界的資料整合場景。
- **具體場景：** 如果你的產品也需要整合多個來源、格式不一致的資料（例如把不同 API 回傳的產品規格、不同客戶上傳的 CSV 欄位對應到統一的 schema），可以參考這篇文章提到的做法：讓 Claude 讀取原始資料、比對既有的分類系統（像這裡的 Mondo Disease Ontology），產出結構化、可供程式使用的輸出。
- **這週可以嘗試：** 找一個你手邊「資料格式不統一、需要人工比對才能整合」的小任務（例如多個第三方 API 的欄位對應表），試著寫一個 prompt 讓 Claude 幫你產生初版的欄位對應 JSON，再由人工覆核，體驗一下用 LLM 做資料整合前置作業的效率提升。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.216 / July 20, 2026

**變更項目：**
- Added `sandbox.filesystem.disabled` setting to skip filesystem isolation while keeping network egress control（新增 `sandbox.filesystem.disabled` 設定，可跳過檔案系統隔離但仍保留網路出口流量控管）
- Fixed a slowdown in long sessions where message normalization cost grew quadratically with the number of turns, causing multi-second stalls and slow resumes（修正長對話中訊息正規化成本隨回合數呈平方成長，導致數秒延遲與 resume 變慢的問題）
- Fixed auto mode denying commands with "HTTP 401" classifier errors after the OAuth token expired or rotated mid-session（修正 auto mode 在 session 中途 OAuth token 過期或輪替後，因分類器回傳 401 而誤拒指令的問題）
- Fixed AskUserQuestion telling Claude to continue even when your answer asked it to wait or explain first — free-text answers now get neutral wording（修正 AskUserQuestion 在使用者要求「等一下」或「先解釋」時仍告訴 Claude 繼續執行的問題，自由文字回答現在會用中性措辭處理）
- Fixed Claude Code on the web re-asking the same question and dropping your answer after the session sat idle for a few minutes（修正網頁版 Claude Code 在 session 閒置幾分鐘後重複問同一個問題、並遺失你回答內容的問題）
- Fixed @-mentions silently attaching nothing after file-modifying hooks, vim dot-repeat of c-operators and paste, statusline running twice on resume, and resume-picker hangs on failure（修正多項小 bug：檔案修改型 hook 執行後 @-mention 靜默失效不附加任何內容、vim 的 c 系列操作與貼上動作的 dot-repeat 失效、resume 時 statusline 執行兩次、resume 選單失敗時卡住）
- Fixed resumed background agent sessions reverting to the default agent: the agent's prompt and tool restrictions are now restored（修正背景 agent session resume 後被還原成預設 agent 的問題，現在會正確還原該 agent 的 prompt 與工具限制）
- Fixed worktree-isolated subagents redirecting git into the shared checkout via `git -C`, `--git-dir`, or `GIT_DIR`/`GIT_WORK_TREE`（修正 worktree 隔離的 subagent 透過 `git -C`、`--git-dir` 或環境變數把 git 操作導向共用 checkout 的問題）
- Fixed worktree sessions landing in another project's leftover worktree when the working directory did not match the selected project（修正工作目錄與所選專案不一致時，worktree session 誤落在其他專案殘留 worktree 的問題）
- Fixed background sessions whose worktree has no git repository being undeletable（修正沒有 git repo 的 worktree 背景 session 無法被刪除的問題）
- Fixed `claude daemon stop --any` potentially terminating an unrelated process via a stale legacy daemon lockfile（修正 `claude daemon stop --any` 可能因過期的舊版 lockfile 而誤殺無關程序的問題）
- Fixed Esc-Esc at an idle prompt not opening the rewind picker in long-running sessions with background tasks（修正在有背景任務的長時間 session 中，閒置畫面按兩下 Esc 無法開啟 rewind 選單的問題）
- Fixed Bash command permission checking for compound statements with redirects inside `&&` lists or negations（修正 Bash 權限檢查在含有重導向的 `&&` 複合指令或否定式指令中判斷有誤的問題）
- Fixed pressing Ctrl+X twice in the agent list failing to delete a session, and deleted sessions reappearing when their background worker had died（修正在 agent 清單按兩次 Ctrl+X 無法刪除 session，以及背景 worker 已死掉的已刪除 session 又重新出現的問題）
- Fixed background subagents getting cancelled when a high-priority message arrives during their startup window（修正背景 subagent 在啟動階段收到高優先訊息時被誤取消的問題）
- Fixed mouse and focus garbage in the terminal while a GUI editor from `/memory`, `/plan`, `/keybindings`, or Ctrl+G is open; `/memory` no longer waits for the editor to close（修正開啟 `/memory`、`/plan`、`/keybindings` 或 Ctrl+G 叫出的 GUI 編輯器時終端機出現滑鼠與焦點亂碼的問題；`/memory` 現在不需等編輯器關閉即可繼續）
- Fixed Claude-in-Chrome 403-looping on reconnect when the session's OAuth token lacks a required scope（修正 Claude-in-Chrome 在 session 的 OAuth token 缺少必要 scope 時，重新連線陷入 403 迴圈的問題）
- Fixed workflow saves and scheduled-task writes following a symlink at `.claude`, which could redirect writes outside the project（修正 workflow 儲存與排程任務寫入時會跟隨 `.claude` 底下的 symlink，可能導致寫入跑到專案外部的安全問題）
- Fixed MCP re-authenticate revoking working credentials before the new sign-in succeeds, and the reconnect needs-auth message in background sessions pointing at an unusable command（修正 MCP 重新驗證會在新登入成功前就先撤銷原本可用的憑證，以及背景 session 的重新連線提示訊息指向無法使用指令的問題）
- Fixed read-only commands on Windows accessing network paths without a permission prompt（修正 Windows 上唯讀指令存取網路路徑時未跳出權限提示的問題）
- Fixed Bash command parsing of non-ASCII characters to match real shell word boundaries（修正 Bash 指令解析對非 ASCII 字元的斷詞邏輯，使其符合實際 shell 的斷詞規則）
- Fixed PowerShell tool permission validation of commands containing invisible Unicode characters（修正 PowerShell 工具在指令含有不可見 Unicode 字元時的權限驗證問題）
- Fixed dialogs in fullscreen mode stretching past the right-hand edge of their panel（修正全螢幕模式下對話框超出面板右邊界的顯示問題）
- Fixed the `/config` settings list in fullscreen mode clipping its keyboard-hint footer（修正全螢幕模式下 `/config` 設定清單底部鍵盤提示被裁切的問題）
- Fixed the transcript-mode (Ctrl+O) footer hint wrapping on terminals narrower than 104 columns（修正 transcript 模式（Ctrl+O）在終端機寬度小於 104 欄時底部提示文字換行異常的問題）
- Fixed the Prometheus metrics endpoint (`OTEL_METRICS_EXPORTER=prometheus`) emitting invalid `# UNIT` lines（修正 Prometheus 指標端點會輸出不合法 `# UNIT` 行的問題）
- Fixed skills and commands changed during a session not appearing in the slash menu until restart（修正 session 期間變更的 skills 與指令，要重啟才會出現在斜線選單的問題）
- Fixed plugin skills with a `name` frontmatter field losing their plugin prefix in slash-command autocomplete（修正帶有 `name` frontmatter 欄位的 plugin skill，在斜線指令自動完成時遺失外掛前綴的問題）
- Fixed telemetry misreporting permission denials: failed permission-prompt requests no longer count as user rejections, and user interrupts are now reported as user aborts instead of rejections（修正遙測數據誤報權限拒絕：失敗的權限提示請求不再被算成使用者拒絕，使用者中斷現在會回報為 abort 而非 rejection）

- Improved the `/ultrareview` diff-too-large error to show configured limits, measured diff size, and largest contributing files（改進 `/ultrareview` 的 diff 過大錯誤訊息，會顯示設定的限制、實際 diff 大小與貢獻最多的檔案）
- Improved `/code-review ultra` empty-diff message to name the exact base ref and suggest passing an explicit base（改進 `/code-review ultra` 空 diff 訊息，會指出確切的 base ref 並建議明確指定 base）
- Improved the spend limit adjustment prompt to show the server's reason when a spend limit change is rejected（改進花費上限調整提示，在請求被拒絕時會顯示伺服器給出的原因）
- `/context` now shows an explicit warning when the conversation exceeds the context window, and a failed `/compact` displays as an error（`/context` 現在會在對話超出上下文視窗時明確跳出警告，`/compact` 失敗時也會顯示為錯誤）
- `/rewind` no longer restores or deletes files through symlinks or hard links at tracked paths and reports how many paths it skipped（`/rewind` 不再透過受追蹤路徑上的 symlink 或 hard link 還原或刪除檔案，並會回報跳過了多少路徑）
- Background sessions: `/mcp` and `/install-github-app` now park a "needs input" request in the agent view when no client is attached（背景 session 中，`/mcp` 與 `/install-github-app` 在沒有客戶端連接時，會在 agent 檢視畫面留下「需要輸入」的請求）
- Updated the bundled dataviz skill: reordered the default chart palette and fixed guidance that suggested direct labels for four-series charts（更新內建 dataviz skill：調整預設圖表配色順序，並修正建議四數列圖表使用直接標籤的指引錯誤）
- [VSCode] Fixed right-to-left text (Arabic, Hebrew, Persian) rendering in the wrong order when mixed with English or code（[VSCode] 修正阿拉伯文、希伯來文、波斯文等由右至左文字與英文或程式碼混排時順序錯亂的問題）
- Fixed cloud sessions dropping the in-flight message when the session's container restarts mid-turn — the interrupted turn now re-runs on resume instead of leaving the session unresponsive（修正雲端 session 容器在回合進行中重啟時會遺失正在傳送訊息的問題，現在中斷的回合會在 resume 時重新執行，而不是讓 session 卡住沒反應）

**核心概念（簡單說）：**
這個版本是一次典型的「大量小修復＋幾個體驗改進」的維護性更新，沒有單一顛覆性新功能，但涵蓋範圍很廣：從效能問題（長 session 訊息正規化的效能退化）、權限與安全性修正（Bash/PowerShell 權限檢查漏洞、symlink 寫入越界風險、daemon 誤殺程序）、多種 UI 顯示問題（全螢幕模式排版、RTL 文字混排），到 background session／worktree／cloud session 這幾個近期主打的「多工執行」功能線上的穩定性修正。整體訊號是：Anthropic 正在把重心放在把已經上線的進階功能（background agents、worktree 隔離、cloud sessions）打磨得更可靠，同時持續補強安全邊界（權限檢查、sandbox 隔離）。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你已經在用 Claude Code 的 background sessions 或 worktree 功能同時跑多個 agent 任務，這次修的好幾個 bug（session resume 還原錯誤 agent、worktree 誤落到別的專案、無法刪除的殘留 session）直接影響你多工開發的穩定性。
- **具體場景：** 假設你習慣開多個 worktree 讓不同 agent 平行處理不同 feature branch，先前如果工作目錄沒切對，session 可能會誤落在別的專案殘留的 worktree 裡，導致改到錯的程式碼還渾然不覺；這個版本修掉了這個問題。
- **這週可以嘗試：** 更新到 2.1.216 後，重新測試一次你常用的 background session／worktree 工作流程（開多個平行 agent、resume 舊 session），確認 resume 後 agent 的 prompt 與工具限制是否正確保留，並留意 `/context` 現在會在對話超出視窗時明確跳警告，可以藉此養成更早 `/compact` 的習慣。
