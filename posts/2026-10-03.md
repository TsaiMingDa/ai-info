（引用 @ClaudeDevs 的公告）Claude Code 新增了一個 plugin：You should Know。它會掃描 Claude 的輸出，找出你可能漏看的重要資訊，讓你隨時掌握狀況。用 `/plugin enable cc-plugin-you-should-know@builtin` 就能開啟。

**核心概念（簡單說）：**
跟 agent 長時間協作時，最大的風險往往不是它做錯，而是它「做了某個決定但你沒注意到」：例如順手改了設定檔、跳過某個測試、選了一個你不會選的套件。這些資訊其實都寫在輸出裡，只是被埋在一長串文字中。「You should know」是官方內建的 mod，用一個在旁觀察的 side agent 讀過 Claude 的輸出，把值得你注意的部分挑出來提醒你，有點像 code review 時同事在旁邊說「欸，這行你有看到嗎？」。

Thariq 特別強調它也是 mod 能力的示範：mod 不只能改 UI 外觀，還能在背景掛一個額外的 agent 來加工主流程的輸出。昨天（2.1.288）的 changelog 也提到這個 mod 改進了措辭，會區分「我們」、「主 agent」或「你」各自做了哪些決定，讓責任歸屬更清楚。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端任務常牽涉大量檔案（元件、樣式、測試、設定），Claude 一輪改下來你很難逐行看完；有個 side agent 幫你標出「它改了 `tsconfig` 的 strict 設定」這類關鍵決策，可以大幅降低漏審的風險。
- **具體場景：** 請 Claude 把 React 專案中的 class component 改寫成 hooks 時，它可能順手把某個 `useEffect` 的 dependency array 留空、或關掉一條 ESLint 規則；「You should know」會把這類容易埋下 bug 的決定挑出來，你可以在 PR 前就先處理。
- **這週可以嘗試：** 執行 `/plugin enable cc-plugin-you-should-know@builtin`，在下一個實際的前端重構任務中開著它，記錄它提醒了哪些事、哪些是你原本會漏掉的，再決定要不要推薦給團隊。

**核心概念（簡單說）：**
2.1.288 是 Mods 上線隔天的「打磨版」：給 mod 開發者新的 `$.ui.selection()` API，讓 mod 能讀到使用者在全螢幕模式選取的文字（例如做「選取一段輸出 → 送去翻譯 / 建 issue」這類 mod），並修了一批 plugin、LSP、hook 的邊角問題。

另一條主線是「長任務的穩定性」：API 中途逾時不再讓整輪失敗、長對話更可靠地自動 compact、`--resume` 不再掉 context、背景指令在互動 session 不再有時間上限。安全面則補上 `bash -c` 包裝下危險 `rm` 的漏洞，並讓 hook 比對失敗時改為「預設擋下」（fail closed），而不是悄悄略過。

**前端工程師實際應用：**
