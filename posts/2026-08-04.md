**原文：**
> I think a lot of people don't realize- if you connect a Claude Connector (e.g. your gmail, calendar, slack, etc), Claude Code will also be able to use them, including in Artifacts.

**繁中改寫：**
其實很多人沒發現——只要你連接了 Claude Connector（例如 Gmail、Google Calendar、Slack 等等），Claude Code 也能直接使用這些連接的服務，甚至在 Artifacts 裡也用得到。

**核心概念（簡單說）：**
Claude Connector 是讓 Claude 存取外部服務（信箱、日曆、Slack 等）資料的授權機制，過去大家可能覺得這只是網頁版 claude.ai 對話用的功能。這則貼文點出一個容易被忽略的重點：這組授權是「帳號等級」共用的，不是每個介面各自綁定。也就是說，你在瀏覽器設定好 Gmail connector 後，改用 Claude Code（終端機 CLI）或產生 Artifacts（可執行的互動式輸出）時，Claude 一樣能直接讀取這些外部資料，不需要重新授權或另外寫串接程式碼。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的開發流程需要 Claude 跨情境（網頁對話、CLI、Artifacts 產出的頁面）存取同一批外部資料，設定一次 connector 就能全通用，省下重複寫 OAuth 串接的功夫。
- **具體場景：** 用 Claude Code 寫一個自動化腳本，要根據 Google Calendar 的會議時間產生每日行程摘要的 Artifact，不用自己寫 Calendar API 串接，直接讓 Claude Code 呼叫已連接的 connector 取資料即可。
- **這週可以嘗試：** 到 claude.ai 的 connector 設定頁面看看你帳號目前有哪些服務可連接，並在 Claude Code 裡下一個需要用到那些資料的指令，測試看看能不能直接呼叫成功。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.221 / August 4, 2026

**變更項目：**
- Added [VSCode] Focus view: a chat-menu toggle that hides tool activity behind an expandable per-turn summary with a live running-tool indicator, toggled with Ctrl+Alt+F — VSCode 擴充新增「Focus view」，可把工具執行過程收合成可展開的每輪摘要，並顯示即時執行中工具的指示燈。
- Added `mode: "mask"` for sandbox credential files on Linux and WSL — sandboxed commands read a sentinel copy while the sandbox proxy substitutes the real value on egress; macOS falls back to deny — Linux/WSL 的 sandbox 新增憑證檔案「遮罩」模式，沙箱內指令讀到的是替身內容，真實值只在對外連線時由 proxy 代換；macOS 目前仍是直接拒絕存取。
- Added warnings to `claude plugin validate` when a marketplace or plugin name would be rejected by Claude Desktop's managed marketplace sync — `claude plugin validate` 新增警告，提前提示會被 Claude Desktop 受管市集同步拒絕的命名。
- Added a prompt-audit subcommand to the claude-api skill for auditing prompts and tool descriptions for patterns written for older models — claude-api skill 新增 prompt-audit 子指令，用來稽核 prompt／工具描述中是否還殘留針對舊模型寫法的痕跡。
- Fixed a Bash tool permission-check bypass where zsh could execute hidden commands in `[[ ]]` regex conditionals — 修復 zsh 在 `[[ ]]` 正規表達式條件式中可繞過 Bash 工具權限檢查、偷跑隱藏指令的漏洞，現在會正常跳出權限確認。
- Fixed PowerShell permission checks mishandling paths containing quote characters on Windows — 修復 Windows 上 PowerShell 權限檢查對含引號字元路徑處理錯誤的問題。
- Fixed the thinking toggle having no effect for the rest of a session that started with thinking off; disabling an MCP server mid-connect no longer silently reverts — 修復一開始關閉 thinking 後，該 session 內切換 thinking 開關失效的問題；連線中途停用 MCP server 也不會再被靜默還原。
- Fixed MCP servers from `--mcp-config` not being connected before the first turn in print mode (`-p`), causing the model to emit tool calls as literal text — 修復 print 模式 (`-p`) 下 `--mcp-config` 指定的 MCP server 來不及在第一輪連線完成、導致模型把工具呼叫當純文字輸出的問題。
- Fixed @-mentioned files being silently dropped when pressing Esc to retract a prompt and resubmitting it — 修復用 Esc 收回 prompt 再重送時，`@` 提及的檔案會被靜默丟失的問題。
- Fixed a crash when preparing API requests for SDK MCP tools named after built-in object properties such as `constructor` — 修復 SDK MCP 工具若命名為 `constructor` 等內建物件屬性名稱時，組 API 請求會當掉的問題。
- Fixed WebSearch failing with a 400 error at effort xhigh/max when thinking is disabled — 修復關閉 thinking 且 effort 設為 xhigh/max 時，WebSearch 會回傳 400 錯誤的問題。
- Fixed sandboxed large uploads failing with TLS errors through the sandbox proxy — 修復沙箱環境中大檔案上傳經過 sandbox proxy 時會出現 TLS 錯誤的問題。
- Fixed Team and Enterprise spend-limit message incorrectly blaming the org's monthly limit instead of your individual spend limit — 修復 Team／Enterprise 方案的花費上限提示訊息，錯誤地歸咎組織月額度而非個人花費上限。
- Fixed Bedrock authentication with AWS SSO named profiles failing in desktop-managed sessions on Windows machines with a stray HOME environment variable — 修復 Windows 上若有殘留 HOME 環境變數，桌面版管理的 session 使用 AWS SSO named profile 做 Bedrock 認證會失敗的問題。
- Fixed `CLAUDE_CODE_RESUME_INTERRUPTED_TURN=0` not disabling interrupted-turn auto-resume — 修復設定 `CLAUDE_CODE_RESUME_INTERRUPTED_TURN=0` 無法真正關閉「中斷後自動恢復」功能的問題，現在會正確生效。
- Fixed a rare wake-from-sleep race where two Claude Code processes could both refresh the same MCP connector or WIF OAuth token at once, forcing re-authentication — 修復電腦睡眠喚醒後偶發的競態問題：兩個 Claude Code 行程可能同時刷新同一個 MCP connector 或 WIF OAuth token，導致被迫重新登入。
- Fixed renaming a session from Claude Code Desktop or claude.ai not updating the CLI's session name; session names are now sanitized across all rename surfaces — 修復在 Claude Code Desktop 或 claude.ai 幫 session 改名，CLI 端名稱沒同步更新的問題，並統一淨化各處改名輸入。
- Fixed plugin- and org-delivered skills named after terminal-only built-ins (e.g. `/help`, `/feedback`) being un-invocable in non-interactive sessions — 修復外掛／組織下發的 skill 若命名跟終端機內建指令（如 `/help`、`/feedback`）撞名，在非互動 session 中無法被呼叫的問題。
- Fixed the "Plugins changed" notification lingering after plugins were reloaded instead of clearing — 修復外掛重新載入後「Plugins changed」通知沒有正確清除、一直停留畫面上的問題。
- Fixed Vim mode: the yank register now survives dialogs, history search, and the transcript view instead of being silently emptied — 修復 Vim 模式下，開對話框、搜尋歷史或查看逐字稿時，yank 暫存區內容會被靜默清空的問題。
- Fixed Vim mode: undoing back to an empty prompt now arms the "press ← again" confirm before returning to the agent view — 修復 Vim 模式下復原到空白 prompt 時，沒有先觸發「再按一次 ← 確認」就直接跳回 agent 畫面的問題。
- Improved tool search on Google Vertex AI: re-enabled for Claude 4.5-generation and newer models — 改善 Google Vertex AI 上的工具搜尋功能，針對 Claude 4.5 世代以上模型重新啟用。
- Improved auto mode: permission checks for parallel tool calls are now cache-efficient, and switching modes while a check is pending reliably prompts instead of applying stale results — 改善 auto 模式下平行工具呼叫的權限檢查快取效率，且檢查進行中切換模式時會確實跳出提示，而不是套用過期結果。
- Reduced prompt-cache costs for auto-mode permission checks by reusing the cached conversation prefix across decisions — 降低 auto 模式權限檢查的 prompt cache 成本，做法是讓多次判斷共用同一段已快取的對話前綴。
- Improved Stats panel to count cache tokens in its token totals, with a breakdown by input, output, cache read, and cache write — 改善 Stats 面板，token 總數會納入 cache token，並拆分成 input／output／cache read／cache write 明細。
- Improved `/ultrareview` error messages when a repo shares no history with its base — 改善 `/ultrareview` 在 repo 與 base 沒有共同歷史時的錯誤訊息，會直接提示建立分支，也不再對已完整 clone 的儲存庫誤導建議 `git fetch --unshallow`。
- Improved Windows startup: process creation times now read via a native kernel32 call instead of spawning PowerShell, so endpoint security tools gating powershell.exe no longer prompt — 改善 Windows 啟動流程，改用原生 kernel32 呼叫讀取行程建立時間，不再另外開 PowerShell，避免被端點防護軟體攔截跳出警告。
- Changed background sessions to commit and push to preserve work, only open a draft PR when the task calls for one, follow your CLAUDE.md git instructions, and always report where the work lives — 背景 session 行為調整：改為自動 commit／push 保存進度，只有任務真的需要時才開 draft PR，並遵循 CLAUDE.md 中的 git 指示，結束時一定會回報工作成果放在哪裡。
- Changed `/plugin install` to refresh a stale marketplace catalog and retry before reporting a plugin not found — `/plugin install` 在回報找不到外掛前，會先刷新過期的市集目錄並重試一次。
- Changed plugins installed from `/plugin` to activate immediately when safe, instead of always requiring `/reload-plugins` — 透過 `/plugin` 安裝的外掛，只要安全就會立即生效，不必每次都手動 `/reload-plugins`。
- Changed plugins to accept "." as a skills path, and the root-level SKILL.md validation error now suggests using the plugin root — 外掛的 skills 路徑可接受 `.`，且根目錄 SKILL.md 驗證錯誤訊息會建議改用外掛根目錄。
- Changed `/status` to show the session kind: interactive, or a background job that is attached or unattended — `/status` 會顯示 session 類型：互動式，或是有人盯著／無人看管的背景工作。
- Changed emoji autocomplete to accept common alternate shortcodes like `:thumbsup:`, `:thumbsdown:`, `:love:` — emoji 自動完成支援更多常見替代簡碼。
- Changed sessions forked with `/fork` to create a new worktree of their own instead of working in the original session's checkout — 用 `/fork` 分岔出的 session 現在會建立自己獨立的 worktree，而不是繼續共用原本 session 的 checkout。
- Changed Claude in Chrome to close the browser tabs it opens once it no longer needs them — Claude in Chrome 用完自己開的分頁後會自動關閉。
- Changed fast mode to report on the stream when usage credits run out mid-session, instead of failing silently — fast 模式在 session 中途額度用盡時，會在串流中回報，而不是靜默失敗。
- Changed Monitor: a watch that exits without producing any output now says so instead of reporting "stream ended" — Monitor 的 watch 若完全沒有輸出就結束，會明確說明，而不是含糊回報「stream ended」。
- Changed the Gateway model field validation: non-string values are rejected with a 400 instead of being forwarded — Gateway 的 model 欄位驗證改為直接拒絕非字串值（回傳 400），不再往下轉送。
- Removed the repeated "Permission mode changed while the auto-mode classifier call was queued" notice from approval prompts — 移除核准提示中重複出現的「auto-mode 分類請求排隊中權限模式被變更」提示訊息。

**核心概念（簡單說）：**
這個版本（2.1.221）是一次典型的維運型更新：一批安全性修復（zsh 權限繞過、PowerShell 引號路徑、sandbox 憑證遮罩）、一批穩定性修復（MCP 連線時序、Vim 模式狀態遺失、session 改名不同步），加上幾項體驗改善（VSCode Focus view 收合工具雜訊、auto 模式權限檢查更省快取成本、背景 session 行為更透明）。整體看得出 Anthropic 持續在補強 Claude Code 作為「長時間背景執行、多工具串接的開發代理」在權限安全與可觀測性上的細節。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你在 Windows 或 WSL 環境用 Claude Code，這次修的 PowerShell 路徑處理、zsh 權限繞過、Windows 啟動效能都直接影響你日常開發體驗與安全性。
- **具體場景：** 你常讓 Claude Code 在背景跑長任務（例如重構一個大型元件庫），這次「背景 session 會自動 commit/push 並回報工作位置」的行為調整，代表你不用再擔心背景工作做完找不到成果放哪裡。
- **這週可以嘗試：** 升級到 2.1.221 後，若用 VS Code 擴充，試著按 `Ctrl+Alt+F` 打開 Focus view，感受一下把工具執行雜訊收合成摘要後，追蹤 Claude 在做什麼是否更輕鬆；也可以檢查一下 `/status` 新增的 session 類型顯示，確認背景工作是否處於預期狀態。
