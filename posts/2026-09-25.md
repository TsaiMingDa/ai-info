**繁中改寫：**
這串收到超多回饋：很多人其實都是自己在做規劃，根本不需要 plan mode；但也有人很喜歡「進入一個模式、讓 Claude 只負責思考跟陪你腦力激盪」的操作體驗。所以我的計畫是：
- 把 plan mode 改成一個內建的 mod
- 讓 mod 可以新增自己的模式，或覆寫 shift+tab 的行為

這樣你就可以客製 plan mode 的 prompt、自己做新模式並分享出去，或者乾脆不理它，把 shift+tab 綁成完全不同的功能。

**核心概念（簡單說）：**
這是昨天「考慮拿掉 plan mode」那串的結論。Thariq 沒有直接砍掉，而是把 plan mode 從「寫死在產品裡的功能」降級成「一個可替換的擴充模組（mod）」。技術上這很像編輯器的設計哲學：VS Code 把很多核心功能做成內建 extension，Vim 讓你 remap 任何按鍵。Plan mode 本質上就是「一段特殊的 system prompt + 限制可用工具（不能改檔）」的組合，一旦這個組合被抽象成 mod，使用者就能自訂 prompt、限制條件，甚至做出「code review mode」「design brainstorm mode」這類全新模式。

換句話說，shift+tab 不再是一個固定開關，而是一個可程式化的「模式切換器」。對重度使用者來說，這代表可以把團隊的工作流（例如先寫測試再實作的 TDD mode）包成可分享的模式，而不只是靠每次手打 prompt。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你依賴 plan mode 先審方案再放行，它不會消失，只是變成可客製的 mod；你也能把團隊慣用的工作節奏做成自己的模式，讓新人一按 shift+tab 就套用。
- **具體場景：** 前端團隊可以做一個「UI spec mode」：只允許讀檔與產出 artifact，prompt 要求 Claude 先列出元件拆分、props 介面、狀態管理方案與 Storybook 案例，審完才切回一般模式動手實作。
- **這週可以嘗試：** 先把你目前「進 plan mode 前習慣補充的指示」整理成一段文字（例如「列出要改的檔案、說明對 bundle size 與 a11y 的影響」），存成 skill 或 CLAUDE.md 片段；等 mods 功能上線就能直接搬進自訂 plan mode prompt。

**原文：**
> my rule for sharing Claude output (PRs, artifacts, messages) is that I only do it if I would be happy sharing the prompts
>
> [Thread 續篇 https://x.com/trq212/status/2103150114386952242] e.g. "make a report on what happened in this incident, searching Slack and Git" is good
>
> "write a message that makes me sound thoughtful and caring" or "make a slide deck about the AI SDLC" is bad

**繁中改寫：**
我分享 Claude 產出的東西（PR、artifact、訊息）有一個原則：只有在我願意連 prompt 一起公開的情況下才分享。

舉例來說，「整理這次事故的經過，去翻 Slack 跟 Git 紀錄」這種就沒問題；但「幫我寫一則讓我看起來很貼心、很有想法的訊息」或「做一份關於 AI SDLC 的簡報」這種就不行。

**核心概念（簡單說）：**
這是一個很實用的「AI 產出倫理檢查」：想像把 prompt 貼在產出旁邊，你會不會尷尬？好的 prompt 是讓 Claude 做「整理、查證、彙整事實」這類你本來就該做、只是加速完成的工作，產出背後有真實的資料來源（Slack、Git log）。壞的 prompt 則是讓 Claude 代替你「假裝有想法」或「憑空生出內容」——收件者以為看到的是你的思考，其實是 AI 的填充物。

背後的邏輯是：分享出去的東西代表你的判斷與信用。事故報告有可驗證的事實基礎，別人讀起來省時間；一份沒有原始觀點、只靠 prompt 生成的簡報，則是在消耗讀者的注意力。

**前端工程師實際應用：**
- **跟你工作的關聯：** 你每天用 Claude Code 開 PR、寫 PR description、回 code review 留言，這條規則可以直接當成「這份產出能不能送出去」的自我檢查。
- **具體場景：** 請 Claude「根據這個 diff 和相關 issue，整理 PR description，列出改動原因與測試方式」是好的；請它「寫一段讓 reviewer 覺得這個改動很有深度的說明」就是壞的——前者有事實依據，後者是包裝。
- **這週可以嘗試：** 下次送出 AI 生成的 PR 或訊息前，問自己一句「我敢把 prompt 貼在留言裡嗎？」；可以試著在一個 PR description 底部真的附上你用的 prompt，觀察 reviewer 的反應。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.282 / September 24, 2026

**變更項目：**
- Added a maxProseWidth setting that caps the width of Claude's prose in wide terminals while tables and code blocks keep the full width（新增 `maxProseWidth` 設定，在寬螢幕終端機中限制 Claude 文字段落的寬度，表格與程式碼區塊仍維持全寬）
- Added a startup notice, and /status and claude doctor entries, listing telemetry variables in a project's settings files that were ignored or that turned telemetry off（啟動時與 `/status`、`claude doctor` 會列出專案設定檔中被忽略或關閉遙測的 telemetry 變數）
- Added the allowClaudeInChromeWithManagedMcp managed setting to let claude --chrome run alongside an exclusive managed-mcp.json（新增 managed 設定 `allowClaudeInChromeWithManagedMcp`，讓 `claude --chrome` 能與獨佔式 `managed-mcp.json` 並存）
- Added a scrollbar to the /feedback drafts list in fullscreen mode（fullscreen 模式下 `/feedback` 草稿清單新增捲軸）
- Fixed every request failing with a 400 error in conversations whose history holds web search results the API cannot decrypt（修正歷史中含有 API 無法解密的 web search 結果時，每個請求都回 400 錯誤的問題）
- Fixed more cases of continued or resumed sessions (--continue, --resume) re-sending earlier messages in a changed form, which could make the API drop Claude's earlier reasoning（再修正更多 `--continue` / `--resume` 時重送的歷史訊息被改動、導致前面推理被丟棄的情況）
- Fixed earlier extended thinking being dropped when /model, /rename, /artifacts or another immediate slash command was used while Claude was working（修正 Claude 工作中使用 `/model`、`/rename`、`/artifacts` 等即時 slash command 時，先前 extended thinking 被丟棄的問題）
- Fixed sessions failing on every turn with an "Invalid data in redacted_thinking block" API error; Claude Code now drops the conversation's thinking blocks and retries once（遇到 redacted_thinking 錯誤時會丟棄 thinking blocks 並重試一次，而不是每回合都失敗）
- Fixed compaction failing when the summarization request is refused; it now retries on a fallback model（壓縮對話時摘要請求被拒絕，現在會改用備援模型重試）
- Fixed Bash permission rules with a mid-pattern :* being skipped in settings files while --allowedTools honored them（修正設定檔中含有中段 `:*` 的 Bash 權限規則被略過的問題，現在所有來源行為一致，並在啟動時提示比對方式）
- Fixed pasted multi-line text being submitted line by line after the terminal's bracketed paste mode was reset mid-session（修正終端機 bracketed paste 模式中途被重設後，貼上多行文字會被逐行送出的問題）
- Fixed a stale character left in the last column of a diff when a redrawn line's CJK character or emoji wrapped to the next row（修正 diff 重繪時 CJK 字元或 emoji 換行後在最後一欄殘留字元的問題）
- Fixed the send-now hint showing ctrl+enter on terminals that send it as a newline (Windows Terminal before 1.25); it now shows ctrl+x ctrl+s there（在會把 ctrl+enter 當換行的終端機，例如舊版 Windows Terminal，改提示 `ctrl+x ctrl+s`）
- Fixed vim mode >>, r, 2J, dd/dj/dG cursor placement, counts before . and other edge cases（修正 vim 模式多項指令與游標位置的邊界行為）
- Improved the time to resume very large sessions, including ones that were never compacted（加快超大型 session 的 resume 速度）
- Improved /artifacts: titles line up in one column, and the list supports PgUp/PgDn, Home/End, the mouse wheel and clicks（`/artifacts` 清單排版改善，支援 PgUp/PgDn、Home/End、滑鼠滾輪與點擊）
- Changed auto mode to use the server-side classifier by default on a direct Anthropic API connection when telemetry is off (CLAUDE_CODE_AUTO_MODE_SERVER=0 opts out)（直連 Anthropic API 且關閉遙測時，auto mode 預設改用 server 端分類器；可用 `CLAUDE_CODE_AUTO_MODE_SERVER=0` 關閉）
- Changed project and local settings to ignore OpenTelemetry variables that turn on export, set its endpoint, or capture content, like CLAUDE_CODE_ENABLE_TELEMETRY and OTEL_LOG_*（專案與 local 設定檔中開啟 OpenTelemetry 匯出、設定 endpoint 或擷取內容的變數將被忽略）
- Changed Skill(anthropic-skills:*) and Skill(claude-ai:*) allow rules to cover only skills synced from claude.ai; local skill folders and MCP servers in those namespaces no longer load their skills（`anthropic-skills` / `claude-ai` 命名空間保留給 claude.ai 同步的 skill，本機同名的 skill 資料夾與 MCP server 不再載入其 skills）
- [VSCode] Fixed long replies falling behind the stream: the panel no longer re-parses the whole reply on every update（VS Code 面板不再於每次更新時重新解析整段回覆，長回覆不會跟不上 stream）
- [Cloud sessions] Added attaching a repository from a different GitHub owner, such as a fork's upstream, to a running cloud session（雲端 session 可額外掛上不同 GitHub owner 的 repo，例如 fork 的 upstream）
- [Claude Tag] 多項 Slack Enterprise Grid、共享頻道、模型退役 fallback、回覆卡片寬度等修正與調整
- 另有 plugin 解除安裝、`/skills` 搜尋、managed settings 驗證、Bedrock / Vertex、渲染器等大量細節修正（完整清單請見原文 changelog）

**核心概念（簡單說）：**
2.1.282 延續上一版的「長 session 可靠度」主軸，繼續補強 extended thinking 在各種情境（resume、切模型、slash command、redacted thinking、compaction 被拒）下不被意外丟棄的問題——這些 bug 的共同點是會讓 Claude「忘記自己之前想過什麼」，進而重複推理、浪費 token 或做出前後不一致的決策。

另一條主線是「設定檔的安全邊界」：專案層級的設定檔不能再偷偷開啟遙測匯出或擷取內容（避免 clone 一個惡意 repo 就把你的對話送到別人的 endpoint），`anthropic-skills` / `claude-ai` 命名空間也被保留，防止本機或 MCP 的同名 skill 冒充官方 skill 取得 allow 權限。體驗面則有 `maxProseWidth` 讓寬螢幕閱讀更舒服、大型 session resume 加速，以及 CJK 字元 diff 殘影這類對中文使用者很有感的修正。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你用超寬螢幕或 ultrawide 分割視窗跑 Claude Code，`maxProseWidth` 可以讓說明文字不再拉成一整條難讀的長行；在 Windows Terminal 上工作的人也會看到正確的送出快捷鍵提示。
- **具體場景：** 你在 monorepo 裡跑一個長時間的重構 session，中途用 `/model` 切模型或隔天 `--resume` 回來繼續，這版之後 Claude 比較不會遺失前面對元件架構的推理脈絡；另外若你會 clone 開源專案讓 Claude 分析，專案 settings 裡的 telemetry 變數也不再能偷偷生效。
- **這週可以嘗試：** 執行 `claude --version` 確認更新到 2.1.282，在 `~/.claude/settings.json` 試設 `"maxProseWidth": 100` 看閱讀體驗；再跑一次 `claude doctor`，檢查是否有專案設定檔中被忽略的 telemetry 變數或以 `:*` 寫法的 Bash 權限規則需要調整。
