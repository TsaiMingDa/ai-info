**繁中改寫：**
一年前我們推出 Opus 4.5，那是第一個幫我寫出 100% 程式碼的模型。

但「把 PR 送上線」這件事一直沒跟上寫 code 的速度，所以今天我們為 Team 與 Enterprise 方案推出 Claude Ship（beta）。我每天整天都在用，已經無法想像沒有它要怎麼 ship。

（引用 @ClaudeDevs）Claude Ship：Claude 可以 review 你的 pull request、動手修問題，並核准團隊政策允許的那些 PR。目標是讓你 ship 的速度跟寫 code 一樣快。

它讓我的速度倍增：不用再枯等 code review、也不用盯著 PR 顧，結果還更好。Code Review 負責抓 bug，PR Steward 負責修正與處理失敗的 check，Claude Approvals 則依團隊政策核准 PR（後兩者為 beta）。

**核心概念（簡單說）：**
AI 寫 code 已經很快，瓶頸轉移到「寫完之後」：等人 review、CI 掛掉要補、reviewer 留言要回、最後還要有人按 approve。Claude Ship 把這段流程拆成三個 agent 角色——Code Review（找 bug）、PR Steward（自動修 failing check、處理 review comment）、Claude Approvals（在團隊預先定義的政策範圍內自動核准）。

關鍵在「政策」：不是所有 PR 都讓 AI 自己放行，而是團隊先定好規則（例如只動文件、只改測試、低風險路徑、diff 小於 N 行），符合的才自動 approve，其餘仍走人工。這就像把 CODEOWNERS + branch protection 的概念延伸成「可程式化的信任邊界」。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端 PR 常卡在「改了一行 CSS 卻等一天 review」或「snapshot test 掛了要手動更新」，這類低風險、機械性的步驟正是 PR Steward 與 Approvals 最能省時間的地方。
- **具體場景：** 你送出一個調整 Tailwind class 的 PR，Vitest snapshot 與 Playwright 視覺測試失敗；PR Steward 判斷是預期內的樣式變更並更新 snapshot、推上新 commit，CI 轉綠後若符合「只改 `*.css` / `*.tsx` 樣式且 diff < 50 行」的政策，就由 Claude Approvals 核准。
- **這週可以嘗試：** 先別急著開自動核准，和團隊列出三種「你們其實都秒過」的 PR 類型（例如 typo、依賴 patch 版升級、測試補充），寫成一份草擬的 approval policy；若你們在 Team / Enterprise 方案，可先只開 Code Review 觀察它抓到的問題品質。

**繁中改寫：**
搭配 Enterprise Frontier Safeguards（EFS）的零資料保留（ZDR）現已對符合資格的企業開放 public beta。它能跨多個 request 偵測濫用行為，同時維持與 ZDR 相容。這是我們與超過 100 家客戶共同開發的。

EFS 目前可在 Claude Platform、Claude Platform on AWS、Amazon Bedrock 與 Claude on Google Cloud 上使用，Microsoft Foundry 的支援即將推出。

**核心概念（簡單說）：**
ZDR（zero data retention）代表 Anthropic 不保存你的 request 與 response，這對處理敏感資料的企業很重要；但「不保存」也讓平台很難發現跨多次請求才看得出的濫用模式（例如把危險任務拆成很多無害片段）。EFS 的目標是在不違反 ZDR 的前提下，仍能做跨請求的安全偵測。

換句話說，過去企業常要在「最高隱私」與「使用最前沿模型所需的安全把關」之間二選一；EFS 試圖讓兩者並存，讓有 ZDR 需求的企業也能用到更強的 frontier 模型。

**前端工程師實際應用：**
- **跟你工作的關聯：** 若你的產品會把使用者輸入（表單、聊天內容、上傳文件）送去 Claude API，資料保留政策會直接影響法遵審查能否通過，也影響你在前端要對使用者揭露什麼。
- **具體場景：** 在醫療或金融類 Next.js 應用中，用 Bedrock 呼叫 Claude 摘要使用者上傳的文件；法務要求 ZDR，EFS 讓你不必因此退回較舊或較弱的模型。
- **這週可以嘗試：** 盤點專案中所有呼叫 LLM API 的地方，整理一張表：送出哪些使用者資料、走哪個平台（API / Bedrock / Vertex）、目前的資料保留設定，並在隱私權說明頁補上對應描述。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.331 / November 23, 2026

**變更項目：**
- Added Code Mode support in terminal sessions on Amazon Bedrock, Google Cloud’s Agent Platform, Microsoft Foundry and Claude Platform on AWS —— 終端機 session 在 Bedrock、Google Cloud、Foundry、Claude Platform on AWS 上也支援 Code Mode
- Added an API connectivity section to `claude doctor` —— `claude doctor` 新增 API 連線檢查，回報能否連上、HTTP 狀態或錯誤原因
- Added a notice when tap-mode voice dictation stops by itself —— 語音聽寫在 15 秒無語音或 2 分鐘上限自動停止時會提示
- Added `CLAUDE_CODE_DISABLE_RESPONSE_COMPRESSION` —— 在會截斷壓縮回應的 proxy 後方，可要求未壓縮的模型回應
- Added `oidc.groups_jsonpath` and `CLAUDE_GATEWAY_IDP_CONNECT_BY_HOSTNAME=1` for Claude apps gateway —— 企業 gateway 的 OIDC 群組解析與 proxy 連線選項
- Added `gen_ai.usage.*`, `gen_ai.response.model`, `gen_ai.operation.name` to `claude_code.llm_request` trace spans —— OpenTelemetry trace 新增 token 用量與模型資訊（input_tokens 含 prompt cache）
- Added `optionalDependencies` to plugin manifests —— plugin 可宣告選用依賴，會一起安裝但可單獨停用或移除
- [VSCode] Added “Fix with Claude Code” quick fix for errors, warnings and failed tests —— 錯誤、警告與失敗測試可一鍵丟給 Claude 修
- [VSCode] Added “Add Cell to Chat”, “Add to Chat” in Source Control, and “Resolve Merge Conflicts” —— notebook cell、變更檔案、merge conflict 都能直接送進對話
- [VSCode] Added a notice before sending a very large selection, and advice under “Prompt is too long” —— 送出超大選取前提醒，並指出 prompt 太長的元兇
- Changed: plugin marketplaces in managed `extraKnownMarketplaces` will auto-update by default on or after November 30, 2026 (opt out with `"autoUpdate": false`) —— 11/30 起受管 marketplace 預設自動更新
- Changed what a PermissionDenied hook’s `retry: true` tells Claude —— 只有在你要求重試該呼叫時才重試
- [VSCode] Changed saving a proposed diff to accept it only after you click or type in its proposed side —— 需先在右側互動，存檔才會接受 diff，避免誤接受
- Improved start-up time, screen reader typing speed, and Code Mode tool search descriptions —— 啟動更快、螢幕閱讀器模式打字更順、Code Mode 工具搜尋顯示更多 MCP 工具說明
- [VSCode] Improved responsiveness in long chats, remote windows (SSH/WSL/containers), and the @ file menu now lists open editor tabs first —— 長對話與遠端視窗效能大幅改善，@ 檔案選單優先列出已開啟的分頁
- （另有 95 項 bug fixes，詳見原頁）

**核心概念（簡單說）：**
這版的主軸是「把 Claude Code 更深地嵌進既有開發流程」：VS Code 端把錯誤、失敗測試、merge conflict、Source Control 變更都變成一鍵送進對話的入口；企業端則補齊多雲平台的 Code Mode、OIDC gateway、OpenTelemetry 用量欄位等營運需求。另外 plugin 開始支援 `optionalDependencies`，延續 plugin 生態系的建置。
