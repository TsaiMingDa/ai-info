> Watermarking without quality loss is a bit unintuitive, doesn't feel like it should work.

> I made this artifact with Claude to help me understand how it works, sharing in case it's helpful.
>
> [Quote] Anthropic @AnthropicAI Aug 15: We've written an FAQ to answer some of the questions we've received about watermarking. In summary: We're implementing watermarking to comply with the EU AI Act. Other major model developers have signed the same Code of Practice and will also be implementing watermarking;

**繁中改寫：**
「無損品質的浮水印」這個概念其實有點反直覺，感覺不應該可行。我用 Claude 做了一個 artifact 來幫助自己理解它的運作原理，分享出來希望對大家有幫助。（引用 Anthropic 官方針對浮水印功能發布的 FAQ：我們正在導入浮水印機制以符合歐盟 AI 法案（EU AI Act）的規範，其他主要模型開發商也簽署了同一份行為準則，同樣會導入浮水印功能。）

**核心概念（簡單說）：**
文字浮水印（text watermarking）是一種在 AI 生成內容中嵌入不可見標記的技術，用來標示「這段文字是 AI 生成的」，但不能影響文字本身的品質或可讀性。這聽起來矛盾——加東西進去怎麼可能不影響品質？實務作法通常是利用 LLM 在生成每個 token 時本來就有機率分佈的特性，在取樣階段動態調整哪些 token 更容易被選中，用統計上幾乎察覺不到的方式嵌入可被特定演算法偵測的模式，而不是真的插入額外字元。這位作者做了一個互動式 Claude artifact 把這個原理視覺化，幫助自己（也幫助其他人）理解。這項功能是為了因應歐盟 AI 法案的合規要求而推出的。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的產品有串接 Claude API 並在歐盟市場營運，未來輸出的文字內容可能會被自動加上浮水印，這會影響內容審核、去重或內容比對邏輯的設計。
- **具體場景：** 假設你在做一個內容聚合平台，需要判斷某段文字是否為 AI 生成，浮水印偵測（若 Anthropic 開放對應 API）會比單純用「AI 生成內容偵測分類器」更可靠，可以在後端串接偵測邏輯。
- **這週可以嘗試：** 用 Claude 做一個小型 artifact，實際模擬 token 機率分佈與取樣的視覺化過程（就像這則貼文提到的做法），幫助自己更直觀理解 LLM 生成機制，這對 debug prompt 或理解 model 行為很有幫助。
