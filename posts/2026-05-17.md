## Claude Code · Changelog

**版本號 / 日期：** 2.1.143 / May 15, 2026

**變更項目：**
- Added plugin dependency enforcement: `claude plugin disable` now refuses when another enabled plugin depends on the target (with a copy-pasteable disable-chain hint), and `claude plugin enable` force-enables transitive dependencies｜**新增 plugin 依賴強制執行**：停用 plugin 時若有其他 plugin 依賴它會拒絕執行（並提示可複製的停用鏈順序）；啟用時自動強制啟用相依 plugin
- Added projected context cost (per-turn and per-invocation token estimates) to the `/plugin` marketplace browse pane｜**新增 context 費用預估**：在 `/plugin` marketplace 瀏覽面板顯示每 turn 與每次呼叫的預估 token 用量
- Added `worktree.bgIsolation: "none"` setting to let background sessions edit the working copy directly without `EnterWorktree`, for repos where worktrees are impractical｜**新增 `worktree.bgIsolation: "none"` 設定**：讓背景 session 可直接編輯 working copy，不需進入 worktree，適合 worktree 難用的 repo
- PowerShell tool now passes `-ExecutionPolicy Bypass`. Opt out with `CLAUDE_CODE_POWERSHELL_RESPECT_EXECUTION_POLICY=1`｜**PowerShell 工具現在自動加入 `-ExecutionPolicy Bypass`**，需保留原政策可用環境變數關閉
- Background sessions now preserve the model and effort level you set after waking from idle｜**背景 session 從閒置喚醒後現在會保留你設定的模型與 effort 等級**
- Shift+Tab in attached agent sessions now includes auto mode in the cycle｜**附加 agent session 中 Shift+Tab 循環現在包含 auto mode**
- `claude agents` now accepts `--add-dir`, `--settings`, `--mcp-config`, `--plugin-dir`, `--permission-mode`, `--model`, `--effort`, and `--dangerously-skip-permissions` flags｜**`claude agents` 新增多個啟動 flag**，可直接指定派出 session 的目錄、設定檔、模型、權限模式等
- `/bg` now preserves `--mcp-config`, `--settings`, `--add-dir`, `--plugin-dir`, and `--strict-mcp-config` across backgrounding｜**`/bg` 現在保留所有相關設定 flag**，背景化後 MCP server 與設定不會遺失
- Background sessions launched from `claude agents` now honor `permissions.defaultMode` from settings.json｜**修正**：`claude agents` 啟動的背景 session 現在遵守 `settings.json` 的 `permissions.defaultMode`，不再強制覆寫為 auto mode
- The PowerShell tool is now enabled by default on Windows for Bedrock, Vertex, and Foundry users. Opt out with `CLAUDE_CODE_USE_POWERSHELL_TOOL=0`｜**PowerShell 工具在 Windows 上對 Bedrock、Vertex、Foundry 用戶預設啟用**
- `/bg` and `←`-detach now preserve `--fallback-model` and `--allow-dangerously-skip-permissions`｜**`/bg` 和 ← detach 現在保留 fallback model 與 bypass-permissions 設定**
- `claude --bg --dangerously-skip-permissions` now persists across retire→wake｜**`--bg --dangerously-skip-permissions` 組合現在在 session retire/wake 後仍保持**
- Fixed a corrupt `.credentials.json` with a non-array `scopes` value hanging the CLI on startup or silently aborting OAuth token refresh｜**修正**：`.credentials.json` 的 `scopes` 非陣列格式導致 CLI 啟動卡死或 OAuth 靜默失敗
- Fixed right-click paste in `claude agents` on Windows Terminal and WSL｜**修正**：Windows Terminal 與 WSL 中 `claude agents` 右鍵貼上失效
- Fixed stop hooks that block repeatedly looping forever — the turn now ends with a warning after 8 consecutive blocks (override via `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`)｜**修正**：stop hook 連續阻擋 8 次後現在以警告結束，不再無限循環
- Fixed Esc/Ctrl+C not cancelling a pending `/loop` wakeup while Claude is idle｜**修正**：Claude 閒置期間 Esc/Ctrl+C 無法取消 `/loop` 排程喚醒
- Fixed `/goal` evaluator firing while background shells or delegated subagents are still running｜**修正**：背景 shell 或 subagent 仍執行時 `/goal` 評估器提前觸發
- Fixed `NO_COLOR`/`FORCE_COLOR` in settings.json `env` stripping Claude Code's own UI colors — they now apply to subprocesses only｜**修正**：`NO_COLOR`/`FORCE_COLOR` 現在只套用至 subprocess，不影響 Claude Code 自身 UI
- Fixed agent view spawning repeated PowerShell processes on Windows when listing sessions｜**修正**：Windows 上 agent view 列出 session 時重複生成 PowerShell 行程

- Fixed `--agent <name>` not finding plugin-contributed agents without the `plugin:` prefix｜**修正**：`--agent` 不加 `plugin:` 前綴也能找到 plugin 貢獻的 agent

- Fixed stale-fragment rendering when scrolling in attached background sessions on Windows Terminal｜**修正**：Windows Terminal 中附加背景 session 滾動時的殘留渲染碎片

- Worktree cleanup no longer falls back to `rm -rf` when `git worktree remove` fails, preventing loss of gitignored or in-progress files｜**修正**：worktree 清除失敗時不再 fallback 到 `rm -rf`，避免 in-progress 或 gitignore 檔遺失
- Fixed background-job sessions on macOS getting "Operation not permitted" errors when reading files under `~/Documents`, `~/Desktop`, or `~/Downloads`, even with Full Disk Access granted｜**修正**：macOS 背景 job 在已授予 Full Disk Access 的情況下讀取特定目錄仍失敗
- Fixed `claude agents` "v to open in editor" using the daemon's default editor instead of your shell's `$EDITOR`/`$VISUAL`｜**修正**：`claude agents` 的 v 鍵開啟編輯器改為使用 shell 的 `$EDITOR`/`$VISUAL`
- Fixed `claude agents` deadlocking on Windows with network-drive working directories; Ctrl+C now works during startup｜**修正**：Windows 網路磁碟工作目錄導致 `claude agents` 死鎖問題
- Fixed background-color bleed when attaching to a `claude agents` session from Apple Terminal or other 256-color-only terminals｜**修正**：Apple Terminal 等 256 色終端附加 session 時的背景顏色滲色
- Fixed session titles being derived from the URL when the first message is a link｜**修正**：第一則訊息為 URL 時 session 標題不再從 URL 衍生

**核心概念（簡單說）：**
2.1.143 是一次以「**background/agent 系統全面整固**」為主軸的版本。想像你在管理一條複雜的生產線：這版更新主要是修補各工作站（背景 session）之間的溝通管道，並讓你在開線時就能預先指定每個 session 用什麼模型、多大 effort、引入哪些工具——不需要上線後再手動調整。

另一個重點是 plugin 依賴管理：過去停用某個 plugin 可能讓依賴它的其他 plugin 靜默崩潰；現在系統會像 npm/apt 一樣提前告訴你「你必須先停用 A，才能停用 B」，讓 plugin 生態系更可預測。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你用 Claude Code 同時跑多個任務（例如一個 session 執行 Vitest watch、另一個在重構 React 元件），新的 `claude agents` flag 讓你在 CLI 啟動時就預設每個 session 的模型、工作目錄與設定檔，省去每次重複手動切換設定的時間
- **具體場景：** 在管理 monorepo（Next.js 前端 + Node.js API）時，執行 `claude agents --add-dir ./packages/ui --model claude-opus-4-7 --permission-mode auto` 可讓前端的 background session 自動套用最強模型並減少權限提示中斷，同時另一個 session 處理 API 邏輯，兩者設定互不干擾
- **這週可以嘗試：** 執行 `npm update -g @anthropic-ai/claude-code` 更新到 2.1.143，然後在 `.claude/settings.json` 加入 `"worktree": { "bgIsolation": "none" }` 看是否讓你的 repo 背景任務更順暢——特別是沒有使用多個 git worktree 的專案效果最明顯
