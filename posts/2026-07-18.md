**原文：**
> building prototypes of mockups, schemas, data models, proof of concepts, etc. is the best way to avoid spending tons of tokens before realizing you don't want the output
>
> Quote
> Evan Tana @evantana:
> The fastest way to build is to find the cheapest way to learn.
> Claude Code's @trq212 talked about this when he came by @southpkcommons.

**繁中改寫：**
Thariq 引用 Evan Tana 的貼文回應道：先做出 mockup、schema、資料模型、概念驗證（proof of concept）這類雛形，是避免燒掉大量 token 卻做出你根本不想要的成果的最好方法。換句話說，與其讓 Claude 一次到位寫出完整實作，不如先用低成本的方式快速驗證方向對不對，再決定要不要投入更多運算資源往下做。

**核心概念（簡單說）：**
這則貼文講的是「用便宜的方式先學習、再花大錢做」的原則，套用到 AI 輔助開發上就是：在讓 Claude Code 大量生成正式程式碼之前，先請它做一個簡化版的 schema、資料模型草圖或最小可行的 prototype。這樣可以用很少的 token（等於很少的時間與成本）就看出這個方向到底可不可行，避免因為需求想清楚才發現整個方向錯了，導致前面大量 token 都浪費掉。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端工程師常常要跟 PM 或後端一起確認資料結構、UI 流程、API 形狀，這些都適合先用低成本方式驗證，而不是直接請 Claude 產出正式元件或完整頁面。
- **具體場景：** 例如要串接一個新的表單頁面，可以先請 Claude Code 只產出資料型別（TypeScript interface）跟一個沒有樣式的靜態 mockup HTML，確認欄位、狀態、edge case 都對了之後，再請它補上實際的樣式與邏輯，而不是一開始就要求完整實作。
- **這週可以嘗試：** 下次要開新功能前，先跟 Claude 說「先幫我畫出資料模型跟一個陽春的 wireframe 就好，先不要寫正式邏輯」，等你確認方向沒問題後，再回頭請它把功能做完整。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.214 / July 18, 2026

**變更項目：**
- Fixed: single-segment `dir/**` allow rules like `Edit(src/**)` 過去會誤判成允許改寫樹狀結構中任何位置的巢狀 `dir/` 目錄，而不是只有 `<cwd>/dir`，現已修正。
- Fixed: 修補了影響 Windows PowerShell 5.1 session 中執行指令的權限檢查繞過（permission-check bypass）漏洞。
- Fixed: Bash 權限檢查現在對 bash 解析方式與權限分析器不同的檔案描述子重導向語法（file-descriptor redirect forms）採取「fail closed」（預設拒絕）。
- Fixed: Bash 權限檢查過去會誤判超長指令，現在超過 10,000 字元的指令一律會跳出確認提示，不再自動執行。
- Fixed: Bash 權限檢查過去會把 `[[ ]]` 比較式中的 zsh 變數下標與修飾符當成無意義文字忽略，現在這類指令會跳出確認提示。
- Fixed: Bash 權限檢查不再自動允許某些可能執行危險選項、command substitution 或反斜線路徑的 help / man 指令。
- Fixed: 修正遠端 session 中的權限提示可能在本機確認對話框跳出前就先繼續執行的問題。
- Added: 新增 `EndConversation` 工具，讓 Claude 可以主動結束與高度濫用或越獄（jailbreak）意圖使用者的對話，此行為與 claude.ai 自 2025 年起的作法一致。
- Added: 為過去會無聲執行很久的長時間工具呼叫，新增週期性的進度心跳（progress heartbeat）提示。
- Added: memory 檔案的 frontmatter 新增 ISO 格式的修改時間戳記。
- Added: OpenTelemetry log 事件新增 `message.uuid`、`client_request_id`、`tool_source` 屬性，方便做訊息層級的關聯與工具來源追蹤。
- Added: 新增 `CLAUDE_CODE_OTEL_CONTENT_MAX_LENGTH` 環境變數，可設定 OpenTelemetry 內容屬性的截斷上限（預設 60 KB）。
- Added: `subagentStatusLine` payload 新增 reasoning effort 欄位，讓自訂 agent 列可以顯示模型與 effort 等級。
- Added: 針對帶有 daemon-redirect 旗標（`--url`、`--connection`、`--identity`，以及 Podman 遠端模式）的 docker 指令（含 Podman docker shim）新增權限確認提示，過去這類指令會直接放行。
- Fixed: 修正 GrowthBook feature 值為 null 時會導致的當機，以及格式錯誤的 flag payload 可能清空快取 feature flags 的錯誤。
- Fixed: 修正 Linux 上 `pkill -f` 誤中 Claude CLI 自身行程時，會把 Bash 工具連同 Claude session 一起殺掉的問題。
- Fixed: `--settings` 指向裝置檔案或超大檔案時會造成記憶體無限成長，現在超過 2 MiB 的設定檔會在啟動時直接報錯拒絕。
- Fixed: 修正 Windows 上企業代理（corporate proxy）環境下串流回合失敗並出現「Socket is closed」的問題。
- Fixed: 修正 stream-json 輸出在退出時，對讀取較慢的 SDK／pipeline 消費者會被截斷的問題，退出前的清空機制現在會依佇列位元組數量調整等待時間，而不是固定 2 秒上限。
- Fixed: 修正排程任務（scheduled tasks）會把自己設定好的 prompt 誤判為不受信任輸入而拒絕執行的問題，現在會把觸發的 prompt 視為該 session 本身被指派的任務。
- Fixed: 修正 Windows 上 PowerShell 工具指令在子行程等待標準輸入時會卡住直到逾時的問題。
- Fixed: 修正 Windows 上透過 PowerShell 工具執行的 Python 腳本讀取非 UTF-8 標準輸入資料時會出現 `UnicodeDecodeError` 當機的問題。
- Fixed: 修正透過 PowerShell 工具執行的 Python 腳本輸出非 ASCII 字元時出現 `UnicodeEncodeError`，以及 PowerShell 7 錯誤訊息中包含原始 ANSI escape 序列的問題。
- Fixed: 修正 PowerShell 工具把 `where.exe`、`fc.exe`、`diff.exe` 回傳有效的否定結果誤判為錯誤的問題。
- Fixed: 修正 Windows PowerShell 5.1 下用 `>` 與 `>>` 寫出的檔案是 UTF-16LE 編碼、導致其他工具無法以 UTF-8 讀取的問題。
- Fixed: 修正背景常駐程式（background daemon）在關閉時誤刪其後繼程式控制 socket，導致下一個 client 反而把健康的新常駐程式殺掉的問題。
- Fixed: 修正用 `←` 或 `/background` 擱置的背景 session 閒置時，仍會讓 background daemon 與 worker 行程無限期存活的問題。
- Fixed: 修正已完成的背景 session，在 background service 進入閒置狀態後，無法透過 `claude rm` 或 agent 檢視畫面移除的問題。
- Fixed: 修正從非 git 資料夾派送出去的背景 session 無法從 agents 檢視畫面刪除的問題。
- Fixed: 修正重新開啟已停止的背景 session 時，若 session 儲存區中存在無法讀取的資料夾，會導致無法還原已儲存對話內容的問題。
- Fixed: 修正 Remote Control 的「session ready」推播通知，在未明確啟用 Remote Control 的 session 上也會誤觸發的問題。
- Fixed: 修正 `/install-github-app` 與 `/mcp` 設定選單在 agent-view session 中被誤擋的問題，現在只有在沒有終端機連接的背景 session 才會被拒絕。
- Fixed: 修正透過 `--settings` CLI 旗標啟用的外掛（plugins）沒有被載入的問題（v2.1.181 之後的回歸錯誤）。
- Fixed: 修正長時間執行的 session 在 OAuth token 輪替後，feature flags 會變得過時（stale）的問題。
- Fixed: 修正 `/ultrareview` 在沒有 merge base 的儲存庫中會直接拒絕執行的問題，現在會改為提議改審查所有已追蹤的檔案。
- Fixed: 修正當 shell 設定檔路徑其實是一個資料夾時，`claude update`、`claude doctor` 會無聲卡住，以及 `/status` 的系統診斷區塊會顯示空白的問題。
- Fixed: 修正 memory 檔案儲存時，frontmatter 內容遇到行內 `#` 符號會被靜默截斷的問題。
- Fixed: 修正在串流中發出多個累積型 `message_delta` frame 時，session 成本與 token 遙測數據會重複計算的問題。
- Fixed: 修正 advisor 思考期間會出現一個沒必要的「check your network」錯誤警告的問題。
- Fixed: 修正當 hook 的 stdout JSON 未通過 schema 驗證時，回傳 exit code 2 的 hook 沒有依文件所述正確阻擋執行的問題。
- Fixed: 修正在回合的非同步情境（async context）外發出的 OTel log 事件，會遺失該互動 span 追蹤上下文（trace context）的問題。
- Fixed: 修正 MCP 暫時性錯誤發生在 prompts/resources 重新整理時，會清空該伺服器 slash commands 與 resources 的問題。
- Improved: 在家目錄下執行 `claude rc` 時的 workspace-trust 錯誤訊息，改為說明「在家目錄的信任設定永遠不會被儲存」，並建議改到專案目錄下執行。
- Changed: 單一層級的 `dir/**` hook `if:` 條件現在只會匹配 `<cwd>/dir`；若要匹配任意深度，請改寫成 `**/dir/**`。`deny`／`ask` 權限規則仍維持任意深度匹配的行為。
- Changed: 使用 `-m`/`--magic-file` 或 `-f`/`--files-from` 的檔案指令，現在需要權限確認，不再被自動視為唯讀而放行。
- Changed: 調整 keep-alive 連線池策略，遇到過期連線錯誤後會停用連線池，讓重試時改開新的 socket。
- Changed: `SessionStart` hooks 在 session 以 fork 方式開始時，現在會回報來源為 `"fork"`，而不是 `"resume"`。

**核心概念（簡單說）：**
這個版本主打「權限檢查系統的補漏」與「背景 session／daemon 生命週期管理」的大掃除：一方面修掉了好幾個 Bash／Docker／PowerShell 權限檢查會誤放行或誤擋的邊界案例（像是超長指令、zsh 變數下標、Windows PowerShell 5.1 的漏洞），讓「危險指令會跳出確認、安全指令不會被過度打擾」這件事更準確；另一方面則修掉一大串背景 session、background daemon 卡死或無法清除的問題，讓長時間掛在背景跑的 agent session 更穩定可控。同時也新增了 `EndConversation` 工具，讓 Claude 可以在遇到高度濫用或越獄嘗試時主動結束對話。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你在 Windows 上用 Claude Code 搭配 PowerShell 工具開發，這次修掉的好幾個 Windows 專屬 bug（UnicodeDecodeError、輸出被誤判、子行程卡住、UTF-16LE 檔案編碼問題）都直接影響你日常開發體驗；若你有用 background session 或 `/background` 功能長時間跑任務，穩定性也會明顯改善。
- **具體場景：** 例如你常用 `>` 或 `>>` 把 PowerShell 指令輸出寫進檔案再用其他工具（如 VS Code、Node script）讀取，過去可能因為 UTF-16LE 編碼而讀不到正確內容，升級後這個問題已經修掉；另外若你曾遇過背景 session 關不掉、`claude rm` 沒反應的情況，這版也一併修正了。
- **這週可以嘗試：** 執行 `claude --version` 確認自己是否已經在 2.1.214 或更新版本，若還沒，跑一次 `claude update`；同時可以檢查一下手上有沒有因為單一層級 `dir/**` 權限規則設定不精確、而不小心放行了不該放行的巢狀目錄寫入，趁這次規則調整重新檢視一次。
