## Claude Code · Changelog

**版本號 / 日期：** 2.1.328 / November 19, 2026

**變更項目：**（本版另有 19 項改進、91 項修正收合未列，以下節錄與日常開發最相關的部分）
- Added auto mode for Claude Opus 4.6 and Sonnet 4.6 on Amazon Bedrock, Google Cloud’s Agent Platform, Microsoft Foundry and Claude apps gateway; interactive sessions with no permission mode start in it — 第三方雲端上的 Opus 4.6／Sonnet 4.6 也支援 auto mode，未設定權限模式的互動 session 會直接以 auto mode 啟動。
- Added `"onFailure": "block"` for `mcp_tool` hooks, as for command and HTTP hooks: a hook whose call fails blocks the action — `mcp_tool` hook 也能設定「呼叫失敗就擋下動作」。
- Added a notice in `/status` and `claude doctor` when an OpenTelemetry exporter has no endpoint and its data would likely be lost — OpenTelemetry exporter 沒設 endpoint 時會提示資料可能遺失。
- Added `CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME`, which lets a host stop `claude -p --resume` and `--continue` from running a tool call that a hook deferred — 新環境變數，可阻止 resume 時執行被 hook 延後的工具呼叫。
- Self-hosted runner: Added `--repository-folder`, `--hook-label`, `--metadata key=value` and new orchestrator metrics — self-hosted runner 新增多個參數與 `/metrics` 指標。
- [VSCode] Added a notice when a message from another session is held, with a link to the settings file that can allow it — VS Code 中其他 session 的訊息被暫留時會提示並附設定檔連結。
- Changed `/code-review` on most models to report only bugs and CLAUDE.md violations; run `/simplify` for reuse, simplification and efficiency cleanups — `/code-review` 只回報 bug 與違反 CLAUDE.md 的地方，重構類建議改用 `/simplify`。
- Changed `/code-review` to mark each finding Important, Pre-existing or Nit on most models, and to end each summary with a suggested fix — 每個 finding 會標 Important／Pre-existing／Nit，並附建議修法。
- Changed Code Mode to no longer run UserPromptSubmit hooks, managed ones included, on scripts’ output; to redact that output, use a PostToolUse hook with `updatedToolOutput` — Code Mode 的腳本輸出不再經過 UserPromptSubmit hook，要遮蔽輸出請改用 PostToolUse hook。
- Changed managed PostToolUse hooks to no longer fire for calls refused before they ran — 執行前就被拒的呼叫不再觸發 managed PostToolUse hook。
- Changed `/bug` to ask Yes or No before sending, so repeated Enters no longer send a report or open GitHub — `/bug` 送出前會先確認，避免連按 Enter 誤送。
- Changed `claude -p` with `CLAUDE_CODE_FORK_SUBAGENT=0` to count a background subagent and those it waits for against one 10-minute wait; raise `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS` for longer chains — `claude -p` 背景 subagent 鏈共用 10 分鐘等待上限，可用環境變數調高。
- Changed how a sandbox that can’t start is reported: the next sandboxed Bash command is refused and says that the sandbox is off for the session — sandbox 無法啟動時，下一個 sandbox 化的 Bash 指令會被拒並說明原因。
- Changed subagent progress summaries in terminal sessions on the Anthropic API to be written by the default small fast model, using far fewer tokens — subagent 進度摘要改由小模型產生，大幅省 token。
- Changed `/list-agents` to show its list to you alone — `/list-agents` 的清單只顯示給你看。

**核心概念（簡單說）：**
2.1.328 的主軸是「把 auto mode 推到第三方雲」以及「讓 `/code-review` 更聚焦」。在 Bedrock、Vertex（Agent Platform）、Foundry 上用 4.6 世代模型的團隊，現在也能用 auto mode 由安全分類器代替人逐一按允許。`/code-review` 則拆職責：它只管 bug 和違反 CLAUDE.md 的規則，並標上嚴重度；「這段可以寫得更簡潔」這類建議交給 `/simplify`。就像把 ESLint 的 `error` 規則和 Prettier 的格式化分開跑，一個抓錯、一個整理。

其餘是 hook 與自動化的細節收斂：`mcp_tool` hook 失敗可直接擋、Code Mode 與 PostToolUse hook 的觸發時機更明確、`claude -p` 背景 subagent 有統一的等待上限，對在 CI 或排程中跑 Claude Code 的人比較有感。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你習慣在 PR 前跑 `/code-review`，輸出格式變了——只剩 bug 與規則違反，且有 Important／Nit 分級，更適合直接貼進 PR 討論；想要重構建議要另外跑 `/simplify`。
- **具體場景：** 你改完一個 React 表單的驗證邏輯，先跑 `/code-review` 看有沒有 Important 等級的問題（例如 `useEffect` 依賴漏掉造成驗證不更新），修完再跑 `/simplify` 讓它整理重複的 `onChange` handler，兩步分開審核也比較好閱讀 diff。
- **這週可以嘗試：** 在專案的 `CLAUDE.md` 寫下兩三條團隊規則（例如「元件不得直接呼叫 `fetch`，須透過 `lib/api`」），然後跑一次 `/code-review`，看它是否會把違規標出來——這版開始，CLAUDE.md 規則違反是 review 的一級公民。
