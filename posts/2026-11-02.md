**繁中改寫：**
Thariq 分享他的格鬥遊戲 side project 新進度：加了一個新角色，是會用火焰戰鬥的跆拳道高手。美術風格也從 3D 模型改成用 AI 生成的 sprite。他還做了一段角色登場的精華開場影片，覺得整體越來越有樣子，希望下週能做出一個 vertical slice。

這串貼文引用的是他 10 月初的想法：以前創過遊戲公司的他認為，做遊戲的過程本身就充滿成就感和創造力，不該整個外包給 AI，而是讓 AI 跟你一起把自己的構想做出來。

**核心概念（簡單說）：**
重點在「AI 是協作者，不是代工廠」。Thariq 自己決定角色設定、美術方向和要呈現的感覺，AI 負責把這些想法快速變成可以看、可以玩的東西。從 3D 模型改成 2D 生成 sprite 是典型的取捨：生成 sprite 讓美術迭代成本大幅下降，一個新角色可以很快試出好幾種造型，但動作一致性和畫面風格統一就要靠人來把關。

「vertical slice」是遊戲開發術語，意思是做出一小段「各層都完整」的成品：玩法、美術、音效、UI 都到接近最終品質，只是範圍很小。可以把它想成前端的「一個完整打通的 feature」，不是把所有頁面都做出 wireframe，而是先讓一條 user flow 從 UI 到 API 到狀態管理都做到可上線的水準，用來驗證整體方向對不對。

**前端工程師實際應用：**
- **跟你工作的關聯：** 用 agent 做 UI 時，最容易犯的錯是讓它決定設計方向。把「品味和決策」留在自己手上、把「實作和產出變體」交給 AI，產出才會有一致的風格。
- **具體場景：** 做一個新的 landing page 時，先自己定好色票、字體和元件風格（例如寫進 Tailwind config 和一份簡短的設計說明），再請 Claude Code 依照這些限制產出三種 hero 區塊的版本，由你挑選和微調，而不是一句「幫我做好看的首頁」就丟給它。
- **這週可以嘗試：** 為手上的 side project 定義一個 vertical slice：挑一條最核心的 user flow（例如註冊到看到第一筆資料），用 agent 把它從頭到尾做到可 demo 的品質，再決定要不要往下擴張。
