## claudeai · X

**原文網址：** https://x.com/claudeai/status/2118403114890137895

**原文：**
> Introducing Personal Finance in Claude, in beta in the US.
>
> Connect the accounts you choose, and Claude answers your money questions in everyday language, from your own balances and transactions. Access is read-only, and Claude can't move, manage, or invest your money.
>
> （同串第二則：https://x.com/claudeai/status/2118403117779988744）
> Like the rest of Claude, Personal Finance has no ads or sponsored recommendations. It helps you understand your money, and it isn't designed to give investment advice.
>
> Rolling out gradually in the US on the Pro, Max, and Ultra plans:
> （附連結卡片：Introducing Personal Finance in Claude）

**繁中改寫：**
Claude 推出 Personal Finance（個人理財）功能，目前在美國以 beta 形式開放。

你可以自己選擇要連結哪些帳戶，Claude 會根據你自己的帳戶餘額與交易紀錄，用日常口語回答你關於錢的問題。存取權限是唯讀的，Claude 無法轉帳、管理或幫你投資任何資金。

就跟 Claude 的其他功能一樣，Personal Finance 沒有廣告、也沒有業配推薦。它的定位是幫你看懂自己的財務狀況，而不是提供投資建議。目前正逐步開放給美國的 Pro、Max 與 Ultra 方案使用者。

**核心概念（簡單說）：**
這是一個把「個人金融資料」當成 connector 接進 Claude 的產品：使用者授權連結銀行、信用卡等帳戶後，Claude 能讀到真實的餘額與交易明細，再用自然語言回答「我這個月外食花了多少？」「哪些訂閱還在扣款？」這類問題。技術上可以想成 RAG + tool use 的組合——模型不是憑記憶回答，而是先呼叫唯讀的資料工具查你的交易，再做彙總與解釋。

設計上最值得注意的是「權限邊界」：官方特別強調 read-only、不能動錢、不給投資建議、沒有廣告。這是處理敏感資料的 AI 功能的典型做法——把 agent 能做的事限縮在「讀與解釋」，把「寫入 / 執行」完全排除，用最小權限原則降低出錯或被濫用時的傷害範圍。逐步 rollout（gradual rollout）則代表它很可能用 feature flag 分批開放，所以有人在回覆中提到側邊欄還看不到入口。

**前端工程師實際應用：**
- **跟你工作的關聯：** 當你在產品裡串 AI 功能、又要碰使用者的敏感資料（帳務、健康、訂單）時，這是很好的參考範本：UI 上要清楚揭露「AI 能看什麼、不能做什麼」，前端也要配合後端的權限設計，只暴露唯讀的 API 給 agent。
- **具體場景：** 你在做一個 Next.js 記帳後台，想加一個「問問你的帳本」聊天框。可以用 Claude API 的 tool use 定義一個 `get_transactions({ from, to, category })` 唯讀工具，後端用 read-only 的 DB role 執行查詢；前端在聊天框上方放一條固定說明「AI 只能讀取你的交易紀錄，無法新增或修改」，並用 feature flag（例如 LaunchDarkly 或自建的 `useFeatureFlag` hook）先只對內部使用者開放。
- **這週可以嘗試：** 挑你手上一個會碰使用者資料的 AI 功能（或規劃中的），列出它目前能呼叫的所有 API，標記哪些是讀、哪些是寫；把寫入類的拿掉或加上二次確認，並在 UI 上補一句清楚的權限說明。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.318 / November 4, 2026

**變更項目：**
- Added the date a stored claude.ai sign-in ends to `claude auth status` (`loginExpiresAt`) and to `claude -p` JSON results (`credential_expires_at`) — `claude auth status` 與 `claude -p` 的 JSON 結果會顯示 claude.ai 登入憑證到期日
- Added a one-line stderr warning to `claude -p` text output, starting 10 days before a stored claude.ai sign-in ends — 登入到期前 10 天，`claude -p` 會在 stderr 印出一行警告
- Added an effort option to a mod's `$.model.fork`, so a quick side job can run at low effort — mod 的 `$.model.fork` 可指定 effort，讓小型旁支任務用低 effort 跑
- [Cloud sessions] Added a No repository option — 雲端 session 可以不選 repo 直接開始
- [Cloud sessions] Added the usual Chrome names to cloud sessions, so tools other than Playwright can find the built-in Chromium through `google-chrome` and `CHROME_PATH` — 雲端環境內建的 Chromium 現在可用 `google-chrome` / `CHROME_PATH` 找到，非 Playwright 的工具也能用
- Changed Claude Code to no longer install or update the IDE extension when started in an IDE terminal; use `/ide` from an outside terminal or your editor's extensions view — 在 IDE 內建終端機啟動時不再自動安裝 / 更新 IDE 擴充套件
- Changed background subagents to move a shell command to the background after 3 minutes on all providers, so the prompt cache doesn't expire while it runs — 背景 subagent 的 shell 指令跑超過 3 分鐘會自動轉背景，避免 prompt cache 過期
- Changed the `/permissions` rule details views to use the standard dialog; pressing Ctrl+C twice now goes back or cancels instead of quitting — `/permissions` 介面統一為標準對話框，連按兩次 Ctrl+C 改為返回而非退出
- 另含 15 項改進與 47 項 bug 修正（詳見官方 changelog）

> 註：自上次 digest 後無更新版本，2.1.318 為最近一次 update（前兩日 digest 亦已收錄）。

**核心概念（簡單說）：**
這版的主軸是「讓無人值守與自動化流程更可靠」。最實用的是登入到期提醒：在 CI、cron 或 scheduled task 裡用 `claude -p` 跑腳本時，最怕的就是 claude.ai 登入憑證某天悄悄過期、整條流程默默失敗；現在可以從 `claude auth status` 或 JSON 結果的 `credential_expires_at` 直接讀到期日，並在到期前 10 天收到 stderr 警告。

另一個重點是效能與穩定性：背景 subagent 的長時間 shell 指令會在 3 分鐘後轉背景，讓 prompt cache 不會因為等待而過期（cache 過期就要重新付完整的輸入 token 成本）。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你在 GitHub Actions 或本機排程裡用 `claude -p` 做 PR review、產生 changelog、跑 lint 修正，這版能幫你提前發現登入即將過期，避免某天早上發現整排 job 都 fail。
- **具體場景：** 在每日跑的腳本開頭加一段 `claude auth status`，用 `jq` 讀出 `loginExpiresAt`，若距今少於 7 天就用 Slack / Discord webhook 通知自己重新登入。
- **這週可以嘗試：** 執行 `claude update` 升到 2.1.318，跑一次 `claude auth status` 看看你的登入何時到期，並把這個檢查寫進你最常用的自動化腳本裡。
