**原文：**
> a big advantage of doing planning like this is that it's a lot more token efficient compared to raw HTML-
>
> the model doesn't need to remake the components or logic to do common things like state machines, diagrams, code snippets, etc.

**繁中改寫：**
用這種方式做規劃有個很大的好處：比起直接生原始 HTML，token 用量省很多——模型不用每次重新刻元件或邏輯，像 state machine、圖表、code snippet 這些常見需求都已經現成。

**核心概念（簡單說）：**
如果讓模型從零寫一份 HTML 計畫，每次都要重新輸出 CSS、圖表渲染邏輯、程式碼高亮等樣板，token 大量浪費在「重複造輪子」。`html-plan` skill 預先準備好元件（state machine 圖、流程圖、code block），模型只需要輸出「資料」或「宣告要用哪個元件」，就像在 React 裡寫 `<StateMachine states={...} />` 而不是每次手刻 SVG。輸出變短、成本變低，格式也更一致。

**前端工程師實際應用：**
- **跟你工作的關聯：** 這正是元件化的思維：把重複的呈現邏輯抽成元件，只傳資料——你每天在做的事，套用在 LLM 輸出上一樣有效。
- **具體場景：** 自己寫 skill 產報告時，與其讓 Claude 每次輸出完整 HTML + Chart.js 設定，不如在 skill 裡放好模板，讓 Claude 只產生 JSON 資料，再由模板渲染。
- **這週可以嘗試：** 檢查你常用的 prompt 或 skill 中，有沒有每次都要模型重新輸出的大段樣板（HTML、表格格式），把它抽成模板檔，只讓模型填內容。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.291 / October 6, 2026

**變更項目：**
- Fixed a regression in 2.1.290 where cloud sessions could drop answers to permission prompts
  - 修正 2.1.290 引入的回歸問題：雲端 session 可能遺失使用者對權限提示的回答。
- Fixed a regression in 2.1.288 where the last messages of a session could be lost when quitting
  - 修正 2.1.288 引入的回歸問題：結束時 session 最後幾則訊息可能遺失。

**核心概念（簡單說）：**
這是一個只修兩個 regression 的熱修版本。第一個影響雲端 session：你按了「允許 / 拒絕」，但答案沒送達，Claude 會一直卡在等待。第二個影響所有人：離開 Claude Code 時，最後幾則對話沒寫進 transcript，之後 `--resume` 會發現少了最後一段。兩者都屬於「狀態沒有確實落地（persist）」的問題，類似前端在 `beforeunload` 前沒把資料 flush 出去。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你常用 `--resume` 或 `/resume` 接續前一天的工作，2.1.288～2.1.290 可能讓你接回的對話少了結尾，升級即可解決。
- **具體場景：** 昨天收工前請 Claude 總結「明天要接著做的事」後直接退出，今天 `claude --continue` 卻找不到那段總結——這正是本次修掉的問題。
- **這週可以嘗試：** 執行 `claude --version` 確認至少是 2.1.291；若要在 session 結尾留交接筆記，養成寫進檔案（例如 `NOTES.md`）的習慣，比只依賴 transcript 更可靠。
