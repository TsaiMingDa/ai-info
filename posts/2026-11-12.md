**繁中改寫：**
Swyx 把 AIE Code 的「閉幕主題演講」排給我，翻成白話就是：那時候大家不是累癱了就是在趕飛機。所以如果你不屬於這兩種人，明天下午 5 點歡迎來聽我的場。講題叫做「苦澀教訓的甜蜜面（the sweet side of the bitter lesson）」。內容是我認為明年使用 coding agent 的體驗可能會長什麼樣子，以及我們能怎麼親手形塑它。

**核心概念（簡單說）：**
「The Bitter Lesson」是 AI 研究者 Rich Sutton 在 2019 年寫的經典短文，主旨是：長期來看，靠「通用方法 + 更多算力」的做法，最終總會打敗研究者精心手刻的人類知識與規則。對寫工具的人來說這很「苦」——你花心思設計的巧妙 heuristic，很可能被下一代更強的模型直接淘汰。Thariq 的講題反過來談「甜」的那一面：既然模型能力會持續變強，工具開發者的價值就不在於彌補模型的弱點，而在於設計「人如何與越來越強的模型協作」的體驗——例如怎麼呈現 agent 的中間狀態、怎麼讓人插手修正、怎麼把品味與意圖傳達給模型。

這跟他前一天說的「少一點 one-shot demo、多一點協作工具」是同一條思路：與其押注某個 prompt 技巧，不如把力氣放在不會被模型進步淘汰的介面與工作流程上。

**前端工程師實際應用：**
- **跟你工作的關聯：** 你為了讓 AI 產出正確程式碼而寫的大量「補丁式」規則（超長的 CLAUDE.md、特定措辭的 prompt），很可能在下一代模型上變得多餘；真正值得投資的是清楚的專案結構、型別、測試與驗證流程，這些對人和模型都有用。
- **具體場景：** 與其在 CLAUDE.md 寫「React 元件一定要用 function component、props 要解構、不要用 any……」二十條規則，不如把這些交給 ESLint（`@typescript-eslint/no-explicit-any`）、TypeScript strict mode 與 Vitest，讓 Claude Code 每次改完自己跑 `pnpm lint && pnpm test` 驗收——模型越強，這套回饋迴圈越有效，而不會過時。
- **這週可以嘗試：** 打開你的 CLAUDE.md，把每一條規則分類成「可以用工具自動檢查」與「真的需要人類脈絡」兩類，把前者改成 lint / type / test 規則，只保留後者，觀察 agent 的表現是否持平或更好。

**原文：**
> Mariko Mori has pushed the boundaries of art for three decades. For her retrospective "All That Shines," she used Claude to write code for a computer-generated animation, presented as a new video installation.

**繁中改寫：**
森萬里子（Mariko Mori）三十年來不斷挑戰藝術的邊界。在她的回顧展「All That Shines」中，她用 Claude 寫程式碼來產生一段電腦生成動畫，並以全新的錄像裝置作品形式展出。

**核心概念（簡單說）：**
這是一個「創作者用 AI 寫 creative coding」的案例。電腦生成動畫（generative / procedural animation）不是手繪每一格，而是用程式描述規則——粒子怎麼移動、顏色怎麼漸變、形狀怎麼隨時間演化——再讓電腦算出每一格畫面。以往這需要藝術家本身懂 Processing、p5.js、GLSL shader 或 TouchDesigner，或是找工程師合作；現在藝術家可以用自然語言描述想要的視覺效果，由 Claude 轉成可執行的程式碼，再反覆調整參數。

重點在於分工改變：藝術家保有美學判斷與作品方向，模型負責把「想要光像水面一樣流動」翻譯成數學與程式。這和前端工程師用 AI 寫動畫的流程本質上一樣。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端越來越常需要做品牌感強的視覺效果（Hero 區動態背景、互動式資料視覺化、載入動畫），這些本質上就是 creative coding，用 Claude 能大幅降低 Canvas / WebGL 的入門門檻。
- **具體場景：** 產品官網需要一個「微光粒子緩慢漂浮」的 Hero 背景，可以請 Claude Code 用 Three.js 或原生 `<canvas>` + `requestAnimationFrame` 寫出來，並要求它把粒子數量、速度、色彩抽成 props，再加上 `prefers-reduced-motion` 判斷與 `IntersectionObserver` 在離開視窗時暫停，兼顧效能與無障礙。
- **這週可以嘗試：** 打開 p5.js Web Editor 或一個空的 Vite 專案，請 Claude 依你的一句描述（例如「像極光一樣的漸層波動」）寫一個 generative 動畫，然後只用自然語言迭代三輪，體會「描述 → 程式 → 調整」的創作迴圈。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.322 / November 10, 2026

**變更項目：**
- Added fast mode on Vertex in the global, us and eu regions, falling back to standard speed if Vertex refuses it（在 Vertex 的 global、us、eu 區域支援 fast mode；若 Vertex 拒絕則自動退回標準速度）

**核心概念（簡單說）：**
自上次 digest 後沒有新版本，這仍是目前最新的一版（前兩日 digest 已收錄）。內容只有一項：透過 Google Cloud Vertex AI 使用 Claude Code 的團隊也能啟用 fast mode，以較高單價換取更快的輸出速度；若 Vertex 端不接受，會自動降級回標準速度，而不是讓請求失敗——這是典型的 graceful degradation 設計。

**前端工程師實際應用：**
- **跟你工作的關聯：** 若公司透過 GCP / Vertex 走企業帳單，現在也能用 fast mode 縮短互動式開發時的等待。
- **具體場景：** 用 Claude Code 在 Vertex 上調整 Tailwind 樣式與 Framer Motion 動畫、搭配 Vite HMR 即時預覽時，fast mode 能讓每輪「改 → 看」更快。
- **這週可以嘗試：** 參考這個「失敗時退回預設」的設計，檢查你專案中呼叫實驗性瀏覽器 API（如 View Transitions API）的地方，是否都有 `if ('startViewTransition' in document)` 這類 feature detection 與 fallback。
