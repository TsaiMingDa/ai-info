**繁中改寫：**
大概一年前，我發了最早一批「用 Claude Code 做影片」的文章之一。

當時那些影片其實每一支都花了很多時間跟 Claude 來回迭代，要一直指出哪裡細節不對、哪裡要修，才終於弄對。

現在回頭看，進步幅度真的很誇張。

（引用自己 2025 年 7 月的貼文）把 Claude Code 當成你的影片剪輯師。信不信由你，下面每一支影片都是用 Claude Code vibe coding 出來的，接下來教你怎麼做。

**核心概念（簡單說）：**
這則是 Thariq 對自己一年前那篇「Claude Code 當影片剪輯師」thread 的回顧。原 thread 的關鍵是 Remotion：一個用 React 寫影片的函式庫，每一幀就是一次 React render，時間軸由 `useCurrentFrame()` 驅動，動畫本質上是「frame 數 → 樣式」的純函式，最後再用 headless Chrome 逐幀截圖並編碼成 MP4。因為影片變成了「程式碼」，Claude Code 就能像改一般前端元件一樣改影片。

他想強調的是模型能力的落差：一年前同樣的作品需要人類不斷指出細節錯誤（時間點偏移、元素位置、動畫節奏），像是在帶一個新人；而以現在的 Opus 5.5 / Fable 5.1 等級，多數細節可以一次到位或只需少量回饋。換句話說，「用程式產生影片」這條路的瓶頸，已經從模型理解力轉移到你怎麼描述想要的畫面。

**前端工程師實際應用：**
- **跟你工作的關聯：** Remotion 就是 React + CSS + 時間軸，前端工程師的既有技能可以直接轉移到產品 demo 影片、release note 動畫、社群宣傳素材，不必另外學 After Effects。
- **具體場景：** 每次發版要做一支 30 秒功能介紹影片：用 `npx create-video@latest` 建專案，把實際 UI 元件（例如你的 Button、Modal）直接 import 進 Remotion composition，讓 Claude Code 依 changelog 產生逐段動畫，再用 `npx remotion render` 輸出 MP4，甚至接進 CI 自動產生。
- **這週可以嘗試：** 開一個 Remotion 範本專案，請 Claude Code「做一支 10 秒影片，展示我們 dashboard 卡片依序淡入、數字從 0 跳到目標值」，觀察它一次產出的正確率，記下需要你修正的細節，當作評估現在模型做動畫能力的基準。
