**繁中改寫：**
我幾乎每天都會跟其他公司的工程師聊天，聽到的都是同一件事：團隊裡總有一個人靠 Claude 把產出衝到 10 倍，但團隊其他人還沒跟上。

觀察各團隊採用 AI 的過程，我一直看到同樣的 4 個階段，整理成一篇文章：《Steps of AI Adoption》。

這幾個階段沒有標準答案，每個團隊、每間公司都不一樣。但在每個階段裡，光靠丟 tokens 進去是不夠的：要往下一階段推進，你得先找出並拆解下一批瓶頸，再建立下一層的防護機制（guardrails）。

實際上這代表要讓 Claude 有辦法端到端驗證自己的工作成果。具體來說包括：開啟權限的 auto mode、預設啟用自動化 code review 與 security review，以及使用能一次管理多個 agent 的介面（CLI 裡的 Agent view、桌面版 App、iOS/Android App、Tag）。

要往更高階段邁進，則要用上 /loop、/batch、動態 workflow，以及讓 subagent 使用 worktree 隔離。重點不是單一個功能，而是搭配對的功能與對的防護機制，讓 Claude 能自動化整類工作，同時讓團隊信得過輸出結果。

等團隊都買單之後，接下來要怎麼追蹤成效？Usage（例如看 dashboard）值得關注，但那只衡量活躍度，不是報酬（return）。更好的問題是：這件事你本來就會花工程資源去做嗎？如果會，要花多少、換算成人力工時的成本是多少？那才是你真正的報酬。

真正的大回報，發生在修 bug 跟維護工作都能在背景自動完成、團隊可以把心力放在真正的開發上的時候。那時候你才會開始做以前根本排不進待辦清單的事。

Anthropic 目前在第 3 階段，正往第 4 階段推進。我個人是剛跨進第 4 階段。很好奇大家的團隊現在在哪個階段？

**核心概念（簡單說）：**
Boris Cherny（Claude Code 團隊）觀察到企業導入 AI 工具普遍會經歷 4 個階段：(1) 個人零星使用、單點 10x 產出但團隊沒跟上；(2) 讓 Claude 具備端到端自我驗證能力（auto mode 權限、自動 code review/security review、多 agent 管理介面）；(3) 用 /loop、/batch、動態 workflow、worktree 隔離等機制擴大自動化範圍，並用「原本要花多少人力工時」而非單純 usage 數據來衡量真正的投資報酬；(4) 修復與維護工作完全在背景自動運作，團隊終於能把心力全部投入「真正在造的東西」，做到過去根本不敢想的事。可以把它想成公司採用 AI 的「成熟度模型」，每往上一階段，需要的不是更多 token，而是更完善的防護機制與信任基礎。

**前端工程師實際應用：**
- **跟你工作的關聯：** 這套 4 階段模型直接對應你在團隊裡導入 Claude Code 的路徑——從自己用得爽，到讓 PR 自動走 code review、security review，再到把重複性高的 bug 修復、小型維護工作丟給背景 agent 處理。
- **具體場景：** 假設前端專案常有一堆「小改動但很花時間」的維護工作（升級 dependency、修 lint warning、補 test coverage），與其自己一個個做，可以設定自動化的 code review + security review 流程，並用 /loop 或 worktree 隔離讓多個 agent 並行處理，同時開著 Agent view 掌握進度。
- **這週可以嘗試：** 挑一項本來就會安排時間做的維護型工作（例如清一輪 ESLint warning），先手動估算「如果自己做要花幾小時」，再讓 Claude Code 自動化跑一次，實際比較時間差，用這個數字說服團隊往「第 3 階段」推進。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.212 / July 17, 2026

**變更項目：**
- `/fork` now copies your conversation into a new background session (its own row in `claude agents`) while you keep working; the in-session subagent it used to launch is now `/subtask` — `/fork` 現在會把對話複製成一個新的背景 session（在 `claude agents` 裡有自己的一行），你可以繼續原本的工作；原本用來啟動的 in-session subagent 改名為 `/subtask`。
- Added `claude auto-mode reset` to restore default auto-mode configuration, with a confirmation prompt (`--yes` to skip) — 新增 `claude auto-mode reset` 指令可一鍵還原 auto-mode 預設設定。
- Added a session-wide limit on WebSearch tool calls (default 200, `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION`) to stop runaway search loops — 新增整個 session 的 WebSearch 呼叫上限，避免搜尋迴圈失控。
- Added a per-session cap on subagent spawns (default 200, `CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION`); `/clear` resets the budget — 新增每個 session 的 subagent 產生上限，避免委派迴圈失控，`/clear` 會重置額度。
- MCP tool calls running longer than 2 minutes now move to background automatically (`CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS` to configure) — 執行超過 2 分鐘的 MCP tool call 會自動轉背景執行，session 才不會卡住。
- Typing `/resume` in the agent view now opens a picker of past sessions (including deleted ones) and resumes as a background session — Agent view 裡打 `/resume` 現在會列出所有歷史 session（含已刪除的），選取後以背景 session 恢復。
- Fixed plan mode auto-running file-modifying Bash commands (e.g. `touch`, `rm`) without a permission prompt — 修正 plan mode 下會未經授權就自動執行 `touch`、`rm` 等會修改檔案的 Bash 指令的問題。
- Fixed worktree creation following a repository-committed symlink at `.claude/worktrees`, which could create files outside the repository — 修正 worktree 建立時會跟隨 repo 內提交的 symlink、導致在 repo 外建立檔案的問題。
- Fixed a `continue:false` hook's halt being dropped when the tool fails or completes mid-stream — 修正 hook 回傳 `continue:false` 時，若工具中途失敗或完成，中止指令會被吃掉的問題。
- Fixed SIGTERM during a running Bash tool orphaning the process tree in print/SDK mode; CLI now aborts, kills the tree, exits 143 — 修正 print/SDK 模式下 Bash 工具執行中收到 SIGTERM 會留下孤兒行程樹的問題。
- Fixed `/background` and `claude --bg` failing with "EUNKNOWN" on Windows when Group Policy blocks PowerShell 5.1; daemon now prefers PowerShell 7 — 修正 Windows 上 Group Policy 擋掉 PowerShell 5.1 時背景模式會失敗的問題，daemon 現在優先用 PowerShell 7。
- Fixed shell mode (`!`) not executing commands containing file paths while the path autocomplete popup was open — 修正 shell mode 下路徑自動完成彈窗開著時，含檔案路徑的指令無法執行的問題。
- Fixed auto-mode denial notifications rendering broken characters when a long denial reason was truncated mid-emoji — 修正 auto-mode 拒絕通知的理由過長、在 emoji 中間被截斷導致亂碼的問題。
- Fixed Ctrl+J not inserting a newline in the agent view dispatch input on terminals with extended key reporting; shortcut now shown in `?` help — 修正部分終端機下 Ctrl+J 無法在 agent view 輸入框換行的問題，並在說明選單標示此快捷鍵。
- Fixed `/ultrareview` rejecting PR references like `#123`、`PR 123`、pasted PR URLs — 修正 `/ultrareview` 無法辨識多種 PR 參照格式的問題。
- Fixed `/ultrareview <branch>` not fetching the branch from origin when it exists remotely; now suggests closest branch name on typos — 修正指定遠端分支時不會自動 fetch 的問題，打錯分支名稱時會提示最接近的名稱。
- Fixed `/ultrareview` skipping the billing confirmation in a new conversation after `/clear` — 修正 `/clear` 後開新對話執行 `/ultrareview` 會跳過計費確認的問題。
- Fixed `/ultrareview`'s "not a git repository" error on Claude Desktop now suggesting the project's repository folder — 修正 Claude Desktop 上該錯誤訊息未提示正確的 repo 資料夾。
- Fixed hosted sessions failing at startup when repository settings configured mTLS certs, extra CA bundles, or OAuth scopes; these are now ignored with a warning — 修正代管 session 因 repo 設定了 mTLS 憑證等傳輸設定而啟動失敗的問題，現在會忽略並顯示警告。

**核心概念（簡單說）：**
這個版本以穩定性與可控性為主軸：一是把「失控風險」收緊，新增 WebSearch 呼叫上限、subagent 產生上限、MCP 工具逾時自動轉背景，避免 agent 在無人監督下無限迴圈燒 token；二是修了一大批跟背景 session、worktree、hook、`/ultrareview`、Windows 平台相關的邊角案例 bug；三是把 `/fork` 從「應急用的內部 subagent」升級成「一個有自己身分、能在背景繼續跑的獨立 session」，並新增更完整的 session 恢復、`/resume` 選單體驗。整體方向是讓多 agent、背景執行的工作流更可靠、更不容易失控。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你已經在用 Claude Code 跑背景 agent、worktree 隔離或 `/loop` 之類的自動化流程，這次的上限與逾時修正直接影響你的 session 會不會失控燒掉 usage 額度，或卡在半死不活的狀態。
- **具體場景：** 假設你在前端專案裡開了多個 worktree 讓不同 agent 平行修 bug，之前可能遇過 MCP tool call 卡住整個 session 沒反應，或 subagent 一路瘋狂往下委派；現在這些都有預設上限與自動轉背景機制保護，出問題時也能透過 `/resume` 選單直接挑回歷史 session 復原進度。
- **這週可以嘗試：** 升級到 2.1.212 後，試著用 `/fork` 把目前手上的對話複製成背景 session，自己繼續原本工作、讓複製出來的 session 在背景跑一個獨立任務（例如清 lint warning），感受一下新的背景多工體驗跟舊版 in-session subagent 有何不同。
