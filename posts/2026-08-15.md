## claudeai · Anthropic Blog

**原文網址：** [https://www.anthropic.com/news/claude-text-watermark](https://www.anthropic.com/news/claude-text-watermark)

**原文：**
> How Claude's text watermark works
>
> Future Claude models will generate text that contains a watermark. This is a way of determining the likelihood that Claude was involved in writing the text, and we, along with several other major AI providers, are implementing this change to comply with the EU AI Act.
>
> We use a method of watermarking that does not have any practical impact on the quality or content of Claude's outputs; the difference between watermarked and un-watermarked text will not be distinguishable to readers; nothing is added to the text and there are no hidden characters; watermarking doesn't require extra tokens, and will not be more expensive; watermarking carries no identifying information and can't be traced to a specific person, organization, or chat.

**繁中改寫：**
Anthropic 公告未來版本的 Claude 會在生成的文字中加入浮水印（watermark），用來判斷一段文字是否由 Claude 生成，這是為了配合歐盟 AI 法案（EU AI Act）而做的合規措施，跟其他主要 AI 廠商一起遵守同一套規範。這個浮水印方法不會影響輸出品質、不會讓文字變得可被肉眼分辨出差異、不會插入任何隱藏字元、不需要額外 token（不會變貴也不會變慢），也不含任何能追溯回特定使用者、組織或對話的識別資訊。

**核心概念（簡單說）：**
LLM 每次生成下一個字時，其實是從一堆候選字裡挑一個機率高的，遇到「怎麼選都差不多」的情況（例如 overcast 還是 grey）時，原本是用隨機亂數決定；浮水印的做法是把「決定隨機性的來源」換成一把只有 Anthropic 有的密鑰（key），這樣文字讀起來完全一樣，但事後可以用密鑰檢查這段文字的用字選擇模式，跟 Claude 用這把 key 會做出的選擇是否一致，藉此算出「這段文字有多大機率是 Claude 生成的」。這種技術叫 SynthID-Text（Google DeepMind 發表），特點是對事實性強、答案唯一的內容（例如數學計算、程式碼）幾乎不留痕跡，因為那些地方本來就沒有「隨便選都可以」的空間；相對地，敘述性、開放性的文字浮水印訊號會比較強。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的產品有整合 Claude API 生成使用者可見的文字內容（例如客服回覆、文案、部落格草稿），未來這些輸出都會帶有浮水印，之後若有偵測 API 上線，你可以拿來做內容溯源或合規稽核。
- **具體場景：** 假設你在做一個內容平台，需要標示哪些文章是 AI 協助生成的（例如遵循 EU AI Act 的揭露義務），未來可以呼叫 Anthropic 即將推出的浮水印偵測 API，自動判斷一篇文章是否由 Claude 生成或大幅編輯過，取代目前土法煉鋼靠人工判斷或用第三方 AI 偵測工具的做法。
- **這週可以嘗試：** 若你的產品有 EU 使用者且用到 Claude 生成文字，先盤點一下目前有沒有標示 AI 生成內容的機制，並留意 Anthropic 之後釋出的浮水印偵測 API 文件，評估要不要接進你的內容審核流程。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.233 / 2026年8月14日

**變更項目：**
- Added GitLab merge request URL support to the `--worktree` flag and the `claude agents` view (where MRs display as `!N`)（`--worktree` flag 與 `claude agents` 畫面新增 GitLab merge request URL 支援，MR 會顯示成 `!N`）
- Added an opt-in `forward_user_identity` apps gateway setting on Anthropic upstreams that sends the signed-in user's identity as headers, so a proxy behind the gateway can attribute spend per user（新增可選的 `forward_user_identity` apps gateway 設定，會把登入使用者的身分以 header 方式傳遞，讓 gateway 後面的 proxy 能依使用者歸戶花費）
- Added opt-in memory cgroup support for Bash tool commands on Linux (`CLAUDE_CODE_TOOL_MEMORY_LIMIT`) so a runaway build can't stall the session（Linux 上 Bash tool 指令新增可選的 memory cgroup 限制 `CLAUDE_CODE_TOOL_MEMORY_LIMIT`，避免失控的 build 卡住整個 session）
- Added `CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS` environment variable to configure the WebFetch session URL cache TTL (default unchanged: 15 minutes)（新增環境變數 `CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS` 可調整 WebFetch session 的 URL 快取存活時間，預設仍為 15 分鐘）
- Fixed cloud sessions occasionally being marked as lost when the environment shut down while Claude was waiting on a permission prompt（修正雲端 session 在環境關閉、Claude 正等待權限確認時，偶爾被誤判為 lost 的問題）
- Fixed MCP v2 connections endlessly reopening the subscriptions/listen stream against servers that terminate long-held streams on a fixed timeout (e.g. serverless hosts)（修正 MCP v2 連線對「會用固定 timeout 中斷長連線」的伺服器（例如 serverless host）不斷重開 subscriptions/listen stream 的問題）
- Fixed Notification hooks not firing for permission prompts when running under Claude Desktop or VS Code（修正在 Claude Desktop 或 VS Code 底下執行時，Notification hooks 不會針對權限確認提示觸發的問題）
- Fixed idle sessions on Linux sometimes keeping one CPU core at 100% when sandboxing is enabled（修正 Linux 上開啟 sandboxing 時，閒置 session 偶爾讓一顆 CPU core 卡在 100% 的問題）
- Fixed bundled skill aliases like `/checkup` and `/review` reporting "Unknown command" in `-p` mode or with plugins/MCP loaded when a user or project skill shadows the bundled skill（修正當使用者或專案 skill 蓋掉內建 skill 名稱時，`/checkup`、`/review` 等內建 skill 別名在 `-p` 模式或載入 plugins/MCP 時回報「Unknown command」的問題）
- Fixed skill/command argument substitution to prevent argument values from being re-expanded as template markers（修正 skill／command 的參數代入邏輯，避免參數值被誤當成 template 標記再展開一次）
- Fixed Windows paths spelled with the NT `\??\` device prefix bypassing UNC path validation, closing an NTLM credential-leak vector（修正 Windows 上用 NT `\??\` 裝置前綴寫法的路徑會繞過 UNC 路徑驗證的問題，封堵一個 NTLM 憑證外洩管道）
- Improved `claude self-hosted-runner` session start time: the session branch is now created without rewriting the working tree, and two server round trips no longer block the agent's launch（改善 `claude self-hosted-runner` 的 session 啟動速度：建立 session branch 時不再重寫 working tree，也不再讓兩次伺服器來回請求卡住 agent 啟動）
- Improved apps gateway error forwarding: 400/413 errors from Vertex, Foundry, and Claude Platform on AWS upstreams now carry the upstream's own message; fixes a bug with auto-compact on apps gateway（改善 apps gateway 的錯誤轉發：來自 Vertex、Foundry、AWS 上 Claude Platform 的 400/413 錯誤現在會帶原始訊息，並修正 apps gateway 上 auto-compact 的一個 bug）
- Improved `claude plugin validate` to check a bare `.claude/skills` directory, reporting SKILL.md files whose frontmatter fails to parse（改善 `claude plugin validate`，會檢查沒有 plugin 外殼的 `.claude/skills` 目錄，回報 frontmatter 解析失敗的 SKILL.md 檔案）
- Improved screen reader mode: the `/effort` selector renders as a numbered list with a typed-number prompt, and hint and dialog text is no longer clipped（改善螢幕報讀模式：`/effort` 選單改成有編號的清單並可輸入數字選擇，提示與對話框文字也不再被裁切）
- Improved print mode diagnostics: a `[claude-code:unrecognized_model]` line is written to stderr when a request goes out for a model ID Claude Code doesn't recognize; map it with `modelOverrides` to silence（改善 print 模式的診斷資訊：當請求使用 Claude Code 不認得的 model ID 時，會在 stderr 印出 `[claude-code:unrecognized_model]`，可用 `modelOverrides` 對應掉來消音）
- Changed the GitHub app setup tip to no longer appear in repositories whose origin remote is on gitlab.com or bitbucket.org; the enterprise marketplace tip now covers non-GitHub internal git hosts（GitHub app 設定提示不再出現在 origin remote 是 gitlab.com 或 bitbucket.org 的 repo 裡；企業 marketplace 提示現在也涵蓋非 GitHub 的內部 git host）
- Todo/task-tracking tools (`TaskCreate`/`Get`/`Update`/`List`, `TodoWrite`) are no longer available on Opus 4.8, Sonnet 5, Fable 5, Mythos 5, and newer models; set `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` to bring them back（Opus 4.8、Sonnet 5、Fable 5、Mythos 5 及更新的模型上，`TaskCreate`／`Get`／`Update`／`List`、`TodoWrite` 這些待辦追蹤工具預設不再提供，需要的話可設定環境變數 `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` 恢復）
- Windows: fixed auto mode repeatedly stopping for manual approval on ordinary `cd <dir> && <command> > file` Bash commands (a 2.1.232 regression)（Windows：修正 auto mode 對一般的 `cd <dir> && <command> > file` 這類 Bash 指令會反覆停下來要求手動核准的問題，這是 2.1.232 造成的回歸 bug）

**核心概念（簡單說）：**
這個版本重點是「安全與穩定性補強」加上「工作流細節優化」：一是把 GitLab 支援再擴大到 merge request 顯示與 agents 畫面；二是修了幾個會影響大型/長時間任務的穩定性問題（雲端 session 誤判 lost、MCP v2 對特定伺服器的重連迴圈、Linux CPU 空轉）；三是補了兩個安全性問題（Windows NT 路徑繞過驗證、Bash 指令 memory 限制避免失控 build 拖垮系統）；最值得前端工程師注意的是「Todo/task-tracking 工具在新模型上預設關閉」，這是一個會直接影響到有使用 TaskCreate/TodoWrite 流程的行為變更。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的專案或個人 workflow 有依賴 Claude Code 的待辦追蹤工具（`TaskCreate`、`TodoWrite` 等）來管理多步驟任務，升級到這個版本後，在 Opus 4.8／Sonnet 5／Fable 5／Mythos 5 等模型上這些工具會預設消失，行為可能會突然不一樣。
- **具體場景：** 你平常習慣看 Claude Code 自動列出 todo list 來追蹤重構任務的進度，升級後發現它不再自動產生 todo，這時就是踩到這個變更；只要在環境變數設定 `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` 就能恢復原本行為。
- **這週可以嘗試：** 檢查一下你目前用的模型是否在受影響清單內（Opus 4.8、Sonnet 5、Fable 5、Mythos 5 或更新），如果你的 workflow 依賴待辦追蹤功能，先在 `.bashrc`／`.zshrc` 或專案的環境設定裡加上 `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`，避免升級後流程被打斷。
