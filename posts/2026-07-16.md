> Boris Cherny reposted ClaudeDevs (@ClaudeDevs)

> Claude Code artifacts can now call MCP connectors, letting you build dashboards and apps that can fetch information and take actions for each viewer on demand.
>
> Available on Pro, Max, Team, and Enterprise plans. Not available on publicly-shared artifacts.

**繁中改寫：**
Claude Code 的 artifacts 現在可以呼叫 MCP connectors 了，讓你能打造真正動態的 dashboard 或應用程式——針對每個瀏覽的使用者即時抓資料、執行動作。目前開放給 Pro、Max、Team、Enterprise 方案使用，但公開分享的 artifacts 還不支援這個功能。（本則為 boris_cherny 轉發 ClaudeDevs 的貼文）

**核心概念（簡單說）：**
Artifacts 原本是靜態或簡單互動的 HTML/React 頁面，現在透過 MCP（Model Context Protocol）connectors，可以在頁面執行階段呼叫外部服務（例如查資料庫、打 API），並且是「per-viewer」的——每個開啟這個 artifact 的人看到的資料跟能執行的動作，可以根據他自己的權限與帳號狀態而不同，不再是所有人共用同一份寫死的資料。可以把它想成是把一個輕量後端能力直接內嵌進前端產出的頁面裡。

**前端工程師實際應用：**
- **跟你工作的關聯：** 這代表在 Claude Code 裡快速產出的 prototype 或內部工具，可以直接接上真實資料源而不用另外架 API server，縮短了「demo」到「堪用工具」的距離。
- **具體場景：** 想像你要給團隊做一個即時查詢 GitHub Issues 狀態或 Notion 任務清單的小 dashboard，過去得自己寫 Express + fetch API + 部署，現在可以直接讓 artifact 呼叫對應的 MCP connector 拿資料。
- **這週可以嘗試：** 找一個你手上已連接的 MCP connector（例如 GitHub、Notion），試著在 Claude Code 裡請它做一個會即時抓資料的小 dashboard artifact，感受一下跟純靜態 artifact 的差異。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.211 / July 15, 2026

**變更項目：**
- Added `--forward-subagent-text` flag and `CLAUDE_CODE_FORWARD_SUBAGENT_TEXT` environment variable to include subagent text and thinking in stream-json output — 新增旗標與環境變數，可讓 subagent 的文字與思考過程也一併出現在 stream-json 輸出裡。
- Fixed permission previews relayed to chat channels not neutralizing bidirectional-override, zero-width, and look-alike quote characters, so tool inputs cannot visually alter the approval message — 修正聊天頻道的權限預覽訊息未過濾特殊字元的問題，避免工具輸入內容視覺上竄改核准訊息。
- Fixed auto mode overriding a PreToolUse hook's ask decision for unsandboxed Bash — a hook ask now floors the decision at a prompt — 修正 auto 模式會蓋掉 PreToolUse hook 對非沙箱 Bash 下的「詢問」決定，現在 hook 要求詢問時一定會跳出提示。
- Fixed parallel Claude Code sessions all logging out simultaneously after wake-from-sleep when many sessions share one credential store — 修正多個 session 共用同一份憑證時，電腦喚醒後全部一起被登出的問題。
- Fixed plugin MCP servers not reconnecting after an idle web session woke, leaving MCP calls failing until the next message — 修正 web session 閒置喚醒後 plugin 的 MCP server 沒有重新連線的問題。
- Fixed Claude Code on Vertex and Bedrock attempting the default Opus model at startup and printing a spurious fallback notice when a model is explicitly configured — 修正在 Vertex／Bedrock 上已明確指定模型時，啟動仍嘗試預設 Opus 並顯示錯誤 fallback 訊息的問題。
- Fixed subagents spawned with an explicit model override reverting to the parent's model when resumed or sent a follow-up message — 修正指定了模型的 subagent 在被 resume 或收到後續訊息時，會被還原成 parent 的模型。
- Fixed nested `.claude/rules/*.md` files loading even when setting sources exclude project settings — 修正即便設定來源排除了專案設定，巢狀的 `.claude/rules/*.md` 仍會被載入的問題。
- Fixed file upload validation: filenames ending in a DOS device suffix (`.prn`) or trailing dot are now accepted, and files with multiple hard links are refused — 修正檔案上傳驗證：接受以 `.prn` 等 DOS 裝置字尾或句點結尾的檔名，並拒絕有多重硬連結的檔案。
- Fixed file uploads to Claude in Chrome from remote and CLI sessions — 修正從 remote 與 CLI session 上傳檔案到 Claude in Chrome 的問題。
- Fixed edits that leave the input as "?" being silently swallowed and toggling the shortcuts panel — 修正輸入框只剩下「?」的編輯會被靜默吞掉並誤觸捷徑面板的問題。
- Fixed a startup hang when the Claude in Chrome extension is enabled but Chrome is not running — 修正啟用 Claude in Chrome 擴充功能但 Chrome 未開啟時的啟動卡住問題。
- Fixed a 300ms delay revealing async content (Settings tabs, Stats, diff views, and other loading states) — 修正 Settings 分頁、Stats、diff 檢視等非同步內容顯示前的 300ms 延遲。
- Fixed reopening a just-stopped background session from the agents view starting a blank conversation under the same session id — 修正從 agents 視圖重開剛停止的背景 session 會用相同 session id 開出空白對話的問題。
- Fixed `/loop` hiding the session from `/resume` after a single use — 修正 `/loop` 用過一次後該 session 會從 `/resume` 清單消失的問題。
- Fixed screen reader users losing the audible terminal bell after `/terminal-setup` or onboarding terminal setup — 修正螢幕報讀使用者在跑過 `/terminal-setup` 後聽不到終端機提示音的問題。
- Fixed background jobs on LLM gateway auth (`ANTHROPIC_AUTH_TOKEN` + `ANTHROPIC_BASE_URL`) coming back "Not logged in" after the daemon respawns them — 修正使用 LLM gateway 驗證的背景工作在 daemon 重啟後回報「未登入」的問題。
- Fixed `claude agents` jobs becoming permanently undeletable when git no longer recognizes their worktree — the row now shows why the delete was refused instead of silently reappearing — 修正 git 已不認得 worktree 時 `claude agents` 工作無法刪除的問題，現在會顯示刪除被拒的原因。
- Fixed `/clear` not resetting the session cost counter — the statusline's cost now starts at $0 after `/clear` — 修正 `/clear` 沒有重設費用計數器的問題，執行後 statusline 費用會歸零。
- Fixed Claude in Chrome setup pages failing to open in the browser on Windows — 修正 Windows 上 Claude in Chrome 設定頁面無法開啟的問題。
- Fixed headless print-mode sessions on Windows crashing or silently exiting when stdin is unreadable — 修正 Windows 上 headless print 模式在 stdin 不可讀時當機或靜默結束的問題。
- Fixed background session titles in the agents view showing the naming model's refusal text when the prompt contains a link — 修正 prompt 含連結時，agents 視圖的背景 session 標題會顯示命名模型的拒絕回應文字。
- Fixed background agents killed by the user auto-respawning, and revived agents re-running stale prompts from old sessions — 修正使用者手動終止的背景 agent 會自動重啟、且復活後會重跑舊 session 過期 prompt 的問題。
- Fixed routines with no schedule reporting a next run time in the year 1 — 修正沒有排程的 routine 會回報下次執行時間是西元 1 年的問題。
- Hardened synced skill/plugin directory naming on Windows and kept CCR web fetch/search proxies working after `/clear` — 強化 Windows 上同步 skill/plugin 目錄命名的穩健性，並確保 `/clear` 後 CCR 的 web fetch/search proxy 仍正常運作。
- Improved terminal layout and rendering performance — 改善終端機版面配置與渲染效能。
- Improved background agent result reporting — Claude now reports the status of still-running agents and waits for the real completion instead of fabricating results — 改善背景 agent 結果回報，Claude 現在會如實回報仍在執行中的狀態，並等待真正完成而非捏造結果。
- Improved the memory index over-limit warning to measure only loaded content, excluding frontmatter and HTML comments — 改善 memory 索引超量警告，只計算實際載入的內容，排除 frontmatter 與 HTML 註解。
- Updated integer environment variables (timeouts, token budgets, retry counts) to accept scientific notation and digit-separator spellings like `1e6` and `64_000` — 整數型環境變數（timeout、token 預算、重試次數）現在支援科學記號與數字分隔符寫法，如 `1e6`、`64_000`。
- Updated documentation links to the current docs sites — 更新文件連結指向目前的文件網站。
- Changed "always allow" permission rules to save at the repository root, so approvals granted in a git worktree persist across sessions and worktrees — 將「always allow」權限規則改存在 repository 根目錄，讓在 git worktree 中核准的規則能跨 session 與 worktree 持續生效。
- Changed `/usage-credits` to ask for confirmation before sending a request to organization admins — `/usage-credits` 在送出請求給組織管理員前，現在會先詢問確認。
- Changed Vim mode `s` and `S`（substitute char/line）to work in NORMAL mode, matching vim behavior — 修正 Vim 模式下 `s`／`S`（替換字元／整行）在 NORMAL 模式下的行為，改為符合 vim 原生行為。
- [VSCode] Updated the Remote Control banner to describe what it does — [VSCode] 更新 Remote Control 橫幅說明文字，讓功能說明更清楚。
- Claude in Chrome: hardened file-upload path validation — Claude in Chrome：強化檔案上傳路徑驗證的安全性。
- Claude in Chrome: `save_to_disk` on screenshot actions now writes the image to disk and returns the path; previously it did nothing — Claude in Chrome：截圖動作的 `save_to_disk` 現在真的會把圖片寫入硬碟並回傳路徑，先前完全沒作用。
- Fixed a prompt-caching regression on Bedrock, Vertex, Mantle, and Foundry that billed the trailing system context block as fresh input tokens on every request — 修正 Bedrock、Vertex、Mantle、Foundry 上的 prompt caching 退化問題，先前每次請求都會把結尾的 system context block 當成全新 input token 計費。

**核心概念（簡單說）：**
這次 2.1.211 是一次修 bug 為主、順帶幾個小功能的版本更新，重點集中在三塊：session／daemon 生命週期的穩定性（登出、重連、resume、背景 agent 狀態回報都更可靠）、安全性強化（權限預覽訊息防止特殊字元竄改、檔案上傳路徑驗證），以及跨 worktree 的權限規則持久化（"always allow" 改存在 repo 根目錄）。另外修掉了一個會讓 Bedrock/Vertex 等平台每次都重複計費 prompt cache 的問題，這個對常態使用 Claude Code 的團隊來說是實際會反映在帳單上的修正。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你有用 git worktree 做隔離開發（例如同時跑多個 feature branch 的 Claude Code session），"always allow" 規則現在能跨 worktree 共用，不用每個 worktree 都重新核准一次相同的權限。
- **具體場景：** 你在 `main` worktree 核准過 `Bash(npm test:*)` 這類規則後，切到用 `git worktree add` 開的 feature branch 目錄再跑 Claude Code，同樣的規則已經生效，不會被重複詢問。
- **這週可以嘗試：** 如果你的團隊常用 Vertex/Bedrock 跑 Claude Code，可以順手升級到 2.1.211，確認一下 usage/帳單是否因為修掉的 prompt-caching 重複計費問題而有變化；同時也可以試試新的 `--forward-subagent-text`，在需要細看 subagent 決策過程時很有用。
