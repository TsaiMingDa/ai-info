**繁中改寫：**
我們看到有幾位客戶正遭到詐騙性請求鎖定，很高興看到 Stripe 在協助他們方面做了不少努力。這類攻擊還有很多要處理的地方，因為它們會傷害到所有合法使用者取得服務的能力。

**核心概念（簡單說）：**
這則貼文談的是 API／計費濫用防護的議題。當一個有金流或計費機制的服務被拿來做詐騙性請求（例如盜刷測試、洗錢相關的自動化操作）時，會消耗系統資源、觸發風控機制，最終可能拖累合法使用者的服務品質，甚至誤傷正常帳號。Stripe 作為支付基礎設施商，在背後協助偵測與阻擋這類異常交易模式——這反映出任何有金流的 API 產品，都需要跟支付／風控服務商緊密協作打詐騙。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的產品串接 Stripe 或其他金流服務做訂閱制計費，前端會直接碰到因風控機制被擋下的付款請求，需要設計對應的錯誤處理與使用者提示文案。
- **具體場景：** 例如做一個 SaaS 訂閱頁面，串 Stripe Checkout 或 Payment Intents API，遇到詐騙偵測擋下交易時，Stripe 會回傳特定的 decline_code（如 fraudulent），前端要能辨識並顯示對使用者友善的錯誤訊息，而不是直接丟出原始錯誤碼。
- **這週可以嘗試：** 翻一下 Stripe 官方文件的 Radar（詐騙偵測工具）與 decline codes 列表，確認手上的付款流程有沒有妥善處理各種拒絕情境的 UI 呈現。

**原文網址：** [https://x.com/claudeai/status/2092755571455758427](https://x.com/claudeai/status/2092755571455758427)

**原文：**
> Claude now has its own built-in browser in Cowork.
>
> When your task involves a website, a browser opens in Cowork's side panel, and Claude navigates, fills forms, and finishes the job.
>
> There's nothing to install. Claude's browser is built into the desktop app and stays separate from your own browser and logins.
>
> Rolling out over the next week on the desktop app for all paid plans:

**繁中改寫：**
Claude 現在在 Cowork 裡有了內建瀏覽器。當任務牽涉到某個網站時，瀏覽器會直接在 Cowork 的側邊面板開啟，Claude 會自己導覽網頁、填表單，把工作完成。完全不需要額外安裝——Claude 的瀏覽器內建在桌面版 App 裡，而且會跟你自己平常用的瀏覽器與登入狀態完全分開。這項功能將在接下來一週內，陸續開放給所有付費方案的桌面版使用者。

**核心概念（簡單說）：**
這是 Claude Cowork（Anthropic 的 agentic 工作平台）新增的「內建瀏覽器」能力。過去要讓 Claude 操作網頁（例如登入某個後台、填寫表單、爬取資料），得靠 MCP 串接第三方瀏覽器自動化工具（像 Playwright），或透過瀏覽器擴充套件跟使用者自己的 Chrome 互動。現在 Cowork 直接內建一個獨立、沙盒化（跟使用者自己的瀏覽器／登入狀態隔離）的瀏覽器實例，讓 agent 能自主完成「開網頁 → 找元素 → 填表單 → 按送出」整套流程，並在側邊面板視覺化呈現，讓使用者即時看到 Claude 在做什麼。這跟每天跑這份 digest routine 所用的 chrome-devtools MCP 概念很類似，只是 Anthropic 把它做成 Cowork 產品原生的第一方能力。

**前端工程師實際應用：**
- **跟你工作的關聯：** 這代表 agentic 工具會愈來愈常需要「操作瀏覽器」這個能力，而且會朝沙盒化、視覺化、跟使用者自己瀏覽器隔離的方向設計，跟你若有在用 Claude Code／MCP 做瀏覽器自動化任務是同一條技術路線的延伸。
- **具體場景：** 假如要做一個內部自動化流程，例如「每天檢查某個第三方後台的報表數字並整理成 Slack 訊息」，過去可能要自己寫 Playwright script 或找人力手動查，現在可以直接讓 Cowork 開啟該後台網頁、登入、擷取資料、產出報告，整套流程用自然語言描述即可。
- **這週可以嘗試：** 如果有 Claude Cowork 的使用權限，找一個平常要手動上網查資料／填表單的重複性工作，試著描述給 Claude 讓它用內建瀏覽器跑一次，感受它跟自己動手操作有什麼落差。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.247 / August 26, 2026

**變更項目：**
- Added the SendFeedback tool: when something goes wrong in a session, Claude can draft a feedback report for you to review and send from `/feedback` (turn off with the `feedbackDrafts` setting)
  （新增 SendFeedback 工具：session 中出狀況時，Claude 能主動幫你草擬一份 feedback report，你審閱後直接從 `/feedback` 送出，可用 `feedbackDrafts` 設定關閉。）
- Added `/claude-api cost-optimize` to profile an existing project's Claude API spend and work through cost levers (caching, token hygiene, batch, effort, model choice) one measured change at a time
  （新增 `/claude-api cost-optimize`，逐項分析既有專案的 API 花費，並依序檢視 cache、token 使用習慣、batch、effort、模型選擇等成本槓桿，一步步做可量化的優化。）
- Added spinner tip customization (`spinnerTipsOverride` with id/cooldown/priority, `tipsFile`, `label`) and a new tip pointing at auto mode on Bash permission prompts
  （新增等待動畫提示的自訂機制，讓組織可輪播自己的提示訊息；另外新增一則在 Bash 權限提示時導引使用者切換到 auto mode 的提示。）
- Updated the `/claude-api` skill with Admin API coverage (organization members, invites, workspaces, API keys, rate limit reports, workload identity federation, CMEK)
  （`/claude-api` skill 補齊 Admin API 涵蓋範圍，包含組織成員、邀請、workspace、API 金鑰、速率限制報告、workload identity federation、CMEK。）
- Fixed several input/navigation bugs: arrow-key + Enter acting on the wrong row in history search/`/config`/`/mcp`/`/skills`/background tasks/`/model`; Ctrl shortcuts not firing under non-Latin keyboard layouts in kitty-protocol terminals; mouse-report text leaking into the prompt
  （修正一系列輸入與導覽問題：快速方向鍵加 Enter 會誤動作到上一列、kitty-protocol 終端機在非拉丁鍵盤配置下 Ctrl 快捷鍵失靈、滑鼠事件被拆成兩次讀取時文字誤插入輸入框。）
- Fixed several session-reliability bugs: sub-agents dying on a first-call model 404 now use the fallback model chain; huge hook/background-agent error output can no longer wedge the session; a background session stuck on "opening…" now fails fast with Enter to restart; cloud sessions reconnecting after a container restart now report lost work
  （修正多項 session 穩定性問題：subagent 第一次呼叫模型就 404 時會改用備援模型鏈、hook 或背景 agent 印出巨量錯誤訊息不會再卡死 session、背景 session 卡在「opening…」現在會快速失敗並可按 Enter 重啟、雲端 session 容器重啟後恢復連線會回報遺失的工作進度。）
- Fixed sandbox/config edge cases: Bash sandbox cleanup no longer deletes a dotfile-managed `~/.claude/settings.json` symlink; `/terminal-setup` no longer overwrites your whole Zed `keymap.json`; version-less marketplace plugin cache no longer gets wiped mid-session on a second install
  （修正沙盒與設定相關的邊界情況：Bash sandbox 清理不再誤刪由 dotfile 工具管理的 `settings.json` symlink、`/terminal-setup` 改成合併寫入而非整個覆蓋 Zed 的 `keymap.json`、沒有版本號的 marketplace 外掛快取不會在第二次安裝時被清空影響正在執行的 session。）
- Changed Sonnet 5's default auto-compact window to its full 1M context (auto-compacts around 967K tokens instead of ~934K); changed cross-session peer messages to collapse to a one-line preview (Ctrl+O expands); changed several markdown/link rendering safety rules
  （Sonnet 5 的自動壓縮視窗改成完整 1M context，觸發壓縮的門檻從約 934K token 提高到約 967K；跨 session 的訊息通知改成預設收合成一行預覽，按 Ctrl+O 展開全文；同時收緊了 markdown 連結渲染的幾項安全規則，避免惡意路徑或隱藏字元偽裝成正常連結。）
- Improved enterprise-auth and telemetry paths: Bedrock/Vertex/Foundry sessions now surface MCP connection failures instead of Claude assuming the tools don't exist; analytics stays off from startup (not just after login) under managed gateway/OAuth deployments; organization sign-in enforcement now exits early if managed settings can't be read
  （改善企業驗證與遙測相關路徑：Bedrock／Vertex／Foundry session 現在會把 MCP 連線失敗的原因回報給 Claude，而不是讓它誤判工具不存在；在強制走 gateway 或自訂 OAuth 的組織部署下，分析追蹤從啟動就保持關閉；組織登入強制機制若讀不到管理設定會提早結束，避免用到不完整的規則。）

**核心概念（簡單說）：**
這個版本最顯眼的新功能是 SendFeedback 工具（也就是 trq212 那則貼文提到的改動），把「回報問題」從使用者手動打字，變成 Claude 主動草擬、使用者審核送出。其餘更新集中在兩大主軸：一是 session 穩定性（subagent 容錯、背景 session 復原、雲端 session 斷線恢復），二是企業／大規模部署場景的安全與可觀測性細節（sandbox 清理不誤刪使用者檔案、MCP 連線失敗要讓模型知道原因、遙測與登入規則在各種 managed 設定下的邊界情況）。整體方向是讓長時間執行與跨團隊使用的 Claude Code 更可靠、更透明。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你平常在用 Claude Code 開發，SendFeedback 工具直接改變了你回報 bug 或體驗問題的方式；如果你的環境用 MCP 串接內部工具，這次針對 MCP 連線失敗回報原因的改善，也會讓你更快抓到到底是網路問題還是設定問題。
- **具體場景：** 假設你在用 Claude Code 搭配自己寫的 MCP server（例如串內部 API），過去如果連線失敗，Claude 可能會誤以為工具根本不存在而跳過不用；更新後 Claude 會被明確告知「連線失敗」，可以直接跟你反映或重試，而不是默默放棄某個功能。
- **這週可以嘗試：** 更新到 2.1.247 後，找一次覺得 Claude Code 表現不如預期的時刻，直接讓它用新的 SendFeedback 流程幫你草擬並送出回饋，順便留意一下你手邊有沒有 dotfile 工具（如 stow、home-manager）管理 `~/.claude/settings.json`，確認這次的 sandbox 修正有沒有解決你之前遇到的 symlink 被誤刪問題。
