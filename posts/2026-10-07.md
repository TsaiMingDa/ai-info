> I am surprised that people are surprised this is how I prompt Claude.
>
> Talk to Claude the way you would a coworker. There's no secret to prompting. There's no need to be overly scaffolded or prescriptive for most tasks -- give Claude a goal, and it will figure it out.
>
> Back in the Sonnet 3.5 days, your prompt mattered a lot. Nowadays, it's much more important to communicate to the model:

> 1. What you want it to do
> 2. How much effort you want it to spend
> 3. How it should verify that it did the right thing

**繁中改寫：**
大家看到我平常怎麼對 Claude 下 prompt 就嚇一跳，這反而讓我很意外。

跟 Claude 講話，就像跟同事講話一樣。Prompt 沒有什麼祕訣，大部分任務也不需要搭一堆鷹架、寫得鉅細靡遺——給 Claude 一個目標，它自己會想辦法。

在 Sonnet 3.5 那個年代，prompt 寫得好不好影響很大；現在更重要的是把這三件事講清楚：

1. 你要它做什麼
2. 你希望它花多少力氣（effort）
3. 它該怎麼驗證自己做對了

**核心概念（簡單說）：**
早期模型能力有限，工程師得用大量格式、範例、步驟拆解來「扶著」模型走，prompt engineering 因此像一門玄學。現在的模型推理與規劃能力已經夠強，過度規定的步驟反而可能限制它找到更好的解法。Boris 的重點是把溝通焦點從「怎麼做」轉到「目標、投入程度、驗收標準」三件事——這其實就是你對資深同事派工的方式：講清楚要解決什麼問題、這件事值得花半小時還是一整天、做完要怎麼證明是對的（跑哪個測試、看哪個畫面）。

第三點尤其關鍵：驗證方式等於是給 agent 一個回饋迴路。有了「跑 `pnpm test` 要全綠」或「打開 `/settings` 頁面截圖確認」這種明確的驗收條件，agent 就能自己迭代到正確為止，而不是做完就交差。

**前端工程師實際應用：**
- **跟你工作的關聯：** 你可能花很多時間在寫冗長的 prompt 模板或 CLAUDE.md 規則；其實把目標與驗證方式講清楚，往往比規定每一步更有效。
- **具體場景：** 與其寫「先打開 `Button.tsx`，再加一個 `loading` prop，再改 CSS……」，不如寫「讓所有送出按鈕在 API 請求期間顯示 loading 並 disable；改完跑 `pnpm vitest Button` 並在 Storybook 截圖確認三種狀態」，讓 Claude 自己決定要改哪些檔案。
- **這週可以嘗試：** 挑一個這週的任務，用「做什麼 / 花多少力氣（例如用 `/effort` 調整）/ 怎麼驗證」三段式寫 prompt，跟你平常的寫法比較結果與來回修正的次數。

**繁中改寫：**
我們會越來越往這個方向走：Claude 的「大腦」放在雲端，再給它一雙「在地的手」，讓它能操作你的電腦。我在 Latent Space 的訪談裡有聊到這件事。

這裡面有些棘手的技術問題還要解決！例如：如果 Claude 只能在你電腦開著的時候存取你的檔案，那電腦一關機，它的工作可能就整個卡住；所以也許需要某種同步機制，但同步又會帶來一堆 edge case。

**核心概念（簡單說）：**
「Local hands」是一種把運算和執行拆開的架構：模型推理、session 狀態、長時間任務跑在雲端（不怕你闔上筆電），而真正讀寫檔案、跑指令則透過一個本機端的代理程式回到你的電腦執行。好處是 agent 可以 24 小時持續工作，又能碰到你本機的專案與工具。

難點就像分散式系統的經典問題：本機離線時雲端怎麼辦？如果把檔案同步到雲端，就會遇到衝突合併、同步延遲、哪一邊才是 source of truth 的問題——跟你做 offline-first 前端（例如 IndexedDB + 背景同步）時遇到的挑戰幾乎一樣。

**前端工程師實際應用：**
- **跟你工作的關聯：** 未來你的 Claude Code session 可能在雲端跑、在本機改檔，理解這個模型能幫你判斷什麼任務適合丟給雲端長跑、什麼要等你本機在線。
- **具體場景：** 下班前請雲端 session 跑一個大型 dependency 升級（例如 React 19 → 下一版的 codemod），它在雲端規劃與驗證，透過 local hands 在你的 repo 改檔；如果你闔上筆電，就要考慮它會不會卡在中途。
- **這週可以嘗試：** 去聽 Latent Space 這集訪談（latent.space/p/thariq），並試用 Claude Code 的 Remote Control 或 cloud session，觀察哪些步驟在雲端跑、哪些回到本機執行。

**繁中改寫：**
Anthropic 推出擴大版的 Cyber Verification Program（CVP），讓通過審核的資安專業人員可以使用進階資安能力、並降低分類器的阻擋。計畫分成三個存取層級，各層級都能使用 Claude Opus 5.5、Sonnet 5.5、Mythos 5.1 及之後的新模型。

資安本質上是「雙面刃」：能幫防守方找漏洞、修漏洞的能力，同樣能幫攻擊者利用漏洞。所以一般公開的模型（Opus 5.5、Fable 5.1、Sonnet 5.5）對資安工作設了保守的防護，會擋掉大部分相關請求。過去半年，Anthropic 透過 Project Glasswing 與 CVP 兩個計畫開放可信任的存取，現在把兩者整合成一個更大的方案：

- **Defense Access（防禦層）：** SOC 與事件應變、惡意程式逆向、漏洞分析與驗證。企業資安團隊、關鍵基礎設施營運者、小型資安公司、**開源維護者**、有回報漏洞紀錄的個人研究員都可申請，目標幾天內回覆。
- **Red Team Access（紅隊層）：** 在防禦用途之外，加上經授權的滲透測試與紅隊演練；僅限組織申請，審核需數週，期間先給 Defense Access。
- **Specialized Access（特殊層）：** 阻擋最少，限少數經驗證、被授權測試航空、電網、電信、銀行間轉帳等高風險系統的組織，與美國政府共同審核。

一般模型仍可用於 code review、修補已知問題、在自己的原始碼裡找漏洞、資安告警分流。實測方面，在 CyScenarioBench 上，未加入 CVP 的任務第一個 prompt 就全被擋；Defense 層 50 次中有 46 次被擋；Red Team 層完全不擋，Opus 5.5 完成 34/50。Project Glasswing 的合作夥伴在 2026 年 4～7 月間找到至少 12.9 萬個經驗證的漏洞，其中超過 3.3 萬個為高風險或嚴重等級。CVP 可在 Claude Platform、Vertex AI、Microsoft Foundry 使用。

**核心概念（簡單說）：**
這是一套「分級授權」的設計：同一個模型，依使用者的身分驗證與用途，套用不同強度的安全分類器。可以把它想成 RBAC（role-based access control）套在模型能力上——一般使用者只有 read 權限，經驗證的資安團隊拿到 write 權限，最高權限則需要政府層級的背景審核。Anthropic 用 benchmark 證明分級有效：防禦層在攻擊型情境下幾乎全擋，紅隊層則幾乎等同無防護的完整能力。

對一般開發者來說，最直接的訊息有兩點：一、日常的 code review、修補已知漏洞、掃描自家程式碼本來就能用一般模型做；二、如果你是開源專案維護者，現在可以申請 Defense Access，拿到更強的漏洞分析能力。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端的 XSS、CSRF、供應鏈套件漏洞（npm 依賴）都屬於「掃描自家程式碼」的範圍，一般模型就能協助；若你維護開源前端套件，則可申請 Defense Access 做更深入的漏洞驗證。
- **具體場景：** 在 Next.js 專案中請 Claude Code 跑 `/security-review`，檢查所有 `dangerouslySetInnerHTML`、未驗證的 `searchParams` 使用、以及 API route 的權限檢查，並針對每個發現寫出重現步驟與修補 PR。
- **這週可以嘗試：** 對手上專案跑一次 `/security-review` 加上 `npm audit`，把結果交給 Claude 做分流與排序；如果你維護開源套件，順手看看 CVP 申請頁面的 Defense Access 資格。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.292 / October 6, 2026

**變更項目：**
- Added `--marketplace <source>` to `claude plugin install`: adds the marketplace if needed, under the same policy checks as `claude plugin marketplace add`, then installs the plugin from it（`claude plugin install` 新增 `--marketplace`，一行指令就能加入 marketplace 並安裝 plugin）
- Added an effort parameter to the Agent tool, so Claude runs a sub-agent at the effort level you ask for（Agent tool 新增 effort 參數，可指定 sub-agent 的思考投入程度）
- Added `CLAUDE_CODE_OVERLOADED_RETRY_BASE_DELAY_MS` environment variable to set a longer base delay for the backoff when retrying an overloaded (529) request（新增環境變數，可拉長遇到 529 overloaded 時的重試退避時間）
- Added `prompt.autocomplete`, an event a mod hooks to add its own rows to the prompt box's autocomplete list（mod 可以在輸入框的自動完成清單加入自訂項目）
- Added prompt caching to `$.model.complete` for mods（mod 呼叫模型時支援 prompt caching）
- Security: Fixed PreToolUse hook approvals and auto mode bypassing the permission prompt for file reads from network (UNC) paths（安全修正：從網路 UNC 路徑讀檔不再能繞過權限確認）
- Fixed `rm -rf` on the 8.3 short name or another alternate Windows spelling of the home folder or a drive not being treated as removing it（Windows 上用 8.3 短檔名等寫法刪除家目錄或磁碟時，現在會被正確辨識為危險操作）
- Fixed `NO_PROXY` being ignored for Claude Code's own API requests when `HTTPS_PROXY` is set（修正設了 `HTTPS_PROXY` 時 `NO_PROXY` 被忽略）
- Fixed an MCP tool with a name longer than 128 characters making every request fail（名稱超過 128 字元的 MCP tool 不再讓所有請求失敗，改為排除並回報錯誤）
- Fixed plan mode not being restored when resuming a session from the `claude --resume` session picker or with `/resume`（resume session 時會正確恢復 plan mode）
- Fixed saved scheduled tasks created after `/resume`, `/branch` or `/clear` never firing（修正這些指令後建立的排程任務不會觸發）
- Fixed a background session's `/loop` silently stopping when the session's process restarted（背景 session 重啟後 `/loop` 不再默默停止）
- Fixed Grep and Glob reporting no matches when the file or folder they were given could not be read（Grep/Glob 讀不到路徑時會重試或明確告知，而不是回報沒有結果）
- Fixed @-mentioned text files over 256KB being left out silently（@ 提及超過 256KB 的檔案時，Claude 會被告知檔案大小並分段讀取）
- Fixed vim mode leaving the cursor past the end of a line, j/k losing their column on shorter lines, and f/t/F/T/;/, jumping across lines（vim 模式多項游標行為修正）
- Improved startup of `claude -p` and SDK sessions: the first turn no longer waits for HTTP and SSE MCP servers to answer `resources/list`（`claude -p` 與 SDK 首輪不再等待遠端 MCP server 回應，啟動更快）
- Improved rendering speed of long bulleted or numbered replies（長條列回覆的渲染速度大幅提升）
- Improved Ctrl+C draft recovery: a cleared prompt now stays reachable with Up after a slash command or a sent message（Ctrl+C 清掉的草稿可用方向鍵上找回）
- Improved hook output handling: `<system-reminder>` tags written in a hook's output are escaped before they reach Claude（hook 輸出中的 `<system-reminder>` 標籤會被跳脫，防止注入）
- Improved tool input handling: Grep accepts `file_path` for `path`, and Write, WebFetch and Read ignore a few stray parameters instead of failing the call（工具參數容錯度提高）
- Changed local (stdio) MCP server connections to negotiate protocol version 2026-07-28 by default; `MCP_PROTOCOL_NEGOTIATION=legacy` opts out（本機 MCP server 預設改用 2026-07-28 版協定協商）
- Changed scheduled and Run now routine runs to publish a new artifact only you can see without asking for approval（排程 routine 產生的私人 artifact 不再需要核准）
- [Code Review] Fixed reviews ignoring a CLAUDE.md's rules when the pull request edits that file; reviews now use its version from the base branch（PR 修改 CLAUDE.md 時，Code Review 改用 base branch 的版本規則）
- （另有數十項 mod / plugin hooks、cloud sessions、Claude Tag、Remote Control 相關修正，詳見原文）

**核心概念（簡單說）：**
這是一次大型維護版本，重點有三：一、**sub-agent 與 plugin 生態更好用**——Agent tool 可指定 effort，讓輕量子任務省 token、困難子任務多想一點；`claude plugin install --marketplace` 把兩步安裝縮成一步。二、**安全性強化**——UNC 網路路徑讀檔、Windows 8.3 短檔名的 `rm -rf`、hook 輸出的 `<system-reminder>` 注入等邊角漏洞都被補上，CLAUDE.md 被 PR 改動時 Code Review 不再被「自己改規則」繞過。三、**長時間/背景工作的可靠度**——`/loop`、排程任務、resume 後的 plan mode 等都修正了會默默失效的狀況。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你用 sub-agent 平行處理多個元件或測試、或用 `/loop` 盯 CI，這版讓成本控制與穩定度都更好；公司走 proxy 的人也終於能讓 `NO_PROXY` 正常運作。
- **具體場景：** 在大型 monorepo 做元件庫遷移時，讓主 agent 用高 effort 規劃，再派低 effort 的 sub-agent 批次處理「把每個 `*.stories.tsx` 升級到 CSF3 格式」這種機械性工作，省下大量 token。
- **這週可以嘗試：** 執行 `claude update` 升到 2.1.292，用 `claude plugin install html-plan@claude-community --marketplace anthropics/claude-plugins-community` 一行裝好昨天 Thariq 分享的 plugin，順便測試新的 `--marketplace` 參數。
