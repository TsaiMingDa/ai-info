> Perf win of the day: Claude Code CLI now uses 2x less CPU at p99.
>
> Bun's garbage collector was running on a fixed timer, so it would kick in mid-turn and steal CPU right when Claude Code was busiest. Now it waits until the process is idle.

**繁中改寫：**
這種小地方的體驗改善累積起來很有感，後續還有更多優化在路上。（引用 ClaudeDevs：今天的效能亮點——Claude Code CLI 在 p99 情境下的 CPU 用量降到只剩一半。原因是 Bun 的垃圾回收機制過去是用固定時間排程觸發，常常在對話進行到一半、Claude Code 最忙的時候硬生生搶走 CPU 資源。現在改成等到 process 閒置時才執行回收，避免搶佔尖峰時段的運算資源。）

**核心概念（簡單說）：**
這是一個典型的效能除錯故事：問題不在演算法本身，而在「時機」。Bun 的 GC（garbage collector，垃圾回收機制）原本用固定計時器觸發，這代表不管當下 CPU 有多忙，時間到了就強制執行回收，等於在最不恰當的時間點跟主要工作搶資源。工程團隊把觸發時機改成「process idle 時才做」，讓 GC 不再跟正在執行的任務打架，於是 p99（也就是最差 1% 情況）的 CPU 使用量直接砍半。這是「把資源密集工作排到閒置時段」這個通用最佳化思路的具體案例。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的前端專案用 Bun 當 runtime 或 bundler，這類 GC 排程優化會直接反映在你本機開發或 CI 執行速度上，不需要你做任何事就能受惠。
- **具體場景：** 假設你在跑一個長時間的 watch mode（例如 `bun run dev` 搭配大量檔案監控），過去可能會偶爾感覺到卡頓，這類卡頓有很高機率就是 GC 在不對的時間點介入造成的。
- **這週可以嘗試：** 更新到最新版 Bun 與 Claude Code CLI，跑一次你平常最吃資源的建置或測試指令，感受一下 CPU 尖峰時刻是否比之前平順。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的工作牽涉到動態視覺效果、資料視覺化、互動式體驗設計，這代表用程式碼（配合 LLM 輔助生成）而非直接用圖像生成工具，可能是更適合前端工程師切入創意內容產出的路線。
- **具體場景：** 需要做產品行銷用的動態展示影片，與其去調 diffusion 模型的 prompt 生成素材，不如用 Claude Code 搭配 Remotion（用 React 寫程式碼產生影片）直接寫出可控、可重複調整的動畫。

- Fixed：權限預覽現在只會轉發給通過 inbound trust gate 核准的 channel server，且會尊重 server 明確關閉權限功能的設定。
- Fixed：轉發權限預覽時的憑證遮蔽機制，過去可能讓核准者看不到指令、路徑或目的地，現在超大的 private key 區塊在完整強度遮蔽下也會被正確遮蔽。
- Fixed：權限預覽中，provider API token 即使緊接在 shell 分隔符號後面也會被正確遮蔽。
- Fixed Claude Desktop 跨 session 訊息在接收端讀取「跨 session 訊息已停用」時被靜默丟棄的問題，過去會導致發送端的查詢卡在「思考中」長達數分鐘。
- Remote Control：把這台電腦登入切換到不同的 claude.ai 帳號或組織時，現在會在數秒內停止正在執行的 session 並說明原因，而非數小時後才顯示誤導性的 HTTP 404。
- 由 Claude Code Desktop 或 VS Code 啟動的 Remote Control session，現在會持續同步 session 的權限模式給手機與 claude.ai/code（model 資訊也會同步給 claude.ai/code）。
- Remote Control：在手機或 claude.ai/code 上選擇的 effort 等級，現在會套用到終端機與 Desktop/VS Code 主持的 session，且該 session 會把目前 effort 等級發佈給所有連線中的 client。
- SendMessage 與 ListAgents 現在會提示「帳號 session 清單過長、未能完整檢查」，而不是把未檢查到的 session 當成不存在。
- 過期的 Anthropic profile 憑證現在會在 claude.ai 登入應優先生效時，正確導向 `/login`。
- 改善 transcript 呈現：你自己輸入的 prompt 現在會以 markdown 格式渲染（語法高亮的程式碼區塊、行內程式碼、清單），與回覆的呈現方式一致。
- 改善「API returned an empty or malformed response」錯誤訊息，會說明實際收到的內容（content type、body 種類、大小、request ID）以及原始串流請求失敗的原因。
- 改善自動產生的 session 標題，現在會是簡短明確的名稱（如「Login button bug」），而非重複陳述需求的完整句子（如「Fix the login button on mobile」）。
- 把內建 `claude-api` skill 的 context 成本從約 20 萬以上 token 降到約 2.5 萬 token，改為按需載入參考文件。
- `/permissions` 現在可以在 Claude 執行任務時開啟，規則變更會套用到當前回合剩餘的部分。
- `/add-dir <path>` 現在可以在 Claude 執行任務時使用；`/add-dir`、`/autocompact`、`/theme`、`/help`、`/config`、`/advisor` 對話框都能在全螢幕 TUI 執行任務中途開啟。
- `/goal` 現在會在回合因不可恢復錯誤（如授權被撤銷、額度耗盡、context 溢出）而中止時自動清除並提示，而非繼續保持啟用狀態。
- `/goal`：當背景任務讓 goal 等待超過 30 分鐘時，Claude 現在會主動確認進度而非無限期等待（可設定 `CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0` 停用此行為）。
- `claude setup-token` 現在會拒絕非預期的額外參數，而非靜默忽略。
- 變更全螢幕模式下 Esc 鍵行為：不再清除滑鼠文字選取，仍會照常中斷或關閉對話框，選取內容維持醒目顯示。
- 移除 auto mode 過去在每次 Agent 工具呼叫下方顯示的多餘「Allowed by auto mode classifier」文字。
- 移除 `/config` 中的「Default teammate model」設定；agent-team 的隊員現在預設沿用發起者的 model，除非產生時另外指定。
- 淡化執行中工具標題上的經過時間計數器，避免與粗體的統計數字搶視覺焦點。
- 回合之間送達的背景任務通知，現在會用 `<system-reminder>` 標籤傳給模型，與回合進行中送達的通知格式一致。
- Mantle：主迴圈 model 已選定時，啟動階段會跳過 admin-pin 可用性探測。
- Windows：`~/.claude.json` 為唯讀時，啟動流程不再因重複的檔名重試而卡住。

**核心概念（簡單說）：**
這是 2.1.234 版一次規模相當大的更新，涵蓋新功能、安全性強化、大量錯誤修正與體驗優化。最值得留意的三個主軸：一是安全性加固（阻擋 Windows NT-namespace 路徑存取、修正權限預覽的憑證遮蔽漏洞），這類修正雖然瑣碎但直接關係到 Claude Code 在企業環境使用時的資安防線；二是 Remote Control（遠端操控，讓你能從手機或網頁繼續本機/桌面上的 Claude Code session）的多項可靠性修正，代表這套跨裝置協作機制正在被大量打磨；三是效能與體驗優化，包括把內建 skill 的 context 成本從 20 萬 token 砍到 2.5 萬 token，這種優化能讓每次對話省下大量可用 context 空間。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你日常用 Claude Code 開發，這次更新會讓你在長 session、跨裝置協作（Remote Control）、以及背景任務等待場景中，得到更穩定、更可預期的行為。
- **具體場景：** 若你常用手機透過 Remote Control 監看在公司電腦上跑的長任務，這次修正解決了「切換 claude.ai 帳號後任務卡住不明確報錯」跟「effort 等級在裝置間不同步」的痛點，體驗會更順暢。
- **這週可以嘗試：** 更新到 2.1.234 後試試 `/permissions` 在任務執行中直接開啟調整規則，以及觀察一下你的 CLAUDE_CODE_PROJECT_DIR_NAME 需求是否適用（例如你在多個容器/沙盒環境共用同一份設定時）。
