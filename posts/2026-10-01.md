**繁中改寫：**
我最近當作個人 side project，在做一款電玩遊戲的原型。

身為前遊戲新創創辦人，我覺得做遊戲的過程本身就非常有成就感、充滿創造力，別把這件事外包給 AI。要讓 AI 跟你一起工作，把你腦中的願景實現出來。

以下是我目前的做法：

這款遊戲的靈感來自《荒野亂鬥》（Brawl Stars）、《降世神通》（Avatar）和《快打旋風》（Street Fighter），目標（大概）是把對手或對方隊伍打出場地邊緣。還沒決定要做 1v1 還是 3v3，我先從角色開始迭代。

我最想反覆打磨的是角色的「手感」：玩起來爽不爽、有沒有力量感？能不能讓你沉浸在這個角色裡？每個角色只有一個移動搖桿加兩個動作鍵，組合起來施放不同技能。

我先做了第一個角色。他的靈感來自波斯與印度的摔角手，體型大、很重，很多技能都是「引導型」（channel）——要站在原地才能發揮最大效益。所以我覺得他需要像一面大牆這樣的防禦工具。我也很喜歡讓他在身邊召喚岩石的點子，既能防守也能進攻，還附帶一點機動性。手感非常讚。

我想讓這個角色有個大跳躍，但到目前為止還沒辦法用我喜歡的方式塞進操作配置，大概試了 2～3 種版本。

這些都還只是原型等級，畫面跟手感都還不到能讓你玩的程度。真要做成正式遊戲，這個角色我大概會再迭代 3～4 個版本，整款遊戲大約 8～10 個角色。

原型雖然好玩，但理想上我會想找 2～3 人的小團隊一起做。動畫、設計這些現在是堪用，但有專業的人加入能讓它好很多。

（有人問是否為即時制，他回：應該會像《荒野亂鬥》一樣是即時制！）

**核心概念（簡單說）：**
這串 thread 的重點不是「AI 幫我做了一款遊戲」，而是**分工的界線**：創意決策（角色定位、手感、操作配置）留在人身上，AI 負責把這些決策快速變成可以玩、可以感受的原型。遊戲的「手感」（game feel）很難用文字規格描述清楚，只能做出來、按下去、感受、再調整——這正是 AI 加速最有價值的地方：把「想法 → 可互動原型」的迴圈從幾天縮短到幾分鐘，讓人可以專心在「這樣對不對」的判斷上。

他提到大跳躍「試了 2～3 種還是塞不進操作配置」，正好說明 AI 再快也替代不了設計判斷：限制條件（一個搖桿＋兩個按鍵）下的取捨，仍然是人要做的決定。最後他也坦承，原型之後還是需要專業的動畫與設計夥伴——AI 拉高了一個人能走到的地方，但沒有取代團隊。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端的「互動手感」（動畫曲線、拖曳回饋、hover / press 狀態、手勢阻尼）跟遊戲手感是同一件事：規格寫不清楚，必須做出來摸過才知道。AI 最適合用來快速產出多個可互動版本讓你比較。
- **具體場景：** 要設計一個可拖曳排序的看板，請 Claude Code 用 `motion`（Framer Motion）或 `@dnd-kit` 做出三個版本：彈簧參數不同（`stiffness` / `damping`）、放下時的回彈不同、拖曳中的陰影與縮放不同，放在同一個 Storybook story 裡切換。你負責實際拖拖看並決定哪個「感覺對」，而不是讓 AI 自己選。
- **這週可以嘗試：** 挑一個你覺得「功能沒問題但用起來卡卡的」互動元件，請 Claude 做出 3 個不同動畫參數的變體並排比較，自己親手操作後挑出最好的一版，再請它把參數抽成 design token。

## Claude Code · Changelog

**變更項目：**（本版條目眾多，以下節錄與日常開發最相關的項目，完整內容見 [changelog](https://code.claude.com/docs/en/changelog)）
- Added a count such as “2 of 5” to the permission prompt when several permission requests stack up
  - 多個權限請求堆疊時，權限提示會顯示「2 of 5」這類計數。
- Added mouse support for the “N more” rows of lists in fullscreen mode
  - fullscreen 模式下清單的「N more」列可以用滑鼠點擊，直接跳到清單該端。
- Fixed `claude --resume` and `--continue` sometimes losing every turn after a batch of parallel tool calls when the earlier session crashed or was killed
  - 修正前一個 session 當掉後，`--resume` / `--continue` 在平行 tool call 之後遺失所有對話的問題。
- Fixed API 400 errors after a tool or hook returned an object, number or boolean instead of text
  - 修正 tool 或 hook 回傳物件、數字、布林值（而非文字）時導致 API 400 錯誤。
- Fixed every turn failing when the Anthropic API refuses the model your default or a model alias resolves to: Claude Code now retries once on the previous model of the same tier
  - API 拒絕預設模型時，會自動改用同等級的前一代模型重試一次，不再每輪都失敗。
- Fixed MCP error messages showing a credential’s value when “Bearer” or “Basic” came before its key name
  - 修正 MCP 錯誤訊息可能洩漏憑證值的問題（多項 secret redaction 修正之一）。
- Fixed MCP connectors listing no tools for up to a day after their server dropped the older MCP handshake
  - 修正 MCP server 移除舊版 handshake 後，connector 長達一天列不出 tools。
- Fixed foreground subagents sometimes missing the task-tracking tools (TaskCreate/Get/Update/List, TodoWrite)
  - 修正前景 subagent 有時拿不到 task 追蹤工具。
- Fixed subagents spawned with worktree isolation loading the project CLAUDE.md and its imports a second time
  - 修正 worktree 隔離的 subagent 重複載入 CLAUDE.md。
- Fixed `/compact`, `/clear`, and `/rewind` typed while viewing a background agent’s or teammate’s transcript silently acting on the main conversation: a dialog now names the target and asks first
  - 在檢視背景 agent 的 transcript 時輸入 `/compact` 等指令，會先跳對話框確認目標，不再默默作用在主對話。
- Fixed background jobs showing done while waiting for your approval
  - 修正背景工作在等待批准時被誤顯示為完成。
- Improved commit guidance: when your project or user skills include one named `verify`, Claude is now told to run it right before committing, except for docs-only and tests-only commits
  - 若專案或使用者 skill 中有名為 `verify` 的 skill，Claude 會在 commit 前自動執行它（純文件、純測試的 commit 除外）。
- Improved send now (ctrl+enter) in a subagent’s view: it now moves the subagent’s running command to the background so your message is read right away
  - 在 subagent 畫面按 ctrl+enter 會把它正在跑的指令移到背景，讓你的訊息立即被讀取。
- Improved Bash, PowerShell and Monitor permission prompts to show the command between dashed lines, matching file edit prompts
  - Bash / PowerShell / Monitor 的權限提示改用虛線框住指令，與檔案編輯提示風格一致。
- Improved the external editor (Ctrl+G): editors that take a line number now open on the line your cursor is on in the prompt
  - Ctrl+G 開外部編輯器時，會直接跳到你游標所在的行。
- Improved slash command suggestion responsiveness while typing when many skills or plugin commands are installed
  - 安裝大量 skill / plugin 指令時，slash command 建議的反應速度提升，描述也改以字首比對。
- Changed how failed API requests are retried: one limit now covers a whole model call, so with the default retry settings a failing call sends at most 14 requests
  - API 重試改為整個 model call 共用一個上限，預設最多送出 14 次請求。

**核心概念（簡單說）：**
2.1.286 的主軸是「多 agent 情境下的可靠性」與「安全細節」。隨著 subagent、背景工作、worktree 隔離越來越常用，這版修掉了一堆「同時有很多東西在跑」才會出現的問題：平行 tool call 後 resume 遺失對話、在背景 agent 畫面下指令卻誤傷主對話、背景工作等待批准時被誤判完成。安全方面則大量補強 secret redaction（各種格式的 token、密碼不再從錯誤訊息或 log 漏出），並收緊 plugin 的 npm 來源。

最值得前端注意的是新的 **`verify` skill 慣例**：只要專案裡有名為 `verify` 的 skill，Claude 在 commit 前就會自動執行它。這等於提供了一個官方認可的「commit 前品質關卡」掛勾點，可以把 lint、type check、測試集中寫進去。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端專案的 commit 前檢查（`eslint`、`tsc --noEmit`、`vitest run`）以往要靠 husky 或口頭提醒 Claude；現在可以用 `verify` skill 讓 Claude 在 commit 前自動跑一遍，減少把型別錯誤推上去的機率。
- **具體場景：** 在 `.claude/skills/verify/SKILL.md` 寫明：「執行 `pnpm lint && pnpm tsc --noEmit && pnpm vitest run --changed`，全部通過才能 commit；失敗時先修正再重跑。」之後請 Claude 改完元件並 commit，它就會先跑這組檢查；純文件或純測試的 commit 則會自動略過。
- **這週可以嘗試：** 更新到 2.1.286，在你最常用的前端專案新增一個 `verify` skill，內容只放最快的檢查（lint + type check），試跑一次 Claude 的 commit 流程，確認它真的在 commit 前執行，再視需要加入測試。
