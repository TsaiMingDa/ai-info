**繁中改寫：**
用了一個禮拜下來，我的心得是：要做出好作品，其實不需要無上限的 token，$200 的方案就非常夠用了。

而且，現在已經是智慧最貴的時候了，之後只會越來越便宜。

**核心概念（簡單說）：**
Thariq 離開 Anthropic 後，改用一般付費訂閱來做自己的專案（例如他最近在做的格鬥遊戲 side project）。他的結論是：在公司內部可能習慣「token 隨便用」，但實際上一個月 $200 的方案（Claude 剛把 Max 20x 改名為 Ultra，並取消驗證帳號的 5 小時限制）已經足以支撐認真的開發工作。關鍵不在於燒多少 token，而是怎麼用：給清楚的目標、適當的 context，比讓 agent 無腦重跑更有效率。

第二句「this is the most expensive intelligence will ever be」是一個趨勢判斷：模型能力每一代都在變強、單位成本卻一直下降（例如 Haiku 5.5 比 Haiku 4.5 便宜 10 倍、Opus 5.5 比 Opus 5 便宜 40%）。就像雲端運算和頻寬的價格曲線，今天付的價格就是未來的天花板，所以現在投入時間學會用好 AI，是報酬率很高的投資。

**前端工程師實際應用：**
- **跟你工作的關聯：** 個人或小團隊不用等到「預算無上限」才能把 AI 當主力工具；固定月費方案就能支撐日常的元件開發、重構和測試撰寫，重點是工作流程設計得好不好。
- **具體場景：** 在 Next.js 專案裡，與其讓 Claude Code 每次都從頭掃整個 repo，不如在 `CLAUDE.md` 寫清楚目錄結構、命名慣例和 `pnpm test` / `pnpm lint` 指令，讓每次任務都少走冤枉路，同樣的額度能完成更多工作。
- **這週可以嘗試：** 用 `/usage` 或 `/cost` 觀察自己一週的用量分布，找出最耗 token 的一兩種任務（例如大範圍搜尋或反覆失敗的修 bug），試著用更精準的 prompt 或補 context 降低它們的消耗。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.317 / November 3, 2026

**變更項目：**
- Added a warning to /schedule when a new cloud scheduled task gets connectors you did not ask for, with how to remove them（`/schedule` 建立雲端排程任務時，若被附上你沒要求的 connector 會跳出警告，並說明如何移除）
- Added a check that asks before a web or shell tool call sends your account email address to the network（web 或 shell 工具呼叫要把你的帳號 email 送到網路上之前，會先詢問你）
- Added onFailure: "block" for Agent SDK hook callbacks, so a callback that fails blocks the action instead of letting it run（Agent SDK 的 hook callback 新增 `onFailure: "block"`，callback 失敗時改為擋下該動作，而不是放行）
- Added a notice in Claude Desktop's Code tab when your organization's remote managed settings haven't loaded for the session, and another once they do（Claude Desktop 的 Code 分頁會在組織遠端管理設定尚未載入、以及載入完成時各顯示提示）
- Added a notice when auto mode's check has no answer for a subagent's tool call, which used to leave nothing in the main view（auto mode 對 subagent 的工具呼叫判斷不出結果時，主畫面會顯示提示，不再無聲無息）
- Added anthropic.plan, anthropic.seat_type, anthropic.provider and anthropic.custom_base_url to OTel metrics, events and spans（OTel 的 metrics、events、spans 新增方案、席位類型、provider 與自訂 base URL 屬性）
- Added a cost report to the Claude apps gateway admin API, GET /v1/organizations/analytics/cost, for reading past spend over a date range in total, per developer, per day or per IdP group（Claude apps gateway admin API 新增費用報表，可依日期區間查總額、每位開發者、每日或每個 IdP 群組的花費）
- Added a daily record of each developer's IdP groups on Claude apps gateways with admin: set, kept for admin.identity_retention_days, which the cost report groups by（設定 admin 的 gateway 會每日記錄開發者的 IdP 群組，保留天數由 `admin.identity_retention_days` 決定，供費用報表分組）
- Added CLAUDE_CODE_DISABLE_NESTED_SESSION_ID: set it to 1 on a self-hosted runner to have claude -p run inside a session use that session's ID and transcript, as in earlier versions（新增 `CLAUDE_CODE_DISABLE_NESTED_SESSION_ID`，在 self-hosted runner 設為 1 時，session 內執行的 `claude -p` 會沿用該 session 的 ID 與 transcript，恢復舊版行為）
- [Cloud sessions] Added a link card to cloud sessions, so you can open or decline a link an MCP server asks you to visit instead of the request going unseen（雲端 session 新增連結卡片，MCP server 要求你開啟連結時可以選擇開啟或拒絕，不會再被忽略）
- Changed SendMessage so a message to a running background agent arrives earlier: its running command moves to the background, without being stopped（`SendMessage` 傳給執行中背景 agent 的訊息會更早送達：它正在跑的指令會被移到背景，而不是被中斷）
- Changed subagents and teammates on a different model from the main conversation to use that model's saved effort level or its default, instead of the session's effort level（使用與主對話不同模型的 subagent / teammate，改用該模型自己儲存的 effort 等級或預設值，不再沿用 session 的 effort）
- Changed exit to skip the "Background work is running" prompt for plugin monitors（離開時若只有 plugin monitor 在跑，不再跳出「背景工作執行中」的確認）
- Changed the built-in plugin-authoring skill to offer once, after a mod you built works, to help share the mod（內建 plugin-authoring skill 在你做的 mod 可以正常運作後，會主動詢問一次是否要協助分享）
- Removed the Read tool's "file unchanged since your last Read" stub: reading an unchanged file again returns its content（移除 Read 工具的「檔案自上次讀取後未變更」替代訊息，重讀未變更的檔案會直接回傳內容）
- [Cloud sessions] Changed the organization environment dialog in admin settings to the personal dialogs' short layout: each section opens from a row, and unsaved input asks before closing（管理設定中的組織環境對話框改成與個人設定一致的精簡版面，未儲存的輸入在關閉前會先確認）
- [Claude Tag] Changed newly pasted artifact links in Slack to show a simpler card with an Open button that opens the artifact in Claude, instead of Slack's side panel（在 Slack 貼上 artifact 連結時改顯示附 Open 按鈕的精簡卡片，直接在 Claude 開啟，而非 Slack 側邊欄）
- 另有 8 項改進與 62 項 bug 修正（頁面收合未展開，詳見原始 changelog）

**核心概念（簡單說）：**
這版的主軸是「安全與可觀測性」加上「agent 協作細節」。安全面：送出帳號 email 前會先詢問、排程任務被附上非預期 connector 時會警告、Agent SDK 的 hook 可以設定「失敗就擋下」（fail-closed），避免安全檢查本身出錯時反而放行危險動作。可觀測性面：OTel 多了方案與 provider 等維度，gateway 新增可依開發者、日期、IdP 群組切分的費用報表，讓團隊能精確追蹤 AI 開發的成本。

agent 協作面：`SendMessage` 不再需要等背景 agent 跑完當前指令才收到訊息，等於把「中途改方向」的延遲大幅縮短；不同模型的 subagent 改用各自適合的 effort 等級，避免例如讓 Haiku subagent 跟著主對話用 max effort 而浪費。Read 工具移除「檔案未變更」的替代訊息，則是讓 agent 在 context 被壓縮後重讀檔案時能真的拿到內容，減少「以為看過了其實沒看到」的錯誤。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你用 Agent SDK 自己包 hook（例如在寫檔前跑 lint 或檢查有沒有動到 `.env`），現在可以讓 hook 出錯時直接擋下，而不是默默放行；團隊導入 Claude Code 時，費用報表和 OTel 新屬性也讓主管更容易評估投資效益。
- **具體場景：** 在 monorepo 裡讓主對話用 Opus 5.5 規劃重構、再派 Haiku 5.5 subagent 去批次修改上百個元件的 import 路徑；新版下 Haiku subagent 會用自己的 effort 預設值，速度更快、花費更低。中途發現 import 規則要改時，用 `SendMessage` 通知背景 agent，訊息會更快被處理。
- **這週可以嘗試：** 升級到 2.1.317 後，檢查你的 Agent SDK hook 設定，把「安全檢查類」的 callback（例如阻擋修改 `package-lock.json` 或 production config）加上 `onFailure: "block"`，確保檢查本身壞掉時是安全地失敗。
