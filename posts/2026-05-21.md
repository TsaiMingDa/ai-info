## Claude Code · Changelog

**版本號 / 日期：** 2.1.146 / May 21, 2026

**變更項目：**
- `/simplify` 更名為 `/code-review`，並新增可選的 effort level（例：`/code-review high`）— 讓指令名稱更語意化，且可控制審查深度
- Auto mode 不再在使用者或 skill 明確依賴 AskUserQuestion 時壓制它 — 修正 auto mode 過於積極略過人工確認的問題
- Fixed：在 Windows 上透過 winget 或 Microsoft Store 安裝的 pwsh 執行 PowerShell tool 時出現「command line is invalid」（v2.1.124 regression）
- Fixed：MCP `resources/list`、`resources/templates/list`、`prompts/list` 在分頁 server 上丟失第 1 頁之後的項目
- Fixed：在 Windows Terminal 的全螢幕 attached background session 中，Claude 串流時出現閃爍（strobing）
- Fixed：auto-updater 狀態列在更新失敗時未顯示目前版本號
- Fixed：Windows 上移除 background-job worktree 時不再跟隨 NTFS junction 進入主 repo
- Fixed：`/background` 拒絕只有 skill 或自訂 slash command 作為輸入的 session
- Fixed：已在 background session 授權過「don't ask again」的工具權限，重新連線後不再重新提示
- Fixed：`/theme` 顏色編輯器和「New custom theme」對話框對 Esc 無反應
- Fixed：透過 Agent SDK 執行 streaming session 結束時出現未捕捉的 exception
- Fixed：`forceLoginOrgUUID` 和 `forceLoginMethod` managed-settings policies 未對 third-party-provider 和 API-key session 強制套用
- Fixed：GNOME Terminal 右鍵和中鍵貼上不插入文字
- Fixed：multi-agent session 中 `CLAUDE_CODE_SUBAGENT_MODEL` 未傳遞給子程序
- Improved：auto-updater 可靠性提升 — 原生版本檢查和下載在暫時性網路失敗時會重試，而非立即失敗
- Improved：大型檔案編輯的 diff 渲染效能提升

**核心概念（簡單說）：**
這次更新最顯眼的是 `/simplify` 正式更名為 `/code-review`，且加了 effort level 選項（`low` / `high` 等）。改名讓指令意圖更清楚——不只是「簡化程式碼」，而是做「程式碼審查」；effort level 則讓你可以決定要快速掃一遍還是深入分析。其餘修正主要集中在 Windows 環境的穩定性（PowerShell、NTFS junction、GNOME Terminal）、MCP 分頁處理、以及 background session 的各種邊緣案例。

**前端工程師實際應用：**
- **跟你工作的關聯：** `/code-review` 取代 `/simplify` 後，前端工程師可以直接在 Claude Code session 裡對剛寫完的 component 或 API layer 做程式碼審查，不需要切換到其他工具，且可以用 `/code-review high` 要求更深入的分析（型別安全、效能、可讀性）
- **具體場景：** 完成一個複雜的 React Server Component 或 TypeScript utility 之後，在 Claude Code 裡直接跑 `/code-review high`，讓 Claude 以更嚴格的標準找出潛在的 edge case、型別漏洞或不必要的 re-render，再根據建議調整
- **這週可以嘗試：** 執行 `claude --version` 確認已更新到 v2.1.146，然後在你目前的前端專案中，對一個你覺得「差不多夠用」的 component 跑 `/code-review`，再對比 `/code-review high` 的輸出，看看不同 effort level 的審查深度差異
