**核心概念（簡單說）：**
AGENTS.md 是目前很多 coding agent（Codex、Cursor 等）共通採用的「專案說明書」檔名，用途跟 CLAUDE.md 一樣：告訴 agent 這個 repo 怎麼 build、測試、命名、有哪些禁區。過去 Claude Code 只認 CLAUDE.md，團隊如果同時用多種 agent，就得維護兩份幾乎一樣的檔案。現在採用 fallback 策略：有 CLAUDE.md 就用 CLAUDE.md，沒有才退而讀 AGENTS.md。

更值得注意的是第二則透露的方向：這功能是用「mod」實作的。可以把 mod 想成 Claude Code 的外掛層，讓你替換或擴充 harness 本身的行為（像這次「怎麼載入專案指令」就是一個可抽換的模組），而不只是加 skill 或 hook。而且原始碼是公開的，等於直接附上一份 mod 的範例寫法。

- **具體場景：** 你的 monorepo（pnpm workspace + Vite + Vitest）已經有一份寫好 lint 規則、元件命名慣例、「改完要跑 `pnpm test`」的 AGENTS.md，給其他 agent 用；升級到 2.1.277 之後，在同一個資料夾直接跑 `claude`，不用再複製出 CLAUDE.md 就能吃到同樣的規則。

**核心概念（簡單說）：**

技術上的重點在於「存取權限」與「獨立性」的拉扯：權限越接近員工，觀察越深入；但資金若由被評測方出，獨立性就會被質疑，所以文中才特別提到需要標準與集資或政府出資的長期機制，並同時引入 METR 這類自籌資金的非營利機構做對照。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.278 / 2026-09-19

**變更項目：**
- Auto mode 預設改用 server-side classifier（Claude API、Enterprise、Bedrock、Vertex、Foundry 與 gateway 使用者），不會為 classifier 額外計費；在 Bedrock／Vertex／Foundry／gateway 可設 `CLAUDE_CODE_AUTO_MODE_SERVER=0` 選擇退出；若退回計費的 fallback 會顯示警告。（Changed auto mode to default to the server-side classifier, which does not charge for classifier overhead.）
- `/status` 新增「Auto mode server」一列，顯示此 session 的 auto mode classifier 是否跑在 server 端。（Added an Auto mode server row to /status.）

**核心概念（簡單說）：**
Auto mode 是讓 Claude 在不逐一詢問你的情況下，由一個 classifier（分類器）判斷每個動作安不安全、可不可以自動放行。過去這個判斷的模型呼叫可能在你這一側執行並計入用量；這次改成預設在 server 端執行，判斷成本不再算到你頭上，`/status` 也多了一列讓你確認實際是走哪條路。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你常開 auto mode 讓 Claude 自己跑 `pnpm install`、跑測試、改檔案，這次更新代表這種「自動放行」的額外開銷降低。
- **具體場景：** 在公司走 Bedrock 或 Vertex 的團隊，升級後預設走 server-side classifier；如果資安要求 classifier 必須留在自己的環境內，就要用 `CLAUDE_CODE_AUTO_MODE_SERVER=0` 退出，並在 `/status` 確認。
- **這週可以嘗試：** 升到 2.1.278，開一個 session 執行 `/status`，確認 Auto mode server 那一列的狀態，並對照你們的計費與資安政策。

- 修復：當 `ANTHROPIC_BASE_URL` 指向 proxy 或 gateway 時，每個請求都因 400 錯誤（input tag `advisor_20260301`）失敗，這是 2.1.275 引入的 regression。（Fixed every request failing with 400 when ANTHROPIC_BASE_URL points at a proxy or gateway.）

**核心概念（簡單說）：**
這是一個緊急修補版：2.1.275 有一個 regression，只要你透過自架 proxy 或公司 gateway 連 Anthropic API，所有請求都會被 400 拒絕。2.1.276 把它修好。

**前端工程師實際應用：**
- **跟你工作的關聯：** 若公司透過內部 gateway（例如 LiteLLM、Cloudflare AI Gateway）轉發 Claude Code 請求，2.1.275 會直接整個壞掉。
- **具體場景：** 你早上升級 Claude Code 後突然每個指令都回 400，檢查 `echo $ANTHROPIC_BASE_URL` 發現有設 gateway，這就是踩到此 regression。
- **這週可以嘗試：** 執行 `claude --version` 確認不是停在 2.1.275；若是，直接升級，並考慮在團隊 wiki 記錄「使用 gateway 的成員不要停在有問題的版本」。
