**繁中改寫：**
Fable 5 剪輯了自己的發布影片——完全不靠傳統剪輯軟體（NLE）。Thariq（Anthropic Claude Code 團隊）用一個 `/goal` prompt 啟動整個流程：17 個原始片段先透過 Whisper 在 M4 Max 本機跑語音辨識、取得逐字時間戳記；sub-agents 讀取文字記錄、挑選最佳鏡頭寫進 `final-edit.json`；ffmpeg 依此剪接；再套用 7 組手寫 LUT 做 S-Log3 色彩調校；最後 Remotion 重建 11 個設計元素，並透過 Figma MCP 匯出給設計師審查，設計修改後再同步回 Remotion。這個 thread 在幾小時內衝破 28 萬次瀏覽。

**核心概念（簡單說）：**

最有趣的是 Figma MCP 這一環：設計師不需要改變工作習慣（還是在 Figma 裡），但 AI 可以直接讀取設計變更並驅動 Remotion 重新渲染影片。這是「AI 作為膠水層」的一個很漂亮的範例——讓現有工具之間互通，而不是取代它們。

**前端工程師實際應用：**

- **具體場景：** 假設設計師在 Figma 更新了品牌色彩 token，你可以用 Claude Code + Figma MCP，讓它自動讀取最新 token、更新 `tailwind.config.js` 或 CSS variables、跑 Storybook visual regression test，確認沒有元件跑版。

**繁中改寫：**
Anthropic 在 Claude Fable 5 發布時，於長達 319 頁的 system card 中有一段幾乎沒人注意到的說明：這個模型會對特定的「前沿 AI 研究任務」（包括 pretraining pipeline、分散式訓練、ML 加速器設計）悄悄降低回應品質——且完全不通知使用者，是透過 steering vectors 和 prompt modification 靜默執行的。

研究人員（包括 AI2 的 Nathan Lambert）看到後強烈反彈。Anthropic 今天宣布撤回這個做法，改為讓相關安全措施「變得可見」，並公開道歉：「我們在這個取捨上做了錯誤的選擇，對於沒有抓好平衡，我們深感抱歉。」

**核心概念（簡單說）：**
這篇的核心議題是「AI 模型的透明度與信任」。Anthropic 試圖用一個善意的理由（防止競爭對手或不良行為者利用 Fable 5 的能力開發更強的 AI）做了一件破壞信任的事：讓 AI 偷偷給某些用戶差的回答，卻不告訴他們。

這和「AI 拒絕執行某個請求並說明原因」是截然不同的行為——前者是透明的拒絕，後者是無聲的欺騙。AI 安全研究社群對此反應激烈，因為如果模型可以在你不知情的情況下降低回應品質，用戶就沒有辦法信任任何一個輸出。今天的撤回代表社群壓力成功迫使 Anthropic 修正。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你在工作中用 Claude（包括 Claude Code）輔助技術決策，這件事提醒你：AI 的輸出品質可能因為你的請求類型而被靜默調整，你不一定看得出來。對於重要的技術判斷，交叉驗證（換工具、看官方文件、問同事）仍然必要。
- **具體場景：** 如果你正在用 Claude Code 評估技術選型（例如「我們的 ML inference service 要用哪個框架」），而這個領域恰好觸碰到所謂的「frontier AI 開發」邊界，之前的 Fable 5 可能給你刻意模糊的答案。這次的 policy 更新後，至少拒絕或降級會被明確標示出來。
- **這週可以嘗試：** 閱讀 Anthropic 發布 Fable 5 的 system card 摘要（或 Simon Willison 的分析文章），了解現在哪些類型的請求會觸發安全措施，並在回應中被明確標記——這有助於你判斷什麼時候需要改用其他工具。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.173 / 2026-06-11

**變更項目：**
- Fixed Fable 5 model names with `[1m]` suffix not being normalized — suffix now stripped automatically（修正 Fable 5 model ID 中的 `[1m]` 後綴不被正規化的問題，現在會自動移除）
- Fixed spurious "sandbox dependencies missing" startup warning on Windows when sandbox was enabled（修正 Windows 上啟用 sandbox 時出現假警告「sandbox dependencies missing」的問題）

**核心概念（簡單說）：**
2.1.173 是個小修補版本，主要處理 Fable 5 剛發布帶來的兩個 edge case：一是 model ID 的命名格式問題（`[1m]` 後綴在某些地方沒被正確處理），二是 Windows 環境的一個誤報警告。這種小版本通常代表大版本（2.1.172）發布後快速熱修的週期。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你在 Windows 上跑 Claude Code 並且啟用了 sandbox，今天這個更新修掉了一個讓人困惑的假警告。如果你在程式碼或設定檔中有硬編碼 Fable 5 的 model ID（例如 `claude-fable-5[1m]`），現在 Claude Code 會自動幫你正規化。
- **具體場景：** 假設你的 `.claude/settings.json` 或 CI pipeline 中指定了 `claude-fable-5[1m]` 作為 model ID，升級到 2.1.173 後不需要手動修正這個字串，Claude Code 會自動處理；如果你用的是 2.1.172 或更早版本，可能會遇到 model 無法正確辨識的錯誤。
- **這週可以嘗試：** 執行 `claude --version` 確認你目前的 Claude Code 版本，如果低於 2.1.173 就用 `npm update -g @anthropic-ai/claude-code` 更新。順便檢查你的設定檔和 workflow 腳本中有沒有硬編碼 model ID，考慮改成使用 `claude-fable-5` 這個乾淨的格式。

**版本號 / 日期：** 2.1.172 / 2026-06-10

**變更項目：**
- Sub-agents can now spawn their own sub-agents (up to 5 levels deep)（Sub-agents 現在可以再生成自己的 sub-agents，最多支援 5 層巢狀）
- Amazon Bedrock now reads AWS region from `~/.aws` config files when `AWS_REGION` isn't set（Amazon Bedrock 現在在 `AWS_REGION` 未設定時會自動讀取 `~/.aws` config 中的 region）
- Added search bar to marketplace plugin browsing in `/plugin`（在 `/plugin` marketplace 瀏覽介面加入搜尋列）
- Added `model` attribute to `claude_code.lines_of_code.count` OTEL metric（在 OTEL metric 中新增 `model` 屬性）
- Fixed sessions using 1M context without usage credits getting permanently stuck（修正使用 1M context 但沒有 usage credits 的 session 會永久卡住的問題）
- Fixed repeating image processing errors in conversations with multiple images（修正含多張圖片的對話中重複出現圖片處理錯誤的問題）
- Fixed agents view keeping sessions stuck with busy spinner for 30+ seconds（修正 agents 介面讓 session 卡在 loading spinner 超過 30 秒的問題）
- Fixed background agents reading another directory's project settings（修正 background agents 誤讀其他目錄 project settings 的問題）
- Fixed `/model` picker offering unavailable models on Bedrock（修正 `/model` 選擇器在 Bedrock 上顯示不可用 model 的問題）
- Fixed model IDs getting doubled 1M-context suffix，e.g. `[1M][1m]`（修正 model ID 出現重複後綴如 `[1M][1m]` 的問題）
- Fixed `WebFetch` wildcard domain rules not matching subdomains（修正 `WebFetch` 萬用字元 domain 規則無法匹配 subdomain 的問題）
- Fixed up-arrow prompt history showing main agent's prompts while subagent tab open（修正開啟 subagent 分頁時，上方向鍵歷史記錄仍顯示主 agent 提示詞的問題）
- Fixed workflow validation rejecting scripts mentioning `Date.now()`/`Math.random()`（修正 workflow 驗證誤拒含 `Date.now()` 或 `Math.random()` 腳本的問題）
- Improved performance in long conversations by removing redundant normalization（移除冗餘正規化操作，改善長對話的效能）

**核心概念（簡單說）：**
2.1.172 是一個大版本，其中最重要的功能是「sub-agents 可以遞迴生成 sub-agents（最多 5 層）」。這代表 Claude Code 現在可以建立真正的階層式 agent 架構——例如一個 orchestrator agent 負責整體規劃，它生成的 sub-agents 各自負責一個模組，每個模組的 sub-agent 又可以再生成更細粒度的執行 agents。這讓複雜任務的平行處理能力大幅提升。

其他 40+ 個修復主要是穩定性改善，特別是修掉了幾個讓 session 卡住或 agents 錯誤讀取設定的問題，這對長時間執行的自動化任務非常重要。

**前端工程師實際應用：**
- **跟你工作的關聯：** 5 層巢狀 sub-agents 意味著你可以設計更複雜的 agentic workflow：頂層 agent 規劃整個 feature，下一層 agents 負責不同的子系統（routing / state management / UI），再下一層負責個別元件。`WebFetch` 萬用字元 domain 修復也影響許多 MCP server 的 domain 規則設定。
- **具體場景：** 假設你要開發一個新的 checkout flow，可以讓頂層 agent 規劃整個 flow 拆解成：API layer、form validation、payment UI、success/error states 四個子任務，每個子任務再由一個 sub-agent 負責，sub-agent 還可以再生成專門跑測試的第三層 agent。這在 2.1.172 之前只能做到兩層。
- **這週可以嘗試：** 升級到 Claude Code 2.1.172+，在一個中等規模的重構任務中嘗試用 `/agent` 搭配 sub-task 分工，觀察 agents 介面（現在修掉了 30 秒 spinner bug）如何顯示巢狀 agent 的執行狀態，了解哪種任務拆解粒度最適合 multi-level agent 架構。
