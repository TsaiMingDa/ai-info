**繁中改寫：**
這次的更新我真的很興奮：MCP server 現在可以自帶 skills，Claude Code 一接上就知道該怎麼用它們，不用再另外教。

（引用 @ClaudeDevs）MCP 兩歲了！它一開始只是讓 AI 應用連接工具與資料的協定，現在正逐步演進成「agent 之間如何溝通、如何協調工作」的標準。我們透過 Skills over MCP 與 Tasks，把更多這類 agentic 能力帶進 Claude。

**核心概念（簡單說）：**
過去 MCP server 只負責「提供工具」：它告訴 Claude 有哪些 tool、參數長怎樣，但「什麼情境該用哪個 tool、要按什麼順序呼叫、有哪些坑」這些操作知識，要嘛靠 tool description 硬塞，要嘛使用者自己寫 skill 或 CLAUDE.md 去補。Skills over MCP 讓 server 作者把這份「使用說明書」（skill：一段 markdown 指示，必要時附腳本）跟著 server 一起發佈，Claude Code 連上後就自動取得，並在 `/` 選單以 `server:skill` 的名稱出現（見今天 Changelog 2.1.332）。

打個比方：以前 MCP 像是給你一台新相機但沒附說明書，現在廠商把「拍夜景要開哪幾個模式」的教學也一起裝進盒子裡。對 agent 而言，skill 是按需載入的，平常只占很少 context，需要時才展開完整指示，所以 server 可以塞入比 tool description 豐富得多的工作流程知識。

**前端工程師實際應用：**
- **跟你工作的關聯：** 你團隊常用的 MCP server（設計稿、元件庫文件、錯誤監控、瀏覽器自動化等）若開始自帶 skill，Claude Code 就能直接遵循「官方建議用法」，少掉一堆自己寫 prompt 教它怎麼查元件、怎麼看 trace 的工夫。
- **具體場景：** 接上 chrome-devtools 之類的瀏覽器 MCP 時，server 若附一個「量測 LCP 並找出 render-blocking 資源」的 skill，你在 `/` 選單選 `server:debug-lcp`，Claude 就會照固定流程開 trace、分析 insight、回報建議，而不是每次臨場亂試工具。
- **這週可以嘗試：** 升級到 Claude Code 2.1.332 後，在 `/` 選單看看已連的 MCP server 是否出現 `server:skill` 形式的項目；如果你們團隊有自建的 MCP server（例如內部 Design System 查詢），試著把現有 CLAUDE.md 裡「怎麼用這個 server」的段落整理成一份 skill 草稿。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.332 / November 25, 2026

**變更項目：**
- Added skills from MCP servers (beta). They show as server:skill in the / menu; other skills keep their names — 新增 MCP server 自帶的 skills（beta），在 `/` 選單以 `server:skill` 顯示，其他 skill 名稱不變
- Added a PreSkillShellCommand hook event that can refuse a skill or command’s inline shell commands as it loads — 新增 `PreSkillShellCommand` hook，可在 skill / command 載入時拒絕其內嵌的 shell 指令（2.1.331 以前版本若設定檔提到它，啟動時會跳對話框）
- Added “Always deliver” to the prompt for held messages from other sessions — 其他 session 傳來被暫留的訊息，提示中多了「一律送達」選項
- Added a warning in VS Code and Desktop’s Code tab when part of a session couldn’t be saved, saying how to save it with /compact — VS Code 與桌面版 Code 分頁在 session 部分內容無法儲存時會警告，並說明可用 `/compact` 儲存
- [VSCode] Added the installed version to the rows of Manage plugins — Manage plugins 清單顯示已安裝版本
- Changed --model default and a Default pick to move to an older model when that model isn’t available, instead of stopping with an error — 預設模型不可用時改為自動降到較舊模型，而非直接報錯
- Changed the default model on Microsoft Foundry to Sonnet 5.5; sonnet alias on Agent Platform / Foundry now Sonnet 5.5 — Foundry 預設模型改為 Sonnet 5.5，Agent Platform 與 Foundry 的 `sonnet` alias 也指向 Sonnet 5.5
- Changed computer-use to a reserved skill name on Macs with computer use on — Mac 上開啟 computer use 時，`computer-use` 成為保留的 skill 名稱，同名自訂 skill 將停止載入
- Changed the default OpenTelemetry service.name of desktop Code tab sessions to claude-code-desktop — 桌面版 Code 分頁的 OTel `service.name` 預設改為 `claude-code-desktop`，依 `claude-code` 過濾的儀表板要更新
- Changed plan mode in the desktop app’s Code tab and VS Code to ask for approval instead of refusing when no auto mode safety check can judge a command — plan mode 遇到 auto mode 無法判斷的指令時改為詢問核准，而非直接拒絕
- Changed tap-mode voice dictation to keep the microphone on until 60 seconds without new words or 10 minutes — 語音聽寫靜默上限由 15 秒 / 2 分鐘延長到 60 秒 / 10 分鐘
- Changed /schedule, permission prompts and /loop’s cloud offer to say “cloud scheduled task” instead of “routine” — 用語統一改為「cloud scheduled task」，`/routines` 仍可使用
- Changed awsCredentialExport to time out after 10 minutes instead of waiting forever — `awsCredentialExport` 加上 10 分鐘逾時
- Improved Glob speed in large local folders on Windows machines with 6 or more CPUs — Windows 6 核以上機器在大型資料夾的 Glob 改為平行走訪，速度提升
- Improved memory use at startup with MCP servers that list many tools, and when resuming a long conversation — 改善大量 MCP tool 啟動與續接長對話時的記憶體用量
- Improved /permissions to refuse a rule that would be skipped at the next start, and show the reason — `/permissions` 會拒絕下次啟動會被略過的規則並說明原因
- [VSCode] Improved the time it takes to open the Claude panel and long sessions, and streaming performance — VS Code 面板開啟與長回覆串流效能提升
- 另有 19 項 improvements 與 93 項 bug fixes（頁面中摺疊，此處列重點）

**核心概念（簡單說）：**
這版的主角是 **Skills over MCP**：MCP server 可以把 skill 一起發佈，Claude Code 自動以 `server:skill` 名稱掛進 `/` 選單，與 bcherny 今天的貼文相呼應。為了配套安全性，同時加入 `PreSkillShellCommand` hook——既然 skill 可能來自第三方 server，且 skill 可以內嵌 shell 指令，你就需要一個在載入當下審查、拒絕這些指令的關卡，概念上類似 CSP 之於第三方 script。

其餘多為可靠性調整：預設模型不可用時自動降級而不是中斷、雲端平台的 `sonnet` alias 換到 Sonnet 5.5、OTel `service.name` 拆分出桌面版、Windows 上 Glob 平行化與多處記憶體優化。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端專案常接多個 MCP server（Figma、瀏覽器、元件文件），現在它們自帶的 skill 會出現在 `/` 選單；同時你要意識到這些 skill 可能執行 shell 指令，需要適當的把關。
- **具體場景：** 在專案 `.claude/settings.json` 設一個 `PreSkillShellCommand` hook，用小腳本檢查來自第三方 MCP skill 的指令，只允許 `npm run`、`npx playwright` 這類白名單，遇到 `curl | sh` 或寫入 `~/.ssh` 的指令就拒絕；若你在 Windows 上的大型 monorepo（例如 Nx / Turborepo）開發，也能感受到 Glob 搜尋變快。
- **這週可以嘗試：** 執行 `claude --version` 確認升到 2.1.332，打開 `/` 選單看有沒有 `server:skill` 項目；若團隊用 OpenTelemetry 監控 Claude Code 使用量，檢查儀表板的 `service.name` 過濾條件是否要加入 `claude-code-desktop`。
