>
> The letter did not provide specific details of its national security concern, but Anthropic's understanding is that the government believes it has become aware of a method of bypassing, or "jailbreaking," Fable 5. The net effect of this order is that Anthropic must abruptly disable Fable 5 and Mythos 5 for all customers to ensure compliance — including customers who are US citizens — because it is not currently possible to identify the nationality of all users in real time. Access to all other Anthropic models will not be affected.
>
> Anthropic publicly disagrees with this directive. The concern identified appears to involve a narrow potential jailbreak that is widely available from other models. Anthropic believes the standard implicit in this directive would halt all new frontier model deployments across the AI industry. The company said it is working urgently with the government to resolve the misunderstanding and restore access to the models as soon as possible.

美國商務部於台北時間 6 月 13 日清晨，透過出口管制指令要求 Anthropic 立即停止所有「外國籍人士」使用 Fable 5 和 Mythos 5，範圍包含美國境內的外國籍員工。由於 Anthropic 目前無法即時驗證所有用戶的國籍，只好直接對全體用戶關閉這兩個模型。

其他模型（包含 Opus 4.8）完全不受影響。

**核心概念（簡單說）：**
這是 AI 產業史上第一次有美國政府透過出口管制手段，強制要求 AI 公司將已公開上線的旗艦模型下架。Fable 5 才剛在 6 月 9 日正式開放給所有 Pro/Max/Enterprise 用戶三天，就被政府一紙公文緊急關停。

核心矛盾在於：政府的規定要求禁止「外國籍人士」使用，但 Anthropic 根本無法在不中斷服務的情況下即時驗證用戶國籍，所以選擇直接全面關閉 Fable 5 和 Mythos 5。Anthropic 的反駁是：這個所謂的安全漏洞（jailbreak）在別的模型上同樣存在，用這個理由只針對 Fable 5 並不合理，而且這個先例一旦成立，未來所有新模型上線都可能面對相同的命運。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.176 / June 12, 2026

**變更項目：**
- Session titles now generated in the language of your conversation（對話語言決定 session 標題語言），可透過 `language` 設定覆蓋
- Added `footerLinksRegexes` setting：可在底部 footer 列新增 regex 匹配的自訂連結 badge
- Improved Bedrock credential caching：改為快取至 `Expiration` 時間點，不再固定 1 小時
- Fixed `availableModels` enforcement：alias 模型選擇現在無法繞過 allowlist 規則
- Fixed auto mode failing on Fable 5 for organizations without Opus 4.8 enabled（自動模式在未啟用 Opus 4.8 的組織中誤判的問題已修正）
- Fixed hook `if` conditions for Read/Edit/Write tool paths（hook 條件判斷路徑問題修正）
- Fixed Linux sandbox failing when `.claude/settings.json` is a symlink with absolute target
- Fixed `/copy` and mouse-selection copy not reaching system clipboard inside tmux over SSH（tmux over SSH 環境下複製到系統剪貼簿失效的問題）
- Fixed Remote Control model switching and disconnect notifications
- Fixed `/cd` and worktree moves not updating git branch status
- Fixed `claude agents` back button behavior
- Fixed backgrounded sessions showing "Working" forever（背景 session 永遠顯示 Working 的問題）
- Fixed background agent search by PR URL
- Background sessions show clearer guidance for auto-update window issues

**核心概念（簡單說）：**
2.1.176 是一個大型修補版本，主軸有兩個：一是多語言支援（session 標題自動跟你說話的語言，不再永遠是英文）；二是修正一大批與 tmux、SSH、Remote Control、Windows、背景 agent 相關的邊緣案例 bug。對於跨語言使用的開發者，`language` 設定值得關注；對於使用 Remote Control 或跑 background agent 的用戶，這版修了很多穩定性問題。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你習慣用 tmux 在遠端 SSH 環境工作，這版修正了在 tmux over SSH 中 `/copy` 和滑鼠選取複製無法同步到系統剪貼簿的問題，日常工作的剪貼操作終於正常。
- **具體場景：** 用 `claude` 在 tmux 裡跑開發任務時，以前選取程式碼後 `ctrl+shift+c` 複製出來的內容無法貼到瀏覽器或本機，現在這個問題在 2.1.176 已修正。
- **這週可以嘗試：** 更新到 2.1.176（`npm update -g @anthropic-ai/claude-code`），然後用 `language: zh-TW` 寫入你的 `.claude/settings.json`，讓 Claude Code 的 session 標題改用中文命名。

**版本號 / 日期：** 2.1.175 / June 12, 2026

**變更項目：**
- Added `enforceAvailableModels` managed setting：啟用後，`availableModels` allowlist 同時限制「Default」模型的解析結果；若 Default 解析後的模型不在 allowlist 內，會自動 fallback 到清單中第一個模型。使用者或 project settings 無法擴展由 managed settings 設定的 allowlist。

**核心概念（簡單說）：**
這是針對企業/團隊管理員的功能。原本 `availableModels` 只能限制用戶手動選擇的模型，但「Default」模型仍然可以解析到被封鎖的模型。`enforceAvailableModels` 填補了這個漏洞，讓 IT/DevOps 可以真正鎖定組織內能使用的模型範圍，不管是手選還是系統自動選。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你所在的公司或團隊有透過 managed settings 管理 Claude Code 的模型使用權限，這個更新影響「預設模型」的行為，可能導致你原本使用的 Default 模型被替換掉。
- **具體場景：** 公司 IT 設定了 `availableModels: ["claude-opus-4-8"]` 並啟用 `enforceAvailableModels: true`，即使你在設定裡指定 Default 為 Fable 5，系統也會自動改用 Opus 4.8。
- **這週可以嘗試：** 如果你是團隊管理員，可以在 managed settings 加上 `enforceAvailableModels: true` 來確保模型使用的一致性，避免不同成員用到不同模型導致的行為差異。
