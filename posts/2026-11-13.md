**繁中改寫：**
（補充脈絡——）引用 Evan Oman 的整理：Thariq 展示了一個很有意思的工作流程：他在做一款遊戲，遊戲引擎幾乎全交給 agent 負責；但角色與技能是用一種 DSL 定義的，他可以手動改這份 DSL，或用 tab 補全模型（！！）來調整遊戲行為。這讓我想到「認知人體工學（cognitive ergonomics）」的概念：把人的注意力集中在真正有趣的部分。

**核心概念（簡單說）：**
這是 Thariq 演講內容最具體的一段：把系統切成兩層。底層的「引擎」（渲染、物理、狀態管理等大量但無聊的程式碼）由 agent 擁有和維護；上層用一個小而清楚的 DSL（領域專用語言，例如一份描述「角色 HP、技能冷卻、火焰攻擊範圍」的設定格式）來表達真正需要創意判斷的東西。人只需要在 DSL 這層工作，可以手改，也可以靠 tab 補全模型快速產生變化。

好處是：DSL 小、結構固定，人類一眼就能審查，模型也很難在這層出錯；而引擎即使是 agent 寫的、人沒逐行讀過，只要它正確執行 DSL 就好。這其實就是「資料驅動 / 設定驅動」設計，只是現在多了 agent 這個新的分工對象。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端早就有這種模式——design tokens、JSON schema 驅動的表單、CMS 的 block 設定、路由設定檔。把這些「宣告式設定層」設計好，就能放心讓 agent 處理底下的實作。
- **具體場景：** 做一個後台表單系統時，先定義一份 TypeScript 型別嚴格的欄位設定（`{ name, type: 'text' | 'select', validation, dependsOn }`），請 Claude Code 寫出渲染引擎（React Hook Form + Zod 動態產生）；之後新增或調整表單只需要改設定檔，甚至在 VS Code 裡靠 Copilot / tab 補全快速寫出新欄位。
- **這週可以嘗試：** 找專案中一個重複度高的 UI（例如設定頁、篩選器、卡片列表），把差異抽成一份宣告式的 config 物件與對應的 TypeScript 型別，再讓 agent 改寫元件去讀這份 config，體驗「人管 DSL、agent 管引擎」的分工。

**繁中改寫：**
推出 Claude Meetings：把 Claude 加進團隊的視訊會議，它會在你們還在討論時，就跟大家一起產出文件、白板和其他 artifact。目前開始以 beta 形式逐步開放給 Team 與 Enterprise 方案。

Claude 會以「看得見的參與者」身分加入會議。你可以直接開口問它問題、在聊天室打字問，或請它開一份文件。整個團隊都看得到它正在做什麼，並能在成形過程中即時修正。

會議紀錄也交給 Claude。會議結束後，筆記、待辦事項、逐字稿，以及 Claude 在會中做出的所有東西，都會整理在 Claude 裡該場會議的頁面上。Claude Meetings 先支援 Google Meet，其他視訊會議平台也即將支援。

**核心概念（簡單說）：**
過去的 AI 會議工具多半是「會後摘要機」：錄音 → 轉逐字稿 → 產生摘要。Claude Meetings 的差異是「會中即時協作」：Claude 是一個能聽、能說、能動手的參與者，在討論的同時就把內容具體化成 artifact（文件、白板、表格），大家看著它長出來、當場糾正。這延續了本週稍早推出的 Claude Whiteboards / Sheets / Data——那些是 Claude 能產出的「工作面」，Meetings 則是把這些工作面接進即時對話的入口。

技術上可以把它想成一個長時間運作的 agent：輸入是即時語音串流與聊天訊息，輸出是對共享 artifact 的持續增量修改，且修改過程對所有人可見——本質上就是一個多人即時協作編輯器裡多了一位 AI 協作者。

**前端工程師實際應用：**
- **跟你工作的關聯：** 需求討論、設計 review、sprint planning 這類會議最常產生「會後沒人整理、規格散落各處」的問題。若會議中就能直接產出結構化的規格文件與待辦清單，前端拿到的需求會清楚很多。
- **具體場景：** 和 PM、設計師在 Google Meet 討論新的結帳流程時，請 Claude 當場把討論畫成使用者流程白板，並列出每個畫面需要的元件、狀態（loading / error / empty）和 API 欄位；會後直接把這份文件丟給 Claude Code 當作實作的 spec。
- **這週可以嘗試：** 就算團隊還沒開通 Meetings，也可以練習這個流程：下次需求會議結束後，把逐字稿或筆記貼給 Claude，請它輸出「元件清單 + 每個元件的 props 與狀態 + 待確認問題」三段式 spec，檢查和你自己理解的需求差多少。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.323 / November 12, 2026

**變更項目：**
- Added Code Mode, an experimental opt-in in which Claude writes JavaScript to call its tools（新增實驗性、需自行開啟的 Code Mode：Claude 改以撰寫 JavaScript 的方式呼叫工具；組織也可統一關閉）
- Added `engines["claude-code"]` to plugin.json（plugin.json 新增 `engines["claude-code"]`：不在宣告版本範圍內的 plugin 不會被安裝、更新或載入，安裝時會挑選符合的最新版本）
- Added type checking of a plugin’s TypeScript hooks module to `claude plugin validate`（`claude plugin validate` 會對 plugin 的 TypeScript hooks 模組做型別檢查，問題以 warning 呈現，`--strict` 時視為失敗）
- Added a progress heartbeat every 30 seconds while hooks run long in `claude -p` and SDK sessions（hooks 執行很久時，每 30 秒送出心跳，避免 Claude Desktop 等宿主誤判卡住而結束回合）
- Added `.docx` support to Artifact tool asset uploads（Artifact 工具的 asset 上傳支援 .docx）
- Added a start-up warning for Bash allow rules with a `*` in a variable’s value, such as `Bash(PORT=* npm run dev)`（Bash allow rule 的變數值中含 `*` 時，啟動時會跳警告）
- Added `CLAUDE_CODE_DISABLE_AGENT_PROGRESS_SUMMARIES` and `CLAUDE_CODE_RESUME_HINT_COMMAND`（新增可關閉 subagent 進度摘要的環境變數，以及讓外部程式自訂離開時 resume 提示指令的環境變數）
- [VSCode] Added a Claude Code trust prompt before the first session in a folder you haven’t trusted; added the live output of a running Bash or PowerShell command to the chat（VS Code：在未信任的資料夾首次開 session 前會先詢問信任；執行中的 Bash / PowerShell 指令輸出會即時顯示在對話中）
- [Claude Tag] / [Code Review] / [Claude Code on the web] 多項管理與介面改進（例如 Code Review 管理頁可下載各 repo 成本 CSV）
- Changed the context window assumed for a model ID that Claude Code doesn’t recognize from 200K to 1M（無法辨識的 model ID 預設 context window 從 200K 改為 1M；可用 `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` 維持 200K）
- Changed `/security-review` to ask before Claude runs it（`/security-review` 執行前會先詢問；skills 內嵌的 git 指令在 bare repo worktree 等資料夾中會先停下等你允許）
- Changed MCP_SDK_GENERATION=v1 to run the v2 MCP client in a compatibility mode, because the v1 MCP client is removed（v1 MCP client 已移除，設定 v1 時改以相容模式跑 v2 client）
- Changed project (.mcp.json) MCP server approvals to match the server’s exact name（專案 .mcp.json 的 MCP server 核准改為嚴格比對名稱，拼法不同會重新詢問）
- Changed “don’t ask again” so an allow rule that looks like it holds a secret, or would be saved to a git-tracked settings.local.json, lasts for the session only（看起來含機密、或會寫進被 git 追蹤的 settings.local.json 的 allow rule，只在本次 session 有效、不會存檔）
- Changed the sandbox on macOS and Linux: git worktree add, move and remove now fail read-only（macOS / Linux sandbox 中 `git worktree add/move/remove` 改為唯讀失敗）
- Changed the maximum of `CLAUDE_CODE_OVERLOADED_RETRY_MAX_DELAY_MS` from 64000 to 300000（過載重試最大延遲上限從 64 秒提高到 300 秒）
- Removed the `subagentStatusLine` setting（移除 `subagentStatusLine` 設定，subagent 列一律使用預設樣式）
- 另有 21 項 improvements 與多項 bug fixes（頁面預設折疊，未逐條列出）

**核心概念（簡單說）：**
這一版最值得注意的是 **Code Mode**：一般情況下模型每呼叫一次工具，就要來回一輪（模型 → 工具 → 結果回到模型）。Code Mode 讓 Claude 直接寫一段 JavaScript，在程式裡串接多個工具呼叫、用迴圈和條件判斷處理中間結果，最後只把需要的輸出交回。好處是減少來回次數與塞進 context 的中間資料，類似把十次 REST 請求改成一次批次腳本。

其餘大多是 plugin 生態與安全性的強化：plugin 可以宣告相容的 Claude Code 版本（像 npm 的 `engines` 欄位）、TypeScript hooks 有型別檢查；權限面則收緊了含機密的 allow rule、`.mcp.json` 核准比對、sandbox 內的 git worktree 操作，以及未知模型預設 1M context window。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你寫過 Claude Code plugin 或 hooks，`engines` 與型別檢查讓你可以像維護 npm 套件一樣管理相容性；Code Mode 則對「需要大量查檔、批次修改」的前端重構任務特別有幫助。
- **具體場景：** 要把專案中 200 個元件從 `styled-components` 遷移到 Tailwind 時，開啟 Code Mode 後 Claude 可以寫一段 JS 一次性 glob 所有檔案、篩出使用特定 API 的元件、彙整成清單，而不是一個檔案一個檔案來回讀，省時也省 context。
- **這週可以嘗試：** 照 https://code.claude.com/docs/en/code-mode 的說明在個人專案開啟 Code Mode，丟一個「找出所有沒有 `alt` 屬性的 `<img>` 並列出檔案與行號」的任務，比較開啟前後的工具呼叫次數與完成速度；如果你維護 plugin，順手在 plugin.json 加上 `engines["claude-code"]` 並跑一次 `claude plugin validate --strict`。
