> （串文續則 https://x.com/trq212/status/2122438328079524159 ）

> （附兩段影片／圖片，內容為與 agents 協作設計遊戲新角色的畫面）

**繁中改寫：**
「軟體工廠」感覺只是個暫時性的問題——模型之後會學會自己幫你把工廠蓋好。

我更感興趣的問題是：要怎麼打造一個讓 agents 能「跟你一起協作」的工作空間。

舉例來說，這是我跟幾個 agents 一起替我的遊戲設計新角色的過程。

**核心概念（簡單說）：**
最近業界很流行「software factory」這個說法：用一堆 agent、pipeline、prompt 模板、CI 串成一條自動化產線，丟需求進去、吐出程式碼出來。Thariq 的觀點是，這種「蓋產線」的工作本身也會被模型吃掉——就像以前大家手刻 webpack 設定，後來框架和 CLI 幫你生好一樣，編排 agent 的鷹架很快會變成模型自己能產生的東西，不值得人花太多心力在上面。

真正難、也更有價值的是「人與 agent 的協作介面」：當好幾個 agent 同時在做事時，人要怎麼看到它們在做什麼、怎麼即時插手修正、怎麼把品味和判斷注入進去？他用自己做遊戲角色當例子——角色設計是高度主觀、需要反覆看與調整的工作，不適合「丟進產線等成品」，而是需要一個像共用畫布一樣的 workspace，人和 agent 在上面來回迭代。這也呼應前幾天 Anthropic 推的 Claude Meetings（Claude 作為可見參與者、邊做邊讓大家修正）的方向。

**前端工程師實際應用：**
- **跟你工作的關聯：** 「協作 workspace」本質上是一個 UI/UX 問題——即時狀態呈現、可中斷、可回溯、多人（多 agent）同時編輯，這些正是前端擅長的領域。未來 agent 工具的差異化很可能落在介面上，而不是後端編排。
- **具體場景：** 你用 Claude Code 開了幾個 subagent 同時改 React 元件庫（一個改樣式、一個補 Storybook story、一個寫 Vitest 測試）。與其等它們全部跑完再看 diff，不如開著 Storybook 的 dev server 即時看每個元件的變化，發現方向不對時立刻在對話中修正某個 agent——你在打造的就是一個「人看得見、改得動」的協作環境。
- **這週可以嘗試：** 挑一個小功能，刻意不寫長篇自動化 pipeline，而是開著瀏覽器預覽 + Claude Code 並排，每輪只讓 agent 做一小步、你看畫面後給回饋；記下哪些時刻你最需要「看見 agent 在做什麼」，那就是值得自己做小工具（例如 status line、mod 或預覽頁）補強的地方。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.326 / November 16, 2026

**變更項目：**（本版有 11 項新增、約 70 項變更、59 項改進、233 項修正，以下節錄與日常開發最相關的部分）
- Added support for turning on Code Mode while agent teams are enabled — agent teams 開啟時也能啟用 Code Mode；已開過的話，有 teams 的 session 會直接以 Code Mode 啟動。
- Added a startup warning when an `--allowedTools`, `--disallowedTools` or `--tools` value has an entry that doesn't look like a complete rule — CLI 工具規則寫得不完整時，啟動就會警告。
- Added a row to `/status` that says when your provider or an environment variable such as `DISABLE_TELEMETRY` turns features off — `/status` 會告訴你哪些功能被 provider 或環境變數關掉了。
- Added Ctrl+O to show hidden startup notices — 用 Ctrl+O 查看被隱藏的啟動提示。
- Added `overflowX="scroll"` on a mod's Box, and `maxLines` and `wrap="clip"` on its Text — mod 的 UI 元件支援水平捲動、行數上限與裁切。
- [VSCode] Added a `claudeCode.promptSuggestions` setting that turns prompt suggestions off — VS Code 可關閉 prompt 建議。
- Changed terminal and VS Code sessions with no mode set to start in auto mode, not Manual mode, when your organization's policy hasn't loaded — 組織政策尚未載入時，未設定模式的 session 改以 auto mode 啟動。
- Changed a hook's `"decision": "block"` to hold in more cases, so a hook that always prints one may start blocking calls — hook 回傳 `block` 會在更多情況生效，總是輸出 block 的 hook 可能開始真的擋下呼叫。
- Changed sandboxed commands on macOS, Linux and WSL to no longer write to some sensitive home folders by default; some can be allowed with `sandbox.filesystem.allowWrite` — sandbox 預設不能寫入某些敏感的家目錄資料夾，可用 `sandbox.filesystem.allowWrite` 放行。
- Changed the Bash sandbox to set aside unexpected entries in a repository's `.git` folder after a command — 指令執行後，`.git` 裡出現的異常檔案會被移到一旁。
- Changed Claude's file tools to refuse writes to Claude Code's sign-in files, such as `.credentials.json` — 檔案工具拒絕寫入登入憑證檔。
- Changed some `cp` and `mv` commands to ask first — 部分 `cp`、`mv` 指令改為先詢問。
- Changed auto mode to ignore some wildcard shell allow rules, such as ones that name no program or that start with `$HOME` — auto mode 會忽略過於寬鬆的萬用字元 allow 規則，改交給安全檢查判斷。
- Changed the PowerShell tool to ask before some more commands; unattended runs refuse them unless an allow rule, auto mode or bypass permissions mode allows them — PowerShell 工具有更多指令需要詢問，無人值守時會被拒絕。
- Changed the `/claude-api` skill to build agents on Managed Agents by default — `/claude-api` skill 預設改用 Managed Agents 建 agent。
- Changed first-run setup to preselect the "Auto (match terminal)" theme instead of Dark mode — 首次設定預設主題改為跟隨終端機。
- Improved response time after reading or editing files, most noticeably on Windows; Windows: Improved the speed of a session's first Bash command by about a second — 讀寫檔案後回應更快，Windows 第一個 Bash 指令快約 1 秒。
- Improved Remote Control: replies now stream to your phone or browser as they are written — Remote Control 回覆改為串流顯示。
- Improved `/update-config` to use about 13,000 tokens of context instead of 93,000 — `/update-config` context 用量從 9.3 萬降到 1.3 萬 tokens。
- Improved the error for a settings or `.mcp.json` file with broken JSON: it now gives the line and column — 設定檔或 `.mcp.json` JSON 壞掉時會指出行與欄。
- Improved hook failures, blocks and timeouts in the transcript: failures are now red, a hook that stops Claude is yellow, and the reason is shown — hook 失敗／阻擋在對話紀錄中會以顏色區分並顯示原因。
- Fixed parallel MCP tool calls reading another call's saved result when two long results arrived in the same millisecond — 修正平行 MCP 呼叫在同一毫秒回傳長結果時讀到彼此結果的問題。
- Fixed grep in the Bash tool silently skipping some text files — 修正 Bash 工具中 grep 靜默略過部分文字檔。
- Fixed Windows paths in Claude's responses losing the backslash before folders like `.claude` or `_build` — 修正 Windows 路徑在回覆中遺失反斜線。
- Fixed bold text showing as raw `**` in Japanese, Chinese and Korean replies when it starts or ends with punctuation — 修正中日韓回覆中，粗體前後接標點時顯示成原始 `**` 的問題。
- Fixed asterisks disappearing from your own prompts in the transcript, such as `src/**/*.ts` — 修正 prompt 中 `src/**/*.ts` 這類星號在紀錄中消失。
- Fixed an error when `max_tokens` exceeded the model's limit: Claude Code now retries with the maximum the API reports — `max_tokens` 超過上限時改為自動以 API 回報的最大值重試。
- [VSCode] Improved Edit and Write speed for files not open in a tab — VS Code 中編輯未開啟分頁的檔案速度更快。

**核心概念（簡單說）：**
2.1.326 是一個超大型的「打磨 + 收緊」版本，延續 2.1.325 的安全強化主軸：sandbox 預設能寫的範圍更小（敏感家目錄、`.git` 異常檔案、登入憑證檔都被保護）、`cp`/`mv`/PowerShell/過寬的萬用字元 allow 規則都更常要求確認，hook 的 `block` 決策也會在更多情況真正生效。可以把它想成把 ESLint 規則從 `warn` 升級到 `error`——原本「剛好能跑」的寬鬆設定，現在可能開始被擋。

另一半是大量體驗改善：Windows 上檔案操作與第一個 Bash 指令變快、Remote Control 串流回覆、設定檔 JSON 錯誤會指出行列、`/update-config` 大幅節省 context，以及兩百多項 UI、輸入、渲染相關的修正（包含中文回覆粗體顯示錯誤、glob 星號消失這類對中文使用者很有感的問題）。Code Mode 也能跟 agent teams 一起用了，代表多 agent 協作與程式化工具呼叫開始整合。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你有排程任務或 CI 用 Claude Code 跑 `npm`／`pnpm` 指令、用萬用字元 allow 規則（如 `Bash(*)` 或 `Bash($HOME/...)`）偷懶，或在 Windows 用 PowerShell 跑自動化，這版很可能讓原本無人值守的流程開始卡在權限詢問或被拒。
- **具體場景：** 你的專案 `.claude/settings.json` 有 `"Bash(*)"` 這類寬鬆規則，排程任務在 auto mode 跑 `pnpm build && pnpm test`。升級後寬鬆規則會被忽略、交給安全檢查判斷；建議改成精確規則如 `Bash(pnpm build)`、`Bash(pnpm test:*)`。若建置腳本需要寫入 `~/.cache` 之類的家目錄資料夾，記得在 `sandbox.filesystem.allowWrite` 加上路徑。
- **這週可以嘗試：** 升級後先跑一次 `/status` 看有哪些功能被關掉，再用 `claude --allowedTools ...` 啟動看有沒有新的「規則不完整」警告；接著手動跑一次你的排程任務，把出現的權限詢問逐一轉成精確的 allow 規則。
