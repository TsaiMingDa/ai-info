## Claude Code · Changelog

**版本號 / 日期：** 2.1.306 / October 21, 2026

**變更項目：**
- Fixed `claude -p` inside cloud sessions reporting "Not logged in" when started without the session's environment variables — 修正在 cloud session 裡、沒帶 session 環境變數就啟動 `claude -p` 時，誤報「Not logged in」的問題
- Fixed an API error being replaced by "prompt is too long", and an unneeded compaction, in sessions with many MCP tools — 修正掛了大量 MCP 工具的 session 中，真正的 API 錯誤被誤顯示成「prompt is too long」，還觸發了不必要的 compaction

**核心概念（簡單說）：**
2.1.306 是一個小型修補版，兩個修正都跟「錯誤訊息騙人」有關。第一個是在 cloud session 裡用 `claude -p`（非互動、headless 模式）呼叫 Claude Code 時，如果子程序沒繼承到 session 的環境變數，就會被判定成未登入；第二個是 MCP 工具一多，tool 定義本身就會佔掉大量 context，原本某個 API 錯誤被誤判成「prompt 太長」，Claude Code 便以為要壓縮對話而跑了一次 compaction，結果把有用的上下文壓掉了，真正的錯誤卻被藏起來。

可以把它想成前端的 error boundary 把所有例外都顯示成「網路錯誤」：使用者看到的訊息跟根因完全不同，除錯方向就會整個跑偏。這版讓錯誤回到它原本的樣子。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你在 CI 或 script 裡用 `claude -p` 跑自動化（例如自動產生 changelog、檢查 a11y），或在專案 `.mcp.json` 掛了 chrome-devtools、Playwright、Figma 等多個 MCP server，這兩個 bug 都可能讓你誤以為是登入或 context 不夠的問題。
- **具體場景：** 你在 cloud session 裡寫了一個 npm script `"review:copy": "claude -p '檢查 src/locales 的翻譯缺漏'"`，以前子程序會莫名報未登入；或你同時開著 chrome-devtools 與 Playwright MCP 做 E2E 除錯，突然看到「prompt is too long」且對話被壓縮，其實是另一個 API 錯誤。升級後這兩種情況都會顯示正確原因。
- **這週可以嘗試：** 執行 `claude update` 升到 2.1.306，並用 `/mcp` 檢查目前專案掛了哪些 MCP server，把很少用到的先停用，減少 tool 定義佔用的 context。

**版本號 / 日期：** 2.1.305 / October 20, 2026

**變更項目：**
- Added `sandbox.allowNestedUserNamespaces` so sandboxed commands on Linux can create user namespaces (Chromium, rootless podman) — 新增設定，讓 Linux sandbox 裡的指令可以建立 user namespace（例如 Chromium、rootless podman）；注意這會讓它們繞過 sandbox 的檔案保護
- Added `CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS` — 無人值守的重試模式（`CLAUDE_CODE_RETRY_WATCHDOG`）可定期重新檢查，在用量限制提前解除時就繼續執行
- [VSCode] Added a "Running start-up hooks" spinner status while SessionStart or Setup hooks run — VS Code 在執行 SessionStart / Setup hook 時顯示「Running start-up hooks」狀態，並支援螢幕閱讀器播報
- [Claude Tag] Added public Slack channels Claude hasn't joined to the admin Add place search — Claude Tag 管理後台可搜尋到 Claude 尚未加入的公開 Slack 頻道並直接設定
- Changed `allowedMcpServers` to stop filtering `managed-mcp.json` stdio servers that use `${VAR}` only in `env` — 只在 `env` 用到 `${VAR}` 的受管 stdio MCP server 不再被 allowlist 過濾，升級後可能會多載入；想擋掉請改用 `deniedMcpServers`
- Changed the `/artifacts` delete confirmation to take 1 or Enter to keep, 2 to delete, and Esc to cancel; y and n no longer answer it — `/artifacts` 刪除確認改為 1／Enter 保留、2 刪除、Esc 取消，不再接受 y / n
- Changed a mod's docked pane to stay within 45% of the terminal's width — mod 的停靠面板寬度最多佔終端機 45%
- [Code Review] Changed re-reviews so they no longer open with LGTM while earlier blocking findings are still open — 先前的阻擋性問題還沒解決時，Code Review 的重新審查不會再以 LGTM 開頭
- Improved `/usage`: each warning is now a one-line fix that names its source, and `f` applies the fixes — `/usage` 每個警告都附上來源與一行修正建議，按 `f` 直接套用（VS Code 與 `/doctor` 也有）
- Improved MCP consent dialogs so an Enter meant for the prompt is less likely to be taken as Accept — 降低原本要送出 prompt 的 Enter 被誤判成同意 MCP 授權的機率
- Fixed every request failing on Vertex, Bedrock and other providers when the endpoint or a gateway rejects tool search (a 2.1.304 regression) — 修正 2.1.304 引入的回歸：gateway 拒絕 tool search 時所有請求失敗，現在會自動不帶它重試
- Fixed `/effort` and `/autocompact` settings not applying when the model name differed from a `modelOverrides` value by letter case or a `[1m]` tag — 修正模型名稱大小寫或 `[1m]` 標記不同時，`/effort`、`/autocompact` 設定沒生效
- Fixed new worktrees in a bare repository sometimes starting from local HEAD instead of the default branch — 修正 bare repo 新建的 worktree 有時從本地 HEAD 而非預設分支開始，且未變更的 subagent worktree 沒被清除
- Fixed Bash commands on a full disk failing with a raw ENOSPC file path — 磁碟滿時改顯示「磁碟已滿、指令沒有執行」，而不是一串 ENOSPC 路徑
- Fixed an MCP server passed by a cloud session or the SDK's `setMcpServers` being replaced by a same-named server from your own settings — 修正 cloud session／SDK 指定的 MCP server 被你設定中同名 server 蓋掉
- Fixed Workflow resume re-running already-completed `pipeline()` and `parallel()` agents — Workflow 恢復執行時不再重跑已完成的 agent，改從 journal 取結果
- Fixed screen reader mode: search boxes now say "Search:" instead of a symbol VoiceOver read as "telephone recorder" — 螢幕閱讀器模式下搜尋框改念「Search:」，不再被 VoiceOver 念成「telephone recorder」
- [Code Review] Fixed Code Review sometimes not reviewing the newest commit when several pushes landed during a review — 修正審查期間連續 push 時，Code Review 有時沒審到最新 commit
- （另有其他 improvements 與共 22 項 bug fixes，詳見原始 changelog）

**核心概念（簡單說）：**
2.1.305 的主軸是「設定與權限邊界變得更精確」。最需要注意的是兩個行為改變：一是 `allowedMcpServers` 不再過濾某類受管 stdio MCP server，升級後可能突然多出原本被擋掉的 server；二是 `sandbox.allowNestedUserNamespaces` 讓 Linux sandbox 能跑 headless Chromium 這類需要 user namespace 的程式，但代價是這些程式可以繞過 sandbox 的檔案保護——方便與安全之間的取捨，必須自己明確打開。

另一個重點是修掉 2.1.304 的回歸：透過 Vertex、Bedrock 或公司內部 LLM gateway 使用時，tool search 被拒會讓「每個請求都失敗」，現在會自動降級重試。其餘多是 UX 修正，例如 `/usage` 的一鍵修正、Code Review 不會在問題未解時說 LGTM、刪除 artifact 改用數字選項避免手滑。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端常在 Linux CI 或 devcontainer 裡用 Claude Code 跑 Playwright / Puppeteer 等 headless Chromium 測試，以前在 sandbox 裡可能因 namespace 限制直接啟動失敗；另外公司走內部 gateway 的人，若 2.1.304 開始整個壞掉，就是這版要修的。
- **具體場景：** 你在 GitHub Codespaces（Linux）裡讓 Claude Code 跑 `npx playwright test` 做視覺回歸，Chromium 因無法建立 user namespace 而崩潰；可以在專案 `.claude/settings.json` 的 `sandbox` 區塊設定 `allowNestedUserNamespaces: true`，但要清楚這等於放寬了檔案保護，最好只在拋棄式容器裡開。
- **這週可以嘗試：** 執行 `claude update` 後打開 `/usage` 看看有沒有警告，按 `f` 套用建議修正；若團隊有用 managed settings，檢查一下升級後 `/mcp` 是否多出預期外的 server，必要時加進 `deniedMcpServers`。
