**繁中改寫：**
教宗良十四世於 2026 年 5 月 25 日發布他就任以來的第一份通諭，題為《Magnifica Humanitas：論在人工智慧時代保護人類》，針對 AI 的風險提出宗教層面的道德宣示。Anthropic 共同創辦人 Chris Olah 受邀出席梵蒂岡的發布典禮並發表演說，成為罕見的科技界代表在宗教場合為 AI 監管背書的案例。

Olah 在演說中強調，AI 的走向不能只交給科技公司自行決定，需要宗教領袖、各國政府與公民社會共同參與監督。他直言 AI 實驗室需要「能夠指出我們何時失敗的知情批評者」，以及「不會被利益收買的道德聲音」。

**核心概念（簡單說）：**
這件事的重要性不在宗教本身，而在它揭示了一個結構性問題：目前最有能力監督 AI 的，幾乎只有 AI 公司自己——而這本質上是個利益衝突。Anthropic 透過 Olah 出席梵蒂岡、公開呼籲外部監督，等於在全球最具象徵意義的舞台上承認「我們需要被監督」。

這對開發者的實際意義是：AI 監管的範圍和力道正在快速擴大。歐盟 AI Act 已在實施，現在宗教機構也開始施壓。未來在產品裡整合 AI 的方式，可能需要符合越來越多的可解釋性（explainability）、透明度、和使用限制要求。

- **具體場景：** 如果你在做一個內容生成平台，試著在 UI 上加一個「此內容由 AI 輔助生成」的標籤，同時在 API response 裡記錄使用了哪個模型和 prompt 版本——這是很多監管框架要求的最低程度透明度。

**版本號 / 日期：** 2.1.149 / May 22, 2026

**變更項目：**
- `/usage` 現在顯示每個分類對 limits 使用量的細分——skills、subagents、plugins、per-MCP-server 各自佔多少（`/usage` now shows a per-category breakdown of what's driving your limits usage）
- `/diff` 詳細檢視畫面現在支援鍵盤捲動：方向鍵、`j`/`k`、`PgUp`/`PgDn`、`Space`、`Home`/`End`（`/diff` detail view can now be scrolled with the keyboard）
- Markdown 輸出現在會渲染 GFM task list checkboxes（`- [ ] todo` / `- [x] done`），而非純粹 bullet（Markdown output now renders GFM task list checkboxes instead of plain bullets）
- Enterprise：新增 `allowAllClaudeAiMcps` managed setting，可同時載入 claude.ai cloud MCP connectors 和 `managed-mcp.json`（Enterprise: added the `allowAllClaudeAiMcps` managed setting）
- **安全修復**：修正 PowerShell 內建 `cd` 函式（`cd..`、`cd\`、`cd~`、`X:`）可無聲更改工作目錄、繞過沙箱限制的漏洞（Fixed a PowerShell permission bypass）
- 修正 git worktrees 的 sandbox write allowlist 覆蓋整個主 repo 根目錄的問題（Fixed the sandbox write allowlist in git worktrees covering the entire main repository root）
- 修正 `find` 在 Bash tool 中耗盡 macOS 系統 file/vnode table 導致主機當機的問題（Fixed `find` in the Bash tool exhausting the macOS system file/vnode table）
- 修正 `/feedback` 報告無法涵蓋 context compaction 之前對話的問題（Improved `/feedback` reports to include the conversation before context compaction）
- 修正多項 UI 問題：thinking spinner 殘留、slash-command 提示截斷、`/config` 誤報變更、session 重新命名不同步等

**核心概念（簡單說）：**
這個版本同時帶來實用 UX 改善和重要安全修復。

UX 亮點：`/usage` 終於可以看到詳細用量分類，讓你知道是哪個功能在吃掉你的配額。`/diff` 支援鍵盤捲動，讓 code review 工作流不需要摸滑鼠。

安全亮點：修復了數個 PowerShell 環境下可繞過沙箱限制的漏洞——這些漏洞讓惡意的 CLAUDE.md 或工具呼叫能悄悄讀取沙箱外的檔案。在 Windows + PowerShell 環境下使用 Claude Code 的人應該盡快升級。

**前端工程師實際應用：**
- **跟你工作的關聯：** `/usage` 的分類細分讓你能追蹤哪個 MCP server 或 skill 在消耗大量配額，有助於優化 Claude Code 的使用效率和成本。`/diff` 的鍵盤導航讓 Claude Code 內建的 diff 審查體驗更接近 Vim 的操作習慣。
- **具體場景：** 跑完一個大型 PR 後，執行 `/usage` 查看 subagents vs. skills 各自的用量，找出哪個工作流程最耗費資源；在 code review 時用 `/diff` 搭配 `j`/`k` 快速瀏覽改動，效率比切換到 GitHub UI 更高。
- **這週可以嘗試：** 在你下一個 Claude Code session 結束前執行 `/usage`，觀察自己的使用分佈——是 subagents 佔最多，還是 MCP tools？這個數字可以幫你判斷哪個工作模式最 cost-effective。

**版本號 / 日期：** 2.1.147 / May 21, 2026

**變更項目：**
- Pinned background sessions（在 `claude agents` 裡用 `Ctrl+T` 釘選的 session）現在在閒置時保持存活，Claude Code 更新時會原地重啟套用新版（Pinned background sessions now stay alive when idle, are restarted in place to apply Claude Code updates）
- `/simplify` 更名為 `/code-review`，現在可用 effort 等級指定審查深度（如 `/code-review high`）；加 `--comment` 可直接把發現的問題發布為 GitHub PR inline comments（Renamed `/simplify` to `/code-review`）
- 改善自動更新器：現在會重試暫時性的網路失敗，並回報具體的錯誤類型和 OS 錯誤碼（Improved auto-updater）
- 改善大型檔案 edit 的 diff 渲染效能（Improved diff rendering performance for large file edits）
- Prompt history 不再記錄連續重複的 entry，重新送出同一個 prompt 不會多一筆記錄（Prompt history no longer records consecutive duplicate entries）

**核心概念（簡單說）：**
這個版本最值得注意的是 `/code-review` 的升級。原本的 `/simplify` 只是清理和修正現有程式碼的工具，現在的 `/code-review` 是一個正式的 code review 工具，可以用不同的 effort 等級深度掃描，而且可以直接把發現的 bug 以 GitHub PR inline comment 的形式發布——這讓 Claude Code 第一次能真正「參與」你的 PR review 流程，而不只是在終端機裡吐出一串文字讓你自己複製。

Pinned background sessions 的改善讓長時間跑的代理人任務更穩定：不再因為太久沒互動就被砍掉，更新時也不需要手動重啟。

**前端工程師實際應用：**
- **跟你工作的關聯：** `/code-review --comment` 讓 Claude 直接在 GitHub PR 上留 inline review comments，可以作為你的自動化 code review 工具，在人工 review 之前先過濾明顯的問題。
- **具體場景：** 在你 push 一個 PR 之後，在 Claude Code 裡執行 `/code-review high --comment`，Claude 會以高深度模式審查你的 diff，並直接在 GitHub PR 上標記有問題的行。這特別適合在 solo 開發或小型團隊裡沒有足夠人手做 thorough review 的情況。
- **這週可以嘗試：** 對下一個 PR 跑一次 `/code-review medium --comment`，看看 Claude 找到的問題和你自己的判斷有多少重疊——這可以幫你校準對這個工具的信任程度，決定要把它放在 workflow 的哪個位置。
