>

**繁中改寫：**
Boris Cherny 徵求大家的意見：這是 Anthropic 團隊對於如何讓 Claude Code 變得更可擴充的早期構想，做法有點大膽但也讓人蠻興奮的，詳情放在 GitHub issue 裡。他轉推的 ClaudeDevs 貼文提到，團隊正在探索一種新方式讓使用者擴充、客製化 Claude Code：**Function Hooks**。目前放了幾支影片展示未來可能做到的事，功能還沒正式推出，希望大家到 GitHub issue 留意見。

**核心概念（簡單說）：**
Function Hooks 是 Claude Code 團隊正在評估的新擴充機制，讓開發者能在 Claude Code 執行的特定時機「掛上」自己的邏輯（例如工具呼叫前後、寫檔前後），類似前端框架裡的 lifecycle hook 或 middleware 概念。跟現有的 plugin hooks 不同的是，這聽起來更偏向函式層級、更細顆粒度的攔截點，目的是讓 Claude Code 的行為可以被更深度地客製化，而不只是靠設定檔調整。

**前端工程師實際應用：**
- **跟你工作的關聯：** Claude Code 是不少前端工程師每天寫程式的主要工具，Hooks 機制直接決定了你能不能把公司內部規範（lint、格式化、安全掃描）自動綁進 Claude 的工作流程。
- **具體場景：** 例如你想在 Claude Code 每次寫入 `.tsx` 檔案後自動跑 `eslint --fix`，或在它讀取程式碼前自動注入專案的 coding style 指南，Function Hooks 未來可能就是官方支援這類需求的正式擴充點。
- **這週可以嘗試：** 到 [GitHub issue #91870](https://github.com/anthropics/claude-code/issues/91870) 看展示影片，了解目前規劃的攔截時機，並留言提出你在前端專案中最想要的 hook 使用情境。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.260 / September 3, 2026

**變更項目：**
- Added a diff panel that opens beside the conversation in fullscreen mode and shows your uncommitted changes as Claude edits; toggle it with `/diff` — 新增了一個在全螢幕模式下並排顯示的 diff 面板，可即時看到 Claude 編輯過程中的未提交變更，用 `/diff` 切換開關。
- Added a likely cause for prompt-cache misses (e.g. tool definitions or system prompt changed, idle past the TTL) to `/cost` and the status line's `prompt_cache` field — `/cost` 與狀態列現在會提示 prompt cache miss 的可能原因（例如工具定義或 system prompt 有變、閒置超過 TTL）。
- Added `/reload-plugins` to headless sessions, so it appears in the Claude Code Desktop and SDK command lists — headless session（桌面版、SDK）現在也能用 `/reload-plugins` 重新載入外掛。
- Added a text form of `/advisor` (`/advisor`, `/advisor <model>`, `/advisor off`) for the desktop app, Remote Control, and other headless sessions — 新增純文字版的 `/advisor` 指令，desktop app、Remote Control 與 headless 場景都能用。
- Fixed Edit/Write/Read permission rules whose path contains parentheses being dropped as invalid or ignored by the Bash sandbox, which left "read-only" folders writable — 修正含括號路徑的權限規則被誤判無效、導致原本設定「唯讀」的資料夾其實仍可被寫入的安全性問題。
- Fixed one file permission rule with an uncompilable pattern (e.g. an unclosed `[`) making every file edit fail with `Invalid regular expression` — 修正一條規則寫錯（例如少寫 `]`）就會讓所有檔案編輯全部失敗的問題。
- Fixed the `/model` picker not showing Fable 5.1 for organizations that can use it, which was only accepted when typed as `/model claude-fable-5-1` — 修正 `/model` 選單沒列出組織其實可以使用的 Fable 5.1，先前只能手動打指令名稱才能切換。
- Fixed prompt caching on Claude Fable 5.1 not covering the context attached after tool results, so it was re-sent as uncached input on every tool-call turn — 修正 Fable 5.1 的 prompt cache 沒涵蓋到工具結果之後附加的內容，導致每次工具呼叫都重複計費未快取的 token。
- Fixed IDE line selections being dropped when running a skill or slash command (the "N lines selected" context now reaches Claude) — 修正在 IDE 選取程式碼片段後執行 skill 或斜線指令時，選取範圍沒有正確傳給 Claude 的問題。
- Fixed an extra browser tab opening when an artifact is published in a session you're driving from claude.ai, the desktop app, or mobile — 修正從 claude.ai、桌面版或手機操作時，發布 artifact 會多開出一個瀏覽器分頁的問題。
- Reverted the 2.1.259 change applying `Read()` deny rules to Bash arguments; it denied `npm run build` under a `Read(./**/build/**)` rule in every mode — 撤銷上個版本（2.1.259）把 `Read()` 拒絕規則套用到 Bash 指令參數的變更，因為它會誤擋像 `npm run build` 這類指令。
- Improved auto-compact for 1M-context models: Opus and Fable sessions now compact shortly before the 1M-token limit — 改善 1M context 模型（Opus、Fable）的自動壓縮時機，會在接近 1M token 上限前提早壓縮。
- Improved `/effort` on Claude Fable 5.1 so changing effort mid-session no longer invalidates the prompt cache — 改善 Fable 5.1 的 `/effort`，session 中途切換 effort 等級不會再讓 prompt cache 失效。

**核心概念（簡單說）：**
2.1.260 是一次份量很大的維運＋功能更新：新增了可視化的 diff 面板與 prompt cache 診斷資訊，修掉一批權限規則、IDE 選取範圍傳遞、model 切換與 artifact 發布相關的 bug，並當機立斷撤銷了前一版本（2.1.259）一個誤傷 `npm run build` 等常見指令的權限規則變更。整體方向是讓 Claude Code 在安全性（權限規則正確性）與日常操作體感（diff 面板、prompt cache 提示）上更可靠。

**前端工程師實際應用：**
- **跟你工作的關聯：** 這些修正直接影響你每天用 Claude Code 寫前端程式的體驗，尤其是新的 `/diff` 面板跟 IDE 選取範圍傳遞的修正，會改變你 review Claude 改動的方式。
- **具體場景：** 在 VS Code 裡選取一段 React 元件程式碼、呼叫自訂 skill 要求「只重構這段」，先前選取範圍可能沒被正確帶入 Claude；升級後可以放心用選取範圍限定修改對象。另外開著 `/diff` 面板邊看 Claude 編輯邊確認變更，不用每次切到終端機打 `git diff`。
- **這週可以嘗試：** 升級到 2.1.260 後，實際測試一次「選取程式碼片段 + 執行慣用 skill」的流程，並開啟 `/diff` 面板觀察 Claude 編輯時的即時 diff，順便檢查自己專案裡有沒有含括號的權限規則（例如路徑帶 `(name)`）需要重新驗證是否生效。
