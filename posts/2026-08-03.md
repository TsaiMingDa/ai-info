**原文網址：** [https://x.com/trq212/status/2083977795290734975](https://x.com/trq212/status/2083977795290734975)

**原文：**
> you can already see Jevons paradox at work in mathematics
>
> there is more happening, it is easier to understand and mathematicians have more time to discuss it with us at higher abstraction levels
>
> demand for people who think and know about math will go up

**繁中改寫：**
其實你已經可以在數學領域看到傑文斯悖論（Jevons paradox）的效應了——現在有更多數學活動在發生、更容易被理解，數學家也有更多時間可以在更高抽象層次上跟我們（AI）討論。這代表懂數學、會思考數學的人的需求反而會上升。

**核心概念（簡單說）：**
Jevons paradox（傑文斯悖論）原本是經濟學概念：當資源使用效率提升、成本下降時，總消耗量反而會增加，而不是減少。Thariq 把這個概念套用在 AI 對數學的影響上——AI 讓數學推導、驗證、探索變得更容易、更便宜，結果不是「數學家變得不需要」，而是數學活動的總量爆炸性增加，進而讓「真正懂數學、能提出好問題、能在高抽象層次思考」的人才變得更稀缺、更有價值。這跟軟體開發的邏輯類似：AI 讓寫程式變便宜，但也讓「軟體想做的事」暴增，反而讓真正懂架構、懂系統設計的工程師更搶手。

**前端工程師實際應用：**
- **跟你工作的關聯：** 這個邏輯完全可以套用到「AI 輔助寫程式」上——當 Claude Code 這類工具讓寫 code 的門檻降低、產出量提升時，前端工程師的價值不會消失，反而會往「更高抽象層次」移動：懂系統設計、懂使用者體驗、懂如何跟 AI 溝通需求的人會更值錢。
- **具體場景：** 想像你用 Claude Code 一次產生十個元件的初稿，這時候比起「手刻程式碼」的能力，你更需要具備「快速審查、判斷架構是否合理、抓出邊界情況」的能力——這就是「更高抽象層次的思考」在前端工作中的體現。
- **這週可以嘗試：** 挑一個你目前手動刻很久的元件或流程，試著用 Claude Code 產生初稿，然後把重心放在「審查與抽象層次的判斷」上，感受一下這種角色轉換。

這則是延續上一則討論的簡短回應。西洋棋是最常被拿來類比 AI 對某個領域衝擊的例子：當電腦棋力超越人類頂尖棋手後，西洋棋並沒有「消失」或「沒人下」，反而因為 AI 輔助訓練（棋手用引擎複盤、學習）讓整體棋藝水準大幅提升、圍觀與參與人口不減反增，職業棋手的存在意義從「贏過對手」轉變為「結合 AI 分析後展現更深層次的理解與創造力」。Thariq 認為數學及其他知識領域接下來走的路徑會很像西洋棋這樣。

**前端工程師實際應用：**
- **跟你工作的關聯：** 這跟「AI 會不會取代工程師」的討論直接相關——西洋棋的例子顯示，AI 超越人類後，人類角色轉變而非消失，前端工程師的角色也很可能往「結合 AI 輸出、加上人類判斷與品味」的方向演化。
- **具體場景：** 就像西洋棋手用引擎複盤精進棋藝，你也可以把 Claude Code 產出的程式碼當作學習素材，反查它為什麼這樣設計、有沒有更好的做法，藉此提升自己的架構判斷力，而不是單純接受它的輸出。
- **這週可以嘗試：** 找一段 Claude Code 幫你寫的程式碼，花 10 分鐘像「複盤」一樣分析它的設計選擇，寫下你認同或不認同的地方。
