- **跟你工作的關聯：** 如果你常用 Claude Code desktop 跑比較長時間的任務（例如大型重構、跑很多輪測試修正），用量額度用完中斷是常見的痛點，這個功能能減少你手動盯著、等額度重置再手動繼續的心力。
- **具體場景：** 你排了一個晚上讓 Claude Code 跑完一個大型 migration 任務，結果半夜額度用完卡住了；開啟 auto-continue 後，額度重置它會自己接著跑完，你早上起來就能看到完整結果，而不是卡在一半。

> A weird experiment I've been trying the last few weeks is having Claude take over day-to-day maintenance of our apps. Seeing early signs of life that this might be possible.
>
> The setup is straightforward: we have a Slack channel called proj-claude-maintains-apps. In it, Claude Tag runs a bunch of daily routines across iOS, Android, Desktop, web, CLI, and Agent SDK:
>
> - Crash fuzzer: open the app in a simulator and tap around to find ways to crash it, then root cause and fix the crashes
> - Dup unifier: scans the codebase for similar-yet-slightly-divergent abstractions, and puts up PRs to unify them
> - Dead-code remover: removes statically unreachable code, and adds logging to suspected dead code to check if it's really dead and if so, remove it the next day
> - Abstraction police: fixes leaky abstractions
> - a bunch more..
>
> Results have been surprisingly positive. Over the last few weeks, these routines have opened 388 PRs across our repos, 180 of which we merged after Claude Code Review + human review. We're now thinking about how to streamline this to make merging these kinds of mechanical changes easier.
>
> Claude generally gets these PRs right on the first shot, and if it doesn't, we ask Claude to tune its routines so it's better the next day. Sometimes it takes a few days of tuning.
>
> To try a similar workflow, ask Claude Code or Tag, or create some routines directly at https://claude.ai/code/routines. A few of the actual prompts I used below.
>
> Has anyone experimented with similar workflows?

**繁中改寫：**
Boris Cherny 分享他這幾週在做的一個實驗：讓 Claude 接手日常維護 apps 的工作。具體做法是開一個叫 proj-claude-maintains-apps 的 Slack 頻道，讓 Claude Tag 在裡面針對 iOS、Android、桌面版、網頁版、CLI、Agent SDK 跑一系列每天執行的例行任務（routines），包括：

- Crash fuzzer：在模擬器裡打開 app 亂點，找出會讓 app 崩潰的操作，然後找出根因並修好
- Dup unifier：掃描程式碼庫，找出「相似但寫法略有差異」的重複抽象層，然後開 PR 把它們統一
- Dead-code remover：移除靜態分析判斷不會被執行到的死代碼，並對「疑似死代碼」先加 log 觀察，確認真的沒人用隔天再刪
- Abstraction police：修正「洩漏的抽象層」（底層實作細節沒有真正藏乾淨）
- 還有更多其他例行任務

結果出乎意料地不錯：這幾週這些例行任務總共開了 388 個 PR，其中 180 個經過 Claude Code Review 加上人工審查後被合併。團隊現在在思考怎麼讓這類機械式變更的合併流程更順暢。Claude 通常第一次就能把 PR 寫對，寫錯的話就請它調整例行任務的 prompt，讓它隔天做得更好，有時候要調幾天才會穩定。如果想試試類似的做法，可以直接問 Claude Code 或 Tag，或是到 claude.ai/code/routines 直接建立例行任務。

**核心概念（簡單說）：**
這是把 Claude 從「你主動問它才做事」升級成「排程自動巡邏你的程式碼庫」的一種用法。概念上很像幫專案請了一個 24 小時值班的資淺工程師，每天固定跑幾個固定流程（找 crash、抓重複程式碼、清死代碼、修抽象層洩漏），發現問題就自己開 PR，人類只要負責最後審查跟偶爾調整「工作說明書」（也就是 prompt）。這展示了 Claude Code 的一個進階模式：不只是互動式問答，而是「排程 + agent + 自動開 PR」的持續性維護機制。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的專案有大量重複但寫法不一致的元件，或累積很多技術債（重複的 hooks、雷同但不完全一樣的 utility function），這種「排程例行任務」的做法提供了一個把 Claude Code 從「問答工具」升級成「自動化維護機器人」的具體範例。
- **具體場景：** 假設你的前端專案有多個團隊各自寫了功能相近的表單驗證邏輯，你可以仿照 Dup unifier 的做法，讓 Claude 定期掃描程式碼庫、找出這些相似但分歧的抽象層，自動開 PR 提議合併，你只需要做最後審查。
- **這週可以嘗試：** 去 claude.ai/code/routines 看看怎麼建立一個例行任務，挑一個小範圍先試（例如針對你專案裡某個目錄跑 dead-code 掃描），觀察 Claude 產出的 PR 品質，評估要不要擴大到整個專案。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.232 / 2026年8月13日

**變更項目：**
- Subagent forking is now on by default: a `subagent_type: "fork"` subagent inherits the full conversation and prompt cache, and non-teammate agent spawns in interactive sessions now run in the background by default（Subagent forking 現在預設開啟：`subagent_type: "fork"` 的 subagent 會繼承完整對話與 prompt cache，互動 session 中非隊友的 agent 派生現在預設在背景執行）
- Type `@` in the prompt to mention another Claude session by name; Claude then uses SendMessage to reach that session directly（在 prompt 打 `@` 可用名字提及另一個 Claude session，Claude 會直接用 SendMessage 送訊息過去）
- SendMessage now delivers to a bare name that exactly matches one live session, instead of asking to confirm with a ref first（SendMessage 現在若名稱剛好唯一對應一個現存 session，會直接送達，不用先確認 ref）
- Interactive sessions on one machine now keep unique names: starting or renaming a session to a name another live session already uses gives it a name-word-word variant and tells you（同一台機器上的互動 session 現在保持名稱唯一：新建或改名撞名時會自動變成「名字-詞-詞」變體並提示你）
- Added `/config` rows for "Dialog expiry" and "Messages from your other sessions"（`/config` 新增「對話框過期時間」與「來自其他 session 的訊息」設定項，可控管跨 session 訊息的接受/保留/拒絕）

- Updated agent panel: completed subagents hide immediately with a `/tasks` footer hint, and the "↓ N more" overflow indicator moved left for visibility（更新 agent 面板：完成的 subagent 立即隱藏並附上 `/tasks` 提示，「↓ 還有 N 個」溢出指示器移到左側更明顯）
- Remote Control: the terminal now says whether a session was taken over by another device, ended from another app, or deleted, and stops suggesting a reconnect that would undo it（Remote Control：終端機現在會說明 session 是被其他裝置接管、被其他 app 結束、還是被刪除，不會再建議一個會把狀態改回去的重連操作）
- Bash input redirections (`< file`) are now permission-checked like their argument spellings on all platforms（Bash 的輸入重導向 `< file` 現在在所有平台上都跟參數寫法一樣會做權限檢查）
- Shortened the message shown when resuming a completed background agent（恢復已完成的背景 agent 時顯示的訊息變短了）
- Cowork sessions no longer inline external `@`-imports from user-scope memory files（Cowork session 不再把使用者層級記憶檔中的外部 `@` 引用內嵌進來）
- Hardened the auto-generated cross-session messaging socket directory on shared `/tmp`: a pre-planted symlink or another user's directory is now refused instead of used（強化共用 `/tmp` 下自動產生的跨 session 訊息 socket 目錄：預先埋入的 symlink 或別的使用者目錄現在會被拒絕而非直接使用）
- Hardened the Linux filesystem sandbox against a protected-path bypass（強化 Linux 檔案系統 sandbox，防範受保護路徑被繞過）

**核心概念（簡單說）：**
這是一個內容量非常大的版本，重點集中在四塊：(1) 多 session 協作再進化——subagent forking 預設開啟、可以用 `@` 直接點名跨 session 傳訊息、同機器 session 名稱自動防撞名；(2) GitLab 生態系整合——token 遮蔽、marketplace 支援、glab CLI 防護；(3) 大量安全性強化——PowerShell / Windows symlink 權限繞過、Linux sandbox 保護路徑繞過、跨 session socket 目錄的符號連結攻擊防護等多個修正；(4) Remote Control 穩定性全面優化——重連邏輯、session 復原、狀態顯示都有多項修正。整體方向是讓 Claude Code 在「多 agent 協作」與「跨裝置遠端操作」這兩個場景下更穩、更安全。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你同時開多個 Claude Code session 分工處理不同任務，subagent forking 預設開啟跟 `@` 點名跨 session 傳訊息，能讓你的多 agent 工作流程更順；如果你的專案用 GitLab 而非 GitHub，這版終於補齊了 plugin marketplace 與 token 防護的支援。
- **具體場景：** 你在一台機器上開了三個 Claude Code session 分別處理不同 branch，之前很容易搞混或撞名，這版會自動用「名字-詞-詞」的方式防止撞名；如果你的公司內部 repo 都在自架 GitLab 上，現在可以直接把 bare gitlab.com URL 當 plugin marketplace 來源用。
- **這週可以嘗試：** 升級到 2.1.232 後，試著用 `@` 在一個 session 裡點名提及另一個正在跑的 session，體驗一下跨 session 直接傳訊息的效果；如果你用 GitLab，順便確認一下 `glab` CLI 的憑證防護設定是否符合預期。
