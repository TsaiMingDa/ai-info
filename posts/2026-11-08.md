> a pattern I'm liking: creator apps like Instagram Edits and Roblox Studio shipping with built-in MCPs, so agents can do some of the work while power users can collaborate and continue the work in tools that they're used to

**繁中改寫：**
我最近很喜歡一種模式：像 Instagram Edits、Roblox Studio 這類創作型 App 直接內建 MCP，讓 agent 先幫忙處理一部分工作，而重度使用者則可以在自己熟悉的工具裡跟 agent 協作、把作品接著做完。

**核心概念（簡單說）：**
MCP（Model Context Protocol）是讓 AI agent 呼叫外部工具的標準介面。過去常見的做法是「AI 產品自己做一套編輯器」，或者「AI 只輸出一份檔案，人再匯入工具」。Thariq 點出的趨勢是反過來：既有的專業工具（影片剪輯、遊戲編輯器）直接把自己的操作能力透過 MCP 暴露出來，agent 就像一個「多出來的使用者」，可以在同一份專案裡新增圖層、調整時間軸、擺放場景物件。

這樣的好處是工作成果不會卡在 AI 的黑盒子裡：agent 做完的東西就是原生專案格式，人可以用熟悉的 UI 微調、撤銷、繼續做。可以把它想成 Figma 的多人協作游標，只是其中一個游標是 agent。對工具開發者來說，這代表「可被 agent 操作」會變成產品功能的一部分，就像以前要提供 REST API 一樣。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你在做 Web 版的編輯器、後台或設計工具，未來「有沒有 MCP server」可能會變成跟「有沒有 API」一樣的基本需求；前端的狀態管理也要能處理「agent 在背景改了資料」的情境（即時同步、undo 歷史、衝突處理）。
- **具體場景：** 你負責一個 React + Zustand 的簡報編輯器，可以把 `addSlide`、`updateTextBlock`、`applyTheme` 這些已存在的 store action 包成 MCP tools（用 `@modelcontextprotocol/sdk` 寫一個小 server，透過 WebSocket 把指令推到前端 store）。使用者在 Claude Code 說「幫我把每頁標題統一成 32px」，畫面就即時更新，且每個 agent 操作都進到 undo stack，使用者可以 Ctrl+Z。
- **這週可以嘗試：** 挑你專案裡 3 個最常用的使用者操作，寫成 MCP tool 的 JSON schema（名稱、描述、參數），不用實作，只是檢查這些操作的參數是否清楚到「agent 也能正確呼叫」；這通常也會暴露出 API 設計上的模糊之處。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.319 / November 6, 2026

**變更項目：**
- Added support for MCP tasks in the terminal: when an MCP server runs a tool call as a task, Claude Code moves it to the background right away and tells Claude the result when it finishes — 終端機支援 MCP tasks：MCP server 以 task 形式執行的 tool call 會立刻轉到背景，完成後再把結果告訴 Claude
- Added the `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND` environment variable to make Claude Code wait for an MCP task inside its tool call — 新增環境變數，可改回在 tool call 內同步等待 MCP task
- Added `permissions.denyInsteadOfPrompting` setting: a tool call that would wait on a permission prompt is denied and the turn continues, in terminal sessions, subagents and teammates — 新設定：原本會跳權限詢問的 tool call 直接拒絕、讓流程繼續跑，不會卡住等人
- Added `/claude-api latency-optimize` to find where your Claude API code makes people wait and try faster settings against your eval — 新指令：找出你的 Claude API 程式碼哪裡讓使用者等最久，並用你的 eval 測試更快的設定
- Added the `CLAUDE_CODE_DISABLE_FEATURE_FLAGS` environment variable, which stops feature-flag fetching without turning off telemetry — 可單獨關閉 feature flag 抓取（不影響 telemetry），所有 flag 使用內建預設值
- Added an "Earlier in this session" row to `/tasks` that lists finished subagents, so you can reopen one and message it even after it leaves the list or you restart — `/tasks` 新增「本 session 稍早」列，已結束的 subagent 也能重新打開並傳訊息
- Added a warning when your claude.ai login ends and Claude Code continues on the sign-in from `ant auth login`, which bills usage to your Claude Console organization — claude.ai 登入失效、改用 `ant auth login` 的 Console 帳號計費時會跳警告
- Added spend for today, this week and this month to `/usage` for developers behind a Claude apps gateway — gateway 使用者的 `/usage` 會顯示今日 / 本週 / 本月花費
- Changed self-paced `/loop` to end when a turn finishes without rescheduling, instead of scheduling a fallback wakeup; set `CLAUDE_CODE_LOOP_KEEPALIVE=1` to keep the old behavior — 自訂節奏的 `/loop` 若該輪沒有重新排程就會結束，不再自動排備援喚醒
- Changed PostToolUse hooks to run, with up to 10 seconds to finish, on tool calls that finish after a new message interrupts the turn — 使用者插話打斷後才完成的 tool call，PostToolUse hook 也會執行（最多 10 秒）
- Changed nested skill loading: with the Bash sandbox on, skills in `.claude/skills` folders below the starting folder load only if you start Claude Code there or `/cd` there — 開啟 Bash sandbox 時，子資料夾的 `.claude/skills` 只有在從該處啟動或 `/cd` 過去才會載入
- Changed the Bash tool to ask for permission before running `which` with flags outside a lookup/display set — `which` 帶非查詢類 flag 時改為要求權限
- Changed a session's exact Bash or PowerShell ask rule to be refused, not asked about, when a broader deny rule covers the command — 範圍更大的 deny 規則會優先於精確的 ask 規則
- Changed auto mode with telemetry or feature flags off, including behind LLM gateways: calls the server can't check are asked about or denied, with no fallback to the built-in classifier; set `CLAUDE_CODE_AUTO_MODE_SERVER=0` to keep using it — 關閉 telemetry / feature flag 時，auto mode 無法由伺服器檢查的呼叫改為詢問或拒絕
- Removed `shortcuts_list` and `shortcuts_execute` from Claude Code's built-in Claude in Chrome tools — 移除內建 Claude in Chrome 工具中的 shortcuts 列出 / 執行功能
- [VSCode] Changed links in Claude's replies that point at Claude sign-in, connector or API addresses to show as text with the address, instead of opening in the browser — VS Code 中指向登入 / connector / API 的連結改以純文字顯示網址
- 另含多項 Claude apps gateway、self-hosted runner、Code Review 相關變更，以及 16 項改進與 90 項 bug 修正（詳見官方 changelog）

**核心概念（簡單說）：**
這版主軸是「長時間任務與無人值守流程」。最重要的是 MCP tasks：有些 MCP 工具（例如跑一次完整 E2E 測試、產生大量圖片、部署）可能要跑好幾分鐘，以前 Claude 只能卡在那個 tool call 上乾等；現在 MCP server 可以把它宣告成 task，Claude Code 立刻把它丟到背景，Claude 可以繼續做別的事，等 task 完成再收到結果，概念上就像把同步的 `await` 改成 Promise + callback。

另一個重點是 `permissions.denyInsteadOfPrompting`：在 CI、排程或 subagent 這種沒人盯著的情境，原本遇到需要權限的動作會一直卡在詢問畫面；開啟後會直接拒絕並讓 Claude 換個方式繼續。搭配 `/loop` 改成「沒重新排程就結束」，整體行為更可預期，不會出現沒人知道的殭屍迴圈。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你寫過自己的 MCP server（例如包裝 Playwright、Storybook 截圖或 Lighthouse），長時間的工具現在可以改成 task 形式，不再阻塞整個對話；在 GitHub Actions 跑 `claude -p` 時也能避免因權限詢問卡死。
- **具體場景：** 你有一個 MCP tool 會跑整套 Playwright 視覺回歸測試（約 5 分鐘）。改成 task 後，你請 Claude「跑視覺測試，同時把 Button 元件的 Storybook stories 補齊」，Claude 會先觸發測試、轉去寫 stories，測試結果回來後再整理失敗的截圖差異。CI 端則在 `.claude/settings.json` 設 `"permissions": { "denyInsteadOfPrompting": true }`，確保沒授權的指令直接被拒，而不是讓 job 卡到 timeout。
- **這週可以嘗試：** 執行 `claude update` 升到 2.1.319，打開 `/tasks` 看看新的「Earlier in this session」列；如果你有在排程裡跑 Claude Code，把 `denyInsteadOfPrompting` 加進該專案的設定，跑一次確認不會再卡在權限詢問。
