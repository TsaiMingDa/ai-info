**繁中改寫：**
延續前一則的想法——如果你的目標只是要「穩定地呼叫工具（tool calling）」，我覺得現在光靠 bash 已經不夠用了。不過如果工作內容牽涉到程式碼的生成與執行，sandbox 加上 bash 仍然是很好的組合。

**核心概念（簡單說）：**
這是 Thariq 對他自己前一天那則「MCP 比 CLI 更適合大多數整合」貼文的延伸補充。他區分兩種不同的 agent 使用情境：一種是單純需要「可靠地呼叫工具」（例如查資料、呼叫 API），這種情境下 MCP 這種結構化、有明確 schema 的協議比起「叫 agent 打 bash 指令」更穩定可靠；但另一種情境是牽涉到「寫程式碼並執行」，這時候 sandbox（隔離的執行環境）加上 bash 仍然是必要的工具組合，因為程式碼執行本來就需要一個能跑任意指令的環境。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你在設計自己的 AI agent 或是幫產品串接 Claude 的工具串（tool use），這則貼文在提醒你「工具設計」要看場景，不是所有東西都應該包成 bash 指令。
- **具體場景：** 假設你在做一個「幫忙查詢公司內部 API 資料」的 agent 功能，與其讓 Claude 用 bash 執行 curl 指令去打 API，不如直接把這個 API 包裝成一個 MCP tool，讓呼叫的參數、回傳格式都是結構化、可預期的，減少出錯機率。
- **這週可以嘗試：** 檢視一下你手上任何用「bash + curl」模式串接外部服務的 Claude Code 設定，評估是否有幾個高頻使用的 API 值得改包裝成專屬的 MCP server / tool。

**核心概念（簡單說）：**
這則延續同一串思考，講的是「幫 agent 設計工具時，該給它多抽象的介面」。Thariq 過去主張過 agent 應該用檔案系統來管理狀態，但這則貼文是他對這個觀念的修正：與其堅持所有東西都要透過檔案系統包裝、再讓 Claude 用 bash 去操作檔案來模擬資料庫查詢，不如直接給 Claude 一個貼近它「真正需求」的工具，例如直接給它一個查資料庫的 API 當作 tool，減少中間的轉譯與出錯空間。

**前端工程師實際應用：**
- **跟你工作的關聯：** 這對正在設計 Claude tool / MCP server 介面的工程師很直接：工具介面設計得越貼近實際需求（例如直接給查詢 API 而非讓它自己拼 SQL 或操作檔案），Claude 執行起來越穩定、越少出錯。
- **具體場景：** 假設你要讓 Claude 讀取公司資料庫裡的訂單資料，與其讓它去讀一份匯出的 CSV 檔案再自己解析篩選，不如直接開一個帶查詢參數（如 order_id、status）的 API 工具給它呼叫，讓篩選邏輯留在你的後端而不是 Claude 手動處理檔案。
- **這週可以嘗試：** 挑一個你目前是用「檔案匯出 + 讓 Claude 自己解析」方式處理的資料流程，評估改成直接暴露一個帶篩選參數的 API/MCP tool 會不會讓結果更準確、更快。

**繁中改寫：**
Claude Cowork 跟一般聊天功能即將合併成同一個 Claude。你可以隨手問個簡單問題，也可以直接把一份完整的報告工作交給它處理，即使你把筆電關掉，Claude 也會繼續處理下去。如果有不清楚的地方，Claude 會主動詢問你——最終決定權還是在你手上。這項功能將在接下來幾週內陸續開放給 Pro 和 Max 用戶。

**核心概念（簡單說）：**
這則公告的重點是把「Cowork」（Claude 面向長時間、可背景執行的委派型工作模式）跟一般的即時對話介面合併成單一體驗。過去這兩種模式（快速問答 vs. 長時間背景任務）是分開的產品線，使用者要自己選擇要用哪一種介面；合併後，同一個對話視窗就能無縫從「隨口一問」延伸到「交辦一個需要花時間處理、關掉電腦也繼續跑」的任務，而且 Claude 在執行過程中遇到不確定的地方會主動回來問你，而不是自己瞎猜著做完。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你已經在用 Claude 處理一些需要長時間執行的任務（例如大範圍重構、產出完整報告），這個合併代表你不用再切換兩套介面，同一個對話串就能無縫升級成背景任務。
- **具體場景：** 你在下班前丟給 Claude 一個「幫我把這個 repo 裡所有用 class component 寫的元件改成 function component + hooks」的大型重構任務，然後關掉電腦下班，Claude 在背景繼續跑，遇到不確定要不要改動的邊界案例時會記下來等你回來再問，而不是自己亂猜。
- **這週可以嘗試：** 功能開放給你的帳號後，找一個你原本覺得「太花時間、懶得現在盯著做」的重構或整理任務交給 Claude，觀察它背景執行與主動提問的體驗如何。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.274 / September 17, 2026

**變更項目（精選重點，原文為英文）：**
- Added a visible warning when memory usage is critical, with steps to free memory or restart safely（記憶體使用量達到危險等級時，現在會顯示明顯警告，並提供釋放記憶體或安全重啟的步驟）
- Fixed sessions getting stuck endlessly retrying "unexpected tool_use_id" 400 errors: corrupted transcripts now self-heal where possible, and otherwise a clear error (with a /rewind hint) ends the loop（修正 session 卡在無限重試 "unexpected tool_use_id" 400 錯誤的問題：損毀的對話紀錄現在能盡量自我修復，修不了的話會直接顯示明確錯誤並提示用 /rewind，結束無限迴圈）
- Fixed MCP tool calls refused with 403 insufficient_scope being reported as an expired sign-in: the error now names the missing permissions and points to /mcp re-authentication（修正 MCP 工具呼叫被 403 insufficient_scope 拒絕時，卻誤報成登入過期的問題，現在會直接列出缺少的權限並引導到 /mcp 重新授權）
- Fixed an active /goal being lost when resuming (--continue / --resume) a session that had compacted（修正 session 被壓縮過後，用 --continue / --resume 恢復時會遺失正在進行中的 /goal 的問題）
- Changed /code-review to use leaner inline review prompts for every model that has no tuned settings of its own, instead of spawning many review subagents（針對沒有專屬調校設定的模型，/code-review 現在改用更精簡的行內審查 prompt，不再額外開一堆 subagent 來做審查）
- Improved Monitor tool notifications: a script's final output and its exit now arrive as one notification instead of two, saving a model turn（改善 Monitor 工具的通知機制：腳本的最終輸出跟結束狀態現在會合併成一則通知，省下一次模型呼叫）
- [VSCode] Added Memory and Instructions entries to the Customize menu: Memory shows the auto-memory toggles, the saved memories and the memory folders, and Instructions edits the CLAUDE.md files（VSCode 版的 Customize 選單新增 Memory 跟 Instructions 項目：Memory 可以看到 auto-memory 開關、已存的記憶內容跟記憶資料夾，Instructions 則可以直接編輯 CLAUDE.md 檔案）
- [Claude Code on the web] Added a "Compare against" branch picker to a cloud session's diff view, so you can diff its changes against any branch instead of only the base branch（Claude Code on the web 的 cloud session diff 畫面新增「Compare against」分支選擇器，現在可以跟任意分支比較差異，不只能跟 base branch 比）

**核心概念（簡單說）：**
這個版本同樣以修正和體驗改善為主，其中比較值得留意的是幾個跟「穩定性」有關的修正：session 卡死重試、MCP 權限錯誤誤報成登入過期、以及 /goal 在 session 壓縮後遺失，這些都是長時間、重度使用 Claude Code 的人容易踩到的坑。另外 /code-review 改用更精簡的 prompt（不再開一堆 subagent），代表官方在優化 code review 功能的執行效率與成本。VSCode 跟 web 版也各自補了一些介面上的便利功能，像是能直接在 VSCode 裡管理 CLAUDE.md 記憶內容，以及 cloud session 現在能跟任意分支比較差異。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你常用 /code-review 或 MCP 工具，這次的修正跟改善會直接影響你日常使用的順暢度與穩定性。
- **具體場景：** 假設你之前遇過 MCP 工具連線被拒絕，卻顯示「登入過期」讓你白白重新登入了好幾次，這次更新後錯誤訊息會直接告訴你缺少哪個權限，讓你能對症下藥去 /mcp 重新授權，而不是瞎猜。
- **這週可以嘗試：** 升級到 2.1.274 後，如果你有用 VSCode 版 Claude Code，去 Customize 選單看看新增的 Memory 跟 Instructions 項目，直接在 IDE 裡管理你的 CLAUDE.md 跟已儲存記憶，省去手動開檔案編輯的步驟。
