還有，你有試過對自己這樣說嗎？

（接著他補上出處：這句話來自「我們如何在兩週內讓 claude.ai 快 3 倍」那篇部落格文章。有網友追問還有沒有其他秘密 prompt，他回：「我不覺得這算什麼秘密 prompt 啦，只是覺得很好玩。」）

**核心概念（簡單說）：**
這則在講 agent 的「保守偏誤」。模型在不確定時傾向選最安全、改動最小的方案：只修症狀、不敢動架構、遇到大重構就先停下來問。在效能優化這種需要大膽假設、大範圍改寫的任務裡，這種謹慎反而會拖慢進度。一句「請更勇敢」本質上是在調整 agent 的風險偏好——明確授權它可以提出激進方案、改動更多檔案、挑戰既有設計。

Thariq 自己也強調這不是咒語，重點是意圖：你要讓 agent 知道「這次的目標是突破，不是維穩」。後面那句「也對自己說說看」則點出，很多時候保守的其實是下指令的人。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端效能優化（bundle 瘦身、減少 re-render、改 SSR/streaming）常需要跨多個元件與設定檔的大改動，agent 預設只會做局部微調，得明確告訴它可以大刀闊斧。
- **具體場景：** 在 Next.js 專案跑 `npx @next/bundle-analyzer` 找出肥大的 chunk 後，對 Claude Code 說：「目標是首頁 JS 減半，你可以重新設計 import 結構、改成 dynamic import、換掉笨重的 library——請大膽一點，先列出最激進的方案再評估風險。」
- **這週可以嘗試：** 挑一個你一直覺得「很慢但不敢動」的頁面，在 plan mode 下請 Claude 提出三個由保守到激進的優化方案，並附上預估效益與風險，再決定要執行哪一個。

**繁中改寫：**
我上了 Swyx 和 Vibhu 的 Latent Space podcast！整體是一場很好玩的深度對談，從 harness engineering 聊到怎麼掌握前沿發展的節奏。以下是我最喜歡的幾段：

1. 聰明的模型需要的驗證比較少，所以整體來看它們是 Pareto 最優的。
2. 如果你真的去看執行紀錄，幾乎所有 eval 都已經飽和了——模型幾乎總是看到正確解法，只是差一點點沒做到。如果你在寫 prompt，請 Claude 保留實作筆記，這樣你就能看到它做了哪些決策。
3. Hugging Face 事件：發生了什麼事，以及為什麼它大幅改變了我的看法。
4. 「想要有品味，你得先吃過」——出自 @jxnlco。
5. 軟體工程變化的速度快得驚人，連那些從沒想過會用 AI 的人現在也在用了。

完整影片在這裡（YouTube：The Future of Claude Code: Mods, Mutable Software, & Multiplayer）。

**核心概念（簡單說）：**
第 1 點是這串最值得消化的觀念：評估模型成本時不能只看每個 token 的單價，還要算上「你得花多少力氣檢查它的產出」。便宜但常出錯的模型，會把成本轉嫁到人工 review、重跑、除錯上；聰明的模型雖然單價高，但驗證成本低，綜合起來反而在「品質 × 總成本」上全面勝出（Pareto dominant 意指在所有維度上都不比別人差）。

第 2 點則是實用技巧：當模型「差一點就對」時，問題通常出在某個中間決策。要它邊做邊寫 implementation notes（為什麼選這個做法、放棄了哪些方案），你就能直接定位是哪一步判斷偏了，而不是從最終 diff 反推。這就像要求同事在 PR 描述裡寫設計取捨，review 時效率高很多。

**前端工程師實際應用：**
- **跟你工作的關聯：** 選模型時別只比價格，要把「你 review 它的 code 花多久」算進去；而實作筆記能讓你 review agent 產出的速度大幅提升。
- **具體場景：** 請 Claude Code 把一個複雜表單從 Formik 遷移到 React Hook Form 時，加一句「每改一個元件，就在 `NOTES.md` 記下你的做法、遇到的邊界情況（例如 async validation、field array）和你放棄的替代方案」，review 時先讀筆記再看 diff。
- **這週可以嘗試：** 在專案 `CLAUDE.md` 加入一條規則：「非瑣碎的改動請在回覆最後附上 3–5 點 implementation notes，說明關鍵決策」，觀察一週內 review agent 產出的時間是否縮短；有空再看看那集 Latent Space podcast。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.285 / September 29, 2026

**變更項目：**（本版條目眾多，以下節錄與日常開發最相關的項目，完整內容見 [changelog](https://code.claude.com/docs/en/changelog)）
- Added `CLAUDE_CODE_DISABLE_WEB_FETCH` environment variable to turn off the WebFetch tool
  - 新增環境變數 `CLAUDE_CODE_DISABLE_WEB_FETCH`，可以直接關掉 WebFetch tool。
- Added `claude --desktop` to open the Claude desktop app on the current directory, or on a session with `--continue` / `--resume <id>`
  - 新增 `claude --desktop`，從終端機直接在 Claude 桌面 app 開啟目前目錄或指定 session。
- Added `claude plugin configure <plugin>` to show a plugin’s options and which are unset, or save new values read from stdin with `--values-stdin`
  - 新增 `claude plugin configure`，列出 plugin 的設定項與尚未設定者，也能從 stdin 寫入設定值。
- Added `<server>.<key>=<value>` to `claude plugin install --config`, so a bundled .mcpb MCP server’s own settings can be set at install time
  - 安裝 plugin 時就能用 `--config` 設定內含 MCP server 的參數，不必事後再進 `/plugin` 設定。
- Added `allowedProviders` managed setting to limit which API providers a machine may use
  - 新增 managed setting `allowedProviders`，企業可限制機器能使用的 API provider。
- Changed background Bash and PowerShell commands to stop after a time limit (their timeout with `run_in_background`, default 30 min, max 2 h); Claude is notified when one is stopped
  - 背景執行的 Bash / PowerShell 指令現在有時間上限（預設 30 分鐘、最多 2 小時），超時會被停止並通知 Claude。
- Changed sessions behind a custom `ANTHROPIC_BASE_URL` to use the 1M context window of models that have one; run `/autocompact 200k` if your gateway stops at 200K
  - 透過自訂 `ANTHROPIC_BASE_URL` 的 session 改用 1M context；若 gateway 只支援 200K，請執行 `/autocompact 200k`。
- Changed `/tasks` to fold background work Claude Code runs for itself under one “System tasks” row
  - `/tasks` 把 Claude Code 自己的背景工作收進一列「System tasks」，清單更乾淨。
- Fixed synchronous hooks hanging Claude Code while a background process the hook started kept its output open
  - 修正 hook 啟動背景程序（如 `some-daemon &`）時會讓 Claude Code 卡住的問題。
- Fixed sandbox auto-allow asking for approval on every run of many inline scripts (`python3 -c`, `node -e`) just because they contain `=`
  - 修正 sandbox 對含 `=` 的 inline script（`node -e` 等）每次都要求批准。
- Fixed fork subagents not keeping the session’s plan mode or dontAsk mode
  - fork 出的 subagent 現在會沿用父 session 的權限模式，也無法自行退出 plan mode。
- Fixed a failing API request being retried up to 21 times when streaming kept failing
  - 修正串流持續失敗時 API 請求最多重試 21 次；非串流 fallback 改為共用重試額度。
- Fixed responses blocked by the API’s output content filter being re-sent and retried, sometimes for minutes
  - 被輸出內容過濾擋下的回應不再反覆重試，會立即顯示錯誤。
- Fixed the PowerShell tool’s permission check skipping deny and ask rules when its command parser failed to start
  - 修正 PowerShell tool 在解析器啟動失敗時略過 deny / ask 規則的安全性問題。
- Improved `/resume` and `claude --resume` on a session that is running in the background: they now open that session instead of refusing
  - 對背景執行中的 session 使用 `/resume` 會直接開啟它，而不是拒絕。
- Improved per-turn performance when many permission deny rules and MCP tools are configured
  - 設定大量 deny 規則與 MCP tools 時，每輪回應的效能提升。
- [VSCode] Added an on-demand diagnostics tool so Claude in the panel can read the Problems panel’s current errors and warnings at any time
  - VS Code 中 Claude 可隨時讀取 Problems 面板的錯誤與警告，不再只限於剛編輯完檔案時。
- [VSCode] Fixed every file Read, Write and Edit stalling for ten minutes when the editor stops responding to the extension’s automatic save
  - 修正編輯器自動存檔無回應時，檔案讀寫會卡 10 分鐘的問題。

**核心概念（簡單說）：**
2.1.285 是一個以「可控性與穩定性」為主軸的版本。可控性方面：背景指令終於有逾時上限，避免忘記關的 dev server 或 watcher 永遠掛著；plugin 可以在安裝時一次設定好內含的 MCP server；企業可以用 `allowedProviders` 與 `CLAUDE_CODE_DISABLE_WEB_FETCH` 收緊能力邊界。穩定性方面：修掉 hook 被背景程序卡死、串流失敗時過度重試、fork subagent 權限模式外洩等長時間使用才會踩到的問題。

對 VS Code 使用者最有感的是新的 diagnostics tool：Claude 現在能主動查看 Problems 面板，等於直接拿到 TypeScript / ESLint 的即時診斷，而不用自己再跑一次 `tsc`。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端常讓 Claude 在背景跑 `npm run dev`、`vitest --watch`，新的逾時機制會影響這類長駐指令；VS Code 的 diagnostics tool 則讓型別錯誤修正更即時。
- **具體場景：** 在 VS Code 面板請 Claude「把 Problems 面板裡所有 TypeScript 錯誤修掉」，它能直接讀取診斷清單逐一處理；若要讓 Claude 在背景跑 `next dev` 超過 30 分鐘，記得請它設定較長的 timeout（最多 2 小時）。
- **這週可以嘗試：** 更新到 2.1.285 後，在 VS Code 裡試一次「讀 Problems 面板並修正錯誤」的流程；如果你有用 hook 啟動背景程序（例如自動起 mock server），確認現在不會再卡住。
