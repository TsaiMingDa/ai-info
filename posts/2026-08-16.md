**繁中改寫：**
Thariq 分享說，「不損失品質的浮水印」這件事其實蠻反直覺的，第一眼看感覺不太可能做到。為了搞懂背後原理，他請 Claude 幫忙做了一個互動式 artifact 來拆解機制，並附上一段 demo 影片，把這個 artifact 分享出來，希望對其他人也有幫助。他同時引用了 Anthropic 官方帳號的貼文——Anthropic 針對外界對浮水印功能提出的疑問寫了一篇 FAQ，說明推出這項功能主要是為了配合歐盟《AI 法案》（EU AI Act），其他主要模型開發商簽署了同一份行為準則（Code of Practice）之後，未來也都會陸續導入類似的浮水印機制。

**核心概念（簡單說）：**
文字浮水印（text watermarking）的原理，是在 AI 生成文字的過程中，利用「選字機率分布」的微調偷偷嵌入一個統計特徵：模型每次挑下一個字時，遇到好幾個候選字都差不多合理的情況，會用一把只有廠商自己有的密鑰（key）去決定實際選哪個，而不是單純隨機挑。這樣一來，文字讀起來完全自然、品質不受影響，但事後可以用同一把密鑰回推「這段文字的用字選擇模式，跟用這把 key 會做出的選擇是否吻合」，藉此算出這段文字有多大機率是該模型生成的。之所以反直覺，是因為大家直覺會覺得「要嵌入可偵測訊號勢必犧牲自然度」，但因為操作發生在機率分布這一層，讀者跟模型輸出品質幾乎感覺不出差異。Thariq 用 Claude 做出一個可互動的 artifact，把這個抽象機制視覺化，是很典型的「用 AI 自己解釋 AI」的學習方式。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的產品有串接 Claude API 產生使用者可見的文字內容（客服回覆、文案生成、agent 輸出等），未來這些輸出可能會自動帶有浮水印，你可能要留意浮水印會不會影響到前端做的內容比對、去重或快取邏輯（例如比對兩次生成結果是否完全一致）。
- **具體場景：** 假設你想在自己的 side project 裡解釋一個抽象的技術概念（例如浮水印、雜湊碰撞、TCP 三向交握），可以參考 Thariq 的做法，直接請 Claude 幫你做一個互動式 HTML/SVG artifact 來視覺化，比自己從頭刻圖表快很多。
- **這週可以嘗試：** 找一個你自己一直「知道但沒真的搞懂」的技術概念，花 15 分鐘請 Claude 幫你做一個小型互動 artifact 來拆解它，體驗一下這種學習方式的效率。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.233 / 2026年8月14日（自上次 digest 後尚無更新版本，列出目前最新版）

**變更項目：**
- Added GitLab merge request URL support to the `--worktree` flag and the `claude agents` view (where MRs display as `!N`)（`--worktree` flag 與 `claude agents` 畫面新增 GitLab merge request URL 支援，MR 會顯示成 `!N`）
- Added an opt-in `forward_user_identity` apps gateway setting on Anthropic upstreams that sends the signed-in user's identity as headers, so a proxy behind the gateway can attribute spend per user（新增可選的 `forward_user_identity` apps gateway 設定，會把登入使用者的身分以 header 方式傳遞，讓 gateway 後面的 proxy 能依使用者歸戶花費）
- Added opt-in memory cgroup support for Bash tool commands on Linux (`CLAUDE_CODE_TOOL_MEMORY_LIMIT`) so a runaway build can't stall the session（Linux 上 Bash tool 指令新增可選的 memory cgroup 限制 `CLAUDE_CODE_TOOL_MEMORY_LIMIT`，避免失控的 build 卡住整個 session）
- Added `CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS` environment variable to configure the WebFetch session URL cache TTL (default unchanged: 15 minutes)（新增環境變數 `CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS` 可調整 WebFetch session 的 URL 快取存活時間，預設仍為 15 分鐘）
- Fixed cloud sessions occasionally being marked as lost when the environment shut down while Claude was waiting on a permission prompt（修正雲端 session 在環境關閉、Claude 正等待權限確認時，偶爾被誤判為 lost 的問題）
- Fixed MCP v2 connections endlessly reopening the subscriptions/listen stream against servers that terminate long-held streams on a fixed timeout (e.g. serverless hosts)（修正 MCP v2 連線對「會用固定 timeout 中斷長連線」的伺服器（例如 serverless host）不斷重開 subscriptions/listen stream 的問題）
- Fixed Notification hooks not firing for permission prompts when running under Claude Desktop or VS Code（修正在 Claude Desktop 或 VS Code 底下執行時，Notification hooks 不會針對權限確認提示觸發的問題）

**核心概念（簡單說）：**
目前最新的 Claude Code 版本仍是 8 月 14 日發布的 2.1.233，自上次 digest 之後還沒有新版釋出。這個版本重點是強化企業／團隊維運相關的選用設定（依使用者歸屬 API 花費、限制 Bash 指令記憶體上限、可調整 WebFetch 快取時間），以及修掉幾個跟雲端長連線、背景 session 相關的邊角案例 bug，方向是讓 Claude Code 在多人團隊、雲端 session、跟第三方工具（GitLab、gateway proxy）整合時更穩定、更好追蹤成本。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你在公司內把 Claude Code 用在雲端 session 或透過 gateway/proxy 集中管理 API key，這幾個選用設定（`forward_user_identity`、`CLAUDE_CODE_TOOL_MEMORY_LIMIT`）可以幫你把「誰用了多少額度」跟「Bash 指令會不會把 CI 機器記憶體吃光」這兩件事管起來。
- **具體場景：** 團隊共用一個 Anthropic API key 跑 Claude Code，但想知道每個工程師實際花了多少 token，可以在 gateway 開啟 `forward_user_identity`，讓後端 proxy 依 header 拆帳。
- **這週可以嘗試：** 跑一次 `claude --version` 確認自己是否已在 2.1.233 版本；如果團隊有搭配 `--worktree` 使用 GitLab merge request，可以試試新的 URL 支援能不能省掉手動貼 MR 連結的步驟。
