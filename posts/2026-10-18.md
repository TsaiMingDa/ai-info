**核心概念（簡單說）：**
Claude Code Review 是掛在 GitHub PR 上的自動化審查：每次開 PR 或 push，就讓 Claude 讀 diff 與相關程式碼脈絡，把疑似 bug 以 inline comment 的形式留在 PR 上。它跟 ESLint、TypeScript 這類靜態檢查的差別在於「懂語意」——能發現「這個 `useEffect` 少了 cleanup 會造成重複訂閱」、「這個分頁邏輯 off-by-one」這種規則寫不出來的問題。

這次 GA 的重點是「審查等級」：Quick 適合小改動、快速回饋；Deep 會花更多時間與 token 深入追查跨檔案的影響。Boris 的說法點出一個關鍵：當 agent 讓寫程式的速度變快，瓶頸就移到 review；用 AI 做第一道 review，人類 reviewer 才能把注意力留給架構與產品判斷，速度和品質才能同時提升。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端 PR 常見的 bug（狀態同步錯誤、race condition、漏處理 loading/error state、a11y 屬性遺漏）正是靜態檢查抓不到、人工 review 又容易看漏的類型。
- **具體場景：** 你的 Next.js repo 對 `app/` 底下的 Server Component 改動設 Deep 等級、對純文案或樣式調整的 repo 設 Quick；PR 開出來後先看 Claude 的 inline comment 修一輪，再請同事 review，同事就不必花時間抓「`fetch` 沒處理 `res.ok`」這種低階問題。
- **這週可以嘗試：** 如果團隊有 Team/Enterprise 方案，挑一個活躍的前端 repo 開啟 Code Review；沒有的話，在本機對目前分支跑 `/code-review`，比較它抓到的問題和你自己 review 會注意到的有什麼不同。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.302 / October 16, 2026

**變更項目：**
- Added `CLAUDE_CODE_AUTO_MODE_MODEL` to choose the model the client-side auto mode classifier uses; it does not change the model for server-side auto mode —— 可指定 client 端 auto mode 分類器使用的模型（server 端 auto mode 不受影響）。
- Added an Idle compaction row to `/config` for turning idle compaction off or back on —— `/config` 新增 Idle compaction 開關，閒置壓縮後的提示也會說明怎麼關閉。
- Added a notice to `/design-sync` and `/design-login` that standalone Claude Design (claude.ai/design) closes by December 14, 2026 —— 提醒獨立版 Claude Design 將於 2026/12/14 關閉。
- [Cloud sessions] Added a banner on a routine's page that says why its last run didn't start —— routine 頁面會顯示上次沒啟動的原因（例如組織的並行 cloud session 已達上限）。
- Changed `claude -p` and Agent SDK sessions with no permission mode to start in default mode on third-party providers, with telemetry off or on a fresh install; `--permission-mode auto` keeps auto —— 第三方供應商等情境下，未指定權限模式時改從 default mode 開始。
- Changed fork subagents (`subagent_type: "fork"`) to be on by default in `claude -p`, the Agent SDK, the desktop app and VS Code; `CLAUDE_CODE_FORK_SUBAGENT=0` turns them off —— fork subagent 在所有介面預設開啟。
- Changed the desktop app and VS Code to always run the main conversation's subagents in the background; a subagent's own Agent calls now run in the foreground by default —— 桌面版與 VS Code 主對話的 subagent 一律背景執行，與 terminal 一致。
- Changed prompt and agent hooks so that at most 12 of one event run at a time —— 同一事件的 prompt/agent hook 最多同時跑 12 個，其餘排隊。
- Changed where the Claude in Chrome instructions sit in the system prompt so that new conversations can read them from the shared prompt cache —— 調整 Claude in Chrome 指示的位置，讓新對話能命中共享 prompt cache。
- [Claude Tag] Changed Claude Tag admin settings to organize Claude's access into four tabs: Bundles, Connectors, Skills and plugins, and Channels —— Claude Tag 管理設定改為四個分頁。
- Improved startup time with many plugins enabled, most of all on Windows —— 啟用大量 plugin 時啟動更快，Windows 改善最明顯。
- Improved auto mode with the server-side classifier: a conversation too long for the safety check is now compacted, instead of every checked tool call being denied —— 對話過長時改為先壓縮，不再整批拒絕工具呼叫。
- [Cloud sessions] Improved the error shown when a cloud session fails to start: it now says "Connection lost" or "Server error" —— cloud session 啟動失敗的錯誤訊息更具體。
- Fixed the Read tool loading an image file of any size entirely into memory; image sources over 128 MB are now refused —— Read 工具不再把超大圖片整個載入記憶體，超過 128 MB 直接拒絕。
- Fixed a prompt cache miss when a tool added mid-session was loaded again through ToolSearch or after compaction —— 修正中途載入的工具重新載入時造成 prompt cache miss。
- Fixed the PowerShell tool not finding commands in a plugin's `bin/` folder, and reporting an error when a search that finds nothing is piped into `Select-Object` —— PowerShell 工具的 plugin 指令與空搜尋結果問題修正。
- Fixed URLs written in backticks being clickable only on their first row when they wrap —— 換行的 backtick URL 現在整段都可點。
- Windows: Fixed every file write being refused or asked about for projects on exFAT or FAT32 drives —— 修正 exFAT/FAT32 磁碟上的專案每次寫檔都被拒或詢問。
- [VSCode] Fixed text after an unclosed code block in a list showing as plain text while a reply streams —— VS Code 串流回覆時，清單中未閉合 code block 的渲染修正。
- [Cloud sessions] Fixed a scheduled routine run that failed partway being run again from the start an hour or more later —— 修正 routine 中途失敗後一小時後被從頭重跑（可能造成重複發文）。
- 另含 4 項 improvements 與36 項 bug fixes（Claude Tag、Cloud sessions、MCP、plugin 等）。

**核心概念（簡單說）：**
這版主軸是「多 agent 行為在各介面一致化」與「長時間 / 無人值守流程的穩定性」。fork subagent 與背景 subagent 原本只在 terminal 是預設行為，現在桌面版、VS Code、`claude -p` 與 Agent SDK 都對齊，代表同一個 workflow 在不同入口跑起來結果更可預期；hook 並行上限 12 個則避免大量 hook 同時觸發把機器拖垮。

另一條線是排程與成本：routine 頁面會說明沒啟動的原因、失敗的 routine 不會再被整個重跑；Chrome 指示改放進共享 prompt cache、修正 ToolSearch 造成的 cache miss，都是在降低每次對話的 token 成本與延遲。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你在 VS Code 擴充或桌面版用 Claude Code 跑「一邊改元件、一邊讓 subagent 跑測試或查文件」的工作流，subagent 現在一律背景執行，你不用等它跑完才能繼續互動。
- **具體場景：** 在 VS Code 請 Claude 重構一個 React 表單，同時讓它派 subagent 去跑 `pnpm vitest run` 和查 React Hook Form 文件；subagent 在背景跑，主對話可以繼續討論 UI 細節。若你用 `claude -p` 寫 CI 腳本且不想要 fork subagent，記得設 `CLAUDE_CODE_FORK_SUBAGENT=0`。
- **這週可以嘗試：** 升級到 2.1.302 後打開 `/config` 檢查新的 Idle compaction 設定；若你常在 Windows 開多個 plugin，量一下 `claude` 啟動時間有沒有變快。
