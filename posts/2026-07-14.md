Thariq 說這讓 artifacts 變得更具表現力，還能用創意方式組合運用。他最喜歡的用法之一，是在 Claude Tag（@Claude 頻道）裡幫專案建立一個 dashboard，讓其他人或自己本機的 Claude Code session 都能編輯。這則貼文引用了 ClaudeDevs 官方公告：Artifacts 現在支援公開分享與多人協作編輯，且可以透過 Claude Tag 直接建立。

- Reduced per-tool-call CPU overhead in print/SDK sessions with many MCP tools by caching tool-pool assembly (up to 7x faster tool rounds at high tool counts)（透過快取工具池組裝，降低 print／SDK session 在大量 MCP 工具時每次工具呼叫的 CPU 開銷，工具數量多時工具回合最高可快 7 倍）
- Reduced memory usage by bounding the file edit read cache to 16 MB instead of pinning up to 1,000 full files（將檔案編輯讀取快取上限設為 16 MB，取代先前最多釘住 1000 份完整檔案的做法，降低記憶體用量）
- Reduced session transcript size (up to 79x in edit-heavy sessions) and bounded checkpoint disk usage by pruning superseded file-history backups（透過清理已過時的檔案歷史備份，大幅縮減 session 逐字稿大小（大量編輯的 session 最高可縮小 79 倍）並限制 checkpoint 磁碟用量）
- Reduced memory usage when resuming sessions with background agents or forks spawned from large conversations（降低從大型對話衍生出的背景 agent 或分支 session 在恢復時的記憶體用量）
- Completed background agents now stay listed in `/tasks` until cleanup instead of vanishing the moment they finish（已完成的背景 agent 現在會留在 `/tasks` 清單中直到清除，不會一結束就消失）
- Attaching to a stopped background agent now shows its transcript immediately while the session warms up（附加到已停止的背景 agent 時，現在會立即顯示其逐字稿，而不是顯示空白的「Session is starting」畫面）
- Background sessions: an older daemon no longer silently restarts workers spawned by a newer version onto the older binary（背景 session：舊版 daemon 不會再靜默地把新版本產生的 worker 重啟到舊版執行檔上）
- Agent view: `Ctrl+X` now deletes renamed-branch worktrees, never destroys unpushed commits, keeps the session row when a worktree is kept, and reused worktree names reset to the current base（agent 檢視中 `Ctrl+X` 現在能刪除已改名分支的 worktree、絕不會刪除未推送的 commit、保留 worktree 時會保留該 session 列，且重複使用的 worktree 名稱會重設回目前的 base）
- Catastrophic removals (e.g. `rm -rf ~`) in commands containing `$(…)`/backticks/`<(…)` now prompt in `--dangerously-skip-permissions` and auto mode, matching the plain form（含 `$(…)`、反引號、`<(…)` 的指令中若有 `rm -rf ~` 等災難性刪除，現在在 `--dangerously-skip-permissions` 與 auto mode 下也會跳出確認提示，與純文字形式一致）
- `/install-github-app` and the `/mcp` settings menu no longer open in background sessions（`/install-github-app` 與 `/mcp` 設定選單不再於背景 session 中開啟）
- MCP servers configured with an empty URL now show as "not configured" in `/mcp` instead of a config error（URL 設為空值的 MCP 伺服器，現在會在 `/mcp` 中顯示為「未設定」而非設定錯誤）
- `/usage` now shows your last-known usage bars with an "as of" note when the usage endpoint is rate-limited, instead of an error screen（用量端點被限流時，`/usage` 現在會顯示最後已知的用量條並附上「截至」時間註記，而不是顯示錯誤畫面）
- Fixed Bedrock auth failing with "Session token not found or invalid" for AWS SSO profiles whose `sso_region` differs from the Bedrock region (2.1.207 regression)（修正 AWS SSO profile 的 `sso_region` 與 Bedrock 所在區域不同時，會出現「Session token not found or invalid」的驗證失敗問題；此為 2.1.207 引入的回歸問題）

**核心概念（簡單說）：**
這是一個內容量非常大的版本，主軸可以歸納成四塊：一是新增無障礙與 vim 使用體驗的細節功能（螢幕閱讀器模式、vim insert 模式按鍵重映射、企業版啟動包裝程式）；二是大量修正背景 session 與 Remote Control 相關的穩定性問題，包含背景 daemon 附加失敗、狀態同步遺失、任務清單顯示異常等，反映出 Claude Code 的「背景多工」功能仍在快速迭代收斂；三是修了一長串記憶體洩漏與效能問題（MCP stdio stderr 累積、LSP 文件無限開啟、session 逐字稿過大、權限規則比對變慢等），對長時間、高強度使用 Claude Code 的使用者影響最大；四是安全與行為調整，例如收緊了 `rm -rf ~` 這類危險指令在 shell 展開式（`$()`、反引號）中的攔截條件。整體來說，這次更新是把過去幾週密集開發背景多工與 Remote Control 功能後，浮現出的大量邊角案例一次性收斂掉的「穩定化」版本。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你長時間開著 Claude Code 背景 session 或用 Remote Control 跨裝置操作，這次大量的記憶體洩漏與同步問題修正，會直接改善你長 session、多工作業時的順暢度與穩定性。
- **具體場景：** 假設你習慣開好幾個背景 agent 同時處理不同 PR 的重構，過去可能遇過任務一結束就從 `/tasks` 消失、或用手機／網頁版 Remote Control 看不到背景進度的狀況，這次更新直接修正了這兩個情境。
- **這週可以嘗試：** 升級到 2.1.208 或以上後，測試看看長時間開啟多個背景 session（含至少一個進 git worktree 的 session）並用 Remote Control 從另一台裝置查看進度，確認任務清單與逐字稿是否即時同步、且結束後任務仍留在 `/tasks` 清單中。
