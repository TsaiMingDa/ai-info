（Thariq repost 此則 Geoffrey Litt 的 thread）

**繁中改寫：**
反主流觀點：就算 agent 幫你寫程式碼，你還是需要理解它寫了什麼。Geoffrey Litt 基於 AIE 演講整理的 mega thread，解釋為什麼這很重要，並分享如何有效率地理解 AI 生成程式碼的方法。

**核心概念（簡單說）：**
有一派觀點認為「AI 寫的程式碼我不需要懂，跑得起來就好」。Litt 的反論是：不理解程式碼會讓你無法有效 debug、無法做正確的架構決策、也無法判斷 AI 什麼時候走偏了。這不是懷舊情懷，而是工程師在 AI 時代維持主控權的實際需要。他的重點在於「如何有效率地理解」，而非「你要從頭到尾看完每一行」——有策略地讀比盲目信任更重要。

**前端工程師實際應用：**
- **跟你工作的關聯：** 當 Claude Code 幫你寫出一個複雜的 React hook 或 state 管理邏輯，你需要有能力快速評估「這段程式有沒有隱患」，而不只是跑過 TypeScript 型別檢查就算了。
- **具體場景：** Claude 幫你生成一個 custom hook 來管理 WebSocket 連線狀態，你用 Litt 的方式「策略性閱讀」：先看 hook 的 return value 和 side effects，再看 cleanup 邏輯，而不是逐行追蹤——這樣 5 分鐘內就能判斷有無 memory leak 風險。
- **這週可以嘗試：** 找出最近 Claude 幫你生成但你沒有細看的一段程式碼，用「關鍵路徑閱讀法」（只看輸入、輸出、副作用）快速評估一次，練習辨識 AI 程式碼的常見盲點。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.198 / July 1, 2026

**變更項目：**
- **Claude in Chrome 正式 GA（Generally Available）**——從 beta 轉正式版本，瀏覽器中的 Claude 整合現在穩定可用
- **背景 agent 通知機制**：`claude agents` 中的 session 需要輸入或完成時，現在會觸發 Notification hook（`agent_needs_input` / `agent_completed`）
- **新增 `/dataviz` skill**：提供圖表與儀表板設計指引，附可執行的色彩調色板驗證器
- **Gateway 增加 AWS 上游**：新增 Claude Platform on AWS（`anthropicAws`）作為 upstream provider；model-not-found 回應現在會推進 failover 鏈
- **背景 agent 自動開 PR**：從 `claude agents` 啟動的背景 agent 在 worktree 完成程式碼工作後，現在會自動 commit、push、並開 draft PR，而不是停下來詢問
- **Explore agent 模型繼承**：內建 Explore agent 現在繼承主 session 的模型（上限為 opus），而不是一律跑在 haiku 上
- **Subagent 繼承 extended thinking 設定**：subagent 和 context compaction 現在繼承 session 的 extended thinking 配置，提升委派任務的輸出品質
- **修復**：短暫網路中斷不再中止進行中的回應——ECONNRESET 等暫時錯誤現在會 retry with backoff
- **修復**：背景 classifier 不再對沙箱程序重複存取的同一個主機發出過多請求
- **修復**：web、desktop、VS Code 任務面板中的背景任務完成後或恢復 session 後不再卡在「Running」狀態
- **修復**：agent 因 API error 死亡時現在正確回報「failed」給 lead，傳訊給卡住的 teammate 可喚醒其立即重試
- **修復**：`/diff` 面板在切換 branch 或在 session 外 commit 後現在會正確更新
- **修復**：AWS 和 Mantle session 的 STS token 過期時不再出現「Please run /login」死路——`awsAuthRefresh` 現在自動執行
- **修復**：macOS 背景 agent session 中「no route to host」問題——加入 Local Network entitlements 解決本地網路主機存取
- **修復**：`/desktop` 在進出 worktree 後不再出現「Cannot determine working directory」
- **修復**：macOS 上 agents view 開啟時，背景 agent 不再每隔約 52 秒重複顯示「Reconnecting…」
- **修復**：在 `claude attach <id>` 中按 ← 不再跳出到 shell，而是正確開啟 agent view
- **修復**：`claude --bg` 和 `--print/-p` 同用時不再靜默建立無法 attach 的 session，現在會在前期拒絕衝突 flags
- **修復**：workflow 進度視圖不再在 phase 計數正確時丟失最早的 agent 項目
- **修復**：`.claude/rules/` 的條件規則透過 symlink 路徑存取目標檔案時現在能正確載入
- **修復**：Warp on macOS 全螢幕模式中 Cmd+click 開 URL 的問題
- **修復**：全螢幕模式雙擊選詞時現在能完整選取包含 scheme 的 URL
- **修復**：plan mode 開始時不再無法自動允許 read-only tool calls
- **修復**：`/branch` 不再從 compaction summary 衍生預設 fork 名稱，改用第一個真實 prompt
- **改善 focus mode**：在某個 turn 中啟動的 subagent 現在出現在其 activity summary，已完成的背景通知折疊成單一計數
- **改善語法高亮**：升級到 highlight.js 11，code block、diff、檔案預覽的語法高亮準確度提升
- **改善鍵盤快捷鍵提示**：透過 SSH 從 Mac 連線時，hint 現在顯示 opt/cmd 而非 alt/super
- **改善 API retry UX**：第二次嘗試後顯示錯誤原因；API 過載時以狀態頁連結取代 spinner 提示
- **`/login` 現在從 `claude agents` view 開啟登入對話框**，而非說「無法使用」
- **Subagent 訊息規則調整**：subagent 現在把啟動它的 agent 的訊息視為一般任務指令；agent 的訊息仍不等同於 user 的核准
- **移除 `/agents` wizard**：改為直接請 Claude 建立/管理 subagent，或手動編輯 `.claude/agents/`

**核心概念（簡單說）：**
2.1.198 是一個大型更新，重點有三個方向：
1. **背景 agent 的自動化升級**——背景 agent 完成後現在自動開 PR（而不是等你手動觸發），加上通知 hook，讓「fire and forget」的 agent 工作流真正可行。
2. **穩定性大掃除**——超過 15 個 bug fix，集中在 AWS/Mantle session、macOS 背景 agent、worktree 環境的各種邊緣 case。
3. **`Claude in Chrome` 正式 GA**——瀏覽器整合從實驗性轉為正式功能。

對前端工程師最有感的可能是：Explore agent 現在繼承 opus 等級模型、背景任務不再卡在「Running」、以及新的 `/dataviz` skill 提供視覺化設計指引。

**前端工程師實際應用：**
- **跟你工作的關聯：** 背景 agent 自動開 draft PR 的功能對前端 CI/CD 工作流影響最直接——你可以讓 Claude 在背景處理一個重構任務，完成後自動開 PR 讓你 review，而不需要守著等它結束。
- **具體場景：** 用 `claude agents` 啟動一個背景 agent 跑前端元件重構（例如「把所有 class component 轉成 functional component 並補 tests」），agent 完成後自動推上 branch 並開 draft PR，你在 GitHub 上 review 即可——完全不用守著終端機。
- **這週可以嘗試：** 更新到 2.1.198（`claude update`），然後試試 `/dataviz` skill——給它一個你現在在做的圖表需求（例如「我要做一個顯示 API 回應時間的折線圖，用 Recharts」），看看它提供的設計指引和色彩驗證器是否有幫助。
