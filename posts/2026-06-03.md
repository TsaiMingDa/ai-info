**繁中改寫：**
Workflows 是繼 skills 和 subagents 之後，Claude Code 最大的能力躍升。Thariq 和 @sidbid 一起深入研究，整理出最佳實踐與使用範例。他特別興奮的是 workflows 讓 Claude Code 也能勝任非技術類型的任務。

**核心概念（簡單說）：**
Claude Code 的 dynamic workflows 功能讓你可以把一個大型任務交給 Claude，它會自己撰寫一份執行計畫（orchestration script），然後平行啟動數十到數百個 subagent 同時執行不同子任務。以前 Claude Code 一次只能「單線」跑，現在更像是一個「工頭」：工頭不自己蓋房子，而是先畫藍圖、再排班一群工人同時進場施工。重點在「非技術任務」這點——過去大家直覺 AI coding tool 只能跑程式，但 workflows 可以用來做研究蒐集、文件整理、測試規劃等跨步驟任務。

**前端工程師實際應用：**
- **跟你工作的關聯：** Workflows 不只用於大型程式 migration，也適合「掃描所有元件的 accessibility 問題並逐一修復」、「批量把舊版 API call 換成新版」等前端常見的跨檔案批次作業
- **具體場景：** 在 Claude Code CLI 輸入 `ultracode: 掃描所有 React 元件，找出缺少 aria-label 的互動元素並補上，最後產出修改報告`，Claude 會自動拆解、平行處理，在 `/workflows` 查看進度
- **這週可以嘗試：** 找一個你一直推遲的「無聊但重要」批次任務（例如統一所有 console.log 格式、或替換舊版 fetch 為新版 API wrapper），用 `ultracode` 觸發 workflow 跑一次，感受平行執行的威力

**原文：**
> What we learned mapping a year's worth of AI-enabled cyber threats
>
> Jun 3, 2026
>
> Anthropic examined 832 accounts banned for malicious cyber activity between March 2025 and March 2026, and mapped them onto MITRE ATT&CK, a database of cyberattack tactics and techniques. Some results were published in Verizon's 2026 Data Breach Investigations Report (DBIR).
>
> Key findings: The most common AI-enabled activity was writing malware (67.3% of accounts), while a smaller number used AI for complex activities like lateral movement inside compromised networks (6.5%). In the first six-month period, 33% of actors were classified as medium risk or higher; by the second six-month period, that share jumped to 56%. Attackers' use of AI shifted toward post-compromise activities, and AI can now perform these highly technical activities on behalf of less sophisticated actors.
> ⚠️ 本則內容為搜尋摘要（snippet），非完整原文

**繁中改寫：**
Anthropic 花一年時間（2025 年 3 月到 2026 年 3 月）分析了 832 個被封鎖的惡意網路攻擊帳號，並將這些攻擊行為對應到 MITRE ATT&CK 框架。研究發現：最常見的 AI 輔助行為是撰寫惡意程式（67.3%），中高風險攻擊者比例從前半年的 33% 飆升至後半年的 56%，且攻擊者開始將 AI 用在入侵後的更複雜階段（如橫向移動），讓技術門檻較低的攻擊者也能執行高難度手法。

**核心概念（簡單說）：**
MITRE ATT&CK 是資安界的「攻擊手冊資料庫」，把駭客的每一個戰術動作都分類好，讓防守方可以按圖索驥地部署偵測。Anthropic 把 AI 輔助攻擊對應到這個框架上，等於建立了「AI 驅動的新型威脅地圖」。最值得警惕的趨勢是：AI 讓「攻擊後階段」（入侵成功後的橫向移動、資料蒐集）也開始 AI 化——這代表就算守好入口，內部一旦被滲透，AI 會讓攻擊者橫行更快、更難被發現。對前端工程師來說，這強調了為什麼「假設已被入侵」的防禦思維比「防住邊界」更重要。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端是攻擊者的常見入口（XSS、供應鏈攻擊、釣魚頁面）；這份報告提醒你：即使攻擊者技術不強，AI 也能幫他們自動化後續攻擊，所以每個安全漏洞都不可輕視
- **具體場景：** 如果你的前端有 npm 套件依賴，可以用 `claude "audit my package.json for known malicious or compromised packages, focusing on supply chain risks"` 做一次快速掃描，防止 supply chain attack 的入口
- **這週可以嘗試：** 用 Claude Code 針對你的 login 或表單頁面做一次 XSS + CSRF 的安全審查：`"Review this form component for XSS vulnerabilities, CSRF risks, and any input that could be exploited by AI-assisted attacks"`

## Claude Code · Changelog

**版本號 / 日期：** 2.1.161 / June 2, 2026

**變更項目：**
- `OTEL_RESOURCE_ATTRIBUTES` 的值現在作為 label 附加到 metric datapoints，可依 team、repo 等自訂維度切分 usage metrics
- `claude agents` 的列在工作 fan-out 時顯示 `done/total` 進度數字；peek 顯示執行最久的 item
- `/mcp` 現在把從未登入的 claude.ai connectors 收折在「Show unused connectors」後面，減少介面雜訊
- **平行 tool call 改善**：一個 Bash 指令失敗不再取消同批次其他 call，每個 tool 各自獨立回傳結果
- **Fullscreen 剪貼簿 (Linux)**：改用 `wl-copy`/`xclip`/`xsel`，同時寫入 clipboard 和 PRIMARY selection（支援滑鼠中鍵貼上），並正確顯示各終端機的按鍵提示
- 修復 `/effort` dialog、workflow animations、prompt keyword shimmer 未遵守「Reduce motion」設定
- 修復 `forceLoginOrgUUID`/`forceLoginMethod` 阻擋 Bedrock、Vertex、Foundry 第三方 provider session 的 regression（v2.1.146 引入）
- 修復 background subagent 輸出污染 `claude -p` 的 stdout（使用 `--output-format text` 或 `json` 時）
- 修復 `/usage-credits` 對 Team/Enterprise admin 觸發 re-login 而非跳轉到組織 usage 設定頁
- 修復 `/autofix-pr` 在 git worktree 或另一個 repository 內誤報「cannot run on the default branch」
- 修復 `--resume` picker 在非 git worktree 目錄（例如 jj workspaces）下不顯示當前目錄 sessions
- 修復 Windows hooks 明確呼叫 bash（例如 `/usr/bin/bash script.sh`）時出現 "command not found" 錯誤
- 修復 OpenTelemetry log events（`user_prompt`、`api_request`、`tool_result`、`tool_decision`）在 telemetry 初始化完成前靜默丟失
- 修復 `claude mcp` list/get/add 把 secrets 輸出到終端：`${VAR}` 參照不再展開，credential headers 和 URL secrets 自動遮罩
- 修復 Workflow agents 在 background session 用 `isolation: "worktree"` 啟動時無法編輯自己 worktree 內的檔案
- 修復 background sessions 從 `claude agents` 啟動時使用 daemon 環境中的舊 model 而非 `settings.json` 設定的 model
- 修復 resume session 後渲染 Write tool 結果時的潛在 crash
- 修復已完成的 subagent 在 finalizing result 時出現錯誤後卡在「running」狀態
- 修復 `EADDRINUSE`：使用 `CLAUDE_CODE_TMPDIR` 指向深層路徑時，bind Unix sockets 的工具出現地址佔用錯誤
- 改善終端機渲染效能：穩定 layout engine 的 JIT compilation profile
- 改善大型檔案寫入的渲染效能
- **[VSCode]** 新增提示，建議關閉終端機 GPU 加速（或執行 `/terminal-setup`）以修復亂碼問題

**核心概念（簡單說）：**
這次更新以 bug fix 為主，修了大量 background session、Windows 相容性、與安全性問題。三個亮點：（1）平行 tool call 現在有更好的錯誤隔離——一個 Bash 失敗不會拖累同批的其他工具；（2）OTEL 可觀測性強化，可按自訂維度（team/repo）分析 token 用量；（3）MCP secret 安全修補，防止 credentials 不慎洩漏到終端機輸出。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你用 Claude Code 在 Windows/WSL 環境開發，或有設定 MCP servers（例如串接 GitHub、Jira 等），這次更新修了多個直接影響你的 bug
- **具體場景：** 設定 `OTEL_RESOURCE_ATTRIBUTES=project=my-app,team=frontend`，之後 Claude Code 的 usage metrics 就帶上這些 label，可在 Grafana 或 Datadog 依維度篩選各專案的 token 消耗成本
- **這週可以嘗試：** 執行 `claude update` 更新到 2.1.161，確認 MCP server 的 credential headers 是否正確被遮罩（執行 `claude mcp list` 看輸出）
