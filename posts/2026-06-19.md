## Claude Code · Changelog

**版本號 / 日期：** v2.1.183 / 2026-06-19

**變更項目：**
- **Auto mode 安全強化：** 以下破壞性 git 指令在你沒有明確要求丟棄本地工作時，現在會被自動封鎖：`git reset --hard`、`git checkout -- .`、`git clean -fd`、`git stash drop`；`git commit --amend` 在此 session 內非 agent 自己建立的 commit 時也會被封鎖；`terraform destroy`、`pulumi destroy`、`cdk destroy` 除非你明確指定 stack 否則一律封鎖
- **模型棄用警告：** 當請求的模型已被棄用或自動切換到更新版本時，現在會在 stderr 顯示警告（print mode `-p` 及 agent frontmatter 設定的模型均適用）
- **Attribution 設定：** 新增 `attribution.sessionUrl` 設定，可在 Web 和 Remote Control session 的 commit 與 PR 中省略 claude.ai session 連結
- **`/config` 改善：** 新增 `/config --help` 列出所有可用的快捷設定鍵；`/config` 切換行為調整：Enter 與 Space 皆可變更選取的設定，Esc 現在會儲存並關閉（而非復原）
- **Bug 修復：** 修復 JetBrains IDE 終端（IntelliJ、PyCharm、WebStorm 等）在 2026.1+ 版本的閃爍問題（改用 synchronized output）；修復使用 Kitty keyboard protocol 的終端遺失 Shift+非 ASCII 字元的問題；修復 Windows 上 PowerShell 指令驗證偶發性卡死問題

**核心概念（簡單說）：**
v2.1.183 的核心是「讓 auto mode 更安全，讓人可以更放心地把它打開」。過去在 auto mode 下，Claude 理論上可以在沒有確認的情況下跑 `git reset --hard` 把你的本地變更全部清掉，這對很多人來說是個顧慮。現在這類指令在「未經你明確要求丟棄工作」的情況下會直接被擋住，等於給 auto mode 加了一道安全網。

另一個值得注意的是 `attribution.sessionUrl` 設定——如果你在 Remote Control 或 Web session 裡讓 Claude 幫你 commit，過去每個 commit 訊息裡都會附上 claude.ai 的 session 連結。有些人不想讓這條連結出現在公開的 commit 歷史裡，現在可以直接關掉。

**前端工程師實際應用：**
- **跟你工作的關聯：** 這次更新讓你在前端專案裡開 auto mode 更安心——再也不用擔心 Claude 在你沒注意到的時候跑 `git checkout -- .` 把你還沒 commit 的修改清掉，特別是在做多步驟重構時。
- **具體場景：** 當你讓 Claude Code 在 auto mode 下跑一個大型 migration（例如把所有 class component 轉 functional component）時，就算任務途中模型判斷需要「清理 working tree」，這類破壞性指令現在也會跳出來要求你確認，而不是默默執行——你的本地草稿和未 commit 的試驗程式碼都是安全的。
- **這週可以嘗試：** 執行 `claude update` 升級到 v2.1.183，然後試試 `/config --help`，看看所有可用的快捷設定鍵有哪些——這是個快速了解 `/config` 功能全貌的好方法，不用去翻文件。
