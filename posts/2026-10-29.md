- **具體場景：** 你接手一個沒人敢動的 AngularJS / React 16 舊後台，可以先讓 Claude Code 讀整個 repo，產出 `ARCHITECTURE.md`（路由結構、狀態管理、API 呼叫點、風險清單），再分批把 class component 改成 hooks，每批用 `npm test` 驗證。
- **這週可以嘗試：** 計時看看：挑一個你不熟的 repo 或模組，用 Claude Code 從 clone 到「能跑起來並解釋主要流程」花多久，跟你過去手動上手的時間比較，評估自己團隊的實際導入成本。

## claudeai · Anthropic Blog

**原文網址：** https://www.anthropic.com/news/expanding-partnership-gsa

**原文：**
> Expanding our partnership with GSA to bring Claude to all levels of government（Oct 28, 2026 · Partnerships）
>
> （節錄）"gives government partners a 40% discount on Claude Enterprise, Claude for Government, and the Claude API."

**繁中改寫：**
Anthropic 擴大與美國總務署（GSA）的合作，新協議讓政府單位購買 Claude Enterprise、Claude for Government 與 Claude API 時享有 6 折優惠。這是第一次折扣涵蓋所有產品管道：現在向 Anthropic 直接購買就適用，未來幾個月也會擴及透過雲端供應商購買；適用對象也從聯邦延伸到州、地方、原住民族與領地政府。Anthropic 同時會推出協助機關導入的專案計畫。

幾個數字：目前約 500 個美國政府組織在用 Claude；Claude for Government 每週活躍使用者自 2 月以來成長約 8 倍；聯邦民事機關的使用量一年內成長約 20 倍。這份協議預估為政府省下 10 億美元，且沒有最低消費門檻，用多少付多少。

文中列出的實際案例：
- 猶他州讓 10 個機關共 34 位開發者試用 Claude Code，80% 在 30 分鐘內完成環境設定，71% 在四週內省下 20 小時以上。
- 某州 CIO 表示團隊靠 Claude 在 8 分鐘內回應勒索軟體攻擊，過去通常要 2–3 天。
- 某聯邦資安團隊用 Claude Mythos 約兩天內找到並修補一個可能導致關鍵正式系統被接管的漏洞，而前一個月的人工滲透測試沒抓到。
- 某州 IT 開發者兩天內把近 900 個 API method 遷移到新框架，原本預估要一個月。
- 某州 IT 主管用 Claude Code 為 12 個 legacy repo 寫文件，盤點出 467 張資料表並標出 27 個風險。

資安合規方面：Claude for Government 已於 9 月 30 日正式上線，具 FedRAMP High 授權；透過 Amazon Bedrock 與 Google Vertex AI 使用也都有 FedRAMP High 授權，部分模型在 AWS GovCloud 可跑 DoD IL4 / IL5 工作負載；Claude Enterprise 正透過 FedRAMP 20x 申請 Moderate 授權。

**核心概念（簡單說）：**
表面上是採購新聞，但真正值得工程師看的是那串案例：大部分都不是「寫新功能」，而是遷移框架、替舊系統補文件、找漏洞、處理事故。這反映出 AI coding agent 目前最有槓桿的地方是「理解並改造既有系統」——人類最痛、最耗時、最少人願意做的工作。

另一個觀念是「計量付費、無最低消費」：導入 agent 不再需要先簽大合約，可以從單一團隊、單一 repo 開始試，依實際效益擴大。這也是為什麼 Utah 能用四週試辦就拿到具體數據。

**前端工程師實際應用：**
- **跟你工作的關聯：** 「900 個 API method 兩天遷移完」這類案例，前端對應的就是大規模 codemod：換 UI library、升 React 大版本、把 REST 呼叫換成 GraphQL / tRPC。
- **具體場景：** 專案要從 `axios` 包裝層換成原生 `fetch` + TanStack Query，牽涉上百個呼叫點。讓 Claude Code 先列出所有呼叫點與共用的 interceptor 行為，訂出轉換規則，再分批改寫並跑 `tsc --noEmit` 與單元測試驗證每一批。
- **這週可以嘗試：** 盤點你專案中一個「大家都知道該做但沒人想做」的遷移任務，請 Claude Code 先只做評估：列出影響範圍、風險與預估批次，不改任何程式碼，看看它的評估是否準確。

> AI for Science expands to foundations and research institutions（Oct 28, 2026 · Announcements）

**繁中改寫：**
Anthropic 擴大 AI for Science 計畫，新增 20 個合作的科學基金會、研究機構與研究專案。這個計畫從 2025 年 5 月開始，原本是直接提供免費 Claude credits 給個別研究者；現在改為透過機構與基金會觸及更多科學家。

合作對象分三類：
- **科學基金會與學會**（負責把 credits 分配給研究者）：Alfred P. Sloan Foundation、Simons Foundation、Schmidt Sciences、Renaissance Philanthropy 的 Open Source for Science Fund、美國國家科學基金會（NSF）、美國化學會旗下的 CAS。
- **研究機構**（內部使用）：Space Telescope Science Institute（負責 Hubble、James Webb 等望遠鏡的科學營運）、Wellcome Sanger Institute、Francis Crick Institute、Imperial College London 生命科學系、EMBL、Gladstone Institutes。
- **研究專案**：Princeton 的 FlyWire（果蠅全腦神經連結圖）、Columbia 的 LEAP（結合機器學習與物理的氣候模型）、Johns Hopkins 的 AstroPath（用天文巡天的校正方法逐細胞拍攝腫瘤）、Broad Institute 的 gnomAD（彙整 80 萬人以上 DNA 的人類遺傳變異參考庫）、Tau Ceti（用 Lean 建立自動形式化的數學證明庫）、澳洲的 Centre for Population Genomics。

文中也提到既有合作：與 HHMI Janelia 共同開發 Model Hardware Standard（MHS），一套讓 AI agent 能安全操作實驗儀器的共用規格，目前為 research preview；Allen Institute 則正在打造 AI agent 團隊分析其大型開放資料集，把數月的人工分析縮短到數小時。

**核心概念（簡單說）：**
這篇的重點是「從個人到機構」的擴張策略：與其一個個發 credits 給研究者，不如讓基金會和研究機構當分發節點，而且許多專案會產出開放資料集、開源軟體、開放標準等公共財，讓效益外溢到整個學界。

最值得工程師注意的是 MHS：它就像實驗儀器版的 MCP——定義一套標準介面，讓 agent 能用一致的方式操作不同廠牌的實驗設備，並內建安全邊界。這跟軟體世界「用 MCP 讓 agent 接上各種工具」是同一個思路：agent 的能力上限，取決於它能安全接上多少真實世界的工具。

**前端工程師實際應用：**
- **跟你工作的關聯：** MHS 和 MCP 的設計思路，可以直接套用在前端：把你常用的內部工具（設計系統、API mock、部署流程）包成標準化介面，agent 才能可靠地使用。
- **具體場景：** 團隊有一個內部的元件文件站與 Storybook，你可以寫一個簡單的 MCP server，提供 `search_component`、`get_component_props` 兩個工具，讓 Claude Code 寫 UI 時直接查詢正確的元件 API，而不是猜 props。
- **這週可以嘗試：** 列出你在開發時最常手動查詢的三個內部資源（例如設計 token、API schema、feature flag 清單），挑一個評估是否值得包成 MCP server 或 skill，讓 agent 能直接讀取。

**繁中改寫：**
Claude for Legal 新功能：提供一整個現成 artifact 範本庫，涵蓋合約審閱、法規動態掃描、引註查核等用途。

你可以從內建範例開始，加入自己的文件與 connector，再把它分享給公司裡任何需要的人。

換個角度看，這就像前端的 starter template 或低程式碼平台的範本市集：把常見工作流程固化成可重複使用、可客製的 app，讓非工程背景的使用者也能自己「組裝」工具。範本 + 資料 connector + 分享，是 AI 原生內部工具的典型組合。

**前端工程師實際應用：**
- **跟你工作的關聯：** 公司內部常有大量「只需要一個小表單或小儀表板」的需求，以前要排進前端 backlog；現在業務單位可能直接用 artifact 範本自己做，前端的角色會轉向提供範本、設計規範與資料串接。
- **具體場景：** 法務或 PM 想要一個「審查合約條款是否符合公司範本」的工具，你可以先用 Claude 建一個 artifact 原型，接上團隊的文件 connector，把它當成需求規格與 demo，再決定是否值得做成正式的內部系統。
- **這週可以嘗試：** 挑一個你最近收到的小型內部工具需求，先用 Claude 的 artifact 做出可互動原型（30 分鐘內），拿去跟需求方確認，觀察能省下多少來回溝通的時間。

## Claude Code · Changelog

- Improved WebFetch errors in cloud sessions — 雲端 session 中 WebFetch 解析不到 host 時，會提示可能不在允許的網域清單內。
- 另有 22 項 bug fixes（頁面預設收合，未逐條列出）。

**核心概念（簡單說）：**
今天沒有新版本釋出。最近一版 2.1.312 主要在打磨雲端 session 與企業部署：雲端 routine 可調 effort、WebFetch 網路白名單錯誤更好懂、企業可用 Entra ID `oid` 識別使用者，並為 hooks 加上明確的併發上限，避免大量 hooks 拖垮 session。
