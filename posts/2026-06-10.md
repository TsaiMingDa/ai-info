## Claude Code · Changelog

**版本號 / 日期：** v2.1.170 / 2026-06-09

**變更項目：**
- **Introducing Claude Fable 5**（引入 Claude Fable 5）：全新 Mythos 等級模型正式公開發布，更新到 v2.1.170 後即可在 Claude Code 中使用
- **Session Transcript Fix**（修復 VS Code 中 session 記錄遺失）：修正在 VS Code 整合終端機或繼承了 Claude Code 環境變數的 shell 中啟動時，session 不會儲存記錄（也不出現在 `--resume` 選項中）的問題

**核心概念（簡單說）：**
這次更新主要是讓 Fable 5 在 Claude Code 中可用，同時修了一個在 VS Code 裡用 Claude Code 時 session 記錄消失的 bug。如果你習慣用 `--resume` 恢復上一個對話、或需要回顧 session 記錄，這個修復對你特別重要——更新前在 VS Code integrated terminal 裡跑的 session 不會被存下來。

**前端工程師實際應用：**
- **跟你工作的關聯：** 升級到 v2.1.170 後，可以在 Claude Code 中直接使用 Fable 5，而且 VS Code 的 session 記錄問題已修復，不會再遇到 `--resume` 找不到記錄的情況。
- **具體場景：** 如果你常在 VS Code 的 integrated terminal 裡開 Claude Code 做長時間重構任務，以前記錄可能消失讓你無法用 `--resume` 繼續——升級後可以安心在 VS Code 裡啟動 Claude Code，並用 `claude --resume` 回到上次的討論。
- **這週可以嘗試：** 執行 `npm install -g @anthropic-ai/claude-code@latest` 升級到最新版，然後在 VS Code 的 terminal 中跑一個任務，結束後用 `claude --resume` 確認 session 記錄有正常保存。

**版本號 / 日期：** v2.1.169 / 2026-06-08

**變更項目：**
- **`--safe-mode` flag**（安全模式旗標）：新增 `--safe-mode` 旗標與 `CLAUDE_CODE_SAFE_MODE` 環境變數，啟動時停用所有自訂設定（CLAUDE.md、plugins、skills、hooks、MCP servers）以方便排除問題
- **`/cd` command**（工作目錄切換指令）：新增 `/cd` 指令，可在同一個 session 中切換工作目錄，且不會中斷 prompt cache
- **`disableBundledSkills` setting**（停用內建 skills 設定）：新增 `disableBundledSkills` 設定與 `CLAUDE_CODE_DISABLE_BUNDLED_SKILLS` 環境變數，可隱藏內建的 skills、workflows 和 slash commands
- **UI bug fixes**（UI 問題修復）：修復方向鍵在已換行的 command history 中跳錯列的問題、JetBrains IDE terminal 閃爍問題、Kitty keyboard protocol 下 Shift+非 ASCII 字元被忽略的問題
- **MCP & Remote Control**（MCP 及遠端控制修復）：修復企業管理的 MCP policies 在重新連線後未正確套用的問題；修復遠端 session 在啟動時遇到短暫後端中斷後永久卡住的問題
- **Agent view enhancements**（Agent 視圖增強）：`claude agents --json` 現在包含被封鎖和剛派發的 session；新增 `--all` 旗標可查看已完成的 session；新增 `id` 和 `state` 欄位
- **Background sessions**（背景 session 改善）：背景 session 在 retire→wake 循環後現在能保留 `--ide`、`--chrome`、`--remote-control` 等 flag

**核心概念（簡單說）：**
v2.1.169 是一個大型更新，主要做了兩件事：加了更多除錯工具（`--safe-mode`、`/cd`），以及修了一堆在各種環境下的 bug。`--safe-mode` 特別有用——當你不確定是哪個 CLAUDE.md 或 plugin 造成行為異常時，直接開 safe mode 就能快速判斷是不是設定問題，排除後再逐一排查，省去大量 debug 時間。

**前端工程師實際應用：**
- **跟你工作的關聯：** `--safe-mode` 和 `/cd` 都直接提升日常使用體驗——前者解決「懷疑是設定問題但不知從哪查起」的困境，後者讓你在一個 session 裡跨專案切換目錄而不會破壞 prompt cache。
- **具體場景：** 當 Claude Code 在某個前端專案裡行為異常（例如一直忽略你的指令或反覆犯同樣錯誤），先用 `claude --safe-mode` 排除是否是 CLAUDE.md 或某個 MCP server 的設定問題，確認後再回到正常模式逐一排查。
- **這週可以嘗試：** 如果你有多個前端專案，試試在同一個 Claude Code session 中用 `/cd ../another-project` 切換到另一個專案目錄，感受這個工作流程的流暢度，以及 context 是否正確對應到新的工作目錄。
