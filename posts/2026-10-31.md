**原文：**
> 摘要（完整原文請見上方連結）：Claude is renaming its Max plans: Max 5x becomes Max and Max 20x becomes Ultra, still priced at $100 and $200 per month, with no action needed from subscribers. The 5-hour limit is also being removed for verified Ultra accounts, starting with most existing subscribers. Newer accounts keep a temporary limit until verified, which helps prevent fraud and abuse, and they get an email when it is lifted. Weekly limits are unchanged. Plans: https://claude.com/pricing

**繁中改寫：**
Claude 把 Max 方案改名了：Max 5x 改叫 Max，Max 20x 改叫 Ultra，價格維持每月 100 美元和 200 美元，現有訂閱者不用做任何事。此外，通過驗證的 Ultra 帳號將取消 5 小時限制，從大部分現有訂閱者開始。較新的帳號在完成驗證前仍有暫時性限制，這是為了防範詐騙和濫用，限制解除時會收到 email。每週限制則維持不變。

**核心概念（簡單說）：**
這則公告其實包含兩件事。改名只影響方案名稱，公告中的價格沒有變。實質變動是 Ultra 取消 5 小時限制，但每週限制仍在，所以高用量使用者可以更集中地使用額度，總量上限則沒有因此取消。

驗證機制是為了防止濫用：沒有短期限制後，新帳號更容易被用來大量消耗資源，所以要先確認帳號可信才開放。這和 API 服務常見的信任分級概念相似，帳號通過審核後才能取得較寬鬆的限制。

**前端工程師實際應用：**
- **跟你工作的關聯：** 查文件、討論區或團隊內部的方案說明時，會同時看到新舊名稱，要知道 Max 5x 對應現在的 Max，Max 20x 對應 Ultra。
- **具體場景：** 如果團隊的 onboarding 文件寫著「請訂閱 Max 20x」，現在應改成「Ultra」，並註明舊名稱，避免新同事找不到方案或選錯。
- **這週可以嘗試：** 到 https://claude.com/pricing 確認新方案內容，然後搜尋團隊文件裡的 `Max 5x` 和 `Max 20x`，一次更新過時的寫法。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.316 / October 31, 2026

**變更項目：**
- `CLAUDE_CODE_SUBAGENT_EFFORT`（新增）：在沒有其他設定指定時，決定 subagent 使用的 effort level，不再繼承 session 的設定
- `CLAUDE_CODE_DISABLE_ULTRATHINK`（新增）：關閉 `ultrathink` 關鍵字
- `CLAUDE_CODE_DISABLE_LOOPED_CROSS_CERT_DROP`（新增）：保留彼此循環認證的系統 cross-certificate，適用於私有 CA 有此需求的伺服器
- Claude apps gateway 新增 pooled group budgets：群組成員共用一筆每月預算，同時保留個人上限，透過 spend limits admin API 的 `pooled_budget` 設定
- Claude apps gateway 新增 `managed.policy_mode: layered`：所有符合開發者的 policy 都會套用並依序合併，不再只套用第一個
- Claude apps gateway 的 Bedrock upstream 新增 `guardrail.input_tagging`：為 prompt 加上 Bedrock guardrail prompt attacks filter 需要的 input tag
- [VSCode] 可以直接在 chat panel 登入 Claude apps gateway，不需要 terminal；`ultrathink` 改為以 xhigh effort 執行該回合，並在輸入框顯示彩虹效果
- [Cloud sessions] 新增 form card，可填寫或拒絕 MCP server 要求的表單；切回尚未同步完的 session 時會顯示 “Catching up…”
- [Code Review] analytics 頁面新增依嚴重程度分類的 findings 卡片
- Opus 4.8 的 fast mode 自 2026 年 10 月 30 日起棄用，將於 11 月 30 日移除；移除後，相關請求會回傳錯誤，不會退回一般 Opus 4.8，要繼續加速需改用 Opus 5.5
- server-managed settings（Team、Enterprise）：從 Anthropic API 取得的設定不再需要核准提示即可套用，驗證失敗的本機副本則會被拒絕
- `/diff` 在大型 repo 上通常可少跑一次完整的 git 指令，git 較慢時也會拉長更新間隔
- 修正：PowerShell hook 在指令開頭為 type cast、`param`、`using` 或 attribute 時，exit code 2 無法阻擋的問題
- 修正：Windows 上 Grep、Glob 在搜尋程序於逾時被終止卻沒有退出時，一直不回傳的問題
- 修正：`--restricted` session 在 Read allow rule 涵蓋時，會上傳工作目錄以外檔案的問題
- 修正：壓縮回應被截斷或損毀時，部分網路請求卡住的問題
- 此版另有其他項目（共 5 項 improvements 與 34 項 bug fixes），本 digest 未逐條收錄；完整內容見 https://code.claude.com/docs/en/changelog

**核心概念（簡單說）：**
這版對一般開發者最實用的是 `CLAUDE_CODE_SUBAGENT_EFFORT`。過去 subagent 預設繼承主 session 的 effort，主 session 開高 effort 時，連簡單的搜尋子任務也會用同樣的等級。現在可以另外設定預設值：主流程維持高 effort，子任務用較低 effort。但如果其他設定已經指定 effort，那些設定仍會優先。

另一個要處理的是 Opus 4.8 fast mode 的棄用時程。11 月 30 日移除後請求會直接報錯，不會自動退回，所以有寫死這個組合的腳本要提早遷移。

**前端工程師實際應用：**
- **跟你工作的關聯：** 用 subagent 平行處理測試、搜尋或元件遷移時，可以用這個環境變數調整子任務的 effort，在速度、用量和品質之間取得平衡。
- **具體場景：** 遷移大量 React 元件時，主 session 用高 effort 規劃遷移策略，並設定 `CLAUDE_CODE_SUBAGENT_EFFORT=low` 讓 subagent 掃描引用和更新 import，再用測試確認結果。
- **這週可以嘗試：** 用同一個小型重構任務，比較設定和未設定 `CLAUDE_CODE_SUBAGENT_EFFORT` 的執行時間與結果品質；也順便搜尋 CI 和腳本有沒有寫死 Opus 4.8 fast mode，趕在 11 月 30 日前改掉。
