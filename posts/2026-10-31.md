**繁中改寫：**
Thariq 認為，用 coding agent 時很容易進入一種亢奮狀態：感覺一直在工作、產出很多，實際上卻沒什麼進展。他覺得這常常是在逃避生活中的其他事。接著他引用 Chris Lakin 的觀點補充：人上癮的對象不是滑手機或過勞本身，而是這些行為帶來的「麻醉」效果。

**核心概念（簡單說）：**
Agent 讓「產出」的成本大幅下降，但「產出」不等於「進展」。以前寫一個功能要花半天，投入的時間會逼你先想清楚值不值得做；現在開五個 session 同時跑，畫面一直在動、PR 一直出現，大腦得到的回饋跟真正完成重要工作很像，於是更難分辨自己是在推進目標，還是只是在維持忙碌的感覺。

這則跟他 10 月 20 日談「多工的人應該慢下來，先問 P0 是什麼」的貼文是同一條思路：瓶頸已經從打字速度，移到判斷什麼值得做。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端特別容易掉進這個陷阱，因為 UI 微調的回饋最即時：間距、動畫、元件重構都能很快看到變化，卻不一定對使用者或專案目標有影響。
- **具體場景：** 你讓 Claude Code 同時重構 design system 的 `Button`、換掉 icon 套件、調 dark mode，一天開了六個 PR，但真正卡住上線的結帳頁 Core Web Vitals（LCP）問題完全沒動。
- **這週可以嘗試：** 每天開第一個 agent session 前，先寫下一句「今天做完什麼才算有進展」；下班前對照實際 merge 的 PR，算算有多少比例跟那句話有關。

**原文：**
> 摘要（完整原文請見上方連結）：Claude's mobile apps got upgrades this week. On iPad and iPhone Duo, what Claude makes now opens beside the chat rather than over it, with a full-screen option. On iOS and Android, you can stay signed into multiple accounts and switch without signing out (https://x.com/claudeai/status/2115859380143030507).

**繁中改寫：**
Claude 行動版 App 這週有幾項更新。在 iPad 和 iPhone Duo 上，Claude 做出來的內容現在會開在對話旁邊，不再蓋住對話，想細看時也能切成全螢幕。iOS 和 Android 則支援同時登入多個帳號，切換時不用先登出。

**核心概念（簡單說）：**
第一項是版面模式的改變：從「覆蓋式（modal / overlay）」變成「並排式（split view）」。覆蓋式一次只能看一邊，想邊看成果邊下指令就得不斷開關；並排式讓對話和產出同時可見，迭代時少了切換的成本，大螢幕的空間也用得更完整。

第二項解決的是工作帳號與個人帳號並用的情境。這看似小事，但多帳號切換牽涉到每個帳號各自的 token 儲存、資料隔離和通知歸屬，是行動 App 常見的棘手需求。

**前端工程師實際應用：**
- **跟你工作的關聯：** 「內容開在旁邊，必要時全螢幕」是 AI 產品和編輯器類工具很常見的 layout pattern，做響應式介面時可以直接參考。
- **具體場景：** 在 React 專案做 AI 預覽面板時，用 CSS container queries 判斷可用寬度：夠寬就用 Grid 兩欄並排，太窄就退回全螢幕的 sheet，切換時保留對話的捲動位置和輸入框草稿。
- **這週可以嘗試：** 找一個你專案裡的 modal 預覽（例如 PDF 或圖片預覽），試做成寬螢幕下並排、窄螢幕下全螢幕的版本，用 `@container` 取代 viewport media query，比較兩者的使用體驗。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.314 / October 30, 2026

**變更項目：**
- `permissions.blockWritesOutsideWorkingDirectories`（新增）：Write、Edit、NotebookEdit 在任何權限模式下都會拒絕寫入工作目錄以外的路徑
- Claude apps gateway upstream 新增選用的 `groups` 清單：只有列在 IdP 群組內的開發者會被導向該 upstream，failover 時也一樣
- Claude apps gateway 的 Bedrock upstream 新增 `guardrail_trace`：記錄是哪個 Bedrock guardrail filter 擋下請求，但不記錄比對到的文字
- VS Code 與 Claude Desktop Code 分頁新增 idle compaction：閒置的 200K+ token 對話會先產生摘要，若 prompt cache 已過期，下次發訊息時就改用摘要
- [Cloud sessions] Scheduled tasks 頁面新增 Include completed 按鈕（當被隱藏的只有已完成的一次性任務時才出現）
- [Claude Tag] Enterprise 組織連接 Slack 後，admin settings 的 Bundles 與 Channels 分頁新增可關閉的 Claude Tag API 文件連結
- bundled dataviz skill 更新：y 軸刻度標籤在 10,000 以下完整顯示；甜甜圈圖和圓餅圖的需求改用排序長條圖或標示數值的分段長條圖回應
- Claude 的檔案工具編輯組織 server-managed settings 的本機副本前會先詢問
- hook 的 `if` 條件（如 `Monitor(tail *)`）現在會比對 Monitor 工具的 shell 指令，比對方式與 `Bash(tail *)` 比對 Bash 指令相同
- `FORCE_HYPERLINK=false`（以及 `no`、`off`）現在會關閉超連結，而不是開啟
- Bash 工具的 shell 會清除繼承的 `which` alias 或 function，確保 `which` 是系統指令或 zsh builtin
- macOS：Claude 執行的多數指令中，`git grep` 改用 C locale，以避開 macOS regex 函式庫處理非 UTF-8 檔案時回報的記憶體洩漏
- [Cloud sessions] 從 web、desktop、mobile 開啟的 cloud session，在 setup script 回傳錯誤時仍會啟動，不再直接失敗
- 此版另有其他 Changed 項目，以及摺疊的 16 項 improvements 與 81 項 bug fixes，本 digest 未逐條收錄；完整內容見 https://code.claude.com/docs/en/changelog

**核心概念（簡單說）：**
這版主軸是「把 agent 的邊界管得更明確」。`blockWritesOutsideWorkingDirectories` 是這次最實用的新設定：它是不受權限模式影響的硬性限制，就算開了較寬鬆的模式，檔案工具也不能寫到專案目錄之外。要注意它涵蓋的是 Write、Edit、NotebookEdit 這幾個檔案工具，原文並未提到 Bash，所以 shell 指令不應視為一併被擋。

另一個值得注意的是 idle compaction：長對話放著不動，等 prompt cache 過期後，下一則訊息本來得用未快取的價格重送整段上下文；先做好摘要，就能降低回來繼續工作時的成本。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端常在 monorepo 或多個 sibling repo 之間工作，agent 誤改到 `~/.npmrc`、全域設定或隔壁專案的風險是真實存在的，這個新設定可以直接降低風險。
- **具體場景：** 在 `.claude/settings.json` 的 `permissions` 內加上 `"blockWritesOutsideWorkingDirectories": true`，然後讓 Claude Code 大批升級 `packages/ui` 的相依套件，確保檔案工具的改動都留在工作目錄內。需要跨 repo 時，再明確把該目錄加進工作目錄。
- **這週可以嘗試：** 在一個實驗用的 repo 打開這個設定，請 Claude 寫一個檔案到上層目錄，確認它會被拒絕，再試試 Bash 的 `echo > ../x` 是否也被擋，親自搞清楚這道防線的實際範圍。
