## boris_cherny · Threads

**原文網址：** https://www.threads.com/@boris_cherny/post/sample-post-1

**原文：**
> TypeScript 5.8 ships today with a new `erasableSyntaxOnly` flag. If you use it, you can run `.ts` files directly with Node 23+ without a build step. This is a big deal for scripts and CLIs.

**繁中改寫：**
TypeScript 5.8 今天正式發布，帶來了全新的 `erasableSyntaxOnly` 旗標。啟用這個選項後，你可以在 Node.js 23+ 環境中直接執行 `.ts` 檔案，完全不需要編譯步驟。對於撰寫腳本和 CLI 工具來說，這是個重大突破。

**核心概念（簡單說）：**
TypeScript 一直以來都需要先「編譯成 JS 再執行」。這個新旗標讓 Node.js 可以在執行時期直接處理 TypeScript 的型別語法（方法是直接忽略它們），所以你的 `.ts` 檔就像寫了型別的 `.js` 一樣可以直接跑。重點是：這只適用於「純粹可抹除的語法」（enum、namespace 等仍不支援），但日常的型別標注全部 OK。

**前端工程師實際應用：**
- **跟你工作的關聯：** 你寫 Node.js 腳本（例如 build 工具、資料轉換）時，再也不用設定 ts-node 或 tsx 才能執行 TypeScript 了
- **具體場景：** 這個 repo 的 `scripts/build-posts-json.ts` 正是用 `tsx` 執行——升級到 Node 23+ 後可以改成原生執行
- **這週可以嘗試：** `node --version` 確認版本；若是 23+，試著 `node scripts/build-posts-json.ts`（不需要 tsx）

## trq212 (Thariq) · Thread Reader App

**原文網址：** https://threadreaderapp.com/thread/sample-thread-1

**原文：**
> We use Claude Code with Skills internally at Anthropic. A Skill is a markdown file that gives Claude a mini-manual for a specific task. Instead of putting everything in CLAUDE.md, you break it up into focused skills. Claude only loads the skill when it's relevant.

**繁中改寫：**
Anthropic 內部使用 Claude Code 的方式是搭配「Skills（技能）」系統。一個 Skill 就是一個 Markdown 檔案，給 Claude 針對特定任務的操作手冊。不是把所有指示都塞進 CLAUDE.md，而是拆分成各自獨立的技能檔案。Claude 只在需要的時候才載入對應的 Skill。

**核心概念（簡單說）：**
把它想成「Claude 的 SOP 卡片抽屜」。CLAUDE.md 是全域規則，Skill 是「這件事的詳細做法」。需要時才叫出來，避免 context 被塞滿。這讓 Claude 在不同任務上都能有深度的脈絡，而不是一個什麼都知道一點點的通才。

**前端工程師實際應用：**
- **跟你工作的關聯：** 你可以為團隊的常見任務（PR review 標準、元件設計規範、API 串接模式）各自寫一個 Skill，讓 Claude Code 在對應情境自動套用
- **具體場景：** 為這個專案寫一個 `digest-update` Skill，讓你更新 posts 時 Claude 自動遵循格式規範
- **這週可以嘗試：** 在 `.claude/` 資料夾建立第一個 `<task-name>.md` skill 檔，試試指定 Claude 呼叫它

## claudeai · Anthropic Blog

**原文網址：** https://www.anthropic.com/news/sample-announcement

**原文：**
> Claude now supports a Files API that lets you upload documents once and reference them across multiple API calls. This reduces token usage for repeated context and enables new patterns for document-heavy workflows.

**繁中改寫：**
Claude 現在支援 Files API，讓你可以先上傳一份文件，之後在多次 API 呼叫中反覆引用它。這樣做可以減少重複傳送相同 context 所消耗的 token，也為需要大量處理文件的工作流程帶來新的設計模式。

**核心概念（簡單說）：**
以前每次呼叫 API 都要把文件內容完整貼進去（浪費 token 又慢）。Files API 讓你「先存好，後引用」——就像上傳到雲端後給 Claude 一個檔案 ID，它就知道內容是什麼，不用重傳。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你正在開發 AI 功能、讓使用者上傳 PDF 或文件讓 Claude 分析，Files API 可以大幅降低成本和延遲
- **具體場景：** 使用者上傳設計稿一次，之後可以問多個問題而不用重複傳送圖片
- **這週可以嘗試：** 閱讀 Anthropic Files API 文件，評估你現有或計畫中的 AI 功能是否適合使用

## Claude Code · Changelog

**版本號 / 日期：** 1.2.0 / 2026-05-10

**變更項目：**
- **Skills system** — Claude Code now supports `.claude/skills/*.md` files. Skills are loaded on-demand based on task context, keeping the main CLAUDE.md focused on global rules. (支援 Skills 系統，依任務情境按需載入技能檔案)
- **Improved hooks** — Pre-tool and post-tool hooks now receive structured JSON with tool name and arguments, making it easier to write conditional logic. (Hook 現在收到結構化 JSON，方便撰寫條件邏輯)
- **Bug fix** — Fixed an issue where `git push` hooks would fire twice on force-push. (修正 force-push 時 hook 觸發兩次的 bug)

**核心概念（簡單說）：**
這次更新最重要的是 Skills 系統——把以往塞在 CLAUDE.md 裡的所有規則，拆成各自獨立的 skill 檔案，讓 Claude 只在需要的時候才載入對應技能，避免 context 被塞爆。Hook 的改進則讓自動化腳本可以知道「現在 Claude 在呼叫什麼工具、帶了什麼參數」，開啟更精細的自動化可能。

**前端工程師實際應用：**
- **跟你工作的關聯：** Skills 讓你可以為不同任務（PR review、元件設計、API 串接）各自寫一份詳細 SOP，Claude Code 會在對的時機自動套用
- **具體場景：** 建立 `.claude/skills/pr-review.md`，裡面寫你的 PR review 標準（例如要求有測試、要有型別標注），之後叫 Claude review PR 時它會自動遵守
- **這週可以嘗試：** 在 `.claude/` 資料夾建立第一個 skill 檔，把你最常重複告訴 Claude 的規則寫進去，看看有沒有差
