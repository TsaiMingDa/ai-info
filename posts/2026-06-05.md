**原文：**
> At Anthropic, we are delegating a growing share of AI development to AI systems themselves, which is speeding up our work. More than 80% of code merged into the company's codebase is now written by Claude. Engineers are shipping roughly eight times as much code per quarter as they were before 2025.
>
> Taken far enough, and given enough compute, this trend points to an AI system capable of fully autonomously designing and developing its own successor—what we call recursive self-improvement. We are not there yet, and recursive self-improvement is not inevitable, but it could come sooner than most institutions are prepared for.
>
> Anthropic believes it would be good for the world to have the option to slow or temporarily pause frontier AI development. A meaningful slowdown or pause would require multiple well-resourced labs at or near the frontier, in multiple countries, agreeing to stop under the same conditions. It would also require that each can verify that the others have actually stopped.
>

Anthropic 今天發布了一篇重量級研究：Anthropic 工程師現在有超過 80% 的 code 是由 Claude 寫的，每季 commit 量是 2024 年以前的 8 倍。

他們把這條路的終點稱為「recursive self-improvement」——AI 系統能夠完全自主地設計、開發自己的下一代。Anthropic 表示目前還沒到那個程度，但這件事可能比大多數機構準備好的還早發生。

因此 Anthropic 呼籲建立一套機制：當需要時，能夠讓多個頂尖 AI 公司在可驗證的條件下，一起按下暫停鍵。

**核心概念（簡單說）：**
這篇文章的核心是一個數字和一個概念。

**數字：** Anthropic 在 2026 年 5 月，超過 80% 的 production code 是由 Claude 寫的。這不是說 Claude 只是「幫忙改 bug」，而是真正驅動工程產出的主力。

**概念：** Recursive self-improvement（遞迴自我改善）——想像 AI 不只是寫 code，而是在設計、訓練比自己更強的下一代 AI，然後那個 AI 再設計更下一代……這個循環如果啟動，人類插手的機會就會越來越少。

Anthropic 的這篇文章等於是在說：「我們自己也在加速這個過程，但我們覺得世界需要有個緊急煞車。」這也引發了外界的討論——一個正在衝刺 IPO 的公司，呼籲全球暫停 AI 開發，這個姿態是真心的安全警告，還是一種競爭壁壘的建立？

**前端工程師實際應用：**

**版本號 / 日期：** v2.1.163 / 2026-06-04

**變更項目：**

*新功能：*
- `requiredMinimumVersion` / `requiredMaximumVersion` managed settings：可在組織設定中鎖定允許的 Claude Code 版本範圍，版本不符時拒絕啟動並引導使用者到指定版本
- `/plugin list` 指令：列出已安裝的 plugin，支援 `--enabled` / `--disabled` 篩選
- `/btw` 新增 "c to copy" 快捷鍵：將原始 markdown 答案複製到剪貼簿，貼到其他地方時保留格式
- Hooks：`Stop` 和 `SubagentStop` hook 現在可以回傳 `hookSpecificOutput.additionalContext`，讓 Claude 收到 feedback 後繼續執行（不被標記為 hook error）
- Skills：新增 `\$` escape 語法，可在 command body 裡在數字前加入字面的 `$`
- stdio MCP server 在 `--resume` 時現在會收到 `CLAUDE_CODE_SESSION_ID`

*Bug Fixes — Bash / Commands：*
- 修正 `claude -p` 在 background 指令沒有正常退出時會 hang 住的問題（background shell 現在在回傳結果後約 5 秒停止）
- 修正 bash 指令在 bazel 和 EDR 工作流下執行失敗的 regression（始於 2.1.154）
- 修正 Windows 上 bash 指令因 session-env 目錄有 read-only 屬性或在 OneDrive 中而出現 "EEXIST: file already exists" 錯誤
- 修正 Windows 上 hook 明確調用 `/usr/bin/bash script.sh` 時 bash 指令失敗的問題

*Bug Fixes — Sessions / Background：*
- Background agent session 現在在背景自動更新到新版本，重新連線後不再需要等待冷啟動
- 修正 background subagent 輸出污染 `claude -p` stdout（在 `--output-format text` 或 `json` 時）
- 修正 fresh config 目錄在 startup 時 fetch 完成後 permission rules 沒有套用到整個 session 的問題
- 修正 `isolation: "worktree"` 的 Workflow agent 被阻止編輯自己 worktree 內的檔案

*其他修復：*
- 修正 hook `if: "Bash(...)"` 條件在任何包含 `$()` 或 `$VAR` 的 bash 指令都會觸發的問題
- 修正 home directory 路徑的 deny rule 沒有阻擋使用 `$HOME` 的 bash 指令
- 修正退出 agent view 時按 Esc 導致 terminal 錯位和多秒 hang 的問題
- 改善 terminal 渲染效能

**核心概念（簡單說）：**
v2.1.163 是一個「大補丁」版本——新功能、改善、修復三管齊下。

最值得注意的兩個新功能：

1. **版本鎖定（`requiredMinimumVersion`/`requiredMaximumVersion`）**：對企業或團隊來說這很重要。你可以在 managed settings 裡設定版本範圍，確保整個團隊用的是同一套行為一致的 Claude Code，避免「我這邊沒問題但你那邊會出錯」的版本問題。

2. **Hook 可以繼續對話（`hookSpecificOutput.additionalContext`）**：以前 hook 只能「擋下來」或「放行」，現在 Stop/SubagentStop hook 可以給 Claude 一段回饋文字，讓 Claude 根據這個回饋繼續當前的 turn，而不是直接結束。這讓自動化工作流可以更聰明地處理邊界情況。

**前端工程師實際應用：**
- **跟你工作的關聯：** `/btw` 的 "c to copy" 快捷鍵對前端工程師特別實用——你可以在 Claude Code 裡問一個技術問題，拿到 markdown 格式的答案後，直接複製貼到 PR description、Notion、或 Slack，格式完整保留。
- **具體場景：** 在 Claude Code 裡詢問某個 API 的使用方式，Claude 回傳 markdown 格式的說明和程式碼範例後，按 `c` 複製，再貼到你的 PR description 裡作為技術文件——省去重新排版的時間。
- **這週可以嘗試：** 如果你的團隊用 Claude Code，可以嘗試在 project 的 `.claude/settings.json` 裡設定 `requiredMinimumVersion`，把值設為 `"2.1.163"`，這樣舊版使用者開啟時會被提示更新，統一團隊版本。
