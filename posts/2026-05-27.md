## Claude Code · Changelog

**版本號 / 日期：** v2.1.152 / 2026-05-27

**變更項目：**

*新功能與指令*
- `/code-review --fix` now applies review findings to your working tree after the review, surfacing reuse, simplification, and efficiency suggestions; `/simplify` now invokes `/code-review --fix`（`/code-review --fix` 直接把 review 建議套用到工作目錄，自動修正重複、簡化和效能問題；`/simplify` 現在等同於呼叫 `/code-review --fix`）
- Skills and slash commands can now set `disallowed-tools` in frontmatter to remove tools from the model while the skill is active（skill / slash command 可在 frontmatter 設定 `disallowed-tools`，在 skill 啟用時限制可用工具）
- Added `/reload-skills` command to re-scan skill directories without restarting the session（新增 `/reload-skills` 指令，無需重啟 session 即可重新掃描 skill 目錄）

*Hook 系統強化*
- `SessionStart` hooks can now return `reloadSkills: true` to re-scan skill directories, making skills installed by the hook available in the same session（`SessionStart` hook 可回傳 `reloadSkills: true`，讓 hook 安裝的 skill 在同一 session 立即生效）
- `SessionStart` hooks can now set the session title via `hookSpecificOutput.sessionTitle` on startup and resume（`SessionStart` hook 可透過 `hookSpecificOutput.sessionTitle` 設定 session 標題）
- Added a `MessageDisplay` hook event that lets hooks transform or hide assistant message text as it is displayed（新增 `MessageDisplay` hook 事件，可轉換或隱藏助理回應文字）

*Plugin 與 Marketplace*
- Added `pluginSuggestionMarketplaces` managed setting: admins can allowlist org marketplaces whose plugins may be suggested via context-aware tips（新增 `pluginSuggestionMarketplaces` 管理設定，admin 可允許特定 org marketplace 的 plugin 建議出現）
- `claude plugin marketplace remove` now accepts `--scope user|project|local` for symmetry with other marketplace commands（`claude plugin marketplace remove` 新增 `--scope user|project|local` 參數）

*穩定性與 UX 改進*
- Claude Code now switches to your configured `--fallback-model` for the rest of the session when the primary model is not found, instead of failing every request（主要 model 找不到時，自動切換到 `--fallback-model` 繼續本 session，而非每次請求都失敗）
- Auto mode no longer requires opt-in consent（Auto mode 不再需要選擇加入確認）
- Vim mode: `/` in NORMAL mode now opens reverse history search (like Ctrl+R), matching bash/zsh vi-mode（Vim mode NORMAL 模式下 `/` 開啟倒序歷史搜尋，行為與 bash/zsh vi-mode 一致）
- The `/usage` breakdown now includes large session files; files are scanned with a streaming read so memory usage stays flat（`/usage` 分解現在納入大型 session 檔案，以串流讀取避免記憶體暴漲）
- Thinking summaries in the collapsed group now stay readable for at least 3 seconds, render as markdown, and cap at 10 lines (`Ctrl+O` shows the full thinking)（摺疊 group 中的 thinking summary 至少保持可讀 3 秒，以 markdown 渲染，上限 10 行；按 Ctrl+O 可展開完整思考）
- In fullscreen mode, the "Thinking for Ns" indicator now counts up live while the model is thinking, and keeps its value if you interrupt mid-thought（全螢幕模式下「Thinking for Ns」指示器實時計數，中斷後保留數值）
- Simplified the Workflow tool's inline progress display — live agent counts now show only in the persistent workflow status row below the prompt（Workflow tool 的行內進度顯示簡化，執行中 agent 計數只顯示在工作流狀態列）
- The post-response timer now shows "Waiting for N background agents/workflows to finish" when backgrounded agents are still running（回應後計時器新增顯示正在等待的背景 agent/workflow 數量）
- Added the session entrypoint as an OpenTelemetry metric attribute (`app.entrypoint`, opt-in via `OTEL_METRICS_INCLUDE_ENTRYPOINT=true`)（新增 `app.entrypoint` 為 OpenTelemetry metric attribute，需 opt-in 開啟）

*Bug 修正（精選）*
- Fixed terminal styling degrading in very long sessions by recycling the renderer's style pool（修正長 session 中終端樣式退化問題）
- Fixed the sandbox-enabled warning not appearing in condensed startup mode（修正精簡啟動模式下 sandbox 警告不顯示的問題）
- Fixed the loading spinner showing "still thinking"/"almost done thinking" while a tool is running（修正工具執行中 spinner 顯示「still thinking」的問題）
- Fixed focus mode showing a spurious "N messages hidden" count on turns with no hidden activity（修正 focus mode 在無隱藏訊息時顯示多餘計數的問題）
- Fixed clicking a link inside an expanded tool result collapsing the section instead of opening the link（修正點擊展開工具結果中的連結卻折疊區塊而非開啟連結的問題）
- Fixed markdown table cell borders inheriting the color of inline code, wrapped continuation lines losing their style, and empty header cells showing a label in the narrow-terminal stacked layout（修正 markdown 表格 border 繼承 inline code 顏色等樣式問題）
- Fixed plugin MCP servers with the same command but different environment variables being incorrectly deduplicated（修正同指令但不同環境變數的 plugin MCP server 被錯誤去重的問題）
- Fixed remote MCP servers failing to connect in Claude Code Remote sessions when the egress proxy is enabled（修正 egress proxy 啟用時 Remote MCP server 連線失敗的問題）
- Fixed sessions getting stuck after a model or login switch left stale thinking-block signatures in history（修正切換 model 或登入後 session 因 history 含 stale thinking-block signatures 而卡住的問題）
- Fixed `cache_creation_input_tokens` reporting as 0 in transcript and result usage when the API reports cache writes only via the nested `cache_creation` breakdown（修正 cache 寫入 token 數在 usage 回報為 0 的問題）
- Fixed the PushNotification tool incorrectly reporting "Mobile push not sent (Remote Control inactive)" in SDK-hosted sessions when Remote Control is enabled（修正 PushNotification tool 在 SDK-hosted session 中誤報推播未送達的問題）

**核心概念（簡單說）：**

v2.1.152 是功能與修復並重的版本，最重要的一筆是 `/code-review --fix`（`/simplify` 現在就是它的別名）：以前跑 `/code-review` 只會列出問題清單，現在加上 `--fix` Claude 會直接把建議——可以重複使用的程式碼、可以簡化的邏輯、效能改善點——寫回工作目錄，讓 code review 從「看報告」變成「直接修完」。

除此之外，這版大幅強化了 hook 和 skill 的可程式化能力：`SessionStart` hook 現在能設定 session 標題、讓 hook 安裝的 skill 立即生效；新的 `MessageDisplay` hook 可以攔截並轉換 Claude 的回應文字；skill 的 `disallowed-tools` frontmatter 讓每個 skill 都可以限定自己能用哪些工具，避免越界操作。整體趨勢是把 Claude Code 從「對話工具」推向更可程式化、可自動化的開發平台。

**前端工程師實際應用：**
- **跟你工作的關聯：** `/simplify` 直接把 code review 建議套用到檔案，特別適合前端工程師在提 PR 前做最後一輪清理——重複的 state 宣告、過長的 useEffect、可以提取的 utility function，Claude 會直接幫你修，你用 `git diff` 確認結果即可。若你有自訂的 skill（例如 `/lint`、`/generate-tests`），`disallowed-tools` 讓你可以精確限制它的操作範圍，例如讓唯讀分析的 skill 無法意外修改檔案。
- **具體場景：** 在 Next.js 專案裡寫完一個新的 server action 或 React 組件後，在 Claude Code 裡跑 `/simplify`，Claude 會掃描並自動合併重複邏輯、簡化條件判斷、提取重複的 JSX 片段，全部直接寫回。或者你寫了一個 `/analyze-bundle` 的 skill，在 frontmatter 加上 `disallowed-tools: [Edit, Write, Bash]`，確保它只能分析輸出，不會意外修改任何檔案。
- **這週可以嘗試：** 更新 Claude Code 到 v2.1.152，選一個你最近寫的、覺得「還可以更好但懶得動」的組件或 hook，在 Claude Code 裡跑 `/simplify`（或 `/code-review --fix`），看看它能找到哪些可以自動改善的地方，再用 `git diff` 決定哪些改動要 accept。
