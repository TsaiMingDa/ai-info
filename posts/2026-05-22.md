**原文網址：** https://www.threads.com/@boris_cherny/post/DYmuD8kiFEQ

**原文：**
> In the next version of Claude Code: run /usage to see a breakdown of which Skills, Agents, MCPs, and Plugins are using your tokens
>
> CLI today, coming to Desktop next

**繁中改寫：**
下一版 Claude Code 將加入 `/usage` 指令，讓你可以看到 Skills、Agents、MCPs 和 Plugins 各自消耗了多少 token。CLI 版今天起可以用，Desktop 版即將跟進。

**核心概念（簡單說）：**
Token 用量一直是 Claude Code 的黑盒子——你知道跑了很多，但不知道是哪個環節最耗資源。`/usage` 指令解決了這個問題，把消耗拆分到每個子系統（Skills、Agents、MCPs、Plugins）。這讓你可以精準診斷：是某個 MCP server 太耗 token？還是某個 Skill 的 prompt 太長？這是做 cost optimization 的前提。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你在 Claude Code 裡裝了多個 MCP（例如 chrome-devtools、context7）或多個 Plugins，現在可以直接知道哪個最燒 token，幫助你決定要不要精簡設定。
- **具體場景：** 你開一個複雜的重構 session，Claude 跑完後 `/usage` 一看，發現 80% 的 token 都是某個 Agent 子任務吃掉的，就知道該拆成更小的 sub-task 或調整 Agent 的 system prompt。
- **這週可以嘗試：** 更新到最新版 Claude Code CLI，跑完下一個複雜任務後執行 `/usage`，觀察哪個來源消耗最多，作為調整 workflow 的依據。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.148 / 2026-05-22

**變更項目：**
- Fixed the Bash tool returning exit code 127 on every command for some users (a regression introduced in 2.1.147) — 修正 Bash 工具對某些使用者每個指令都回傳 exit code 127 的問題（2.1.147 引入的退步）

**核心概念（簡單說）：**
2.1.148 是一個緊急 hotfix，修正了前一版（2.1.147）引入的嚴重 bug：Bash tool 對部分使用者的每個指令都會回傳 exit code 127（即「command not found」）。Exit code 127 在 Unix/Windows shell 裡代表找不到對應的執行檔，但這裡是 Claude Code 本身的誤報，實際上指令完全正確。這類 bug 直接癱瘓所有依賴 Bash tool 的工作流程——只要 Claude 需要跑任何 shell 指令，全部都會失敗。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你用 Claude Code 執行 `npm run build`、`git push`、`npx`、或任何 shell 指令，在 2.1.147 版本可能會一律失敗並看到 exit code 127，即使指令本身完全正確。
- **具體場景：** 讓 Claude Code 執行 `npm run dev` 啟動開發伺服器，或跑 `git add . && git commit -m "..."` 時，Claude 回報「指令執行失敗（127）」，但同樣的指令在終端手動執行完全正常——這就是 2.1.147 的 bug。
- **這週可以嘗試：** 執行 `claude --version` 確認目前版本；若低於 2.1.148 請立即更新（`npm install -g @anthropic-ai/claude-code` 或透過 Claude Code Desktop 的自動更新），以避免 Bash tool 失效影響工作流程。
