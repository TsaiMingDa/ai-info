## Claude Code · Changelog

**版本號 / 日期：** v2.1.148 / 2026-05-22

**變更項目：**
- Fixed the Bash tool returning exit code 127 on every command for some users (a regression introduced in 2.1.147) — 修正部分使用者的 Bash 工具每次執行都回傳 exit code 127 的問題（此問題為 v2.1.147 引入的 regression）

**核心概念（簡單說）：**
這是一個緊急 hotfix：v2.1.147 引入了一個 regression，導致部分使用者的 Bash 工具無法正常執行任何指令，每次都回傳 exit code 127（「找不到指令」的錯誤碼）。v2.1.148 直接修復這個問題，讓 Bash 工具恢復正常運作。

**前端工程師實際應用：**
- **跟你工作的關聯：** Claude Code 的 Bash 工具是執行 `npm run`、`git`、`tsc` 等日常指令的核心通道，如果你在 v2.1.147 上遇到任何指令都失敗的情況，就是這個 bug 的影響。
- **具體場景：** 你在 Claude Code 裡叫它執行 `npm run build` 卻一直收到 exit code 127，升級到 v2.1.148 即可解決。
- **這週可以嘗試：** 執行 `claude --version` 確認目前版本，若低於 v2.1.148 則執行 `claude update` 升級。

**版本號 / 日期：** v2.1.147 / 2026-05-21

**變更項目：**
- Pinned background sessions (`Ctrl+T` in `claude agents`) now stay alive when idle, are restarted in place to apply Claude Code updates, and are shed under memory pressure only after non-pinned sessions — 釘選的背景 session（在 `claude agents` 中按 `Ctrl+T`）閒置時不會被自動終止、更新時原地重啟，且在記憶體壓力下比未釘選的 session 更晚被回收
- Renamed `/simplify` to `/code-review`; now reports correctness bugs at a chosen effort level (e.g., `/code-review high`); pass `--comment` to post findings as inline GitHub PR comments — 將 `/simplify` 更名為 `/code-review`，可指定 effort level（如 `high`），加 `--comment` 可直接把結果貼為 GitHub PR 的 inline comment；原有的清理與修正行為已移除
- Improved auto-updater: retries transient network failures, reports specific error categories and OS error codes on failure, shows current version when an update fails — 自動更新機制改善：遇到暫時性網路問題自動重試，失敗時顯示具體錯誤類型與 OS error code
- Improved diff rendering performance for large file edits — 大型檔案編輯時的 diff 渲染效能提升
- Prompt history no longer records consecutive duplicate entries — 避免重複提交相同 prompt 在歷史記錄中堆疊重複條目
- Fixed enterprise login restrictions (`forceLoginOrgUUID` and `forceLoginMethod`) not being enforced against third-party-provider and API-key sessions — 修正企業登入限制未正確套用至第三方 provider 及 API key session 的問題
- Fixed `&` in `!` command output displaying as `&amp;`, which broke copy-pasting URLs from commands like `gcloud auth login` — 修正 `!` 指令輸出中 `&` 被顯示為 `&amp;` 的問題（影響複製含 `&` 的 URL）
- Fixed unknown slash commands silently doing nothing in headless/SDK mode — 修正 headless/SDK 模式下未知 slash command 靜默無反應的問題
- Fixed `/help` rendering a broken tab header and showing only one command per page on small terminals — 修正 `/help` 在小型終端機上版面破損且每頁只顯示一個指令的問題
- Fixed shell snapshot dropping user functions whose names start with a single underscore — 修正 shell snapshot 遺漏名稱以單底線開頭的 function，導致依賴這些 function 的 alias 失效
- Fixed plugin agents that declare multiple `Agent(...)` types in `tools:` frontmatter dropping all but the last entry — 修正 plugin agent 宣告多個 `Agent(...)` 類型時只保留最後一個的問題
- Fixed hook `if` conditions like `PowerShell(git push*)` never matching — 修正 hook 的 `if` 條件（如 `PowerShell(git push*)`）永遠無法匹配的問題（之前只有 `PowerShell(*)` 有效）
- Fixed PowerShell tool dropping output for commands that rely on the default formatter — 修正 PowerShell 工具遺漏使用預設 formatter 的指令輸出
- Fixed "Yes, and don't ask again" for PowerShell script invocations not persisting on Windows — 修正 Windows 上對 PowerShell script 選擇「不再詢問」後，後續執行仍會再次詢問的問題
- Fixed PowerShell tool failing on Windows with exit code 1 when `pwsh` is installed via winget or Microsoft Store — 修正透過 winget 或 Microsoft Store 安裝的 `pwsh` 導致 PowerShell 工具失敗的問題
- Fixed `/effort` opening with the slider on the wrong level — 修正 `/effort` 滑桿開啟時顯示錯誤位置
- Fixed paginating MCP servers dropping resources, templates, and prompts past page 1 — 修正 MCP server 分頁時遺漏第 2 頁後的 resources、templates、prompts
- Fixed full-screen strobing in attached background sessions on Windows Terminal while Claude is streaming — 修正 Windows Terminal 中 Claude streaming 時全螢幕閃爍問題
- Fixed removing a background-job worktree following NTFS junctions into the main repo on Windows — 修正 Windows 上刪除背景 job 的 worktree 時 NTFS junction 被錯誤延伸至主 repo
- Fixed `/background` refusing sessions whose only typed input was a skill or custom slash command — 修正 `/background` 拒絕以 skill 或自訂 slash command 作為唯一輸入的 session
- Fixed auto mode suppressing `AskUserQuestion` when the user or skill explicitly relies on it — 修正 auto mode 在使用者或 skill 明確需要 `AskUserQuestion` 時卻被壓制的問題
- Fixed `/theme` "New custom theme" and color editor dialogs not responding to Esc — 修正 `/theme` 自訂主題與色彩編輯對話框無法用 Esc 關閉的問題
- Fixed an uncaught exception at the end of streaming sessions when running via the Agent SDK — 修正透過 Agent SDK 執行時 streaming session 結束時的 uncaught exception
- Fixed stale and doubled rows in the agent view list on Windows when background session results contain wide (CJK) characters — 修正 Windows agent view 列表中 CJK 字元導致行列重複或殘留的問題
- Fixed pasted text being delivered to agents as `[Pasted text #N]` placeholder instead of actual content — 修正貼上的文字被以佔位符 `[Pasted text #N]` 傳給 agent 而非實際內容的問題
- Fixed plugin component counts in `claude plugin details` being doubled — 修正 `claude plugin details` 中 plugin 元件計數被重複計算的問題
- Fixed backgrounded sessions re-prompting for tool permissions already granted with "don't ask again" — 修正背景 session 重複詢問已選擇「不再詢問」的工具權限
- Fixed GNOME Terminal right-click and middle-click paste not inserting text — 修正 GNOME Terminal 右鍵與中鍵貼上無法插入文字的問題
- Fixed `CLAUDE_CODE_SUBAGENT_MODEL` not applying to teammate processes spawned by agent teams — 修正 `CLAUDE_CODE_SUBAGENT_MODEL` 未套用至 agent team 中衍生的 teammate process
- Fixed slash commands followed by a tab or newline being treated as unknown commands — 修正 slash command 後接 tab 或換行被誤判為未知指令的問題
- Fixed several spacing and layout glitches in `/plugin`, `/status`, `/mobile`, `/sandbox`, and `/permissions` menus — 修正多個選單的排版與間距問題
- Fixed stripped images prompting the model to repeatedly re-read media no longer present — 修正圖片被移除後模型仍反覆嘗試讀取已不存在媒體的問題

**核心概念（簡單說）：**
v2.1.147 是一個大型 patch release，帶來兩個重頭戲：第一，`/code-review` 取代 `/simplify`，可以指定 effort level 控制 review 深度，並能用 `--comment` 直接把結果推上 GitHub PR 的 inline comment，讓 AI code review 融入 PR 工作流程；第二，釘選背景 session 的行為更穩定，閒置不被砍、更新原地重啟，適合跑長時間的後台任務。此外修復了超過 30 個 bug，覆蓋 Windows、PowerShell、MCP、hook、agent view 等各面向。

**前端工程師實際應用：**
- **跟你工作的關聯：** `/code-review` 直接影響 code review 工作流程——你現在可以在送出 PR 前先讓 Claude 做一遍 correctness check，並自動把問題以 inline comment 貼到 GitHub，省去手動搬運的步驟。
- **具體場景：** 在本機完成一個 feature 分支後，在 Claude Code 執行 `/code-review high --comment`，Claude 會以高力度掃描你的 diff 並自動把 correctness bug 以 inline comment 貼至 GitHub PR，讓隊友直接在 GitHub 上看到 AI review 結果。
- **這週可以嘗試：** 找一個準備送 review 的 PR，在 Claude Code 執行 `/code-review medium`，看看 Claude 找到了哪些問題；若結果有用，下次加上 `--comment` 直接把 review 結果推到 PR 上。
