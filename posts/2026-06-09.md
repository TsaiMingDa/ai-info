## Claude Code · Changelog

**版本號 / 日期：** 2.1.169 / 2026-06-08

**變更項目：**
- `--safe-mode` 旗標（及 `CLAUDE_CODE_SAFE_MODE` 環境變數）：啟動時停用所有自訂設定（CLAUDE.md、plugins、skills、hooks、MCP servers），方便除錯
- `/cd` 指令：在不中斷 prompt cache 的前提下，將 session 切換到新的工作目錄
- `disableBundledSkills` 設定 + `CLAUDE_CODE_DISABLE_BUNDLED_SKILLS` 環境變數：向模型隱藏所有內建 skills、workflows 和斜線指令
- `/workflows` 現在在任務進行中也能立即開啟（不需等任務完成）
- 恢復 Vertex/Foundry 上 5 分鐘的預設 idle timeout，避免 stream 卡住無限等待
- 修復 Up/Down 方向鍵在多行輸入中跳過 wrapped row 直接進入命令歷史的問題
- 修復企業 MCP 政策（`allowedMcpServers`/`deniedMcpServers`）在重新連線、IDE 設定、`--mcp-config` 伺服器於首次安裝後或 remote settings 載入前未執行的問題
- 修復 macOS 使用 claude.ai 憑證登入時每個 turn 開始有約 30-50ms UI 卡頓的問題
- 修復 `claude -p` 在 Windows 上緩慢或卡住的 regression（自 2.1.161 引入）
- 修復 Remote Control 在 OAuth token 刷新時卡在「reconnecting」狀態
- 修復 Windows 啟動時 Git Credential Manager 跳出「Connect to GitHub」彈窗
- 修復 background agents 忽略 project-level settings `env` 值的問題（例如 `ANTHROPIC_MODEL`）
- 修復 `claude agents --json` 遺漏被封鎖及剛 dispatch 的 background sessions
- 修復 MCPB plugin cache 在 Windows 上被不必要地使快取失效
- 改善 `TaskCreate` 可靠性：自動修復格式錯誤的輸入
- 減少 response streaming 和 spinner 動畫時的 CPU 使用率
- Remote Control 重新連線後不再重複顯示過期的權限請求和 dialog 提示

**核心概念（簡單說）：**
v2.1.169 是以「除錯友善性」和「系統穩定性」為主軸的維護版本，正好在 Fable 5 發布前一天推出。

最重要的新功能是 `--safe-mode`：當你的 Claude Code 行為異常，懷疑是某個 hook、plugin 或 MCP server 在搗亂時，可以用 safe mode 啟動，暫時停用所有自訂設定，快速確認問題來源。

`/cd` 指令則解決了一個常見痛點：以前在 session 中切換工作目錄必須開新 session，會造成 prompt cache 中斷（cache miss → 增加 latency 和成本）。現在 `/cd` 讓你在同一個 session 內換目錄，完整保留 context 和 cache。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你有配置 CLAUDE.md、hooks 或 MCP servers，`--safe-mode` 是遇到奇怪行為時的第一個除錯工具。`/cd` 讓 monorepo 工作流更順暢——不用再為前後端各開一個 session。
- **具體場景：** 你有一個 monorepo，前端在 `packages/web`，後端 API 在 `packages/api`。啟動 Claude Code 後，用 `/cd packages/web` 處理前端問題，再用 `/cd packages/api` 切換到後端，context 和 cache 全程保持連貫，不用重新交代背景。
- **這週可以嘗試：** 如果你有設定 hooks 或 CLAUDE.md，試試 `claude --safe-mode` 看看沒有這些自訂設定時行為有何不同，驗證哪些自訂設定真的對你的工作流有效果、哪些可能是在干擾。

**版本號 / 日期：** 2.1.166 / 2026-06-06

**變更項目：**
- `fallbackModel` 設定：可配置最多三個備用模型，在主要模型過載或不可用時依序嘗試；`--fallback-model` 現在也適用於互動式 session
- Deny rule 的 tool 名稱位置支援 glob pattern（`"*"` 拒絕所有 tools）
- `MAX_THINKING_TOKENS=0`、`--thinking disabled` 和每個模型的 thinking toggle 現在可以在預設啟用 thinking 的模型上停用 thinking
- 加強跨 session 訊息安全：透過 `SendMessage` 從其他 Claude session 傳來的訊息不再帶有使用者授權
- API 在意外的 non-retryable 錯誤時，現在會在 fallback 模型上重試一次（auth、rate-limit、request-size、transport 錯誤仍然立即浮現）
- `claude update` 現在在下載前會先公告目標版本，不再靜默進行
- 修復 JetBrains IDE 終端機（IntelliJ、PyCharm、WebStorm 等）在 2026.1+ 版本的閃爍問題
- 修復 Shift+非 ASCII 字元（例如 Shift+ä → Ä）在使用 Kitty keyboard protocol 的終端機（WezTerm、Ghostty、kitty）中被丟棄的問題
- 修復 background agent sessions 在 git worktree 中的 crash-loop 問題

**核心概念（簡單說）：**
v2.1.166 最重要的功能是 `fallbackModel`。當你指定的主要模型（例如 Fable 5）因為流量過大過載時，系統可以自動切換到你設定的備用模型，而不是直接報錯中斷任務。這對需要長時間運行的 agent 任務特別關鍵——可以在 `.claude/settings.json` 設定 `"fallbackModel": ["claude-opus-4-8"]`，讓任務在高峰期也能繼續執行而不中斷。

**前端工程師實際應用：**
- **跟你工作的關聯：** 在 Fable 5 剛發布、流量處於高峰期間，設定 `fallbackModel` 能讓你的 Claude Code 任務更穩定，不因 API 過載而中斷長時間任務。
- **具體場景：** 在 `.claude/settings.json` 加入 `"fallbackModel": ["claude-opus-4-8"]`，讓跑大型 migration 或 codebase audit 時，即使 Fable 5 過載也能自動切到 Opus 4.8 繼續，不用你手動重試。
- **這週可以嘗試：** 趁 Fable 5 發布初期需求高峰，先設好 `fallbackModel` 備用，確保你用 Dynamic Workflows 或 background agents 跑複雜任務時不會因模型過載而半途而廢。
