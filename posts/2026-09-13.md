**繁中改寫：**
現在光看 pass/fail 分數,基本上已經無法真正解讀 eval 的意義了。

我看到很多 benchmark 裡的「失敗」,其實是因為隱藏測試寫得過於嚴格——有些情況下,模型給出的答案反而比預期的 eval 結果更合理。

**核心概念（簡單說）：**
Thariq 指出目前 AI 評測(evals/benchmarks)常見的一個問題:很多「失敗」案例並非模型真的答錯,而是評測本身的標準答案或隱藏測試設計得太死板,導致模型給出更合理的答案卻被判定為失敗。這提醒大家不要只看分數表面數字,要實際去檢視失敗案例的內容。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的團隊也用類似 eval/benchmark 的方式驗證自己寫的 prompt 或 AI 功能(例如 LLM-judge、自動化測試套件),這個提醒很實用——分數低不代表功能真的壞掉。
- **具體場景：** 假設你幫產品加了 AI 客服功能,寫了 50 條測試案例驗證回覆品質,結果通過率從 95% 掉到 85%,先別急著回滾——應該去看那 15% 失敗案例的實際回覆內容,有可能是測試的預期答案太死板,而不是模型真的變差。
- **這週可以嘗試：** 檢查你手上任何自動化 eval/測試套件裡「失敗」的案例,人工讀幾筆實際輸出內容,確認是模型真的錯,還是測試案例本身寫得太嚴格。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.270 / September 12, 2026

**變更項目：**
- Fixed read-only git commands in Bash unexpectedly asking for permission after a session had been running for a while (regression in 2.1.269)（修正:長時間執行的 session 中,唯讀的 git 指令在 Bash 裡會意外跳出權限詢問,這是 2.1.269 版引入的回歸錯誤）

**核心概念（簡單說）：**
這是一個小型修補版本,修正上一版(2.1.269)引入的回歸錯誤——session 跑久了之後,原本不需要權限確認的唯讀 git 指令(如 `git status`、`git log`)會突然又跳出權限詢問,打斷工作流程。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你長時間開著同一個 Claude Code session 進行開發,常會用 `git status`/`git diff` 之類的唯讀指令確認狀態,這個 bug 會讓你每次都要多按一次「允許」,現在已修正。
- **具體場景：** 你整天掛著一個 Claude Code session 做 code review 或除錯,中途讓它跑 `git log` 確認最近的 commit,卻跳出權限詢問而非照設定直接允許——更新到 2.1.270 就能解決。
- **這週可以嘗試：** 若你目前版本是 2.1.269 且遇到類似的權限彈出問題,執行 `claude --version` 確認版本後更新到 2.1.270（或更新版）。

**版本號 / 日期：** 2.1.269 / September 11, 2026

**變更項目（原始清單約 80 項,以下為與前端工程師最相關的精選重點）：**
- Added `claude plugin eval`: run a plugin's eval suite against Claude Code and get scored, reproducible results (JSON + HTML report)（新增:可對 plugin 執行 eval 測試套件,產生可重現的評分結果,含 JSON 與 HTML 報告）
- Added `/output-style [name]` to list and switch output styles, including over Remote Control and in cloud/headless sessions（新增:可用 `/output-style [name]` 列出並切換輸出風格,支援 Remote Control 及雲端/headless session）
- Added a diff of the files a Bash command changed to the Bash tool result (setting `bashEditDiffEnabled`)（新增:Bash 工具結果會附上該指令異動的檔案 diff,可透過 `bashEditDiffEnabled` 設定開關）
- Fixed the prompt cache being partially invalidated on the turn after a response was cut off at the output-token limit and automatically resumed（修正:回覆因輸出 token 上限被截斷並自動接續後,下一輪的 prompt cache 會被部分失效）
- Fixed F1/F2/F4 and other key handling issues in kitty-protocol, st, rxvt-unicode and WezTerm terminals（修正:kitty-protocol、st、rxvt-unicode、WezTerm 等終端機的按鍵行為問題）
- [VSCode] Added an agent map: an "N agents" footer pill opens a map of the session's sub-agents with per-agent cards, Stop agent, and read-only transcripts（新增:VSCode 版新增 agent 地圖,可視覺化檢視 session 中所有 sub-agent 狀態並個別停止）
- [VSCode] Added a Hooks dialog and a Permission rules dialog for viewing/editing hooks and permission rules directly in the UI（新增:VSCode 版新增 Hooks 與 Permission rules 對話框,可直接在 UI 內編輯 hooks 與權限規則,不必手改設定檔）
- [Claude Code on the web] Added taking back a queued message in a cloud session before Claude reads it（新增:雲端 session 中,可以在 Claude 讀取前收回已排入佇列的訊息）

**核心概念（簡單說）：**
這是一個內容量非常大的版本更新,重點包含三大類:(1) plugin/skill 品質驗證工具(`claude plugin eval`)、(2) VSCode 端更多 UI 管理功能(agent map、Hooks/Permission 對話框,讓你不用手改設定檔就能管理權限與 hooks)、(3) 大量穩定性與終端機相容性修正(prompt cache、按鍵處理、session 恢復等)。整體方向是讓 Claude Code 在長時間、多 agent、跨平台(VSCode/web/Slack)使用時更穩定、更好管理。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你在 VSCode 裡用 Claude Code 且會同時開多個 subagent 平行處理任務,新的 agent map 讓你能一目了然看到每個 agent 在做什麼、要停就停,不用再切來切去看 transcript。
- **具體場景：** 你請 Claude Code 同時跑 3 個 subagent,分別處理前端元件重構、測試撰寫、文件更新,過去很難掌握每個 agent 進度,現在點開 footer 的「3 agents」就能看到卡片式總覽,個別停止或檢視 transcript。
- **這週可以嘗試：** 更新到 2.1.269 以上,在 VSCode 裡開一個多 subagent 任務,點開新的 agent map 面板體驗一下;同時也可以試著在既有 plugin 資料夾跑 `claude plugin eval init`,熟悉評測流程。
