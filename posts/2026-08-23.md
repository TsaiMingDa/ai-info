**原文：**
> a skill people at Anthropic have been using a lot recently: ELI5
>
> /eli5 <what you want explained>
>
> "explain like I'm someone who knows nothing about this topic, using a HTML artifact with big pictures and few words"

**繁中改寫：**
Anthropic 內部最近很紅的一個 skill：ELI5（Explain Like I'm 5）。用法很簡單，打 `/eli5 <你想搞懂的東西>`，Claude 就會用「假設對方完全不懂這個主題」的方式，做一個圖多字少的 HTML artifact 出來解釋給你看。

**核心概念（簡單說）：**
這其實是把「向新手解釋複雜概念」這件事包裝成一個可重複使用的 skill，輸出形式固定是視覺化的 HTML artifact（大圖、少文字），而不是一大段純文字說明。對工程師來說，這代表 Claude Code 的 skill 系統可以把「輸出風格」也標準化，而不只是「執行什麼任務」。

**前端工程師實際應用：**
- **跟你工作的關聯：** 平常要跟 PM、設計師或新進同事解釋一個技術決策（例如為什麼要用 SSR、為什麼某個 bug 會發生）時，常常要花時間畫圖或簡化說明，這個 skill 直接把這個流程自動化。
- **具體場景：** 在 Claude Code 裡對一段複雜的 state management 邏輯或 CI/CD pipeline 下 `/eli5 這段 code 在幹嘛`，會產生一個帶示意圖的 HTML 頁面，可以直接截圖丟到 Slack 跟非工程背景的同事說明。
- **這週可以嘗試：** 找一個你最近正在跟人解釋卻解釋得很卡的技術主題（例如 React Server Components 跟 Client Components 的差異），試著用類似的 prompt 風格（"explain like I'm someone who knows nothing, using big pictures and few words"）請 Claude 幫你先做一版草稿。

**原文：**
> Point Claude Security at a GitHub repo and Mythos scans for vulnerabilities tracing data across files and reasoning about how components interact. Each finding comes back with a CWE category, confidence and severity ratings, and a suggested fix.

**繁中改寫：**
只要把 Claude Security 指向一個 GitHub repo，Mythos 就會掃描漏洞，而且是跨檔案追蹤資料流、推理元件之間怎麼互動的（不是單檔案孤立分析）。每個發現的問題都會附上 CWE 分類、信心分數、嚴重程度評級，以及建議的修復方式。

**核心概念（簡單說）：**
這則補充說明了掃描的技術深度：不是關鍵字比對式的簡易掃描，而是像人類 reviewer 一樣「跨檔案追資料流」，例如追蹤一個未經過濾的使用者輸入怎麼從 API 一路傳到前端渲染的地方。輸出格式也很標準化（CWE 分類 + 信心分數 + 嚴重度 + 修復建議），方便接入既有的安全流程或 ticket 系統。

**前端工程師實際應用：**
- **跟你工作的關聯：** CWE（Common Weakness Enumeration）分類是業界標準漏洞分類法，如果你的團隊有合規需求（SOC2、ISO 27001 等），這種結構化輸出可以直接餵進既有的安全報告流程。
- **具體場景：** 前端常見的跨檔案漏洞像是「某個 API response 沒有做 escape，直接被丟進 `dangerouslySetInnerHTML`」，這種需要追蹤資料流的問題正是 Claude Security 強調能處理的類型。
- **這週可以嘗試：** 檢查自己專案裡有沒有使用 `dangerouslySetInnerHTML`、`v-html`、或直接操作 `innerHTML` 的地方，先手動確認資料來源是否可信，作為之後對照 Claude Security 掃描結果的基準。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.239 / 2026年8月21日

**變更項目：**
- Cost estimates (/cost, status line, --max-budget-usd) now include the 1.1× US-only-inference premium for data-residency workspaces（成本估算 /cost、status line、--max-budget-usd 現在會納入 data-residency workspace 的 1.1 倍美國專屬推理加成費用）
- Added the one-time fullscreen renderer offer on Bedrock, Vertex, Foundry and other previously excluded setups; new installs there now start in fullscreen（Bedrock、Vertex、Foundry 等原本被排除的環境，現在新安裝時也會提示一次性啟用 fullscreen renderer）
- Added `/claude-api upgrade` to migrate Python projects from anthropic 0.x to 1.x（新增 `/claude-api upgrade`，協助把 Python 專案的 anthropic SDK 從 0.x 升級到 1.x，並更新對應的參考文件）
- Cloud sessions: plugins synced from claude.ai now show as `name@synced`, work with `claude plugin enable/disable <name>@synced`, and never override a same-named plugin you installed（雲端 session 中從 claude.ai 同步的 plugin 會標示為 `name@synced`，且不會覆蓋你本機已安裝的同名 plugin）
- Fixed Bedrock streaming behind proxies that strip the response Content-Type header, which silently doubled billed API calls by re-running every turn non-streaming（修正 Bedrock 在會去除 Content-Type header 的 proxy 後方時，會靜默地以非串流方式重跑每個 turn，導致計費 API 呼叫數翻倍的問題）
- Fixed Claude Code hanging at startup behind an HTTPS proxy when using Bedrock with an SSO profile and awsAuthRefresh（修正搭配 Bedrock SSO profile 與 awsAuthRefresh 時，在 HTTPS proxy 後方啟動會卡住的問題）
- Fixed a race where pressing Esc with a prompt queued could let the next turn finish early, leaving the session idle while Claude was still working（修正佇列中的 prompt 按 Esc 時可能出現的 race condition，導致 session 顯示閒置但 Claude 其實還在跑）
- Fixed WebFetch retaining expired page content in memory for the whole session instead of the intended 15 minutes（修正 WebFetch 快取的網頁內容應該只保留 15 分鐘，卻整個 session 都留在記憶體中的問題）
- Fixed custom session titles disappearing from /resume after more than ~64 KB of conversation was written following the rename（修正自訂 session 標題在改名後對話超過約 64KB 就會從 /resume 清單消失的問題）
- （其餘還有大量 Windows、Remote Control、fullscreen mode、vim mode、MCP 相關細節修正，詳見官方 changelog）

**核心概念（簡單說）：**
這個版本重點在修正幾個「靜默出錯」的 bug（例如 Bedrock proxy 環境下計費 API 呼叫數會偷偷翻倍、WebFetch 快取沒有照時間過期釋放），以及擴大 fullscreen renderer 到更多企業部署環境（Bedrock/Vertex/Foundry）。另外新增了 anthropic Python SDK 從 0.x 升到 1.x 的自動遷移指令。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的團隊用 Bedrock 或企業內部 proxy 跑 Claude Code，這次修的計費翻倍問題值得注意 — 之前可能一直在多付錢卻沒發現。
- **具體場景：** 若專案裡有用 Python 版 anthropic SDK 呼叫 Claude API（例如後端 BFF 層），可以用新增的 `/claude-api upgrade` 指令輔助遷移到 1.x 版本，減少手動改 timeout 寫法（`anthropic.Timeout` 取代 `httpx.Timeout`）的麻煩。
- **這週可以嘗試：** 如果公司走 Bedrock/proxy 架構，檢查一下最近的 API 用量帳單有沒有異常偏高的跡象，這可能就是這次修正的那個雙倍計費 bug。
