**繁中改寫：**
Agent Skills 一開始只是 Claude Code 裡的一個實驗，後來整個產業都陸續採用，所以 Anthropic 覺得更適合把它捐給 Agentic AI Foundation（AAIF），跟 MCP 放在同一個家。

Boris 引用的 ClaudeDevs 貼文補充：自 2025 年 12 月公開標準以來，已有超過 70 個 agent 平台整合 Agent Skills，包括 ChatGPT、Cursor、GitHub Copilot 和 VS Code。

**核心概念（簡單說）：**
Skill 就是一個資料夾，裡面放一個 `SKILL.md` 加上需要的腳本或參考資料，用來教 agent「某件特定工作該怎麼做」。它原本是 Claude Code 自家的格式，現在交給中立的基金會（Linux Foundation 底下的 AAIF）管理，代表它從「某家廠商的功能」正式變成「業界共用的標準」。

類比的話，這很像當年 Node.js 從 Joyent 轉到 OpenJS Foundation：程式碼本身沒變，但治理權中立化之後，其他公司才敢放心長期投入。對開發者來說，最實際的意義是：你今天寫的 skill，未來在不同 agent 工具之間可攜性會更有保障。

**前端工程師實際應用：**
- **跟你工作的關聯：** 你在專案裡寫給 Claude Code 的 skill（例如元件產生規範、測試流程），同一份 `SKILL.md` 也能被 Cursor、Copilot、VS Code 等工具讀取，不必為每個工具各寫一份 prompt。
- **具體場景：** 團隊有人用 Claude Code、有人用 Cursor，你在 repo 放一個 `.claude/skills/new-component/SKILL.md`，寫清楚「新元件要用 Tailwind + shadcn/ui、附 Storybook story 與 Vitest 測試」，兩邊的 agent 都能照同一套規則產 code。
- **這週可以嘗試：** 到 agentskills.io 看一下規格，把你最常重複交代 AI 的一件事（例如「幫我建一個新頁面」的步驟）整理成一個 skill 資料夾，commit 進 repo。

> ⚠️ 本則內容為原文重點摘錄，非完整原文；完整內容請見原文網址

**繁中改寫：**
Anthropic 正式把 Agent Skills 捐給 Agentic AI Foundation。Skill 的概念很簡單：一個資料夾、一份 `SKILL.md`，再加上需要的腳本與參考資料，就能讓 agent 學會某個具體流程。它源自 Claude Code 團隊發現模型「通用知識夠，但缺少實際業務需要的程序性知識」，上線幾週內社群就在 GitHub 上發布了數千個 skill，還自己幫 Codex、Cursor、OpenCode 寫了 loader。

這次捐贈的不只是規格，還包括名稱、logo、GitHub organization 和 agentskills.io 網域。之後由跨公司的工程師以個人身分共同維護，roadmap 會先處理版本化發布、提案流程與安全指引。

**核心概念（簡單說）：**
MCP 解決的是「agent 怎麼連上外部工具與資料」，Agent Skills 解決的是「agent 怎麼知道一件事該照什麼步驟做」。兩者現在都在同一個中立基金會底下，等於 agent 生態系的兩塊基礎規格都脫離單一廠商控制。

文中特別提到 roadmap 要加上「versioned releases」和「security guidance」：skill 可以附帶可執行的腳本，本質上就像一個 npm 套件，所以版本鎖定與供應鏈安全會是接下來的重點，跟前端熟悉的 `package-lock.json`、`npm audit` 是同一類問題。

**前端工程師實際應用：**
- **跟你工作的關聯：** 安裝別人寫的 skill 就像裝 npm 套件，裡面的腳本會在你的機器上被 agent 執行；標準化之後會有更多公開 skill 可用，但也代表你要開始用看待第三方依賴的眼光看待它們。
- **具體場景：** 你從 GitHub 找到一個「自動跑 Lighthouse 並修正 a11y 問題」的 skill，裝進專案前應該先打開 `SKILL.md` 和附帶的 `scripts/`，確認它會執行哪些指令、會不會改到 CI 設定或送資料到外部。
- **這週可以嘗試：** 列出你目前專案或 `~/.claude/skills` 裡裝了哪些 skill，逐一看過它們附帶的腳本；再到 agentskills.io 的 GitHub 追蹤 roadmap 中的安全指引提案。

- **這週可以嘗試：** 若團隊使用 GCP，問一下 infra 負責人是否已啟用這項服務；自己先在 sandbox 專案用 service account 呼叫一次 Claude，確認 Skills API 或 Fast mode 是否能在你的區域使用。

**原文：**
> Starting next week, sessions across Claude web, desktop, and mobile apps will run in auto mode by default on Pro, Max, and Team plans.

> Auto mode reviews shell commands and actions with a separate classifier. In testing, it caught 89% of dangerous commands. Manual approval caught 14%.

**繁中改寫：**
從下週開始，Pro、Max 與 Team 方案在 Claude 網頁版、桌面版和手機 app 上的 session，預設都會以 auto mode 執行。不再每一步都要你按核准，而是由自動檢查擋下有風險的動作；隨時都可以切回手動模式。

這延續了 8 月 Claude Code 的做法：當時 auto mode 已成為 Claude Code 的預設權限模式，用獨立的 classifier 審查 shell 指令與動作。測試中它攔下 89% 的危險指令，人工逐一核准只攔下 14%。

**核心概念（簡單說）：**
「每一步都要人按同意」聽起來最安全，但數據顯示人會疲勞、會無腦按 Enter，實際攔截率很低。auto mode 改成讓另一個專門的 classifier 當守門員：一般操作直接放行，高風險操作（刪檔、對外送出、改系統設定）才擋下或詢問。

這就像前端的 ESLint + CI 對比「全靠 code review 人眼抓 bug」：自動化檢查不會累，能穩定攔下大部分已知危險模式，人只需要處理真正需要判斷的少數情況。

**前端工程師實際應用：**
- **跟你工作的關聯：** 你在桌面 app 或網頁版用 Claude 處理專案時，它會更自主地連續執行多個步驟；你需要更清楚地在 prompt 或 `CLAUDE.md` 裡交代邊界（哪些資料夾不能動、哪些指令不要跑）。
- **具體場景：** 請 Claude 把專案從 Jest 遷移到 Vitest，auto mode 下它會自己改設定、跑 `npm test`、修測試，一路做完；但如果它想 `rm -rf node_modules` 或 push 到 main，classifier 會攔下來。
- **這週可以嘗試：** 在 repo 的 `CLAUDE.md` 加一段「禁止事項」（例如不要直接 push main、不要改 `.env`），再用 auto mode 跑一個小型重構任務，觀察哪些動作被自動放行、哪些被攔下。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.309 / October 22, 2026

**變更項目：**
- [VSCode] Added a log warning that says what to do when dictation or the extension's own requests fail certificate verification, such as behind a TLS-inspecting proxy（VS Code 擴充在 TLS 檢查型 proxy 後方憑證驗證失敗時，log 會提示該怎麼處理）
- Updated the bundled dataviz skill to accept APCA as a text-contrast measure, add an `apca(text, background)` function to its palette validator scripts, and say whether a label inside a colored chart fill should be white or near-black（內建 dataviz skill 支援 APCA 文字對比度，並新增 `apca()` 驗證函式，能判斷圖表色塊內的標籤該用白字還是近黑字）
- Updated the /claude-api skill: service account keys and Workload Identity Federation tokens can now manage OpenTelemetry destinations（/claude-api skill：service account key 與 WIF token 現在可管理 OpenTelemetry 目的地）
- Changed `sed -i` to get the standard Bash prompt and run as written, not a simulated file-edit preview; like other Bash edits, it is no longer restored by /rewind（`sed -i` 改為一般 Bash 權限提示並照原樣執行，不再模擬成檔案編輯預覽，也不會被 /rewind 還原）
- Changed `claude ultrareview` to require workspace trust; scripts pass `--trust-workspace` or set `CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1`（`claude ultrareview` 需要 workspace trust，腳本可用 `--trust-workspace` 或環境變數略過）
- Changed the dangerous rm and rmdir prompt in bypass permissions mode in the Desktop app and VS Code to deny the command at once with a rewrite hint, so unattended sessions keep going（Desktop 與 VS Code 在 bypass 模式下遇到危險 rm / rmdir 直接拒絕並給改寫提示，無人值守的 session 不會卡住）
- Changed commands the settings exclude from the sandbox to ask before writing to its write-list paths while the sandbox is enabled but cannot run（sandbox 啟用但無法執行時，被排除在 sandbox 外的指令寫入 write-list 路徑前會先詢問）
- Changed worktree creation and reuse so git no longer fetches objects on demand（建立 / 重用 worktree 時 git 不再隨需 fetch 物件）
- Changed the /claude-api skill to build Managed Agents subagent teams on `multiagent_20261001` with dynamic workflows on by default（/claude-api skill 改用 `multiagent_20261001` 建立 Managed Agents subagent 團隊，預設開啟 dynamic workflows）
- Improved the speed of many git commands Claude Code runs for itself on Windows; errors from those commands now show in English（Windows 上 Claude Code 內部 git 指令變快，錯誤訊息統一用英文）
- Improved disk-full handling with clear messages instead of a raw ENOSPC error（磁碟滿時給出明確訊息，不再只丟 ENOSPC）
- [VSCode] Improved Edit and Write speed in the chat panel: the wait for new problems after each edit is now 0.75 seconds in most cases, down from 1 to 1.5 seconds（VS Code 聊天面板 Edit / Write 後等待 Problems 的時間從 1–1.5 秒降到約 0.75 秒）
- 另含其他 improvements 與 62 項 bug fixes，詳見原文

**核心概念（簡單說）：**
這版主軸是「讓無人值守的 session 更可靠」：bypass 模式下危險的 `rm` 直接拒絕並給提示而不是卡在確認框、`sed -i` 回歸一般 Bash 語意、ultrareview 加上 workspace trust 檢查、磁碟滿時錯誤更清楚。另外內建的 dataviz skill 加入 APCA（WCAG 3 草案採用的新一代對比度演算法），比 WCAG 2 的對比比值更貼近人眼對文字可讀性的實際感受。

**前端工程師實際應用：**
- **跟你工作的關聯：** APCA 直接影響圖表與 UI 的色彩可讀性判斷；VS Code 的 Edit / Write 加速則讓你在編輯器裡用 Claude 改 TypeScript 時，每次編輯後等 type check 回報的時間更短。
- **具體場景：** 你在做一個 Recharts 儀表板，長條圖內要放數值標籤；請 Claude 用 dataviz skill 檢查配色，它現在能用 `apca()` 算出每個色塊上該用白字還是近黑字，避免淺黃色塊配白字這種看不清楚的組合。
- **這週可以嘗試：** 執行 `claude update` 升到 2.1.309，然後請 Claude 用 dataviz skill 檢查你專案裡某張圖表的文字對比度，比較 APCA 與 WCAG 2 的判斷結果是否一致。
