## Claude Code · Changelog

**版本號 / 日期：** 2.1.319 / November 6, 2026

**變更項目：**
- Added support for MCP tasks in the terminal: when an MCP server runs a tool call as a task, Claude Code moves it to the background right away and tells Claude the result when it finishes — 終端機支援 MCP tasks：長時間的 MCP tool call 會立刻轉到背景，完成後再通知 Claude
- Added `permissions.denyInsteadOfPrompting` setting: a tool call that would wait on a permission prompt is denied and the turn continues — 原本會跳權限詢問的 tool call 直接拒絕、讓流程繼續跑
- Added `/claude-api latency-optimize` to find where your Claude API code makes people wait and try faster settings against your eval — 找出 Claude API 程式碼的延遲瓶頸並用 eval 測試更快的設定
- Added an "Earlier in this session" row to `/tasks` that lists finished subagents — `/tasks` 可重新打開已結束的 subagent
- Changed self-paced `/loop` to end when a turn finishes without rescheduling; set `CLAUDE_CODE_LOOP_KEEPALIVE=1` to keep the old behavior — 自訂節奏的 `/loop` 沒有重新排程就會結束

> 註：自上次 digest 後無更新版本，2.1.319 為最近一次 update（2026-11-08 digest 已完整收錄）。

**核心概念（簡單說）：**
這版主軸是「長時間任務與無人值守流程」。MCP tasks 讓跑好幾分鐘的工具（E2E 測試、部署、大量產圖）不再卡住對話，概念上像把同步的 `await` 改成背景 Promise + 完成通知；`denyInsteadOfPrompting` 則讓 CI、排程或 subagent 這種沒人盯的情境遇到權限問題時直接拒絕並繼續，而不是卡在詢問畫面直到 timeout。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你有包裝 Playwright、Storybook 或 Lighthouse 的 MCP server，長任務可以改成 task 形式；在 GitHub Actions 跑 `claude -p` 也能避免因權限詢問卡死。
- **具體場景：** 請 Claude「跑 Playwright 視覺回歸測試，同時補齊 Button 元件的 Storybook stories」，測試在背景跑、Claude 先寫 stories，結果回來再整理失敗截圖；CI 端在 `.claude/settings.json` 設 `"permissions": { "denyInsteadOfPrompting": true }`。
- **這週可以嘗試：** 若還沒升級，執行 `claude update` 到 2.1.319，在排程或 CI 專案加上 `denyInsteadOfPrompting`，跑一次確認不會再卡在權限詢問。
