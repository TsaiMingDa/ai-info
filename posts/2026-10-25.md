另外，Gmail 那邊有沒有人可以處理一下，讓別人沒辦法掃描「已停用的 email 地址」啊 🫩？我本來還希望能有個輕鬆的星期五晚上。

**核心概念（簡單說）：**
這是一句帶點苦笑的抱怨：公司帳號在離職後被停用，外界就能透過「寄信是否被退回」或登入、註冊流程的回應差異，偵測出哪些 email 已經失效，等於變相洩漏「這個人離職了」的消息。這類問題在資安上叫做 account enumeration（帳號列舉）：系統對「帳號存在 / 不存在 / 已停用」給出不同回應，攻擊者或好事者就能批次掃描推論出資訊。

**前端工程師實際應用：**
- **跟你工作的關聯：** 登入、註冊、忘記密碼這幾個表單通常是前端負責的 UI，錯誤訊息怎麼寫，直接決定會不會洩漏帳號狀態。
- **具體場景：** 忘記密碼頁如果顯示「此 email 未註冊」或「此帳號已停用」，任何人都能拿名單逐一測試；比較安全的做法是不管帳號狀態，都顯示「如果此 email 有註冊，我們已寄出重設信」，並讓 API 回應時間與狀態碼保持一致。
- **這週可以嘗試：** 檢查你專案的 login / forgot-password 流程，用 DevTools Network 面板比對「存在」與「不存在」帳號的 response body、status code 是否不同；有差異就統一成同一種訊息。

## Claude Code · Changelog

**版本號 / 日期：** 2.1.310 / October 23, 2026

**變更項目：**
- Added the Monitor tool and plugin monitors on Bedrock, Vertex, and Foundry, and when telemetry or nonessential traffic is disabled; long foreground sleeps are now blocked there too
  - Monitor 工具與 plugin monitors 現在也能在 Bedrock、Vertex、Foundry 上使用，關閉 telemetry 或非必要流量時也可用；這些環境同樣會擋下長時間的前景 sleep。
- [Cloud sessions] Added Claude Code cloud sessions and Remote Control permissions to Enterprise custom roles, so Owners can control access to each by role
  - Enterprise 自訂角色新增 cloud sessions 與 Remote Control 權限，Owner 可依角色分別控管。
- [Cloud sessions] Added a Choose file button to load a cloud environment’s setup script from a file
  - 雲端環境的 setup script 可以直接從檔案載入（新增 Choose file 按鈕）。
- Changed the error for an MCP tool call that times out in a non-interactive session while the server’s elicitation is unanswered: it now tells Claude that no answer came and not to repeat the call
  - 非互動 session 中，MCP server 的 elicitation 沒人回應而逾時時，錯誤訊息會明確告訴 Claude「沒有收到回答、不要重複呼叫」。
- [Cloud sessions] Changed turning on Cloud sessions or Remote Control in admin settings to ask for confirmation and list the custom roles that have that permission
  - 管理設定開啟 Cloud sessions 或 Remote Control 時會先要求確認，並列出擁有該權限的自訂角色。
- [Cloud sessions] Changed the cloud environment dialog to open network access, setup script and environment variables from rows instead of listing every editor at once
  - 雲端環境對話框改成一列一列點開網路存取、setup script、環境變數，不再一次攤開所有編輯器。
- Improved auto mode’s prompt before the first read outside the working directories: it now says when blocking those reads makes shell commands ask for permission
  - auto mode 第一次要讀工作目錄以外的檔案時，提示會說明「若擋下這類讀取，shell 指令會改為詢問權限」。
- Improved memory use of non-interactive sessions (-p, Agent SDK) during compaction when the transcript file is very large
  - 非互動 session（`-p`、Agent SDK）在 transcript 很大時，compaction 期間的記憶體用量降低。
- Improved a mod’s Image to draw inside tmux with allow-passthrough and focus-events on, in kitty, Ghostty, and iTerm2 3.5+ with fullscreen rendering
  - mod 的 Image 現在能在開啟 allow-passthrough 與 focus-events 的 tmux 內（kitty、Ghostty、iTerm2 3.5+ 全螢幕渲染）正常顯示，不再只剩 alt text。
- Linux: Improved /sandbox and the sandbox startup warning to name Ubuntu’s AppArmor restriction on user namespaces, and how to lift it
  - Linux：`/sandbox` 與啟動警告會點名 Ubuntu AppArmor 對 user namespaces 的限制，並說明如何解除。
- [Cloud sessions] Improved the session start checklist to show a cloud environment’s setup script output in a scrolling box
  - session 啟動檢查清單會用可捲動區塊顯示 setup script 輸出。
- [Code Review] Improved the Code Review admin section to retry the first load and show one Try again banner when it still fails
  - Code Review 管理頁首次載入會自動重試，仍失敗時只顯示一個 Try again 橫幅。
- Fixed requests failing behind some gateways and compatible servers that reject the effort-2025-11-24 beta value or mid-conversation system messages; Claude Code now retries without them
  - 修正部分 gateway / 相容伺服器拒絕 `effort-2025-11-24` beta 值或對話中 system message 時請求失敗的問題，現在會自動拿掉後重試。
- Fixed background cleanup deleting some recent files, such as pasted images, when cleanupPeriodDays is set to a very large value
  - 修正 `cleanupPeriodDays` 設得很大時，背景清理反而刪掉近期檔案（例如貼上的圖片）。
- Fixed compaction after a “Prompt is too long” error keeping too much of a conversation with dense text, such as base64 or SVG
  - 修正遇到「Prompt is too long」後的 compaction 保留太多 base64、SVG 等高密度文字，導致下一次請求又失敗。
- Fixed file read permission prompts not showing where a symbolic link leads
  - 檔案讀取權限提示現在會顯示 symbolic link 實際指向哪裡。
- Fixed a question’s auto-continue timeout firing the moment the external editor closed after a long edit
  - 修正在外部編輯器長時間編輯後一關閉，問題的自動繼續計時就立刻觸發。
- Windows: Fixed PreToolUse and PermissionRequest hooks letting a tool call through when Git Bash is missing and the hook’s command is only quoted strings
  - Windows：修正缺少 Git Bash、且 hook 指令只是加引號的字串（如路徑）時，PreToolUse / PermissionRequest hook 會放行工具呼叫的問題。
- [VSCode] Fixed pressing Enter on the plan review card’s “Send feedback and keep planning” button approving the plan instead of sending your comments back
  - VS Code：在計畫審核卡片的「Send feedback and keep planning」按 Enter，不會再誤批准計畫。
- [VSCode] Fixed the panel showing “Something went wrong” after “Switch branch & continue” on a cloud session opened from Session history’s Web tab
  - VS Code：修正從 Session history 的 Web 分頁開雲端 session 後按「Switch branch & continue」出現錯誤畫面。
- 其餘修正：Cloud sessions 編輯對話框與 routine API token 操作失敗時會在對話框內顯示錯誤；Claude Tag 修正粗體 / 斜體 / 刪除線的 `!` 指令被當一般訊息、管理頁背景刷新失敗與頻道載入中的誤判；Code Review 管理頁修正刷新失敗後隱藏 repo 清單。

**核心概念（簡單說）：**
這版主軸是「讓 Claude Code 在受限或無人值守的環境更穩」。一方面把 Monitor 工具帶到 Bedrock / Vertex / Foundry 這類雲端供應商與關閉 telemetry 的企業環境，讓背景任務可以用事件驅動的方式等結果，而不是靠長時間 `sleep` 輪詢；另一方面修了一批會讓自動化流程卡住或誤判的邊角問題，例如 MCP elicitation 逾時後 Claude 不斷重試、compaction 遇到 base64 / SVG 這種「高 token 密度」內容又爆掉、Windows 上 hook 在缺 Git Bash 時被意外放行。

可以把它想成前端 CI 的「穩定性修補版」：沒有大新功能，但每一項都對應到真實的失敗情境，特別是那些在半夜跑、沒人盯著的 agent 任務。

**前端工程師實際應用：**
- **跟你工作的關聯：** 前端專案常有大量 SVG icon、base64 inline 圖片，以前把這類檔案丟進對話容易觸發「Prompt is too long」且 compaction 後仍失敗，這版修正後長 session 會穩定許多。
- **具體場景：** 你讓 Claude Code 整理 `src/assets/icons/` 裡上百個 SVG 並轉成 React 元件，途中 context 爆掉；更新後 compaction 會主動丟掉高密度內容，接著跑下一批不會又卡住。若你在 Windows 用 PreToolUse hook 擋 `npm publish`，也記得確認 Git Bash 已安裝，避免 hook 在舊版被繞過。
- **這週可以嘗試：** 執行 `claude update` 後用 `claude --version` 確認到 2.1.310；接著把一個原本用 `sleep` 等 `vite build` 或 Playwright 測試的流程，改請 Claude 用 Monitor 工具監看輸出直到出現 `built in` 或測試結果。
