**原文：**

>
> Quote — ClaudeDevs @ClaudeDevs · Aug 19:
> Claude Desktop now starts ~2x faster than it did a month ago. When the app started in the background, its timers got throttled and the JS engine dropped into power-saving mode. We now boot at full speed even while the window's still hidden, along with some smaller perf fixes!

**繁中改寫：**
Boris Cherny 分享 Claude Desktop 的效能優化：現在啟動速度比一個月前快了約 2 倍。原因是當 app 在背景啟動時，計時器（timers）會被瀏覽器節流（throttle），JS engine 也會進入省電模式，導致啟動變慢。團隊修正後，即使視窗還隱藏在背景，也能以全速啟動，同時還附帶了一些其他效能修正。Boris 表示這類日常會用到的小型體感優化還會持續推出。

**核心概念（簡單說）：**
這是一個典型的「背景頁面節流」問題——現代瀏覽器（以及 Electron-based 的 Desktop app）為了省電，會對不在前景的分頁或視窗降低 timer 執行頻率、把 JS engine 切到省電模式。Claude Desktop 團隊發現這個機制反而拖慢了 app 從背景啟動到可用狀態的時間，於是針對啟動流程做了特殊處理，讓它不受節流影響，啟動速度因此翻倍。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你的 app 是用 Electron 或瀏覽器分頁常駐在背景（例如聊天工具、通知中心），Chrome/V8 的背景節流機制（background tab throttling）很可能也在悄悄拖慢你的啟動或喚醒流程。
- **具體場景：** 一個用 Electron 做的桌面助理，使用者從系統匣（tray）點擊圖示喚醒視窗時，若 app 一直在背景執行 `setInterval` 排程，Chromium 背景節流會讓這些 timer 延遲觸發，導致喚醒後畫面卡頓好幾秒才能互動。
- **這週可以嘗試：** 用 Chrome DevTools 的 Performance 面板模擬把分頁切到背景再喚醒，觀察 `requestAnimationFrame`／`setTimeout` 的實際觸發間隔是否被拉長；若確認有節流影響關鍵啟動路徑，可評估用 Web Worker 或（Electron 則是 `backgroundThrottling: false`）繞過節流。

**原文網址：** [https://x.com/bcherny/status/2089538781909332210](https://x.com/bcherny/status/2089538781909332210)

**原文：**
> Small quality of life improvements like this add up. More on the way
>
> Quote — ClaudeDevs @ClaudeDevs · Aug 18:
> Perf win of the day: Claude Code CLI now uses 2x less CPU at p99. Bun's garbage collector was running on a fixed timer, so it would kick in mid-turn and steal CPU right when Claude Code was busiest. Now it waits until the process is idle.

**繁中改寫：**
Boris 轉發了 Claude Code CLI 的另一項效能修正：p99 CPU 使用量降低了一半。問題出在 Bun 的 garbage collector（垃圾回收機制）原本是用固定計時器觸發，所以常常在 Claude Code 正在忙碌處理一輪對話（mid-turn）時跳出來搶佔 CPU。修正後改成等到 process 閒置時才觸發 GC，避免了這種「最忙的時候被打斷」的情況。

**核心概念（簡單說）：**
這是一個經典的 GC（garbage collection）排程問題。用固定時間間隔觸發 GC，看似公平，但完全沒考慮到程式當下的負載狀態——在最需要 CPU 的時候被迫暫停去清記憶體，等於是雪上加霜。解法是把「定時觸發」改成「閒置時才觸發」（idle-triggered GC），這樣就能把 GC 的成本安排在不影響使用者體感的時間點。

**前端工程師實際應用：**
- **跟你工作的關聯：** 若你的 Node.js／Bun 後端服務或長駐的前端建置工具（如 dev server、bundler）有明顯的 CPU 尖峰（p99 latency 突增），GC 排程時機是常被忽略的排查方向。
- **具體場景：** 一個即時協作編輯器的 WebSocket 後端，在使用者密集輸入的尖峰時段，若 V8/Bun 的 GC 剛好被固定計時器觸發，會造成訊息廣播延遲的毛刺（jitter），使用者會感覺到打字「一頓一頓」。
- **這週可以嘗試：** 用 `--expose-gc` 搭配 `perf_hooks` 觀察你服務在尖峰負載時的 GC 暫停時間，評估是否能改用 `setImmediate`／idle callback 之類機制把非必要的清理工作挪到閒置時段執行。

**變更項目：**
- Added `ANTHROPIC_DEFAULT_MODEL` environment variable：新增環境變數，可設定新 session 預設啟用的模型
- Added `notify_when_idle` to cross-session SendMessage：讓不同 Claude Code session 之間可以互相通知「我閒置了」，一次性、不需輪詢，支援 macOS/Linux
- Sandbox: on macOS, wildcard read-deny rules (e.g. `**/.env`) now take precedence and can't be bypassed by renaming the denied file：macOS 沙箱的萬用字元讀取封鎖規則現在優先生效，且無法透過改檔名繞過
- Fixed clipboard copy、background housekeeping、background sessions 與 local MCP logs 在切換目錄後失效的問題（2.1.229 起的迴歸）
- Fixed the fullscreen renderer failing permanently after a single failed start：全螢幕渲染器一次啟動失敗後，改為自動降級回傳統渲染器而非每次都失敗
- Fixed the `/model` picker rendering taller than the terminal：模型選單現在會依終端機視窗高度自動限制顯示筆數，可捲動查看其餘
- Fixed SendMessage calls being rejected when a malformed closing tag left the message text inside the summary field
- Fixed unhandled promise rejections when a subprocess fails to start（例如 WSL 上停用 Windows interop 時的 powershell.exe，這是 2.1.234 的迴歸）
- Improved auto mode: Monitor allow rules are now set aside while auto mode is active, so Monitor commands are reviewed the same way Bash commands are
- Improved auto mode: the git status check can no longer be fooled by a repo's `status.showUntrackedFiles=no` setting
- `/goal`: an idle session whose goal is parked behind long-running background work now checks in automatically after 30 minutes（之後每 1 小時、2 小時）
- `/usage` now shows the usage-credits spend row for Team and Enterprise members
- [VSCode] Added screen reader support for the transcript：加入螢幕閱讀器支援，含即時語音播報回覆、權限請求、錯誤與逐輪標題導覽

**核心概念（簡單說）：**
這個版本大量修正了跨 session 通訊、沙箱安全性與 UI 渲染的邊角案例 bug，同時強化了 auto mode（自動核准模式）的安全審查邏輯，讓它在企業環境下更難被繞過，另外也為 VSCode 版補上了無障礙（accessibility）功能。

**前端工程師實際應用：**
- **跟你工作的關聯：** 如果你有用多個 Claude Code session 協作（例如一個負責前端、一個負責後端），`notify_when_idle` 這個跨 session 通知機制可以幫你省下手動輪詢確認進度的時間。
- **具體場景：** 你同時開了兩個 terminal 各跑一個 Claude Code session 處理不同的 feature branch，可以請其中一個 session 在完成後透過 SendMessage 主動通知另一個 session，串接成簡易的多 agent 協作流程。
- **這週可以嘗試：** 試著設定 `ANTHROPIC_DEFAULT_MODEL` 環境變數，固定你團隊常用的模型版本，避免每次開新 session 都要手動 `/model` 切換；同時可以測試一下 auto mode 搭配 Monitor 指令的審查行為是否符合你的預期。

**版本號 / 日期：** 2.1.235 / August 18, 2026

**變更項目：**
- Added an optional spellcheck setting：新增選用的拼字檢查，輸入時即時底線標示錯字（使用系統已安裝的 aspell、hunspell 或 ispell）
- Fixed whole-prompt-cache invalidation when a language server disconnected or reconnected mid-session
- Fixed nested markdown list items misaligning at depth 3+，並為換行的清單項目加上懸掛縮排
- Fixed prompt input highlights appearing shifted by one or more characters in some multi-line prompts
- Fixed Shift+Tab inside the permission prompt's comment field approving the edit and granting session-wide edit permission instead of closing the field（修正一個可能誤授權的邊角案例）
- Fixed the Agent tool advertising a general-purpose default in sessions where that agent is unavailable
- Fixed notebook cell delete/replace approval dialogs silently omitting the existing cell content
- Fixed slash commands run while Claude is responding showing HTML entities instead of the actual characters
- Fixed the prompt footer not showing the "Update installed" restart notice after a background auto-update
- Fixed the expanded task list (ctrl+t) always starting collapsed when resuming a session with open tasks
- Improved memory and CPU usage while cloud sessions such as `/ultrareview` or `/autofix-pr` run in the background
- Improved permission dialogs：顯示文字與「don't ask again」選項現在會確保跟實際授權範圍一致
- Improved the embedded grep in native macOS/Linux builds：病態正則表達式（pathological regex）現在會快速失敗而非吃光記憶體
- Vim mode: NORMAL mode and cursor position are now preserved when toggling the detailed transcript
- [VSCode] Fixed focus jumping between open Claude tabs on its own

**核心概念（簡單說）：**
這版持續在打磨 UI 細節與穩定性：新增了拼字檢查、修正多項 markdown 排版與權限對話框的邊角案例 bug，並針對 grep 工具做了防止「病態正則表達式」吃光記憶體的防護，屬於典型的「使用體感打磨」更新。

**前端工程師實際應用：**
- **跟你工作的關聯：** 這裡修正的「權限授權文字要跟實際授權範圍完全一致」的問題，其實是任何有 permission/approval UI 的產品都該注意的細節——顯示的敘述文字若跟實際生效範圍對不上，會造成使用者誤授權。
- **具體場景：** 你在設計一個檔案存取權限彈窗，若「僅本次允許」跟「永久允許」兩個按鈕在某些情境下文字顯示錯誤，使用者可能在不知情下授予了比預期更大的權限，這正是這次修正處理的類型錯誤。
- **這週可以嘗試：** 開啟 Claude Code 的 spellcheck 設定實際試用幾天，同時檢查一下自己專案中若有類似的 permission 對話框，是否也存在「顯示文字」與「實際授權範圍」不一致的風險，列成 checklist 逐一 review。

**版本號 / 日期：** 2.1.234 / August 17, 2026

**變更項目：**
- Added the optional `CLAUDE_CODE_PROJECT_DIR_NAME` environment variable for hosts that give each session its own config directory
- Added the `selection:clear` keybinding action
- Added a GitLab merge request badge to the footer and statusline
- Claude Code now continues your session automatically when a claude.ai usage limit resets（可在 /config 關閉）
- Security: remote file reads, session restore, CLAUDE.md includes, workflow scripts and file uploads now reject Windows NT-namespace (`\??\`) paths（安全性修正：封鎖 Windows NT-namespace 路徑，避免 NTLM 憑證外洩攻擊向量）
- Fixed auto mode in very long sessions repeatedly re-checking and denying sandboxed commands' network access after compaction
- Fixed session-scoped permission answers being dropped when answering background subagent tool permission prompts
- Fixed a crash when an API response on the non-streaming fallback path contained a malformed thinking or text block
- Fixed markdown rendering becoming extremely slow for some messages containing unusual Unicode sequences
- Fixed MCP diagnostics printing resolved secrets：scope-conflict warnings 現在只顯示設定中的 `${VAR}` 形式
- Improved `claude self-hosted-runner` session start time
- Improved apps gateway error forwarding for Vertex, Foundry, and Claude Platform on AWS upstreams
- Todo/task-tracking tools are no longer available on Opus 4.8, Sonnet 5, Fable 5, Mythos 5 and newer models by default（可設定 `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` 恢復）
- Windows: fixed auto mode repeatedly stopping for manual approval on ordinary `cd <dir> && <command> > file` Bash commands（2.1.232 迴歸修正）

**核心概念（簡單說）：**
這版有兩個重點：一是安全性強化——封鎖了 Windows 上一種透過 NT-namespace 路徑（`\??\`）繞過路徑驗證、進而洩漏 NTLM 憑證的攻擊手法；二是把 Todo/task-tracking 工具在新一代模型（Opus 4.8、Sonnet 5 等）上預設關閉，代表官方認為這些新模型不再需要靠外部工具追蹤任務清單。

**前端工程師實際應用：**
- **跟你工作的關聯：** Todo 工具預設關閉這件事，如果你的工作流程或 CI script 有依賴 Claude Code 的 TodoWrite 功能來追蹤多步驟任務，升級後可能會發現行為改變。
- **具體場景：** 你寫了一個自動化腳本，透過 print 模式呼叫 Claude Code 執行多步驟重構任務，並依賴輸出的 todo list 格式來解析進度，這次更新後在新模型上預設不會再產生 todo list。
- **這週可以嘗試：** 若有用到 Sonnet 5 / Opus 4.8 等新模型跑多步驟任務，先確認是否需要設定 `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`；同時留意這次的 Windows NT-namespace 路徑安全修正，若你的團隊在 Windows 上有用 Claude Code 存取敏感檔案，建議盡快升級到此版本以上。
